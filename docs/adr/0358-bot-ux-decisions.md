# 0358 bot の画面の使い勝手: DM のスレッドの返信・失敗の表示とやり直し・失敗の通知・作業中の 1 行と止める・スレッドと DM の ToDo・狭い画面のスレッドの頭と会話内の検索

- 状態: 提案
- 改めた: [0109](0109-bot-and-dispatch.md)（「bot ごとに 1 本の DM の会話（スレッドは作らない）」のうち、DM の流れの投稿の返事は 1 本のまま、DM の**スレッド**の返信だけ別の会話に分ける）
- 使用量の仕組みを外す決定は [0357](0357-remove-bot-usage-mechanism.md)。この ADR は、同じ bot の画面のモックの確認（`temporary/mockups/bot-ux.html`）で決まった残りのうち、実装の形が決まったものを書く

## 状況

bot の画面を実際に使うと、次の 4 つが使い勝手を壊していた。

- **DM の「スレッドで返信」が DM の流れに出る。** DM は bot ごとに 1 本の会話で、スレッドを作らないとしていたため、スレッドへの返信も DM の流れ（1 本の会話）へ届き、返事も流れに出た。チャンネルでは返信がそのスレッドに閉じる（流れには返信の数の行だけが出る）のに、DM だけ違った。
- **失敗が、本文「失敗しました: …」の投稿として並ぶだけ。** 理由が文の中に混ざり、やり直す手段が無い。始められなかった失敗（作業フォルダーが無いなど）は、投稿が 1 つも出ずスレッドの状態だけが変わり、利用者には何も起きなかったように見えた。
- **失敗の通知が、人に見せない bot の中の会話を開く。** 通知を押すと、元のスレッドでなく、bot が内部で動かした会話へ着いた。
- **作業中の表示が 2 か所に割れ、数字が多い。** 返事の場所は「…」だけで、状態は入力欄の上の帯（「Owl が作業中 · 呼び合い n 回 · このスレッドで 12.3k トークン」・予算の %・［止める］）に出た。数字は利用者の判断に使われず、［止める］は通常の会話の中断（送信の横の ■）と違う形だった。

## 決定

- **DM の流れの投稿へスレッドで返信すると、そのスレッドの会話が受ける。**
  - DM の流れの投稿（根）は、今までどおり bot の DM の会話（`bots.ensureDmSession`）が受ける。
  - 流れの投稿への返信（`threadId` = 根の投稿の id）は、**スレッドごとの会話**（`kind: 'thread'`）が受ける。会話は最初の返信のときに作り、`ThreadState.sessions[botId]` に登録する（チャンネルのスレッドと同じ）。返事は同じスレッドへ出る。返信は DM の流れには出ず、流れの投稿の下の返信の数の行だけが変わる。
  - 会話の題は「🦉 Owl › 根の投稿の頭」（DM の会話は「🦉 Owl」のまま）。
  - スレッドの会話は DM の会話とは別なので、根が別の会話のターンの投稿（bot の返事）のときは、その本文を文脈に履歴として受ける（根が人の投稿のときは、チャンネルと同じく、そのスレッドの投稿として届く）。
  - 投稿を運んだ会話を引く `channels.deliveries` は、DM の流れの投稿なら DM の会話、DM のスレッドの返信ならそのスレッドの会話を返す。
- **失敗は、返事の場所に「✕ 失敗 · 理由」と［やり直す］で出す。**
  - ターンの投稿に **`failure`**（理由。1 行・300 字まで）を足す。返事の本文が無い失敗（`state: 'failed'`）に付ける。本文のある失敗（`failedWithBody`。途中までの返事を残したもの）には付けず、本文を返事として残す。ターンの投稿以外には付かない。
  - 始められなかったターンも、返事の場所（スレッド・DM の流れ）に、`state: 'failed'`・`failure` つきのターンの投稿を足す。足せないときだけ、従来どおり Pleiad のお知らせにする。本文「失敗しました: …」は、画面の外の読み手（`channels.read` を使う別の bot など）のために残す。
  - 画面は `failure` を持つ失敗の投稿の本文を出さず、返事の場所に「✕ 失敗 · 理由」を出す。
  - **［やり直す］は、失敗がそのスレッド（DM の流れ）の最後の投稿で、その前に人の投稿があるときだけ出す。** 後ろに何か書かれたら消える（古い失敗を押して、今の話と食い違うことを防ぐ）。押すと、スレッドの返信の失敗は、元の投稿を `channels.resend`（[0157](0157-unify-chat-thread.md)）で送り直す。スレッドの根・DM の流れの失敗は、`resend` が根を送り直せないので、同じ本文をもう一度 `channels.post` する（チャンネルの流れの根は、宛先の bot を `to` に付ける）。
- **作業中は、返事の場所に 1 行「考えている · 12 秒」で出す。**
  - 返事の本文がまだ無い間は「考えている」、書き出したら「書いている」。経過は等幅の数字で、画面に残っている分だけ 1 秒ごとに進める。「…」の本文は出さない。
  - **止めるのは送信の横の ■**（通常の会話の中断と同じ部品・同じ形）。bot が作業中（承認待ちを含む）の間だけ出る。押すと `channels.stopThread`。
  - 止めたら、スレッドに Pleiad の投稿「中断しました」（`state: 'stopped'`）が残り、画面は「■ 中断しました · 17:34」と描く。**誰が止めたかは文に出さず**、`ThreadState.stopped.by` が持つ。
  - **入力欄の上の帯を外す**（作業中の文・呼び合いの回数・スレッドのトークン・予算の %・コンテキストの量）。`ThreadState.tokens`・トークンの書き込み・復元の札 `botCredited` も外す。呼び合いの回数 `ThreadState.calls` は、数えるだけ残し、画面には出さない。
- **ToDo は、スレッドごと・DM ごとに、Chats と同じ部品で出す。**
  - スレッドの頭（検索の前）と DM の頭（ルーティンの後ろ・⋮ の前）に ToDo の入口を置く。押すと Chats と同じ面（`web/session-todo.mjs`。[0342](0342-session-todo.md)・[0344](0344-session-todo-visibility.md)）が頭の下・右に浮く。項目の読み書き・状態・フロー・成果物・AI の変更の知らせは Chats と同じで、新しく描くものは無い。
  - 開く先の会話は、スレッドなら `activeSession()`（そのスレッドで最後に動いた bot の会話）、DM なら bot の DM の会話（`dmSessionId`）。bot の会話が無い間は入口を出さない。スレッドを替えると中身も替わる。
  - bot のページ・ほかの面に、ToDo の集計は出さない。チャンネルの頭にも出さない。
- **狭い画面（700px 以下）のスレッドの頭は、虫眼鏡と ⋮ だけにする。**
  - 右は ☰（脇を開く）・虫眼鏡（会話内を検索）・⋮・✕。ToDo・通話・題の候補（✦）は ⋮ のメニューへ移す。並びは先頭が「ToDo · 2/5 完了」、次が「通話を始める」（使えるとき）、最後が「AI にタイトルを考えてもらう」。Chats の狭い画面の ⋮（`openConversationMenu`）と同じ並び・同じ部品（`host.showMenu`）。AI が ToDo を変えたとき（面を閉じている間）は、⋮ の右上と ToDo の項目の右に未読の点を出す。
  - 入力欄の案内は、狭い画面では「スレッドに返信」だけにする（広い画面は今のまま）。入力欄の下の並び・宛先のチップは今回変えない。
- **会話内の検索の入口を、Chats と同じ虫眼鏡にする。**
  - スレッドの頭の目次のアイコン（「このスレッドの目次」）をやめ、Chats と同じ虫眼鏡・同じ名前「会話内を検索（Ctrl+F）」にする。押すと、今の目次と検索の面（`web/conversation-toc.mjs`）が開き、検索欄にカーソルが入る。目次の機能は外さない（入口を替えるだけ）。
  - スレッドを見ている間の Ctrl+F（macOS は ⌘F）も同じ面を開く（`thread.mjs` が先に受ける。入力欄にカーソルがあっても奪う）。
- **失敗の通知は、元のスレッド（DM）を開く。** 通知の宛先を `{ channelId, threadId?, postId }`（bot の中の会話の `sessionId` は付けない）にし、通知の題は「<bot の名前>の返事が失敗しました」。`postId` は失敗した返事の投稿が引けたときだけ付ける。

## 理由

- DM のスレッドを流れに混ぜない方が、チャンネルと同じ約束（返信はスレッドに閉じる）で、利用者が 1 つの規則で覚えられる。
- DM のスレッドの返信を DM の会話へ届けたままにすると、返信がどの話題のものか bot が区別できず、返事が流れに出る。スレッドごとの会話にすると、チャンネルのスレッドの仕組み（会話の登録・文脈・止める・やり直し）をそのまま使える。足すコードが少なく、DM だけの特別な分岐が減る。
- 失敗の理由を本文でなく欄に持つと、表示を変えられ（本文を隠して理由と［やり直す］を出せる）、本文を読む側（他の bot）には従来の文が残る。
- 始められなかった失敗を投稿にすると、利用者が「返事を待っている場所」に結果が出る。
- ［やり直す］を最後の失敗だけに絞るのは、スレッドの途中の古い失敗を押すと、その後の会話の順序を壊すため。
- 作業中の状態を返事の場所の 1 行に寄せると、利用者が「返事を待っている場所」だけを見ればよい。止める操作を通常の会話と同じ ■ にすると、覚える形が 1 つで済み、足す部品も無い（入力欄の部品に既にある ■ をつなぐだけ）。
- トークン・予算・コンテキストの量は、bot の画面で利用者が判断に使っていない。bot 専用の使用量の仕組みごと外した（[0357](0357-remove-bot-usage-mechanism.md)）ので、画面からも外す。
- 狭い画面の頭に 5 つの入口を並べると、題が「…」でしか読めなくなる。頻度の高い検索だけを頭に残し、残りを ⋮ に寄せるのは、Chats の狭い画面の頭（通話・目次・⋮）と同じ考え方で、メニューの部品も ToDo の項目の作りも既にある。
- 入口の絵と名前を Chats に揃えると、利用者が「会話の中を探す」を 1 つの形で覚えられる。目次のアイコンは、押しても目次ではなく検索欄が先に出る使われ方だったため、虫眼鏡の方が行き先を正しく示す。

## 採らなかった案

- **DM を 1 本の会話のまま、スレッドの返信も同じ会話で受け、返事の置き場所だけ変える。** 会話の中で、流れの投稿とスレッドの返信が混ざり、どちらへの返事か決められない。スレッドごとの会話の方が、既にある仕組みで足りる。
- **DM のスレッドを作れなくする。** 「スレッドで返信」の入口が消え、チャンネルとの違いが増える。
- **失敗した投稿をその場で「考えている」に戻して再実行する。** 根の投稿は `resend` できない（0157）。スレッドの返信と根で動きが分かれるため、どちらも「同じ本文をもう一度送る」に揃えた。
- **作業中の帯を残して「考えている」だけ足す。** 状態が帯と返事の場所に二重になる。
- **止めた人の名前を「<誰>が止めました」で残す。** 止められるのは人か bot で、画面の文は「中断しました」だけで足りる。誰かは `ThreadState.stopped.by` から引ける。
- **失敗の通知を、bot の中の会話のまま開く。** 内部の会話は人に見せないもので、押した先で何が起きたか分からない。

## 影響

- DM のスレッドで返信すると、bot の会話が 1 本増える。DM の流れの会話の文脈（それまでの DM のやり取り）は、スレッドの会話には引き継がれない。スレッドの根が bot の返事なら、その本文だけが文脈に入る。
- DM のスレッドの返信は、web では編集・送り直し・分岐ができない（根の側の制約は変えない）。
- ルーチンが DM で動くときのスレッドの会話の題が「🦉 Owl › ルーチン名」になる（題の付け方が DM の会話とスレッドの会話で分かれた）。
- 止めた知らせの文が「あなた が止めました」から「中断しました」に替わった（`channel.stopped`）。保存済みの古い知らせは、そのままの文で残る。
- 止めたターンの投稿は、文章が残っていれば状態の行を出さない（止めた記録は「■ 中断しました」の行が持つ）。何も書けずに止めたときだけ、返事の場所にも「■ 中断しました」が出る。
- 作業中・あなた待ちの状態の行が、スレッドでも出る（以前は帯が語るため隠していた）。
- 複数の bot が動くスレッドの ToDo は、最後に動いた bot の会話のものを出す（bot ごとに分けて並べることはしない）。DM の ToDo の項目から開く作業の子の会話は、DM の会話を基準にした場所で開く。
- 通知の `target` に `postId` が加わった（`notifications` の `DATA_KEYS`）。保存済みの古い失敗の通知は、押すと従来の宛先へ行く。
- 狭い画面では、スレッドの頭から ToDo・通話・✦ の入口が消え、⋮ の中だけになる（⋮ を押す 1 手が増える）。DM の頭の ⋮ は今も設定を直接開くので、DM の頭の ToDo の入口は広い画面と同じく頭に残す（DM の ⋮ にメニューを足すかは別の判断）。
- スレッドの頭の辞書のキー `channels:thread.entry.toc` を外し、Chats の `nav.toc.entry` を使う。
- `docs/channels.md` は今の形だけを書く。
