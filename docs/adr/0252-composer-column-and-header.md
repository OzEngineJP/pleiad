# 0252 入力欄と履歴を 1 本の列にそろえ、承認モードをモデルの面に入れる

- 状態: 承認（2026-10-22）

## 状況

会話の画面では、履歴の本文と入力欄の箱の左端がそろっていなかった。入力欄の下の行には、添付・宛先とモデル・作業ディレクトリ・「保存済み」・承認モード・送信が並んでいた。箱の先頭には「添付 N 件 ▾」の行と一覧の面があり、文中の札と同じ添付を 2 か所で扱っていた。
承認モードの独立したチップは、既定のままでも常に場所を取っていた。表示の「YOLO」は、何を外すのかが名前から分からない。頭の行の ✦ は題の左で常に場所を取り、目次のアイコンは検索の入口に見えなかった。
可視化は列の幅に収まるので、横に広い図が読みにくかった。デザインの lint は CSS の規則の中だけを見ていたので、`.btn-quiet` に JS が `on` を足して灰色の面に青い字を作る組み合わせを拾えなかった。
ユーザーはモック（推奨の形）を承認した。

## 決定

1. 履歴と入力欄は、中央の 760px の 1 本の列を共有する。発言の左の溝は列の左に固定し、本文の左端と入力欄の左端をそろえる。
2. 入力欄の下の行は［＋］［宛先とモデル］［作業ディレクトリ］…［送信］にする。
   - 「保存済み」は、保存に失敗したときだけ出す。
   - 作業中などの付帯の字は、作業ディレクトリの面の中だけに出す。
   - 「添付 N 件 ▾」の行と、入力欄から開く一覧の面は無くす。文中に無い添付は、字の欄の末尾に札で置く。
3. 承認モードは、宛先とモデルの面の一番下の区分けにし、選んでいる段の 1 行の説明を添える。
   - チップには、既定でないときだけ印を出す（盾と名前を差しの青で、Bypass は ⚠ と強い字）。
   - Chats の欄の独立した承認モードのチップは無くす。スレッドの欄はチップのまま。
   - 宛先に bot を選んでいる間は区分けを押せない。
   - 承認モードは選んだ時点で効き、モデルは次のターンから効く。AI が承認モードを変えられないこと（[ADR 0094](0094-human-only-five.md)）は変えない。
4. 表示の「YOLO」を「Bypass」にする。内部の値（`yolo`・`bypass`）は変えない。
5. ＋のメニューは、ホストの PC の画面を含むどの接続でも、見出し「この端末から」「ホストから」を出す。開いている間、＋は × に回る。
6. 文中の添付の札は、送信中は × と「キャンセル」、失敗は「外す」と「↻ 再試行」にする。一覧の面と一緒に「文中の位置へ移動」も無くす。
7. 頭の行の ✦ は、題にホバー・フォーカスしたときだけ題の右に出す。目次のアイコンは虫眼鏡の「会話内を検索（Ctrl+F）」にする。
8. 可視化のカードの操作の先頭に「広げる」を置く。
   - 押すと本文の領域の右端まで広がり、同じボタン（「元の幅に戻す」）か Esc で戻る。
   - 広げた状態は覚えない。動きは 560ms で、動きを減らす設定ではすぐ切り替わる。
9. デザインの lint について:
   - web/ の CSS を全部検査する。
   - 無彩色の面と `--ink-blue` の字の組み合わせ（`quiet-blue`）を、JS と HTML が組み合わせるクラスも含めて落とす。
   - 役割のある青（リンク・今いる場所・選んでいる印など）は、行の `allow-blue` で残す。

## 理由

列をそろえると、送った発言と書いている文が同じ幅・同じ左端で読める。行に並ぶものを減らすと、狭い幅でも作業ディレクトリと宛先の名前が残る。
添付の入口を札に一本化すると、同じ添付を 2 か所で直す手間が無くなる。承認モードは安全に関わるので、既定から外れたときだけ目立たせ、選ぶ場所はモデルと同じ面にまとめる。説明の 1 行で、何を任せるかを選ぶ前に読める。
「Bypass」は確認を飛ばすことを名前で示す。＋の面を常に同じ形にすると、接続ごとに動きが変わらない。
広げるは読むための一時の操作なので、覚えずに戻せる形にした。lint は、規則の中だけでは見えない実際の組み合わせを見るために広げた。

## 影響

- 保存形式・操作の一覧・承認モードの値と権限は変えない。
- `#modeChip`・`#modePop`・入力欄の添付の入口と一覧、`busySuffix` などの不要な文言を削除する。
- 送った発言の「添付 N 件」の一覧の面（`web/attachment-list.mjs`）は残す。
- 画面の形は design-system.md「入力欄・列の幅・上部」に、lint の規則は §5 に記録する。
