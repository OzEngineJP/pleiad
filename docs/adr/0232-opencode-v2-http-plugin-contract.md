# 0232: OpenCode v2 の HTTP/SSE と専用プラグインへ移行する

日付: 2026-10-18
状態: 提案
関連: [Issue #96](https://github.com/OzEngineJP/pleiad/issues/96)、[ADR 0221](0221-opencode-shared-server-and-plugin-relay.md)、[ADR 0229](0229-opencode-limit-retry-wait.md)

## 背景

OpenCode v2.0.32 は、起動通知、HTTP の URL と応答、イベント、プラグインを変更した。
従来の接続では起動を検出できず、送信や承認も通らない。既存の会話と Pleiad の機能を保って v2 へ移す。

## 決定

- OpenCode v2.0.32 以降の v2 を対象とする。実装の根拠は公式 commit `843a6c514e606b436a7fe713422ace0a93ad3d61`。起動時に製品版と API schema を確かめる。
- HTTP/SSE を使う。ACP は Pleiad が必要とする履歴・分岐・圧縮・保留中の承認・設定の契約をすべて提供しないため主経路にしない。
- `opencode-v2.mjs` が native API を内部の会話形式へ写す。公開 backend メソッドと UI の契約は保つ。v1 wire への恒久的な切り戻し経路は設けない。
- `serve --stdio` を起こし、stdout の JSON から loopback の URL を読む。Basic 認証を使い、保持役が stdin を維持する。
- 送信には Pleiad の発言ごとの安定した ID を使う。受付と会話への配送を分け、HTTP 応答が不明なら inbox と履歴を照合する。途中送信も本文ではなく ID で確認する。
- SSE の再接続では履歴、子孫の会話、保留中の承認・質問、実行状態、inbox を取り直す。差分を履歴に重ねず、終了時の全文で補う。使用量は同じ発言の累計差分だけ足す。
- MCP の配送には OpenCode が付ける `_meta["ai.opencode/sessionID"]` を使う。これは OpenCode 固有の規約。引数に書かれた会話 ID は信頼しない。account ごとの HMAC token と会話の結び付きを両方確かめる。
- 専用の v2 plugin がツール前後の Hooks と指示の注入を担う。Code Mode の外側も都度確認・編集・計画モードの承認にかける。会話の移動と外部 worktree 作成は YOLO に限る。
- 指示・Skills・MCP の担当が異なるターンは、独立した HOME と設定の写しを持つ専用プロセスで動かす。下位の read が追加した native 指示は、Pleiad 担当ならモデルに渡さない。分離できないシステム設定がある場合は開始を断り、担当の変更を案内する。
- 子の会話は native API で親を確かめ、シェルの環境を設定してから通す。plugin の shell hook でも連携用の認証情報を除く。
- 新規 DB の初回復元は公式 credential API を使う。初回取り込みの印と安定した ID で再試行し、既存の資格情報やログアウト済みの DB は上書きしない。
- 下位の指示が圧縮の recent に残った場合も、モデルへ送る前に本文一致で除く。圧縮した HTTP 本文は同じ形式で圧縮し直す。SigV4 署名済みの本文の除去は上流の制約により実行できないため、要求を止めて理由と戻し方を表示する。
- 資格情報は v2 の active 行を優先し、同順位は作成時刻と ID の降順で選ぶ。アカウントごとに HOME・設定・DB を分け、更新済みの DB を古い `auth.json` で上書きしない。

## 会話の移行と更新

旧データがある場合は、CLI を起こす前に SQLite の一貫したバックアップを作る。公式の v1 変換が完了するまで待ち、継続する会話の ID・発言・添付を検証する。変換途中の新テーブルを完全な履歴として扱わない。失われた発言や外部添付を検出した会話は継続を断り、原本とバックアップを残す。

v1 の実行中ターンを v2 の接続層へ渡さない。handover の世代を 2 に上げ、最初の更新は旧サーバーの作業が終わってから切り替える。v2 同士は保持役のプロセスと会話を引き継ぐ。plugin はコールバック先の小さな設定ファイルを毎回読み、新しい Pleiad は MCP の接続先も更新する。

圧縮の受付応答は完了ではない。受付 ID に一致する compaction の `completed` を確認して区切りを作り、`failed` と時間切れは失敗として残す。ファイルの巻き戻しは引き続き Pleiad の snapshot を使う。

## 影響

v1 の利用には CLI の更新が必要になる。コンテキストを Pleiad が担当する間は、共有プロセスの無停止更新ではなくターンの終了を待つ。大きな会話の履歴はページに分けるが、表示用の組み立てには会話の長さに応じたメモリを使う。

MCP の処理中に Pleiad が切り替わると、その呼び出しが一度失敗する場合がある。以降の呼び出しは新しい接続先へ届く。補助の題生成やツール後の Hooks の失敗で、完了済みの処理を失敗に変えない。
