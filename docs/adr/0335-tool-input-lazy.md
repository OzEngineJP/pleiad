# 0335 ツール呼び出しの入力の大きい文字列は頭だけ運び、全文は行を開いたときに取る

- 状態: 提案
- 日付: 2026-11-15
- 関連: [ADR 0182](0182-session-open-window.md)（会話を開くときの窓と提示の遅延。これはその続きで、同じ仕組み・同じ互換の決め方に載せる）、[ADR 0062](0062-incremental-session-load.md)（差分の読み直し）、[ADR 0179](0179-remote-throughput-and-list-size.md)（大きい返事を `/bulk/<id>` で渡す）

## 状況

会話を開くと末尾の窓（50 発言・約 256 KiB。`windowStart`）だけが届く（ADR 0182）。ところが窓の大きさは「窓に入れた発言の JSON の長さ」で数えるので、**1 つの発言に入れたツール呼び出しの `input` が数 MiB あると、窓がそのまま数 MiB になる**。ツールの結果（`result`）は保存のときに 2,000 字へ切ってあるが（`cutToolResult`）、入力は切っていない。コマンド・ファイルの書き込みの本文・MCP の引数（画像の base64 など）が、そのまま運ばれる。

実物（Codex の子の会話 `311efdba…`。11 発言・保存 7.5 MiB）では、窓の返事が **6,095,576 B（5.81 MiB）**で、そのほとんどが 1〜2 件の巨大な入力だった（最大は MCP 呼び出し 1 件が 1.70 MiB）。しかも窓は「最低 6 件は運ぶ」ので、上限の 256 KiB では守れない。

提示（Visualize の本文・画像）は ADR 0182 で、本文を印に置き換えて HTTP で取る形（`lazy`・`/present-body`）にした。ツールの入力には同じ仕組みが無かった。

## 決定

1. **頼みに `lazyInput: true` があるときだけ、入力の大きい文字列を頭だけにして運ぶ**。`lazy` とは別の旗にした。`lazy` を送る画面（ADR 0182 の画面）が、入力の印を読めるとは限らないため。旗の無い頼み（古い画面・リモートの閲覧・チャンネル・保存の写しなど）は、これまでどおり全文を返す。画面は `loadSession`（窓・全量）と上へ送って読み足す `older` の両方で `lazyInput: true` を送る。`lazyInput` だけの頼み（`lazy` も `tail` も無い）は、`lazy` の全量と同じ形（`base: 0`・`total`・`presentBase`・`presentTotal`）で返す。
2. **入力の中の `LAZY_MIN`（2048 字）以上の文字列だけを、先頭 `INPUT_HEAD`（200 字）＋「…」にする**。しきい値は提示の本文（`LAZY_MIN`）と同じ。文字列ごとに数えるので、小さい文字列・数・真偽・キーの名前はそのまま残る。切り口がサロゲートペアの前半なら 1 字手前で切る。入れ子は 16 段まで辿り、それより深い文字列は全文のまま運ぶ（壊れた・悪意のある入力でも全部は辿らない）。写しは変えた枝だけ作り、変えるところが無い入力は同じオブジェクトを返す（`stubMessage` は何も変えなければ発言そのものを返す）。入力のオブジェクトごとに頭・大きさ・署名・量を `WeakMap` に覚え、同じ会話を何度運んでも数 MiB を数え直さない。
3. **印は呼び出しに付ける**: `call.lazyInput = { size, sig, change? }`。`size` は入力の JSON の長さ、`sig` は入力全体の `hash53(JSON.stringify(input))`（`inputSig`）、`change` は行の右端の「−N +M」（下の 6）。運ばないもの: `id` が文字列でない呼び出し（全文を指せない）・入力がオブジェクトでない・`LAZY_MIN` 以上の文字列が無い・**委譲の呼び出し**（`Task`・`Agent`・`collabAgentToolCall`・`subAgentActivity` などのサブエージェントのツールと `ply_delegate`。依頼文を画面の状態から読み〔`requestOf`・`linkDelegateCard`〕、サブエージェントの要約〔`subagentCalls`〕も入力の `description` / `task` / `prompt` を読むので全文のまま）。
4. **署名は運ぶ形で揃える（署名の中立）**。`lazyInput` の頼みでは、サーバーは窓の大きさの数え方・`messageSig` / `anchorSig` を、頭だけにした形（`stubMessage` した発言）で計算する。画面が持っている形（頭だけ）をそのまま `digestOf` で数えるので、サーバーの計算と一致し、差分の読み直し（`syncRequest`）・手前の読み足し（`older`）が成り立つ。全文の形と頭の形が混ざると署名が合わず、差分は全量の窓へ・手前の読み足しは `stale` へ落ちる（壊れずに取り直す）。
5. **全文は `/tool-input?sessionId=…&id=…&sig=…` で取る**。`/present-body` と同じ作りで、`immutable` のキャッシュ・`nosniff`・`Content-Security-Policy: sandbox; default-src 'none'`・`Accept-Encoding` に gzip があれば gzip（`vary: Accept-Encoding`）・HEAD 対応・`/present-body` と同じ認証。見つからない／署名が合わないのは 404、引数が壊れている（`id` が 512 字超など）のは 400（どちらも `private, no-store`）。探す順は、走っているターンの発言（まだ履歴に無い呼び出し）→ 履歴（`backend.getMessages`）で、`id` と `inputSig` の両方が合う呼び出しの入力を JSON で返す（`findToolInput`）。サーバーの検索（`sessionSearch.ingest`）は全文のまま取り込む（頭にするのは返事の写しだけ）。
6. **閉じた行の見た目は変えない**。行の要約・ラベルは入力の先頭の 1 行（160 字まで）を使うので、頭の 200 字で足りる。行の右端の「−N +M」と、まとまりの見出しの「N ファイルを変更」は全文の行数を数えるので、サーバーが全文から数えた量を `lazyInput.change = { path, del, add }` に添える。種類の決め方は画面と同じ関数（`web/tool-change.mjs` の `changeKind` / `changeOf`。画面の `toolChange` もこれを呼ぶ）で、名前（Write / Edit / MultiEdit / NotebookEdit）に加えて、バックエンドが申告したツールの shape（`toolHintsOf`。Codex の `fileChange`・agy の `write_file` / `edit_file`）でも決める。量を持たないと分かっているツールは `null`（画面は何も描かない）、申告が分からず名前でも決まらないときは `change` を付けない（画面が頭の入力から数える）。
7. **開いたときに全文を取り、同じ関数で本文を描き直す**。画面は頭の入力で行を 1 度描き、行を開く（`toggle`。最初から開く行は描いてすぐ）と `fetchToolInput` で全文を取り、`fillBody` が本文だけを全文の入力で描き直す（カードの閉包・時刻の吹き出し・まとまりへの参照はそのまま。選んでいたペインを戻し、すでに付いた結果は `card.toolResult` から付け直す）。取っている間は本文の上に「読み込み中…」の札（`.tc-lazy-note`・`tc-lazy-loading`）を出す。失敗（404・通信）は札を「読み込めませんでした」＋［再試行］に替える（`role="alert"`。失敗は覚えず、再試行で取り直す）。本文の中のコピーのボタン・差分・コマンドは、描き直した全文に対して働く。取った全文は 4 件の LRU に持つ（同じ入力を開き直しても取り直さない。HTTP の `immutable` のキャッシュも効く）。
8. **互換は引数で決める**（ADR 0182 の 5 と同じ）。能力の印も `PROTOCOL_VERSION` / `COMMANDS` の変更も無い。
   - 古い画面 × 新しいサーバー: `lazyInput` を送らないので、全文のまま（これまでと同じ形）。
   - 新しい画面 × 古いサーバー: 古いサーバーは `lazyInput` を知らず無視して全文を返す。画面は持っている形をそのまま数えるので整合する（印が無い呼び出しは、これまでどおり全文で描く）。`lazyInputOf` は印が無い・壊れた呼び出しを「全文」として扱う。
   - 新しい画面 × 新しいサーバーで、窓の途中に全文の発言と頭の発言が混ざる場合: 署名が合わず、差分は全量の窓へ戻る（4）。

## 理由

- 巨大な入力は、運んでも閉じた行の見た目にまったく効かない（要約は先頭の 1 行・量はサーバーが添える）。画面が見るのは開いた行だけなので、開くときに取るのが最小の運び方。実物で窓の返事が 6,095,576 B → 688,949 B（−88.7%）になる（下の測った値）。
- 提示の遅延（ADR 0182）と同じ形（印・`/…-body` の取得・`immutable`・引数で決める互換）にしたので、新しい概念が増えず、`lazy` を送る既存の画面・サーバーが壊れない。別の旗にしたのは、`lazy` だけを送る画面が入力の印を知らないまま頭だけの入力を受け取ると、行を開いても全文が出なくなるため。
- 署名を運ぶ形で揃えるのは、画面が持つ頭の形でサーバーの署名と一致させるためで、これが無いと差分の読み直しが毎回全量に戻る。
- 入力の全文を JSON で返すだけの経路は小さく、`present-body` のテストと審査（認証・CSP・キャッシュ・gzip）をそのまま流用できる。
- 採らなかった案: ① 入力を保存のときに切る（`cutToolResult` と同じ）。履歴・検索・コピーから全文が消え、元に戻せない。② 頼みの形を変えず `lazy` に相乗りする。古い画面が全文を失う。③ 提示の `/present-body` を入力にも使う。提示は会話内の位置（`i`）で引くが、入力は呼び出しの `id`＋署名で引くほうが窓の位置に依らず、署名で取り違えを防げる。④ 大きい文字列を全部サーバー側の別の保存へ移す。記録の形（バックエンドごと）に手を入れることになり、範囲が広い。⑤ 画面が開くたびにサーバーへ WS で取りに行く。HTTP のキャッシュ（`immutable`）が効かず、WS の順序の後ろに並ぶ（ADR 0182 の没案と同じ）。

## 影響

- **測った値**（実物の会話 `311efdba…`〔Codex の子。11 発言・保存 7,898,162 B〕を読み取りだけで。`windowStart` の既定 50 発言・256 KiB）: 窓の返事 **6,095,576 B（5.81 MiB。6 発言・`base: 5`）→ 688,949 B（0.66 MiB。11 発言すべて・`base: 0`）、−88.7%**。頭にした呼び出しは 229 件、入力＋印が 111,051 B。残りの 534,923 B はツールの結果（2,000 字に切った分の積み上げ。この ADR の範囲外）、本文のテキストが 6,615 B。窓が小さくなるぶん、同じ 256 KiB の上限でより多くの発言が 1 つの窓に入る。サーバー側の頭づくりは、初回 23 ms・2 回目以降 1.9 ms（`WeakMap`）。最大の呼び出し（MCP 1.70 MiB）も署名が一致して取れる。
- **入力を読む画面の場所と扱い**: ① 閉じた行の要約・ラベル → 頭で足りる（先頭の 1 行・160 字）。② 行の右端の変更量 → `lazyInput.change`。③ まとまりの見出し「N ファイルを変更」（`tool-bundle.mjs` の `card.toolChange`）・「編集して再送信」の帯の「ファイルを変えた返答が消える」（`resend-band.mjs` の `toolChange` を真偽だけで使う。パスは頭にならないので、頭だけの入力でも同じ答え）→ `change`／頭の入力。④ 開いた本文（コマンド・書き込みの内容・差分・JSON の入力・コピー）→ 開いたときに全文を取って描き直す。⑤ 委譲のカード（`linkDelegateCard`・`requestOf`・`subagentCalls` の `said`）→ 運ばない対象（全文のまま）。⑥ 画面の中の検索（ブラウザーの Ctrl+F）→ 閉じた行・取る前の行は頭しか持たないので、頭より後ろの文字は開くまで見つからない（許容）。脇の検索（`searchSessions`）はサーバー側の全文の索引なのでヒットはする。ただ、抜粋から開いた先で語を強調するのは画面に出ている文字だけなので、取る前の行の頭より後ろの語には付かない。⑦ チャンネル・リモートの閲覧（`core/remote/agent-view.mjs` は入力の文字列を 2 KiB に切る）→ `lazyInput` を送らないので変わらない。
- **行を開くたびの取得**: 2048 字以上の入力を持つ行を最初に開くときは 1 回の HTTP が要る（以降は LRU とブラウザーのキャッシュ）。ふつうの会話（入力が 2 KiB 未満）では取得は起きない。取れなかった行は、頭の本文と再試行のボタンが出る。
- 古い会話の保存・記録の形は変えない。サーバーの検索の索引は全文のまま。
- 試験: `tests/unit/tool-input-lazy.mjs`（頭の形・除外・量・サロゲート・深さ・`serveHistory` / `serveOlder` の有無・署名の中立・DOM の開く／失敗／再試行・古い呼び出し）、`tests/unit/server-tool-input.mjs`（窓・全量・手前・差分の各形・`/tool-input` の状態コードと応答の頭・gzip・HEAD・認証・`findToolInput`）、`tests/unit/history-window.mjs`（配線）。
- 仕様の今の形は `docs/design.md`「会話を開くときの窓」。
