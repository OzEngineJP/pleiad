# 0340 登録した Claude アカウントで claude.ai のコネクターを使う（方式 b1・入口は既定でオフ・段階の出し方）

- 状態: 提案（未承認。段 0・段 1・段 2 の実装は、この決定を縛らない範囲に収めてある。段 2 は試験と手での確認でだけオンにでき、利用者の入口は無い）
- 関係: [ADR 0329](0329-claude-per-account-model-catalog.md)（アカウントごとのモデル一覧）・[ADR 0327](0327-external-mcp-by-name-and-agent.md)（外部 MCP と claude.ai のコネクターの一覧）・[ADR 0270](0270-server-may-die-anytime.md)

## 状況

Pleiad に登録した Claude のアカウント（長期トークン）で動く会話は、claude.ai のコネクター（組織が claude.ai で繋いだ MCP）が使えない。長期トークンの権限にコネクターの読み出しが無いため。ログイン中のアカウントの会話は使える。
段 2 以降の実装は、認証の経路・信頼の確認・MCP の取り込みに触れるので、段 2 を始める前に次を決めておく。決めずに進めると「動くがほかのアカウントの会話へ影響が出る」「古い CLI で黙って別の動きになる」が起きる。

## 決定

### 方式（b1）

- 入口をオンにしたアカウントの会話の子プロセスにだけ、共有の `~/.claude`（`CLAUDE_CONFIG_DIR`）と、使用量のログインで得たアクセストークン（とその scope）を渡す。親（Pleiad 本体）の `process.env` は書き換えない。
- プロフィール（`~/.claude/.claude.json`）には、許可リストの `mcpServers` と、その作業場所の `projects.<root>` のうち許可リストの項目だけを反映する。`oauthAccount`・資格情報・組織の情報は写さない。
- 入口はアカウントごとに 1 つのスイッチ。全体の設定も会話ごとの設定も作らない。コネクターの名前ごとのオフは、同じアカウントの設定に後から足せる形にしておく（段 1 では実装しない）。
- 入口が未設定・オフの会話の起動は、変更前と 1 バイトも変えない。入ってから中でオフを処理する作りにしない（呼び出しの手前で分ける）。

### 確かめた版

- CLI 2.1.322・SDK 0.3.288 で確かめた。確かめていない版では、この機能を有効にしない（入口がオンでも使わない）。版が上がったら確かめ直してから許可の版を足す。

### MCP・信頼・権限の許可リストと競合

- 反映してよいものは許可リストだけ。リストに無い項目（未知の項目・資格情報に近い名前のもの）は反映しない。
- 競合: 同じ名前の MCP が Pleiad の登録・作業場所・利用者の設定にある場合は、既存の側を優先し、コネクターの側は出さない（既存の会話の動きを変えない）。信頼（作業場所の許可）と権限の規則は、反映先に既にある値を上書きしない。
- 許可リストの中身と競合の細目は、下の「段 2 の決定」に書いた（段 2 の実装と同じ変更）。

### 止める条件（黙って古い経路へ戻さない）

次のどれかなら、会話を新しい経路で始めず、理由を通知して止める。古い経路（コネクターの無い動き）へ黙って戻さない（コネクターが使える前提の指示で、使えないまま走るため）。

- ログインの期限切れ（使用量のログインのトークンが更新できない）。
- 持ち主の不一致（登録したアカウントと使用量のログインのアカウントが違う）。
- 確かめていない版（上の版）。
- 対応していない OS（段 4 で OS ごとに出すまで、確かめた OS だけ）。

段 1 だけは例外にする: 入口をオンにする手段が存在せず（画面・書き込みの操作が無い）、利用者は到達できない。設定ファイルを手で置いてオンにした場合の認証の解決は「まだ使えない」を返し、**オフと同じく従来の経路で会話を始める**。段 2 で、この「使えない」を上の止める条件の通知に置き換えた（下の「段 2 の決定」）。

### 保存

- 設定は独立した版付きのファイル（`<データ置き場>/claude-account-connectors.json`。秘密を含まない。設定 › 外部 MCP のコネクターの一覧の覚え（`claude-connectors.json`）とは別のファイル）に置く。アカウントの保存（`claude-accounts.json`）の版は上げない。
- 未設定・読めない・知らない版・知らない値はすべてオフ。段 1 を戻しても、残ったファイルは旧いコードに読まれず、旧いコードの動きに影響しない。
- 保持役・モデル一覧・コネクター一覧のキャッシュのキーは、オンのときだけ識別子の接尾辞を足せる形にする。オフのキーは今までの文字列のまま。

### 段階の出し方

| 段 | 内容 | 出る範囲 |
|---|---|---|
| 0 | 起動の記録（main の値）を試験で固定する | 利用者に出ない |
| 1 | 既定オフの入口（設定の読み取りと、オンのときだけ通る認証の解決の差し込み口） | 利用者に出ない（画面・書き込みなし） |
| 2 | 方式 b1 の実装（実際の認証の受け渡し・プロフィールの反映）を限定して試す | 開発者の手元のみ |
| 3 | 表示と、すべての起動の経路（保持役・付け直し・内部ターン・題・一覧・使用量）への適用 | 限定 |
| 4 | OS ごとに限定して出す（確かめた OS だけ） | 限定 → 一般 |

各段は、前の段の記録の試験（入口がオフの起動が段 0 の記録と同じ）が通ることを条件にする。

### 段 2 の決定

実装: `core/claude-connectors-auth.mjs`（認証の解決・設定の反映・server の組み立て `createClaudeConnectorsWiring`・コネクターの一覧の読み取り `connectorListProbe`）・`core/backends/claude.mjs`（起動の直前に認証を取り直す層）・`core/backends/claude-usage.mjs`（使用量の読み取りの排他）・`core/server.mjs`（入口に認証を差す配線）。試験: `tests/unit/claude-connectors-auth.mjs`・`tests/unit/server-claude-connectors-list.mjs`（server の配線を通した一覧の読み取り）。

**オンにする手段。** 入口の設定（`<データ置き場>/claude-account-connectors.json` の `{ version: 1, accounts: { <id>: { enabled: true } } }`）を、試験と手での確認が書く。画面・ops・CLI・モバイル・デスクトップには出さない（段 3）。オンのアカウントだけが `createClaudeConnectorsAuth` を通る。オフ・未設定・別のアカウント・ログイン中のアカウント・互換の接続先の会話は、この経路を呼ばない（起動の引数と env は段 0 の記録と 1 バイトも変わらない）。

**渡すもの。** 会話の子プロセスの env に、次の 3 つだけを足す。親の `process.env` は変えない。

| キー | 値 |
|---|---|
| `CLAUDE_CONFIG_DIR` | 共有の設定フォルダ（親に `CLAUDE_CONFIG_DIR` があればそれ、無ければ `~/.claude`）。履歴・設定・Skills・プラグインは今までと同じ場所のまま共用する |
| `CLAUDE_CODE_OAUTH_TOKEN` | 使用量のログイン（`claude-usage/<id>/.credentials.json`）のアクセス用トークン。会話用に登録したトークンは使わない |
| `CLAUDE_CODE_OAUTH_SCOPES` | そのログインに記録された scope を、空白区切り・順序そのままで並べたもの |

更新用トークンは取り出さない・渡さない・写さない（ファイルを解析するが、使うのはアクセス用トークン・期限・scope の 3 項目だけ）。オンの経路の差分はこの 3 つに限る。ほかの差分が出たら試験が落ちる。

**更新の持ち主は CLI だけ。** Pleiad は更新用の私的な口を呼ばない。起動の直前に期限を読み、残りが 60 分（`EXPIRY_MARGIN_MS`。この 1 つの定数だけで決める）より短ければ使用量の読み取りを 1 回流して CLI に更新させ、読み直す。それでも短ければ「期限切れ」で止める。資格情報のファイルは CLI が書き換え中に壊れて見えることがあるので、読み取りを 3 回まで間を置いてやり直してから止める。

**期限の余裕を 60 分にした理由。** 期限を確かめるのは起動の直前だけで、起動した子プロセス（保持役が持ち続ける会話の CLI を含む）は、起動のときの env のトークンのまま走り続ける。余裕が 5 分だと、起動から 5 分を過ぎた長いターン・保持中の会話の次の発言の途中で切れうる。60 分は 1 回のターン（長いツールの実行を含む）と、保持中の会話の続けての発言の多くが収まる目安。更新は CLI の通常の口（使用量の読み取り）を期限の 60 分前に寄せて流すだけで、更新用トークンの扱いは変わらない。途中で切れたときに CLI が黙って共有の `~/.claude/.credentials.json`（ログイン中のアカウント）へ切り替えるかは未確認（実機の確認項目。下の「段 2 では未確認・未対応」）。期限の前に保持している子プロセスを起こし直すのは段 3。

**使用量の読み取りの排他。** 入口がオンのアカウントの使用量の設定フォルダには、認証の解決のときに印を付ける（`guardUsageDir`）。印の付いたフォルダの読み取りと CLI の更新（`refreshUsageDir`）は順に流し、同じフォルダを 2 つの CLI が同時に更新しにいかない。印を付ける前から走っていた読み取りも数えておき、更新はそれが終わってから始める。印は入口の設定がオンの間だけ効き、オフにすると次の読み取りで外れて今までの道に戻る。印を付けたことの無いフォルダ・ログイン中のアカウントの読み取りは今までの道のまま（呼んだその場で始まり、待たない）。

**止める条件と文面。** 次のどれかなら、そのアカウントの会話・一覧は理由を付けて断られる（`ConnectorsAuthError` → 既存の `accountUnavailableBackend`）。会話用に登録したトークンへは戻さない（`account.token` を入口でアクセス用トークンに置き換え、起動・一覧は必ず `connectors.fresh()` を通す）。文面にトークン・メールアドレス・組織の id は出さない。

| 種類 | 条件 |
|---|---|
| `login` | 使用量のログインが無い・読めない |
| `format` | 資格情報の形が違う（アクセス用トークン・期限・scope が揃わない） |
| `expired` | 更新させても期限が近い |
| `owner` | 登録したアカウントと使用量のログインの組織が違う・確かめられない（組織の単位。下の「持ち主の確かめの限り」） |
| `version` | CLI・SDK の版が確かめた組（CLI 2.1.322・SDK 0.3.288）と違う、または版を取れない |
| `platform` | Windows・Linux 以外（macOS はキーチェーンの項目名が設定フォルダに依存するので段 4 まで出さない） |
| `env` | 親の環境に別の認証・接続先がある（`ANTHROPIC_API_KEY`・`ANTHROPIC_AUTH_TOKEN`・`CLAUDE_CODE_OAUTH_REFRESH_TOKEN`・`ANTHROPIC_BASE_URL`・Bedrock・Vertex・Foundry などの指定）。共有の設定フォルダの `settings.json` の `env` に同じ指定か、渡す 3 つの名前（`CLAUDE_CODE_OAUTH_TOKEN`・`CLAUDE_CODE_OAUTH_SCOPES`・`CLAUDE_CONFIG_DIR`）がある、`apiKeyHelper` がある。`settings.json` が読めない・壊れている・形が違う（コメント入りを含む）も止める（CLI がどう読むか分からないため） |
| `history` | 履歴の置き場を動かす `CLAUDE_CODE_PROJECT_DIR_NAME` が親か、共有の `settings.json` の `env` にある |
| `profile` | 設定の反映に失敗した |

知らない版は、オンを止める（古い経路へ黙って戻さない）。確かめた版は `VERIFIED_VERSIONS` に足して増やす。

**設定の反映（許可リスト）。** 反映元は CLI が読むホームの `.claude.json`（`cliConfigFile`。読むだけで書かない）、反映先は共有の設定フォルダの `.claude.json`。

- 最上位: `mcpServers` だけ。
- 作業場所ごと（`projects.<キー>`。キーは下の「作業場所のキー」）: `mcpServers`・`allowedTools`・`hasTrustDialogAccepted`・`hasCompletedProjectOnboarding`・`hasClaudeMdExternalIncludesApproved`・`ignorePatterns`。
- 競合: 反映先に既にある値を上書きしない（`mcpServers` は名前ごとに、既存の名前を優先）。足す物が無ければ書かない。反映元と反映先が同じなら何もしない。
- 書き方: 反映先は CLI も書く（プロセスをまたぐ排他は CLI 側の約束に頼れない）ので、CLI の設定の保存と同じ印（`<反映先>.lock` のフォルダ。CLI は proper-lockfile で 10 秒より古い印を捨てる）を取り、最長 5 秒待つ。印の中で読み直して足りない分だけ足し、一時ファイルに書いて名前を付け替える。付け替えの直前に反映先が変わっていたら（印を取らない書き手）読み直してやり直す。Windows の付け替えが一時的に断られたら（EPERM・EBUSY・EACCES）間を置いて 6 回まで繰り返す。書いた後に読み直し、足した項目が無ければやり直す。3 回で収まらなければ `profile` で止める。反映先が壊れている・オブジェクトでなければ書かずに `profile` で止める（`{}` で上書きしない）。
- 両方のファイルの状態（mtime・大きさ・ino）とキーが前に確かめたときと同じなら、ファイルを読まない。
- `oauthAccount`・`userID`・組織・モデルのキャッシュ・資格情報は写さない。ホーム直下の `~/.claude.json` へは書かない。

**キャッシュのキー。** オンのときだけ識別子 `b1`（接尾辞 `:cn:b1`）を足し、オンの保持役・モデル一覧・コネクター一覧をオフと分ける。オフのキーは今までの文字列のまま。アカウントを消す・入れ替えたときのモデル一覧の消去（`invalidateModels`）は、オフのキーと `:cn:` のキーの両方を消す。

**作業場所のキー。** CLI 2.1.322 が `.claude.json` の `projects` のキーを作る規則に合わせる（`projectKeyOf`）。

1. 起動の作業場所を realpath する（CLI が使う JS の実装。大文字小文字は直さない）。
2. そこから上へ、`.git`（フォルダ・ファイル）のある最初の場所。無ければ 1 の場所。
3. そこが worktree（`.git` がファイル）で、`gitdir` → `commondir` → `<共通>/worktrees` → `gitdir` の戻りの指す先（realpath で比べる）がすべて合えば、本体の作業ツリーの場所。一つでも合わなければ worktree の場所のまま。
4. Windows はバックスラッシュを `/` にする。ドライブ文字の大文字小文字は直さない（小文字のドライブ文字で開いた作業場所は小文字のキー。CLI と同じ）。

確かめたもの: CLI 2.1.322 のコード、node の realpath の実験（JS の実装は大文字小文字を直さない）、本物の `~/.claude.json` の既存のキーの形（値は読まない。すべて `/`・ドライブ文字は大文字と小文字の両方がある）。本物には worktree のキーが無かったので、3 はコードからだけ確かめた（実機の確認項目）。CLI がシンボリックリンクをたどる安全性の検査は写していない。その場合は CLI が worktree の場所を使い、こちらは本体の場所へ足す（反映が効かないだけで、ほかの場所の設定は壊さない）。

**持ち主の確かめの限り（組織の単位）。** 持ち主の確認（`ownerStatus`。PR #202 のアカウントの面の持ち主の食い違いの警告と共用）は、会話用に登録したトークンの組織（`/v1/models` の応答の `anthropic-organization-id`）と、使用量のログインの組織を比べる。人の単位では比べられない: 会話用に登録したトークン（`claude setup-token`）の権限は `user:inference` だけで、人を表す id やメールを返す口を呼べず、`/v1/models` の応答にも組織の id しか出ない。このため、同じ組織の別の人のログインは通る（例: チームの組織で、A さんのトークンを登録し、使用量は B さんでログインした場合）。段 2 は開発者の手元だけでオンにするので、この限りのまま進める。段 3 で、オンにするときに使用量のログインの持ち主を利用者に確かめてもらう表示を足す。`ownerStatus` と警告の表示の動きは変えない。

**設定 › 外部 MCP のコネクターの一覧と付け直し。** 一覧は新しい会話の既定のアカウントで読む（`connectorListProbe`）。そのアカウントの入口がオンなら会話と同じ組み立て（`connectors.fresh()`。期限の確かめと 3 つの env）を通し、止める条件に当たればログイン中のアカウントで読み直さず、読めなかった扱いにする（覚えの一覧 `claude-connectors.json` は書かない）。オンの解決の中の想定外の例外（持ち主の確かめが読めない・使用量の設定フォルダを引けないなど）も止める条件に揃える（持ち主の確かめの例外は `owner`、それ以外は `login`。元の文面は出さない）。一覧はそれ以外の失敗をログイン中のアカウントで読むため、ここで揃えないとオンでもログイン中へ落ちる。入口がオフ・アカウントが無いなどは今までどおり。保持役への付け直し（`adoptTurn`）も、会話と同じく起動の直前に `connectors.fresh()` を通す（失敗の文面からトークンを伏せる処理も会話と同じ）。

**段 2 では未確認・未対応。**

- 走っている会話（保持している子プロセス）の途中でアクセス用トークンが切れる場合: 期限の確認は起動の直前だけ（余裕は 60 分）。途中で切れた場合の挙動（CLI が自分で更新するか、黙って共有の `~/.claude/.credentials.json` のログイン中のアカウントへ切り替えるか）は未確認。実機で確かめる。
- 共有の設定フォルダの `settings.json` 以外の設定（作業場所の `.claude/settings.json`・`.claude/settings.local.json`・管理者の設定）の `env`・`apiKeyHelper` は見ていない（段 3）。
- macOS・Linux の実機、複数アカウントを同時にオンにした場合の長時間の確認。

**段 3 に回すもの（段 2 では実装しない）。**

- 期限の前に、保持している子プロセスを起こし直す（途中で切れないように）。
- 作業場所・ローカル・管理者の `settings.json` の別の認証で止める。
- 持ち主の確かめが組織の単位であることの補い（オンにするときに、使用量のログインの持ち主を利用者に確かめてもらう）。
- 入口の画面・ops。

## 理由と捨てた案

- 親の `process.env` を書き換える案は、別のアカウントの会話・走っている会話へ漏れるので捨てた。子プロセスの env だけに渡す。
- コネクターの許可を全体の設定にする案は、アカウントごとに組織が違うので捨てた。
- 版を見ずに有効にする案は、CLI の内部の変更で黙って壊れるので捨てた。

## 帰結

- 段 2 以降の実装はこの ADR を元にし、許可リストの中身・競合の細目が決まったらここへ追記する。
- 承認が出るまで、段 2 以降は実装しない。
