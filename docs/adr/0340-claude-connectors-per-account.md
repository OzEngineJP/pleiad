# 0340 登録した Claude アカウントで claude.ai のコネクターを使う（方式 b1・入口は既定でオフ・段階の出し方）

- 状態: 提案（未承認。段 0・段 1・段 2 の実装は、この決定を縛らない範囲に収めてある。段 2 は試験と手での確認でだけオンにでき、利用者の入口は無い）
- 関係: [ADR 0329](0329-claude-per-account-model-catalog.md)（アカウントごとのモデル一覧）・[ADR 0327](0327-external-mcp-by-name-and-agent.md)（外部 MCP と claude.ai のコネクターの一覧）・[ADR 0270](0270-server-may-die-anytime.md)

## 状況

Pleiad に登録した Claude のアカウント（長期トークン）で動く会話は、claude.ai のコネクター（組織が claude.ai で繋いだ MCP）が使えない。長期トークンの権限にコネクターの読み出しが無いため。ログイン中のアカウントの会話は使える。
段 2 以降の実装は、認証の経路・信頼の確認・MCP の取り込みに触れるので、段 2 を始める前に次を決めておく。決めずに進めると「動くがほかのアカウントの会話へ影響が出る」「古い CLI で黙って別の動きになる」が起きる。

## 決定

### 方式（b1）

- 入口をオンにしたアカウントの会話の子プロセスにだけ、共有の `~/.claude`（`CLAUDE_CONFIG_DIR`）と、使用量のログインで得たアクセストークン（とその scope）を渡す。親（Pleiad 本体）の `process.env` は書き換えない。
- プロフィール（`~/.claude/.claude.json`）には、許可リストの `mcpServers` と、その作業場所の `projects.<root>` のうち許可リストの項目だけを反映する。`oauthAccount`・資格情報・組織の情報は写さない。
- 入口はアカウントごとに 1 つのスイッチ。全体の設定も会話ごとの設定も作らない。コネクターの名前ごとのオフは、同じアカウントの設定に後から足せる形にしておく（段 1 では実装しない）。
- 入口が未設定・オフの会話の起動は、変更前と 1 バイトも変えない。入ってから中でオフを処理する作りにしない（呼び出しの手前で分ける）。

### 確かめた版

- CLI 2.1.322・SDK 0.3.288 で確かめた。確かめていない版では、この機能を有効にしない（入口がオンでも使わない）。版が上がったら確かめ直してから許可の版を足す。

### MCP・信頼・権限の許可リストと競合

- 反映してよいものは許可リストだけ。リストに無い項目（未知の項目・資格情報に近い名前のもの）は反映しない。
- 競合: 同じ名前の MCP が Pleiad の登録・作業場所・利用者の設定にある場合は、既存の側を優先し、コネクターの側は出さない（既存の会話の動きを変えない）。信頼（作業場所の許可）と権限の規則は、反映先に既にある値を上書きしない。
- 許可リストの中身と競合の細目は、下の「段 2 の決定」に書いた（段 2 の実装と同じ変更）。

### 止める条件（黙って古い経路へ戻さない）

次のどれかなら、会話を新しい経路で始めず、理由を通知して止める。古い経路（コネクターの無い動き）へ黙って戻さない（コネクターが使える前提の指示で、使えないまま走るため）。

- ログインの期限切れ（使用量のログインのトークンが更新できない）。
- 持ち主の不一致（登録したアカウントと使用量のログインのアカウントが違う）。
- 確かめていない版（上の版）。
- 対応していない OS（段 4 で OS ごとに出すまで、確かめた OS だけ）。

段 1 だけは例外にする: 入口をオンにする手段が存在せず（画面・書き込みの操作が無い）、利用者は到達できない。設定ファイルを手で置いてオンにした場合の認証の解決は「まだ使えない」を返し、**オフと同じく従来の経路で会話を始める**。段 2 で、この「使えない」を上の止める条件の通知に置き換えた（下の「段 2 の決定」）。

### 保存

- 設定は独立した版付きのファイル（`<データ置き場>/claude-account-connectors.json`。秘密を含まない。設定 › 外部 MCP のコネクターの一覧の覚え（`claude-connectors.json`）とは別のファイル）に置く。アカウントの保存（`claude-accounts.json`）の版は上げない。
- 未設定・読めない・知らない版・知らない値はすべてオフ。段 1 を戻しても、残ったファイルは旧いコードに読まれず、旧いコードの動きに影響しない。
- 保持役・モデル一覧・コネクター一覧のキャッシュのキーは、オンのときだけ識別子の接尾辞を足せる形にする。オフのキーは今までの文字列のまま。

### 段階の出し方

| 段 | 内容 | 出る範囲 |
|---|---|---|
| 0 | 起動の記録（main の値）を試験で固定する | 利用者に出ない |
| 1 | 既定オフの入口（設定の読み取りと、オンのときだけ通る認証の解決の差し込み口） | 利用者に出ない（画面・書き込みなし） |
| 2 | 方式 b1 の実装（実際の認証の受け渡し・プロフィールの反映）を限定して試す | 開発者の手元のみ |
| 3 | 表示と、すべての起動の経路（保持役・付け直し・内部ターン・題・一覧・使用量）への適用 | 限定 |
| 4 | OS ごとに限定して出す（確かめた OS だけ） | 限定 → 一般 |

各段は、前の段の記録の試験（入口がオフの起動が段 0 の記録と同じ）が通ることを条件にする。

### 段 2 の決定

実装: `core/claude-connectors-auth.mjs`（認証の解決・設定の反映）・`core/backends/claude.mjs`（起動の直前に認証を取り直す層）・`core/backends/claude-usage.mjs`（使用量の読み取りの排他）・`core/server.mjs`（入口に認証を差す配線）。試験: `tests/unit/claude-connectors-auth.mjs`。

**オンにする手段。** 入口の設定（`<データ置き場>/claude-account-connectors.json` の `{ version: 1, accounts: { <id>: { enabled: true } } }`）を、試験と手での確認が書く。画面・ops・CLI・モバイル・デスクトップには出さない（段 3）。オンのアカウントだけが `createClaudeConnectorsAuth` を通る。オフ・未設定・別のアカウント・ログイン中のアカウント・互換の接続先の会話は、この経路を呼ばない（起動の引数と env は段 0 の記録と 1 バイトも変わらない）。

**渡すもの。** 会話の子プロセスの env に、次の 3 つだけを足す。親の `process.env` は変えない。

| キー | 値 |
|---|---|
| `CLAUDE_CONFIG_DIR` | 共有の設定フォルダ（親に `CLAUDE_CONFIG_DIR` があればそれ、無ければ `~/.claude`）。履歴・設定・Skills・プラグインは今までと同じ場所のまま共用する |
| `CLAUDE_CODE_OAUTH_TOKEN` | 使用量のログイン（`claude-usage/<id>/.credentials.json`）のアクセス用トークン。会話用に登録したトークンは使わない |
| `CLAUDE_CODE_OAUTH_SCOPES` | そのログインに記録された scope を、空白区切り・順序そのままで並べたもの |

更新用トークンは取り出さない・渡さない・写さない（ファイルを解析するが、使うのはアクセス用トークン・期限・scope の 3 項目だけ）。オンの経路の差分はこの 3 つに限る。ほかの差分が出たら試験が落ちる。

**更新の持ち主は CLI だけ。** Pleiad は更新用の私的な口を呼ばない。起動の直前に期限を読み、残りが 5 分より短ければ使用量の読み取りを 1 回流して CLI に更新させ、読み直す。それでも短ければ「期限切れ」で止める。オンのアカウントの設定フォルダは、使用量の読み取りを順に流す（`guardUsageDir`・`withUsageLock`）ので、同じフォルダを 2 つの CLI が同時に更新しにいかない。オフのアカウント・ログイン中のアカウントの使用量の読み取りは今までの経路のまま。資格情報のファイルは CLI が書き換え中に壊れて見えることがあるので、読み取りを 3 回まで間を置いてやり直してから止める。

**止める条件と文面。** 次のどれかなら、そのアカウントの会話・一覧は理由を付けて断られる（`ConnectorsAuthError` → 既存の `accountUnavailableBackend`）。会話用に登録したトークンへは戻さない（`account.token` を入口でアクセス用トークンに置き換え、起動・一覧は必ず `connectors.fresh()` を通す）。文面にトークン・メールアドレス・組織の id は出さない。

| 種類 | 条件 |
|---|---|
| `login` | 使用量のログインが無い・読めない |
| `format` | 資格情報の形が違う（アクセス用トークン・期限・scope が揃わない） |
| `expired` | 更新させても期限が近い |
| `owner` | 登録したアカウントと使用量のログインの持ち主が違う・確かめられない |
| `version` | CLI・SDK の版が確かめた組（CLI 2.1.322・SDK 0.3.288）と違う、または版を取れない |
| `platform` | Windows・Linux 以外（macOS はキーチェーンの項目名が設定フォルダに依存するので段 4 まで出さない） |
| `env` | 親の環境に別の認証・接続先がある（`ANTHROPIC_API_KEY`・`ANTHROPIC_AUTH_TOKEN`・`CLAUDE_CODE_OAUTH_REFRESH_TOKEN`・`ANTHROPIC_BASE_URL`・Bedrock・Vertex・Foundry などの指定） |
| `history` | 履歴の置き場を動かす `CLAUDE_CODE_PROJECT_DIR_NAME` が親にある |
| `profile` | 設定の反映に失敗した |

知らない版は、オンを止める（古い経路へ黙って戻さない）。確かめた版は `VERIFIED_VERSIONS` に足して増やす。

**設定の反映（許可リスト）。** 反映元は CLI が読むホームの `.claude.json`（`cliConfigFile`。読むだけで書かない）、反映先は共有の設定フォルダの `.claude.json`。

- 最上位: `mcpServers` だけ。
- 作業場所ごと（Git のルートの `projects.<root>`。スラッシュ・バックスラッシュの両方の表記を引く）: `mcpServers`・`allowedTools`・`hasTrustDialogAccepted`・`hasCompletedProjectOnboarding`・`hasClaudeMdExternalIncludesApproved`・`ignorePatterns`。
- 競合: 反映先に既にある値を上書きしない（`mcpServers` は名前ごとに、既存の名前を優先）。変わらなければ書かない。書くときは一時ファイルに書いて名前を付け替える。反映元と反映先が同じなら何もしない。
- `oauthAccount`・`userID`・組織・モデルのキャッシュ・資格情報は写さない。ホーム直下の `~/.claude.json` へは書かない。

**キャッシュのキー。** オンのときだけ識別子 `b1`（接尾辞 `:cn:b1`）を足し、オンの保持役・モデル一覧・コネクター一覧をオフと分ける。オフのキーは今までの文字列のまま。

**段 2 では未確認・未対応。**

- 走っている会話（保持している子プロセス）の途中でアクセス用トークンが切れる場合: 期限の確認は起動の直前だけ。次の起動で取り直す。途中で切れた場合の挙動（CLI が自分で更新するか）は、長い会話での確認が済むまで未確認。
- コネクター一覧の取得（server の一覧の画面）は、段 3 でこの認証へ通す。
- macOS・Linux の実機、複数アカウントを同時にオンにした場合の長時間の確認。

## 理由と捨てた案

- 親の `process.env` を書き換える案は、別のアカウントの会話・走っている会話へ漏れるので捨てた。子プロセスの env だけに渡す。
- コネクターの許可を全体の設定にする案は、アカウントごとに組織が違うので捨てた。
- 版を見ずに有効にする案は、CLI の内部の変更で黙って壊れるので捨てた。

## 帰結

- 段 2 以降の実装はこの ADR を元にし、許可リストの中身・競合の細目が決まったらここへ追記する。
- 承認が出るまで、段 2 以降は実装しない。
