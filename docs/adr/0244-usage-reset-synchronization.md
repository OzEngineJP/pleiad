# ADR 0244: 使用枠のリセット後の取得と表示を同期する

## 状態

承認済み（2026-10-22）

## 状況

使用量の取得中に届いた更新通知が既存の要求へ相乗りして失われ、古い応答が後着すると画面が巻き戻っていた。キャッシュの期限もリセット境界を見ていなかった。期限切れを示す「更新待ち」だけでは、取得中・失敗・再試行を待っている状態を区別できない。

## 決定

- 自動振り分け、設定、札、`ply_usage` は共通の使用枠ストアを読み続ける。
- 取得中の通知を記録し、完了後にまとめて最新 snapshot を読む。通知による読み直しでは外部サービスを取り直さない。ローカル実績の集計を待った応答も、その時点の最新 snapshot を返す。
- snapshot はサーバーの世代と revision を持ち、画面は古い応答を捨てる。再接続では切断前の要求を無効にして同期する。アカウントごとの値の時刻は保持する。
- 通常のキャッシュ期限と最も近い未来のリセット時刻の早い方を使う。画面はリセットと上限解除の直後に通常取得を一度だけ行い、非表示なら復帰時に行う。同じ過去時刻が返っても短い取得ループを作らない。
- 失敗後の行ごとの待ち時間を守る。自動取得を force にせず、人の ↻ だけが待ち時間を飛ばす。読まなかった行は取得中にしない。
- 期限切れは「—」。取得中は「更新中…」と回る ↻、失敗は「取得できませんでした」、成功応答の時刻が過去のままなら「再試行待ち」。暫定 0% や回復の成功メッセージは出さない。動きを減らす設定では回転を止めて文字を残す。
- 上限停止の文言を残し、その行を囲む灰色の面だけを外す。札は有効な枠の最大値を選ぶ規則と幅を維持する。
- 設定の使用量ページは表示中に 60 秒ごとに更新する。

## 影響

リセットの後の実測値と取得の状態が一致する。↻ の押せる範囲を確保し、Esc で札へフォーカスを戻す。失敗時は有効な前回値を残し、別アカウントの値で補わない。画面の規則は [design-system](../design-system.md) の「使用量の札」に記載する。
