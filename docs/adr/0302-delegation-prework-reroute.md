# 0302 自動の委譲が仕事を始める前に断られたら、次の候補へ任せ直す

- 状態: 提案
- 関連: [0229](0229-opencode-limit-retry-wait.md)（上限の待ち・委譲先を外す記録）、[0040](0040-delegation-routing-headroom.md)（委譲の振り分け）、[0164](0164-delegation-effort-tiers.md)（段の強さ）、[0264](0264-delegation-tier-accounts.md)（段ごとのアカウント）、[0089](0089-delegation-worktree.md)（委譲の worktree）、Issue #111

## 状況

- 2026-11-08、一時の会話（`067a7101-…`）から Devin へ自動で委譲した子が、仕事を始める前に Devin 側の一日の使用枠（`cognition.ai/errorKind: resource_exhausted`）で断られ、依頼元には「Devin ACP request failed」とだけ届いた。子は何も出力しておらず、副作用は無かった。
- `de0fb8d2`（fix/acp-resource-exhausted）で、このエラーを `limited` に分類するようにした。`limitedSlots` に載り、振り分け（`route()` の `blocked: slotBlocked`）は同じ委譲先を選ばなくなった。しかし、**委譲のタスク自体は `failed` で依頼元へ届き、やり直しは依頼元のエージェント（または人）の判断に任せたまま**だった。
- 振り分けは、子を作る前の段階（`routeDelegation` の preflight）では候補を順に試して落ちたものを `rejected` に足す仕組みを持つ。だが、選んで・子の会話を作って・`session/prompt` を送った後の拒否には、次の候補へ進む経路が無かった。

## 決定

- **自動の振り分け（`routing.mode === 'auto'`）の最初の回だけ、委譲先が仕事を始める前に断ったと確かめられる失敗を、同じタスクのまま次の候補へ任せ直す。**
  - 対象の失敗: `execute` の結果が `error` または `limited` で、子のターンが何も仕事をしていないとき。
  - 「何も仕事をしていない」の目印: 実行の控え（`newExecution`）に `touched` を足し、子のターンの `text.delta` / `thinking.delta` / `tool.start` / `tool.result` / `activity` 系の出来事が 1 つでも来たら立てる。**経過時間は目印に使わない**（11 秒で落ちても、仕事の痕跡があれば任せ直さない。痕跡が無ければ、長く待たされた後の失敗でも任せ直す）。
  - 経過時間を使わない理由: 時間は「仕事を始めたか」の証拠にならない。短時間の失敗でもプロンプトが届き副作用が起きている可能性があり、別の委譲先へ同じ依頼を出すと作業が重複する。重複は上書き・二重の副作用を招くので、痕跡がある場合は必ず失敗として届ける。
  - `execute` の戻り値に `touched` を添え、`run()` が「任せ直せる失敗か」を判定する。判定は実行の層（`agent-tasks`）に置き、バックエンドの中では行わない。
- **任せ直しの手順（`run()` の最初の回の内側で回す）:**
  1. `execute` が任せ直せる失敗を返す。
  2. `routing.mode === 'auto'` かつ最初の回（最初の依頼の本文。追加指示の回ではない）かつ試行の残があるか確かめる。
  3. `reroute`（`createAgentTasks` の新しい口、server が実装する）を呼ぶ。失敗した候補を `rejected` に足し、`route()` を呼び直して次の候補を得る。`blocked: slotBlocked` はそのまま効くので、`limited` で記録済みの委譲先はここでも外れる。
  4. 次の候補が取れたら、その委譲先で新しい子の会話を作る（`prepare` の子の会話を作る部分を、候補を替えて再利用する。worktree は新しく作らず、タスクのものを継ぐ。アカウント・接続先・強さの決定は自動のときと同じ規則）。
  5. タスクの記録を新しい会話・委譲先・振り分けへ書き換え（`record` と `bySession` の対応付けも）、同じ依頼の本文で `execute` をやり直す。
  6. 任せ直せる失敗でない・候補が尽きた・上限の回数に達したら、今までどおり失敗として届ける（`routing.exhausted` と同じ集計の文面でなく、最後の失敗の形で）。
- **試行の上限は 2 回の任せ直し（合計 3 候補まで）とする。** 全候補をなめ尽くすまで試さない。断られ方が同じ原因（アカウント全体の枠・CLI の不具合）でも回り続けないための上限で、候補が尽きる方が先ならそこで終える。
- **失敗した回の記録は残す。** タスクの `routing.attempts` に `{ target: { backend, model, account }, sessionId, outcome, error }`（`error` は完了通知に載せるのと同じ、安全に伏せた文言）を足していく。新しい子の会話の `routing` データにも同じ `attempts` を書く。失敗した子の会話は消さない（失敗の経緯が残るようにし、`delegation` のデータに `superseded: <新しい sessionId>` を添えて、任せ直しで役目を終えたことが分かるようにする）。`ended(oldSessionId)` は交換の時点で呼び、ブラウザーのデーモンなどを片付ける。
- **委譲カードと `ply_task_status` は `routing.attempts` をそのまま出す。** 完了通知には、任せ直しが起きたときだけ短い 1 行（「<元の委譲先> は <理由> で断られたので、<新しい委譲先> へ任せ直した」の形、辞書のキーを足す）を添えて、依頼元が実際に走った委譲先を見間違えないようにする。
- **任せ直さないもの:**
  - 固定・ピン留めの委譲（`routing.mode === 'auto'` 以外。依頼元が `backend`/`account` を書いたもの、人が委譲カードで選んだ `mode === 'manual'` のやり直し）。
  - 最初の回以外（`ply_task_send` の追加指示。会話には文脈が積まれているので、別の委譲先へ移すと失われる）。
  - `requeue`（別のターンが走っている。`undelivered` 含む、送ったか分からないままのものも。重複を防ぐ既存のルールを変えない）。
  - `aborted` / 取り消し。
  - 付け直したターン（`adoptRun`。起動の復元で引き継いだ回。v2 で検討する）。
  - リモートのホストに任せたタスク（`row.host`。振り分けはホスト側の仕事）。
  - `prepare` の時点で落ちたもの（子の会話が作れなかった・モデルが一覧に無い。今回は `session/prompt` 以後の拒否だけ。作る前に落ちる系は preflight の `rejected` の仕組みの延長として別途）。

## 理由

- 「上限で断られた」は、今の委譲先ではなく別の委譲先で仕事が進められる失敗の典型。仕事が 1 行も始まっていなければ、別の候補で同じ依頼を出しても重複しない。依頼元へ失敗として届けて判断を委ねると、依頼元のエージェントが同じ指示をもう一度組み立てて送る往復（1 ターン分のコストと時間）が要る。
- 「仕事を始めた」以後の失敗は、途中の出力・副作用が分からないまま別の委譲先で同じ依頼を出すと、書きかけの変更が 2 箇所に分かれる・同じ副作用が二度起きる。痕跡が 1 つでもあれば失敗として届けるのが安全。
- 試行の回数に上限を置くのは、同じ断られ方（アカウント全体の枠など）で候補をなめ尽くすのを防ぐため。`route()` の `skipped`/`rejected` の仕組みに乗せるので、同じ候補を二度選ぶことも無い。
- 失敗した子の会話を残すのは、「どの委譲先が・どう断られたか」の記録が画面と調査の両方で役立つため。消すと任せ直しの理由が追えなくなる。

## 影響

- `core/server.mjs`: `newExecution` に `touched`、出来事の集めで立てる。`execute` の戻り値に `touched`（または任せ直せる印）。`reroute`（候補を再選し、子の会話を作る。`prepare` の会話を作る部分の再利用）と、`route()` の呼び直し（`rejected`・`blocked`）。
- `core/agent-tasks.mjs`: `run()` の最初の回の任せ直しのループ（上限・記録の書き換え・`bySession`・`ended`）、`createAgentTasks` の `reroute` の口、完了通知の 1 行、`routing.attempts`。
- `web/locales/*/agent.json`（または対応の辞書）: 完了通知の任せ直しの 1 行のキー。
- `docs/agent-delegation.md`: 任せ直しの条件・上限・記録。
- テスト: 偽のバックエンドで「断られ→次の候補で成功」「仕事の痕跡があれば任せ直さない」「固定では任せ直さない」「上限で打ち止め」「`limitedSlots` に記録された委譲先を次でも外す」。
