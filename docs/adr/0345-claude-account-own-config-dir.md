# 0345 登録した Claude アカウントの会話の子 CLI に、アカウント専用の設定フォルダを直接渡す（方式 b1 の置き換えの提案）

- 状態: 承認（2026-11-20。段 1 まで。段 2 は別に承認を取る）

## 状況

[ADR 0340](0340-claude-connectors-per-account.md) の方式 b1 は、会話の子 CLI（コマンドラインで動く Claude Code）に共有の `~/.claude` と、アカウント専用フォルダ `~/.agent-host/claude-usage/<id>/` から読んだアクセス用トークンを `CLAUDE_CODE_OAUTH_TOKEN` として渡す。子 CLI は渡されたトークンを更新できず、起動時の値を使い続ける。Pleiad は `fresh()` による起動前の期限確認と更新依頼、タイマーによる保持中の子 CLI の再起動、ログイン切れの印を管理し、本人照合と `projectProfile` による設定の反映も行う。

CLI が更新を始めるのは期限の約 5 分前だが、Pleiad は約 60 分前から更新を求めていたため、残り 5〜60 分で「期限切れ」と誤判定し、会話を始められなかった。0.42.7 で 60 分前の更新要求をやめて修正した。Pleiad による期限管理は残っている。

## 決定

- コネクターをオンにしたアカウントの会話では、子 CLI の `CLAUDE_CONFIG_DIR` にアカウント専用の設定フォルダを渡す。`CLAUDE_CODE_OAUTH_TOKEN` と `CLAUDE_CODE_OAUTH_SCOPES` は渡さず、CLI が専用フォルダのログインを使って自分で更新する。
- 専用フォルダの `projects/`（履歴）・`skills/`・`plugins/` は共有の `~/.claude` の対応する場所へジャンクション（Windows）またはシンボリックリンクで向ける。`settings.json` はファイル用のシンボリックリンクで共有する。アカウントを分離するため、`.claude.json` と `.credentials.json` は専用フォルダに置く。Pleiad はリンクを作成・維持し、アカウントを削除するときはリンクだけを解除する。
- Pleiad 本体は、会話一覧・履歴・使用量の集計・コンテキストの走査・フック・プラグイン一覧をこれまでどおり共有の `~/.claude` から読む。リンクしたデータは子 CLI と同じものを参照できる。
- 専用フォルダ方式では、トークンの取り出しと受け渡し、期限判定と更新依頼、期限タイマーと保持中の子 CLI の再起動、期限による起動前の停止を廃止する。ログイン切れの印は、CLI が認証失敗を返したときの画面表示に限って残す。
- 許可リストに基づく外部ツール接続（MCP）・作業場所への信頼・権限の引き継ぎは、反映先を専用フォルダの `.claude.json` に変えて続ける。反映処理の書き手は一つにする。
- CLI が専用フォルダのログインを直接使うため、渡したトークンと設定フォルダの食い違いを検査する必要がなくなる。識別ハッシュによる本人照合と初回確認のうち、何を残すかは実装前に決める。
- アカウント解決の順序を変え、コネクターをオンにしたアカウントで専用フォルダ方式を選んだ場合は、登録済みの会話用トークンを求めず専用ログインだけで起動できるようにする。
- 段 1 では方式 b1 と並べて追加する。コネクターをオンにしたアカウントだけが入口のスイッチで方式を選べ、既定は b1 とする。段 2 では実運用で問題がないことを確かめてから専用フォルダ方式を既定にし、b1 の仕組みを削除する。段 2 は別の ADR または ADR 0340 の置換で承認を取る。

## 理由

- CLI に期限管理を任せると、Pleiad の独自判定に起因する起動停止を解消できる。Pleiad はトークンを持ち運ぶ必要がなくなり、更新用トークンを扱わず子 CLI にも渡さない構成になる。
- Pleiad が更新用トークンで直接更新する案は採らない。使い捨ての更新用トークンは、更新後の書き込みに失敗するとログインを失う。Anthropic の更新先を直接呼ぶ実装は仕様変更の影響も受ける。0.42.7 と同様に期限判定を弱めるだけの案は、独自判定が残るため採らない。

実機確認は 2026-11-20 に Windows、Claude Code 2.1.328、Claude Agent SDK 0.3.288 で行った。使い捨ての新しいログインを使い、実アカウントのログインは複製・変更していない。

- 会話用トークンなしで `accountInfo()` が本人情報を返した。`mcpServerStatus()` には claude.ai のコネクターが現れ、Claude Docs・Google Drive・Slack は `connected`、Notion は `needs-auth` だった。短いターンも通った。
- `projects/`・`skills/`・`plugins/` のジャンクションと `settings.json` のファイル用シンボリックリンクを使うと、会話の記録が共有の `projects/` に作られた。ログインのない別の設定フォルダから SDK で一覧を取得し、記録を読めた。
- ファイル上の期限（`expiresAt`）を約 3 分後にすると、CLI がターンの前に更新した。約 8 分後に設定し、ターン中の 9 分の待機が期限をまたいだ場合も、待機の終了直後に CLI が更新して同じ会話が続いた。
- 期限を約 3 分後にして同じ専用フォルダで CLI を 2 つ同時に起動すると、両方が成功し、その後のターンも通った。`readClaudeUsageNow` と同じ SDK 呼び出しによる使用量の読み取りと会話の同時実行は、1 回の試験で競合しなかった。
- サーバー側で実際にトークンが失効したときの挙動、同時更新を繰り返したときの再現性、Pleiad 本体を通す使用量取得と会話の同時実行、macOS・Linux での動作は未確認。期限の試験はファイル上の `expiresAt` を変更してクライアント側の判定を再現した。

## 影響

- `core/claude-connectors-auth.mjs` の `createClaudeConnectorsAuth` と `fresh()` から、専用フォルダ方式のトークン受け渡し、期限確認、更新依頼を外す。b1 の廃止時に、その方式向けの `readAccessCredentials` による読み取りも削る。`projectProfile` の反映先を専用フォルダに変え、`createConnectorVerification` で残す検査は実装前に決める。
- `core/backends/claude.mjs` の `withConnectorsAuth` と `probeClaudeConnectors` は、専用フォルダを子 CLI に渡す。専用フォルダ方式では `onExpiryReached` と `scheduleExpiryTimer` による再起動を使わず、b1 の廃止時に削る。
- `core/server.mjs` の `accountResolve` は、専用フォルダ方式で会話用トークンの取得を先に求めないようにする。`markConnectorsLoginExpired` で付ける印は、専用フォルダ方式では CLI の認証失敗を画面に出す用途に限る。
- 共有側では履歴の同時追記、設定やプラグイン登録の同時更新が起こりうる。リンクの作成権限（特に Windows のファイル用シンボリックリンク）、アカウント削除時にリンク先を残せること、既存の b1 の会話を専用フォルダ方式で再開できることは未確認。履歴の保存先は共有の `projects/` のままとする。
