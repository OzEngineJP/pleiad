# 0359 bot の記憶を 3 段に分け、要る分だけ AI へ渡す

- 状態: 承認（2026-11-26）
- 改める: [0110](0110-bot-memory.md)（核の写しと夜の整理の渡し方）、[0118](0118-memory-strength-and-learner-runs.md)（段の付いた記憶への重みの使用）
- 根拠の調査: `temporary/reports/memory-stage2-status.md`、`temporary/reports/memory-quality.md`、承認済みの計画 `temporary/mockups/memory-update/plan-v2.html`（2026-11-26）

## 状況

段階1の記憶は、夜の整理が 1 回の呼び出しに既存の記憶を全部入れていた。2026-11 の実データの写しでは記憶が 1,907 件あり、1 回の呼び出しの記憶部分だけで約 253k トークンになっていた。会話の始まりに渡す量は層ごとの目安で抑えられていても、夜の整理は新しい発言より既存の記憶の方がずっと大きく、整理の費用と時間を支配していた。

中身を調べると、長く効くものは 3 割、特定の作業場所や題材にだけ効くものは 4 割弱、その場限りの経過や約束は 3 割だった。重みは 58% が 3 で、低い重みにも一般的な記憶が多く、振り分けの根拠には使えなかった。約束は 367 件（開いたまま 364 件）あり、記憶のかなりの部分を占めていたが、約束や作業の経過は会話ごとの ToDo と bot の気がかりに置く仕組みが別にできていた。

## 決定

- **記憶を 3 段に分ける。** 行のメタに段 `tier` と作業場所 `ws` を足す。新しい保存先・表・常駐処理は作らない。段の無い既存の記憶は、振り分けが済むまで従来どおりの渡し方にする。
  - `always`（画面は「いつも」）: 作業場所に関係なく守るもの。会話の始まりに毎回、上限まで渡す。
  - `workspace`（画面は「この作業場所で」）: あるリポジトリ・フォルダーの中でだけ意味のあるもの。その作業場所の会話のときだけ渡す。
  - `archive`（画面は「保存だけ」）: その場限りの記録。消さずに残すが、会話・`memory.search`・夜の整理のどれにも AI へ渡さない。人は記憶の一覧で見て、上の段へ戻せる。
- **作業場所は覚えた会話のフォルダーから決める。** git の作業木ならリポジトリの根へ寄せ、worktree なら本体の作業木へ寄せる。リポジトリでない場所は作業場所なし。段だけの変更では `updatedAt` を動かさない。
- **新しい記憶の既定。** 人が書いた記憶は `always`。bot が書いた記憶は段を指定し、無ければ会話に作業場所があれば `workspace`、無ければ `always`。夜の整理も読んだ会話の作業場所から段と作業場所を付ける。
- **会話の始まりと圧縮の後に渡す量。** `always` は 6,000 トークンまで、今の作業場所の `workspace` は 3,000 トークンまで。段の無い記憶は従来の層ごと 1,200 トークンのまま。上限を超えたときは、人が書いた・直した記憶 → やめたこと → 新しく更新した順に入れ、入らない分は件数だけ伝え、関係する話のときに渡す。段の付いた記憶には重み・薄れを使わない。
- **ターンの末尾と検索。** 前のターンからの差分は 20 件まで。関係する記憶は 5 件まで、始まりに入りきらなかった `always` と今の作業場所の `workspace` から渡す。`memory.search` は `archive` だけを外し、ほかの作業場所の `workspace` も探したときは出す（8 件まで）。同じ内容をもう覚えていないか・忘れると指定した内容ではないかの確認は、AI に全件を渡さずコードが全件（保存だけ・忘れたものも含む）と照らす。
- **約束と作業の経過は記憶に書かない。** bot が会話の中で約束を記憶へ書こうとしたら断り、スレッドに ToDo があれば ToDo へ、無ければ気がかりへ置くよう返す。夜の整理が会話の中に約束を見つけても、記憶にも気がかりにも書かない。既存の約束は AI を使わずコードで `archive` にする。ToDo・気がかりへは写さない（消さない前提と、開いた気がかりの上限が合わないため）。
- **一度きりの振り分けは人が始める。** 設定 › 記憶の「振り分けを始める」からだけ走る（自動整理がオフでもよい）。まずコードで約束を `archive` にし、残りを 50 件または本文 8,000 トークンごとに AI へ送る。送るのは本文・理由・種類・覚えた作業場所の名前だけで、返すのは id・段・短い理由だけ。本文は書き換えない。知らない id・壊れた返事は捨て、その件は段なしのままにする。`workspace` と答えたが作業場所をコードが決められない件は `archive` にし、理由を残す。
- **振り分けは止められる・続けられる・戻せる。** 1 回ごとに段を書いてから進み具合を保存する。アプリを閉じても済んだ所は残り、続きは「この振り分けで段が付いた件」を飛ばして始める。同じ小分けが 2 回続けて失敗したらその件は段なしのまま次へ進む。何回目の振り分けか・始めた時刻・済んだ件数・段ごとの件数・失敗した件数は `memory_state` に置く。1 件ごとの前後の段は変更記録に残し、「この振り分けを戻す」はその振り分けが付けた段を外す。振り分けの後に人が直した件は戻さない。
- **夜の整理は「増やす」から「選び直す」へ変える。** 既存の記憶を全部は送らず、`always`（上限内）と、読む会話の作業場所の `workspace` のうち関係する候補だけを 12,000 トークンまで送る。新しく覚えるのに加えて段の付け直しも 1 回 20 件まで行い、結果に段を変えた件数を出す。重みは段の振り分けと配送に使わない。

## 理由

- 記憶の大半は、毎回の会話や整理に要らないものだった。段で先に絞れば、AI の出力品質を保ったまま入力を大きく減らせる。意味検索や新しい保存先を足す前に、既存の文字検索で足りる範囲へ問題を小さくできる。
- 保存だけにして消さないのは、誤った振り分けを人が戻せるようにし、記憶の正本・変更記録・元の会話を消さない前提を保つため。
- 約束を記憶に混ぜると、終わった作業が毎回の文脈を食い、本当に長く効く決まりが押し出される。一方、既存の約束を今さら ToDo や気がかりへ写しても見る場面がなく、気がかりの上限で古いものが手放される。保存だけが「消さない」と両立する。
- 作業場所は、リポジトリの worktree が同じ題材として扱えるよう canonical な根に寄せる。フォルダーそのものをキーにすると、同じリポジトリでも worktree ごとに記憶が分かれる。
- 振り分けを人の明示操作にするのは、費用と時間が分かる大きな一括処理だから。バッチごとに保存すれば、失敗やアプリの終了で最初からやり直さなくて済む。段だけではなく前後を変更記録に残すので、まとめて戻せる。
- 重みは実データで識別力を失っていた。段が渡す範囲を決めるようになった後も重みで配送を絞ると、人が付けた段を重みが事実上上書きする。段の無い古い記憶だけ、移行の間は従来の強さで扱う。

## 影響

- 記憶の markdown のメタに `tier`・`ws` が増える。版の印 `pleiad-memory v1` は変えず、知らないキーを残す今の仕組みで古い版に戻しても段は消えない。データ置き場の形式番号は変えない（DB の表は変わらず、`memory_state` に振り分けの状態が増えるだけ）。
- `memory.write`・`memory.edit`・`memory.list`・`memory.search` の入出力に `tier`・`workspace` が増える。人が書いた行の段・作業場所を AI が変えるのは、本文・種類と同じく承認が要る。
- 会話の始まりに渡る量は、段が付いた記憶では従来の計 2,400 トークンから最大 9,000 トークンへ増える。増えるのは長く効く記憶を一度に見せるためで、無関係な作業場所・保存だけは入らない。入りきらない件数は設定 › 記憶に出す。
- bot が約束を `memory.write` へ書いても記憶は増えず、ToDo または気がかりへ移される。既存の promise は一覧では「保存だけ」に見える。
- 夜の整理の入力は大きく減るが、段が未振り分けの記憶は従来どおりの扱いが残る。効果を完全に出すには、リリース後に人が設定 › 記憶から一度きりの振り分けを始める必要がある。
