# ADR 0347: チャットの送信を会話ごとに受け付け、準備と配送を後で行う

## 状態

承認済み（2026-11-23）。第 1 段はチャットの入力欄と作業場所の作成が対象。

## 状況

チャットの入力欄は会話間で共有する。会話の作成、設定の保存、worktree の作成が終わるまで待ってから欄を読むと、その間に別の会話を開いた場合に送信を続けられない。送信待ちの読み書きも、配送の準備が終わるまで同じ会話で待たされていた。

## 決定

- 画面は送信を押した時点で宛先、メッセージ ID、本文、添付の順序と文中の位置、設定、下書きの版を確定する。受付確認後は送った版だけを片付ける。
- ホストは会話の送信待ちに項目を永続化して受付を返す。設定の適用と worktree 作成は配送側で進め、準備中も一覧取得と配送前の取り消しを受け付ける。再起動時は配送前の項目を続ける。配送開始後の結果が確認できない項目は「届いたか不明」として扱う。
- 会話の作成要求には画面が発行した要求 ID を使う。ホストは正式な会話 ID と要求 ID の対応を保存する。作成の再試行では同じ会話を返し、送信の再試行では会話の送信待ちに保存した同じメッセージ ID の項目を返す。
- 通常のターンと途中送信はその項目の設定を使う。後から選んだ設定は次の送信で使う。使えなくなった接続先やアカウントはその項目の失敗理由にする。

## 理由

会話を切り替えても、開始時に確定した対象に処理を続けられる。受付と準備の時間が分かれ、画面や接続が切れても同じ ID で受付を確かめられる。

## 影響

入力欄と配送の見え方は [design-system.md](../design-system.md) の「入力欄の待ち」「作業中の設定の変更」に記載する。既存の送信待ちの項目は従来の設定の取り込み方で動く。ADR 0326 の「待ちの間に別の会話へ移ったら送らずに知らせる」動きと、その記録 `submit-switched` は外した。
