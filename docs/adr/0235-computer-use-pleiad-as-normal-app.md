# 0235. Computer use で Pleiad を通常のアプリとして扱う

状態: 承認（2026-10-20）

## 状況

Windows では、Pleiad の子孫プロセスをすべて `self` と判定していた。`open_application` やエージェントのシェルから起動した一般の GUI アプリも禁止され、起動前に与えた承認が起動後に効かなくなる（[#110](https://github.com/OzEngineJP/pleiad/issues/110)）。

Pleiad 自身も常に禁止していたが、Pleiad を操作するツールはすでに同梱しており、画面操作だけを一律に禁止する必要はない。

## 決定

- Windows・macOS とも、Pleiad を通常のアプリと同じ承認の対象にする。未許可なら確認し、許可・拒否・確認なしのモードを通常どおり適用する。
- `self` はアプリを識別する情報として残し、禁止や入力拒否には使わない。Windows の識別は同じ PID・実行ファイルに限定し、任意の子孫を含めない。
- Pleiad の exe・バンドル ID を禁止一覧から外し、入力直前の Pleiad 専用の拒否をなくす。
- ターミナル・パスワード管理・セキュリティソフト・OS の保護された画面・ほかのエージェントの禁止は維持する。対象アプリの変化・昇格・停止の検査も維持する。

## 理由

アプリを誰が起動したかで承認の扱いが変わると、許可したアプリを操作できなくなる。起動経路による例外登録ではなく、操作対象のアプリに承認を適用する。

## 影響

[ADR 0071](0071-computer-use-approval-and-safety.md) の Pleiad の禁止と、[ADR 0173](0173-computer-use-macos.md) の `self` による禁止を、この範囲で置き換える。設定画面・指示文・拒否時の説明も、Pleiad を禁止対象に含めない。
