# ADR 0222: 登録アカウントと接続先ごとの使用枠

日付: 2026-10-18

## 状態

提案

## 状況

会話・委譲・使用量に散っていた Claude 専用の分岐を広げると、資格情報を選んだのに履歴や候補生成だけ別のログインで動くおそれがある。認証の保存方法はエージェントごとに違うため、共通の台帳と、認証を使うバックエンドを分ける。

## 決定

- 能力 `accounts` は `false`、`'token'`、`'agent'`。全バックエンドが明示する。`'token'` は既存の Claude の台帳とトークンをそのまま使う。`'agent'` は `accountLogin`・`accountStatus`・`forAccount` を必須とする。
- 共通の台帳は `agent-accounts.json`。最大100件で、ID・エージェント・表示名だけを保存する。資格情報は `agent-account-secrets.json` に既存の暗号器で保存し、画面・イベント・会話の記録へ返さない。CLI 自身が資格情報ファイルを必要とするときは、専用ディレクトリで所有者のみにアクセスを制限する。
- アカウントの追加・名前変更・削除・ログイン・取消は操作の一覧 `accounts.*` に定義し、人の画面だけに出す。会話や委譲は、人が登録したアカウントを選べる。空の選択は現在の CLI ログイン。削除済み・未ログインの選択から現在のログインへ黙って戻さない。
- 保存済みの会話の欄 `claudeAccount` は互換性のため残し、全エージェントで使う。新しい会話の既定は `prefs.backends[id].account`。Claude の既存の既定値も読む。
- `forAccount(account)` はネイティブの各メソッドを認証に束縛したバックエンドを返す。それを会話のラッパーで包む。これにより、ラッパー内部の履歴取得・分岐・巻き戻しにも認証が届く。モデル一覧、思考の強さ、タイトル、候補生成、圧縮も同じ認証を使う。
- `'agent'` の会話で認証を替えると、保存した会話を引き継ぎ、切替先に新しいネイティブの実行区間を作る。以前の認証のネイティブIDを別の認証に渡さない。認証を削除しても保存済みの履歴は読める。
- ログインの試行には識別子を付け、古い応答・取消を新しい試行へ適用しない。取消はバックエンドの終了を待ち、その後に届いた資格情報を保存しない。資格情報の保存を始めた後は保存の完了を待ち、取消ではなく完了として扱う。削除は進行中のログインを止め、バックエンドの使用中ガードを通してから専用ディレクトリを消す。共有ディレクトリのリンクはリンクだけを消す。
- サーバー更新の引き継ぎでは、台帳の登録と専用ホームの認証を検証する。デスクトップ本体の接続前に秘密ストアの復号を待たず、既存の CLI を引き継ぐ。OpenCode の引き継ぎ先を失った場合は、待ち受け開始前の新規起動を断って循環待ちを防ぐ。

## 理由

認証方法の違いはバックエンドが担当し、会話・委譲・画面は同じ選択を使う。登録アカウントを増やしても、履歴や補助処理が別の資格情報へ流れない形にする。

## エージェントの境界

Codex はアカウントごとの `CODEX_HOME` と app-server を使う。OpenCode はアカウントごとに XDG のデータ・設定・キャッシュ・状態を分けてサーバーを使う。認証の更新は CLI が書いた最新の値を優先し、古い保存物で上書きしない。

Antigravity 1.4.2 は OS の共有キーリングを使い、アプリ・外部 CLI と認証を共有する。Pleiad 内のロックでは外部の参照や更新を止められないため、資格情報の差替えは実装せず `accounts: false` を維持する。別の OS ユーザーや仮想マシンで認証を分けるか、CLI が認証プロファイルを提供した時点で対応する。[公式の認証の説明](https://www.antigravity.google/docs/install?tab=cli)を参照。

## 影響と検証

使用量のアカウント行は `accountId`・`label`・`ready`・`windows`・`checkedAt` を持つ。取得できない行は空の枠と `checkedAt: null`。他のアカウントの成功を、その行の成功とみなさない。接続先ごとの枠は `provider` を持ち、モデルIDの接続先と一致する枠だけを振り分けに使う。無料モデルや未対応の接続先に、別の接続先の使用率を割り当てない。

共通の台帳・ログインの競合、バックエンドごとの認証隔離、サーバー越しの選択・履歴・分岐・認証変更・削除後の保存分を試験する。能力の契約、対応表、操作の権限と辞書、保存先の上限も既存の検査に載せる。実CLIの認可と提供元のAPIの互換性は、偽のCLIによる通常試験とは別に確認する。
