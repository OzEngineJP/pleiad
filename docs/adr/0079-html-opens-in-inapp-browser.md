# 0079 HTML は内蔵ブラウザーのタブで開き、確認と file: の守りを PC のファイルのタブにも効かせる

- 状態: 承認（2026-10-02）。`file:` の守りと読み込みの方針は残し、方針の受け渡しはビューアの橋 `desktop/browser-viewer-bridge.cjs` へ移った（0148 の第 7 段、2026-10-08）。決定 1・3・5・6（HTML とカードの開き先・既定のブラウザーを選んだ人・リモート）は置換（0207）

## 状況

デスクトップ版のホストの画面では、HTML ファイルのリンクは右パネルのプレビュー（`sandbox="allow-scripts"`、ADR 0009・0042）で開き、内蔵ブラウザー（ADR 0041）で見るには道具の列の「ブラウザーで開く」をもう一度押す。押すたびに新しいタブができ、可視化のカードの「サイドパネルに表示」も、パネルの「ブラウザーで開く」まで 2 段かかる。内蔵ブラウザーなら相対の資源・ストレージ・DevTools・再読み込みがそのまま効き、エージェント（agent-browser）も同じページを見られる。

一方、実測（2026-10-02）で、内蔵ブラウザーの `file:` のタブ（HTML ファイル）には、設定 › ブラウザーの「外部の読み込みの前に確認」が効いていなかった。プレビューとカードは https・http の資源を止めて「N 件止めています」を出すのに、`file:` のタブは確認が ON でも読み込む（`desktop/` に確認の設定の参照が無く、`webRequest` の制限も CSP も無い）。可視化の写しは書いた時点の meta の CSP で止まるが、件数も「読み込む」も出ない。また `file:` のページは相対・絶対の `file:` で PC の任意のファイルを `<img>`・`<script>`・`<link>` として読み込め、ADR 0050 が API の側で拒む範囲（UNC・デバイスパス・データ置き場）の外になる。リンクの既定の行き先を内蔵ブラウザーにすると、この機会が増える。

ユーザーはモックを承認し（2026-10-02）、次の選択をした: 既定のブラウザーを選んだ人の HTML はプレビューのまま・可視化のカードは置き換える・確認 ON では http を localhost も止める・リモートの「PC のブラウザーで見る」は今回は足さない。

## 決定

1. **リンクの行き先**: デスクトップ版のホストの画面で「リンクの開き先 = 内蔵ブラウザー」のとき、HTML ファイルのリンク（会話・ツリー・ファイルのカード・Markdown の中）は内蔵ブラウザーのタブで開く。同じ実体のパス（可視化の写しは会話と記録の id）のタブがその会話にあれば、新しく作らず前に出して読み直す。Ctrl/⌘+クリックと中クリックは既定のブラウザー（Web のリンクと同じ）。ファイルのメニューは「ブラウザーで開く」を先頭にし、「右パネルで開く」は HTML では「プレビューで開く」として残す。ADR 0041 の「内蔵ブラウザーは会話・プレビューのリンク・『ブラウザーで開く』の受け皿」を、HTML ファイルのリンクの既定の行き先まで広げる。
2. **PC のファイルのタブ**: 画面が開いた `file:` のタブ（今の `allowFile` と同じ条件）と可視化の写しのタブだけ、⋯ の先頭にファイルの操作（原文を見る・エクスプローラーで表示・パスのコピー・相対パスのコピー・保存・会話で使う。写しは「元のファイルを開く」も）を足す。道具の列は増やさない（ADR 0041 の最小限を保つ）。アドレス欄は作業ディレクトリからの相対（外なら完全なパス）、写しは「可視化 · 題」。
3. **可視化のカード**: 内蔵ブラウザーが使えるホストの画面（リンクの開き先が内蔵ブラウザー）では、「サイドパネルに表示」を「ブラウザーで開く」に置き換える（写しを内蔵ブラウザーで開く。同じ記録はタブを使い回す）。原文・元のファイルを開くはタブの ⋯ から辿る。内蔵ブラウザーの無い画面と、既定のブラウザーを選んだ画面は今のまま。
4. **確認を PC のファイルのタブにも効かせる**: 「外部の読み込みの前に確認」が ON のとき、画面が開いた `file:` のタブ（HTML ファイル・可視化の写し）の資源を、main が session の `webRequest` で止める。規則はプレビューと同じ: 「常に」許可した https の出どころだけ通し、**http は localhost も止める**。ページの中で移った先の `file:` と Web のページ、エージェントが開いたページには効かせない。道具の列とページの間に「外部の読み込みを N 件止めています / 読み込む / 設定」をプレビューと同じ語彙で出す。件数には http も数える（プレビューも揃える）。「読み込む」はそのタブだけの一時の許可で https を通して読み直す（http は設定が ON の間は通さない。件数に http しか無いときは「読み込む」を出さない）。可視化の写しは meta の CSP が先に止めるので、一時の許可付きで写しを書き直して同じタブで開き直す。設定は core から main へ `browser-load-policy` として届ける（`core/agent-browser.mjs` の `loadPolicy`）。
5. **既定のブラウザーを選んだ人**: HTML ファイルは今のプレビューのまま。⋯・Ctrl/⌘+クリック・「ブラウザーで開く」で今どおり既定のブラウザーへ出せる。外のブラウザーには確認の設定を効かせられないので、押すたびに Pleiad を離れる変更はしない。
6. **リモート・モバイル**: ブラウザーで開いた Pleiad・リモートの窓・スマホはプレビューのまま。sandbox（`allow-same-origin` を付けない）も変えない。設定 › ブラウザーの見出しを「外部の読み込み」にし、設定がプレビューと内蔵ブラウザーの両方に効くことを書く。リモートにもページの説明を足し、リンクの開き先がホストの画面だけである理由を一言添える。
7. **`file:` の資源の守り**: 4 の `webRequest` は、画面が開いた `file:` のタブからの `file:` の資源も、UNC・デバイスパスとデータ置き場（添付の `uploads` を除く）を、確認の ON/OFF によらず止める（ADR 0050 と同じ範囲。実体を解決して比べる）。ページ自身の移動（リンク）も同じ範囲の `file:` へは移らせない。同じ保存領域の `localStorage` を可視化の写しと HTML ファイルが共有する問題は、今回は直さず既知の制約として docs に書く。

## 理由

- 見るために形を変える（プレビュー → ブラウザー）手間と、押すたびに増えるタブをなくす。リンクを押すのは「今のファイルを見たい」ときなので、同じタブを使い回して読み直す。
- 内蔵ブラウザーを `file:` の既定の行き先にするなら、確認の設定が効かない穴を先に塞ぐ。止める対象は画面が開いた `file:` のタブに限る: Web のページの読み込みを止めるのは「内蔵ブラウザーは最小限」に反し、エージェントが操作するページを壊す。
- http を localhost も止めるのは、確認の意味（外へ出る平文の通信も含めて止める）と、プレビューとの規則の一致を優先したため。手元の開発サーバーの資源を読む HTML は確認を OFF にするか、https で配る。
- 写しの書き直しを選んだのは、meta の CSP を外して `webRequest` に任せる案より、既定のブラウザーやリモートで開く写しと同じ守りを残せるため。止めた件数は写しが `console` へ知らせる（親が無いので `postMessage` は使えない）。
- ファイルの操作を ⋯ の条件付きの群にしたのは、プレビューにしか無かった操作の行き場を作りつつ、道具の列を増やさないため。
- 採らなかった案: 既定のブラウザーを選んだ人の HTML も既定のブラウザーへ出す（Pleiad を離れ、確認の設定が効かない）。サイドパネルに表示とブラウザーで開くを並べて残す（カードの道具が増え、どちらを押すか迷う）。リモートに「PC のブラウザーで見る」を足す（今回の要望の外。別の作業にする）。

## 影響

- 同じリンクを押すと読み直すので、ページの中の入力・スクロールは初期に戻る。エージェントが書き換えた後に見ることを優先した。
- 確認が OFF のとき、`file:` のタブはプレビューより緩い（http も読み、フォームも送れる）。内蔵ブラウザーは Web のページと同じ扱い、気にする人は ON にする。
- `file:` のページと可視化の写しは同じ保存領域の `localStorage` を共有する。「このサイトのデータを消す」が `file:` で何を消すかは確かめていない。
- 開いた `file:` のタブはその会話のタブなので、エージェントから見える。人がリンクを押して読み直すと、エージェントの操作は解除される（今の「人の操作」と同じ）。
- 写しの ⋯ の原文・保存は、画面が持っている中身（開いたときに覚える）を使う。画面を読み直した後は、元のパスの操作だけが残る。
- 内蔵ブラウザーのプロフィール（[ADR 0078](0078-inapp-browser-profiles.md)）は保存領域を複数の session に分ける。`webRequest` は session を初めて使うとき（ADR 0078 の「session ごとの設定」）に 1 度張り、持ち主のタブは webContents の id で引くので、どのプロフィールの `file:` のタブにも同じに効く。タブの使い回しは会話の今のプロフィールのタブの中で探す（プロフィールを替えて同じリンクを押すと、今のプロフィールで新しいタブを開く）。外部の読み込みの許可（`externalSitePermissions`）と確認の設定はプレビューと共通で、プロフィールとは関係しない。

## 追記（2026-10-06）: プロフィールの段落は無くなる

内蔵ブラウザーのプロフィール（[ADR 0078](0078-inapp-browser-profiles.md)）は削除された（[ADR 0148](0148-agent-browser-in-chrome.md)）。上の「影響」のプロフィールの段落は、保存領域が `persist:pleiad-browser` の 1 つに戻ることで読み替える。また、開いた `file:` のタブはエージェントから見えない（エージェントは内蔵ブラウザーを触らない）。
