# 0258: 右へのスワイプで脇を開く

## 状態

承認（2026-10-23）

## 状況

700px 以下の画面では脇が引き出しになる。片手でも会話の本文から一覧へ移れる操作が必要になった。横スクロール、文字選択、端末の「戻る」と両立させる。

## 決定

本文のどこからでも右へ引いて脇を開く。設定画面と 701px 以上では効かせない。左上のボタンも残す。

| 条件 | 扱い |
|---|---|
| 開始 | 最初に触れた 1 本の指（Pointer Events の `isPrimary` が true の指）だけ。横 12px 以上、横が縦の 1.5 倍を超える |
| 縦の拒否 | 横と確定する前に縦 10px 動いたら、その操作の間は開始しない |
| 向き | 閉じているときは右、開いているときは左 |
| 追従 | 引いた距離だけ移動し、幕も開いた割合の不透明度にする。transition を外し pointer capture で追う |
| 位置 | 開いた幅の 45% 以上なら開く |
| 速度 | 直近 100ms の右 0.5px/ms 以上なら開き、左 −0.5px/ms 以下なら閉じる。位置より優先 |
| 停止 | 最後の移動から 100ms 以上経ったら位置だけで決める |
| 確定 | 240ms、`cubic-bezier(.2,.7,.2,1)`。動きを減らす設定では追従を残し、確定後は 0ms |
| キャンセル | pointercancel・capture の喪失で開始時の開閉に戻す |
| 閉じる | 左へのスワイプ・幕・閉じるボタン・会話などへの移動・Esc・既存の `plyremote:back` |

横スクロールのある祖先、コードの pre、表、iframe、端末、タブの段は中身の操作を優先する。端に達しても脇へ切り替えない。入力・編集可能な要素・リンク・選択中の文字・閉じた画面の操作ボタンから始めない。先に成立した並べ替えや長押しも奪わない。

左右 24px と下端 28px から始まる操作は OS に譲る。Android の殻は `systemGestures` のうちページ内に残る幅を `plyRemote.gestureInsets()` で CSS px に換算して渡し、既定より大きければその幅を除外する。システムのジェスチャー除外領域は設定しない。

横スクロールの祖先に `touch-action:pan-y` を置かない。既定のパンを許したまま、横への意図が確定した指の touchmove だけを止める。

## 理由

本文からの操作は片手で届きやすい。端末の端から始まる操作と、入力・選択・横スクロールを先に除外すれば、それぞれの操作を保ちながら脇へ移れる。しきい値を越えるまでは既定のスクロールに任せる。

## 影響

判定と追従を `web/drawer-swipe.mjs` に分離する。確定は既存の `setDrawer()` に渡し、inert・フォーカス・幅変更の後始末を共有する。開閉状態は保存しない。単体試験と 360px 幅の実タッチのブラウザー試験で判定とスクロールとの両立を確かめる。
