# 0315 接続が見る会話を「主」と「モーダル」の 2 つにして、子の会話のモーダルの中で右の欄を開く

- 状態: 承認（2026-11-11）。段 1（右の欄をモーダルの中に出す）と、その幅に要る一覧の開け閉めまで。モーダルの入力欄・検索・メニューは別の ADR で決める
- 置き換えた: [0024](0024-watch-open-session-stream.md)（「接続は開いている会話を 1 つだけ伝える」を 2 つの口に改める。それ以外の送り方は 0024 のまま）

## 状況

- 子の会話のモーダル（`#workDialog`）の中のファイルのリンクは、押すとモーダルを閉じて主の右の欄で開いていた。子の会話を読みながらファイルを見たい利用者は、押すたびに読んでいた場所を失った。
- 右の欄（`aside#filePreview`。タブ・ファイル・ページ）は、画面に 1 つだけの部品で、映す会話は 1 つ（接続が見ている会話）に決まっている。モーダルで子の欄を開くと、画面は主の会話と子の会話の両方の流れ・ページの映像を必要とする。
- サーバーは、接続が見ている 1 つの会話の子孫だけをページの口（`pageOpen`・`pageResolve`・`pageWatch`）に通し、流れの出来事もその会話の分だけ送る。子の会話を見るために `watchSession` を子へ替えると、主の会話の流れが止まる。

## 決定

1. 接続が見る会話は `main` と `modal` の 2 つの口を持つ。`watchSession` は `{ sessionId, slot? }` を取り、`slot` を省くと `main`（古い画面と試験のクライアントはこれまでどおり）。`modal` の口は、モーダルが子の会話（`taskThread`）を映している間だけ画面が埋め、閉じると空にする。
2. 流れの出来事は、2 つの口のどちらかの会話の分を送る（`wanted`）。ページの口の許可（`allowed`）と窓口の範囲（`scope`）は、2 つの口それぞれの子孫の和集合にする。`turnEnd` など全部送るものは変えない。
3. 在席（`presence`）は接続と口ごとに持ち、口ごとに時間切れを数える。
4. 右の欄は、モーダルが開いている間、モーダルの中（`#workSplit` の右）へ付け替え、閉じたら主へ戻す。別の部品は作らず、主と同じ部品・同じ動き（`web/motion.mjs`・[ADR 0312](0312-right-panel-close-tabs-motion.md)。`prefers-reduced-motion` に従う）を使う。
5. モーダルの中のリンク（本文の `[名前](パス)`・ツール行のパス・可視化の「ページで開く」）は、モーダルを閉じず、その子のタブで開く。相対パスはその子の cwd で解く。中身の種類で分ける: 子の会話（`taskThread`）は子の会話の欄、サブエージェント（`subagentThread`）は親の会話の欄、委譲先ホストの子（`hostTaskThread`）は欄なし（従来どおりモーダルを閉じて主で開く）。
6. 主で開いていた欄は、モーダルを開いて欄を出すときに閉じ、モーダルを閉じたら親のタブで開き直す。Esc は一段ずつ（欄 → モーダル）で、閉じた欄から押したリンクへ焦点を戻す。
7. 幅と一覧: 1280px 以上は一覧・会話・欄の 3 列で、一覧は畳まない。700px 以下は主の狭い幅と同じ部品で、一覧 → 会話 → ページの 3 段にして戻るボタンで戻る。
   701〜1150px は、会話の列を 360px 以上に保つ（欄を開いたまま 701〜1040px で会話が 53〜383px まで潰れていた）。
   一覧は主の脇と同じ 52px のレールに畳め（押し出しで、重ねも暗転も無い。ボタンは主と同じ部品、名前は「一覧を開く」「一覧を閉じる」、Ctrl+B は作業のダイアログが開いている間だけそちらを動かす）、畳んだ状態は覚える。
   761〜1150px で欄を開くと、利用者が畳んでいない一覧は自動で畳み、欄を閉じたら（自動で畳んだ分だけ）開き直す。利用者が自動の後に一覧を開いたときは 3 列に戻し、会話を 360px に保つために欄を縮める。701〜760px は自動では畳まず、ダイアログを画面いっぱいに広げて欄を重ねて出す（一覧は利用者が畳める）。

## 理由

- 子の欄のために `main` の会話を替えると、主の会話の流れ・完了の印・通知が止まる。口を 2 つにすれば、主の流れを保ったまま、子の欄だけ別の会話に向けられる。
- 範囲を和集合にするので、`allowed` は口が増えても「この接続が今見ている会話の子孫」という 1 つの意味のまま。口を数える側（presence・時間切れ）が増える分だけを口ごとに持てば足りる。
- 右の欄は 1 つの部品のまま付け替えるので、主とモーダルで見た目・操作・動きが分かれない。モーダルだけの欄を作ると、片方だけ直る・直らないが続く。
- 欄を持てない中身（ホストの子）は、持たせるより従来の道（閉じて主で開く）のほうが、戻る手段を失わない。

## 影響

- 新しい流れの出来事・ページの口を足すときは、主の口だけでなく `modal` の口の会話も許可の範囲に入ることを前提にする（`browser-unify-ws` の `scope`・`allowed`、`core/server.mjs` の `wanted`）。
- 画面は接続し直すたびに `modal` の口を伝え直す（`syncModalWatch({ force: true })`）。伝えないと、モーダルを開いたまま再接続した後、子の欄が映らない。
- `docs/design-system.md` の作業のダイアログに、右の欄の出し方と一覧の開け閉めを足した。主の右の欄・脇の表示は変わらない。
- 以降の段（モーダルの入力欄・検索・メニュー、子の進行の即時表示、主を開く入口の整理）は、この 2 つの口を前提に別の ADR で決める。
