# 0290 同じ名前の Skill があっても発言を止めず、使う定義を選べるようにする

- 状態: 承認（2026-11-06）

## 状況

Pleiad が Skills をそろえる会話で、同じ名前の Skill が 2 つ以上見つかると（ユーザーの `~/.claude/skills` と作業場所の `.claude/skills` に同じ `write-prd` があるなど）、実行時の解決が「同じ名前の Skill があります」で失敗し、その会話の発言がすべて送れなくなっていた。右パネルは前のターンの記録のままか「まだ始まっていません」で、どの定義がぶつかっているかはどこにも出なかった。外部 MCP は同じ状況で止めず、選んだ定義（`prefer`）か先に見つかった方を使い、右パネルと設定（「どちらの定義を使いますか」）で選び直せる。

## 決定

1. **同じ名前の Skill があっても止めない。** 選んだ定義（`plan.skill.prefer`: 名前 → SKILL.md）、無ければ先に見つかった方（ユーザー → 作業場所）を使い、残りは `shadowed`（`shadowedBy: 'choice'`）にする。外部 MCP と同じ仕組み（`core/context-scan.mjs` の選択、`core/context-runtime.mjs` の `markChoices`）。同じ実体（realPath が同じ）は 1 つとして数え、選ぶ対象にしない。
2. **設定の形**: 種類の設定 K の `prefer` を Skills にも許す（指示には許さない。`disabled` は外部 MCP だけのまま）。保存した場所から解決して絶対パスで持つ。
3. **会話の右パネルの Skills の面**: 使った方の行の下に「同じ名前の定義が N つ · ○○の方を使用（先に見つかった方／設定で選んだもの）」と［変更］。［変更］で `.cx-choice` の選択肢を開き、選ぶとその場で保存する。保存先は、この場所の定義が絡めばこの場所、ユーザーの定義どうしなら今効いている設定（上の場所か全体）。使わなかった方は折りたたみ「使わなかった同じ名前の定義 N 件」に置き場所と理由を並べる。
4. **設定 › プラグイン › Skills**: 外部 MCP のカードと同じ形（名前ごとに 1 行・スイッチ 1 つ・「どちらの定義を使いますか」）。全体の設定に保存する。
5. **「/」の候補**（`skillList()`）も同じ決め方の 1 件を出す。
6. 右パネルの外（会話の中・札・通知）では知らせない。
7. 探索の上限・解析できないファイルで止める（`context.runtime.unresolved`）のは変えない。

## 理由

- 同じ名前の Skill は、共通の置き場所（`.agents/skills`）と各エージェントの置き場所に同じものを置く、リポジトリにも同じ Skill を入れる、といった普通の使い方で起きる。1 つの名前のぶつかりで会話全体が送れなくなるのは、得られる安全に対して損が大きすぎる。
- 先に見つかった方（ユーザー → 作業場所）を既定にするのは外部 MCP と同じで、どちらを使ったかは右パネルに必ず出る。違う方を使いたければその場で選べる。
- 作業場所の定義は設定の画面（ユーザーの範囲だけを探す）に出ないので、選び直しは右パネルでできる必要がある。
- 新しい見た目を作らず MCP の部品と文言を使うと、同じ状況が同じ形で出る。

## 影響

- `core/context-settings.mjs`: K の `prefer` を Skills にも許し、計画に `skill: { prefer }` を載せる。`core/context-session.mjs` の計画も同じ形。
- `core/context-scan.mjs`: 名前の選択を外部 MCP と Skills の両方で行う。`core/context-runtime.mjs`: 「同じ名前の Skill があります」の例外をやめ、`markChoices` で Skills の理由（置き場所で示す）を書く。`context.runtime.duplicateName` の文言は消す。
- `web/session-context.mjs`・`web/context.mjs`・`web/context.css`: 右パネルの 1 行・［変更］・選択肢・折りたたみ、設定の名前ごとの行と選択肢。
- 保存形式は足すだけ（前の版は `prefer` の無い Skills の設定をそのまま読む）。
