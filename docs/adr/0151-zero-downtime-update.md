# 0151 更新で走っているターンを止めない（ターンの保持役と版ごとの実行場所）

- 状態: 承認（2026-10-06）
- 置き換えた: [ADR 0036](0036-interrupt-and-update-while-running.md) の「実行中でも更新・終了できる」のうち**更新**の部分（通常は作業を中断せずに更新する。「中断して更新」は戻し道として残る）。終了の「中断して終了」と、中断を会話の状態として残す部分は 0036 のまま
- 置き換えられた: [0270](0270-server-may-die-anytime.md)（引き継ぎの部分。決定 5・9・11 のうち、引き継ぎ専用の経路と、切り替えを先送り・確認する形。起動を復元にして、更新も「普通に止めて普通に起こす」にそろえる。決定 1〜4・6・10・12 はこのまま）
- 詳しい設計: [docs/zero-downtime-update/design.md](../zero-downtime-update/design.md)。段階と作業項目: [plan.md](../zero-downtime-update/plan.md)。実測の記録: [stage0-claude.md](../zero-downtime-update/stage0-claude.md)・[stage0-codex-agy.md](../zero-downtime-update/stage0-codex-agy.md)・[stage0-runtime.md](../zero-downtime-update/stage0-runtime.md)。管理: [issue #54](https://github.com/tekalu1/pleiad/issues/54)

## 状況

更新は、走っている作業を全部 `update` の理由で中断してから適用する（ADR 0036）。中断は会話に残り「再開」で続けられるが、途中のツール 1 回分と承認待ちを失い、人が押すまで止まったままになる。先行版を 1 日に何度も出すので、そのたびに全部の会話・委譲・bot の作業が止まる。「再起動して更新」から新しい版が立つまでは、実測で約 55〜70 秒かかる。

止まる理由は 3 つある（design.md §1）。

- サーバーは main の子の utilityProcess で、main と一緒に終わる。NSIS は `$INSTDIR` のプロセスを全部止める。npm で入れた `claude`・`codex` は `$INSTDIR\Ply.exe` を Node として走るので、エージェントの CLI まで止められる
- エージェントの CLI はサーバーの stdio の子で、承認（`canUseTool`）・in-process の MCP・hooks は SDK の `Query` の中、承認待ち・MCP の口のトークン・画面のトークンはサーバーのメモリにある
- データ置き場はサーバー 1 つだけが開ける（[ADR 0115](0115-records-in-sqlite.md)）ので、新旧のサーバーを並べて引き継げない

リリースはほぼ毎回 `core/` を変えるので、Electron の入れ替えを越えるだけでは足りず、**サーバーそのものを入れ替えてもターンが続く**必要がある。

段階 0 で、この作りの前提を実機で測った（stage0-*.md）。要点:

- Claude Code の CLI（2.1.284・2.1.288）は、同じ stdio での 2 回目の `initialize` を受け、承認待ちの最中でも承認が元の `requestId` で新しい `canUseTool` に回り直り、hooks と in-process の MCP も効く。親が居ない 300 秒でも待ち続ける。ただし読まれない stdout は約 240 KB で詰まる
- Codex（0.160.0）と agy（1.2.17）は付け直しに握手が要らない
- `$INSTDIR` の外の、名前が `Ply.exe` でない detached のプロセスは、更新・アンインストールをまたいで生き残る。`$INSTDIR` の中・前方一致の兄弟のフォルダーは止められる
- 実データ（会話 1,438 件）でのサーバーの起動は `ready` まで 1.2〜1.3 秒。ロックの引き継ぎは最大 18.6 ms。実行場所は約 107 MB・4,017 ファイル（Claude Code の同梱バイナリーを外した後）

## 決定

1. **プロセスを 3 層に分ける。** main（Electron。`$INSTDIR`。NSIS が入れ替える）／サーバー（`core/`・`web/`・`bin/`。版ごとの実行場所。引き継ぎで入れ替える）／ターンの保持役（エージェントの CLI の stdio を持つ。入れ替えない）。
2. **サーバーと保持役は `$INSTDIR` の外の版ごとの実行場所で、公式の Node を同梱して動かす。** 置き場は `%LOCALAPPDATA%\agent-host-runtime\`。Node は `pleiad-node.exe` の名前で使う（`Ply.exe` にしない。NSIS が名前で止めることがある）。起動は `detached: true` + `stdio: 'ignore'` + `windowsHide: true`。main は起動時に自分の Job の制限を調べ、生き残れない環境では今の「中断して更新」に落とす。中身は main が `resources\app` から写し、ビルド時の `manifest.json`（SHA-256）と突き合わせる。版をまたいで同じファイルはハードリンクで共有する（ディスクと、Defender の再検査を避けた再起動の速さのため）。使っているプロセスがある版は消さない。`$INSTDIR` の文字列で始まる場所には置かない。インストーラーは Node の分だけ大きくなる。**全ユーザー向けのインストールでも、利用者が書ける場所の実行ファイルでサーバーが走る**（同じ利用者の権限で、権限の昇格にはならない）。
3. **サーバーは main の子にしない。** main との口は名前付きパイプにし、運ぶメッセージの型は今の parentPort のものをそのまま使う。**更新のたびに main は入れ替わるので、内蔵ブラウザーのタブの中身と computer use の操作は一度切れる**（避けるには、段階 5 の「Electron を再起動しない core だけの更新」とその署名の仕組みが要る）。main が居ない間は、main に頼む機能ごとに待たせる・止める・別の道で行うを決める（design.md §7.2）。computer use は Esc と同じに扱って止める（ADR 0071・0072）。内蔵ブラウザーの中継は、新しい main が同じポートと鍵で張り直し、タブを URL で開き直す（[ADR 0148](0148-agent-browser-in-chrome.md) でエージェントの操作が Chrome の専用の窓に移った後は、エージェントのタブは main の入れ替えで消えない。design.md §7.2）。
4. **ターンの保持役は、プロトコルを解釈しない薄いプロセスにする。** 子の起動・stdio・終了、親の有無にかかわらず常に読む出力の記録（通番・ack・印）、答えていない依頼の控え（Claude の `mcp_message` だけを渡し直す）、サーバーが置く不透明な札と預かり物だけを持つ。JSON-RPC の id の付け替えと `initialize` の答えは持たない（新しいサーバーが世代つきの文字列の id を使う）。データ置き場には書かない。依存は Node の組み込みだけ。規約の版はパイプの名前に入れ、サーバーは 2 つの版を話す。規約を変えた版は新しい世代を立て、古い世代は子が終わったら消える。
5. **サーバーの入れ替えは引き継ぎで行う。** 旧サーバーは新しい作業の開始を送信待ちに回し、短い処理・走っている hooks のコールバック・`mcp_message` のハンドラー・処理中の MCP の呼び出しを上限つきで待ち、書き込みを済ませ、保持役に `detach` してから SDK の `query` を閉じ（先に閉じると CLI が終わる）、データ置き場のロックを放して終わる。新サーバーはロックを待って取り、同じトークン・同じポートで待ち受け、HTTP の口を立ててから付け直し、新しい作業を始める。データ置き場を同時に開くプロセスはいつも 1 つ（ADR 0115 を保つ）。
6. **付け直したターンは、保持役の記録を今と同じ正規化に流して組み立て直す。** サーバーのメモリを版をまたいで直列化しない。再生は uuid で冪等にし、流す位置は「アプリが処理し終えた最後の行」。Claude は SDK の `spawnClaudeCodeProcess` で CLI の起動を保持役へ回し（最初の stdin の書き込みより前に）、付け直しでは同じ CLI に `query` を作り直す。**in-process の `host` MCP は HTTP に移さず、そのままにする**（付け直しで効き、HTTP に移すと不通中は待たずに失敗するため）。Codex は共有の app-server を、agy は会話ごとのプロセスを、`!` の行はシェルを、保持役の子にする。Codex の `--listen` / `daemon` は採らない（切れ目の通知が欠け、規約が揃わない）。
7. **画面は同じトークン・同じポートでつなぎ直し、版が変わっていれば 1 回だけ読み直す。** `ready` に `appVersion` を足す。
8. **実装は段階に分ける。** 段階 1: 実行場所・名前付きパイプ・main が居ない間の扱い・切り替えの先送り（保持役なし）。段階 2: 保持役と Claude の付け直し。段階 3: Codex・agy・`!` の行。段階 4: 待ち受けを保持役が持つ（引き継ぎの間の MCP の失敗が実機で問題になったときだけ）。段階 5: Electron を再起動しない core だけの更新（任意。別の ADR で署名を決める）。
9. **段階 1 の「サーバー切り替えの先送り」は、0036 が退けた「終わったら更新する」予約とは別のものとして認める。** 保持役に載っていないターンがある間はサーバーの入れ替えだけを先送りし、作業が 0 件になったら新しいサーバーへ切り替えて窓を読み直す（下書きは保存済み）。0036 が退けたのは、作業が終わった直後に**アプリが勝手に再起動する**こと。先送りは、利用者が更新を選んだ後の切り替えで、アプリの再起動を起こさず、止まるものは無く、変わるのは画面の読み直しだけ。窓には待ちの件数と「今すぐ中断して切り替える」を出す。段階 3 の後も、古い CLI の版のターンなどの戻し道として残る。
10. **データの形式番号が変わる版は、今どおり作業を中断して更新する。** 移行は「全書き込みを止めて、写しで移行して確かめる」ので、ターンを走らせたまま・利用者が選ばない時に行わない。新しい main の事前の確かめで分かり、「あとで／中断して更新」のダイアログ（0036 の形）を出す。「あとで」では自動で切り替えない。
11. **合わない更新は今の「中断して更新」に落とす。** 形式番号が変わる版・保持役の規約や引き継ぎの形式が範囲の外の版・実行場所の写しが manifest と合わない版・付け直しに使えない CLI の版のターンがある更新は、引き継ぎを始める前に分かる。引き継ぎを始めた後に新サーバーが立たなければ、前の版のサーバーで付け直して動かし続ける。それも駄目なら保持役の子を止め、起動時の `restart` の回復に任せる。環境変数 `AGENT_HOST_HANDOVER=off` で、いつでも今の流れ（`utilityProcess`）だけにできる。
12. **終了は今のまま。** 「中断して終了」（ADR 0036）で全部を止め、サーバーと保持役も終わる。
13. **この機能を持たない版から最初にこの機能を持つ版への更新は、古い版の main が行うので、今の「中断して更新」になる。** 無停止になるのはその次の更新から。

## 理由

- core の入れ替えでターンが止まらない切り方は、ターンの持ち主（CLI の stdio）をサーバーの外に置くものだけ。サーバー全体を外に出すだけでは、core を替えるたびに止まるか、手が空くまで古い版が残り続ける（委譲や bot で作業が絶えない使い方では、いつまでも新しい版にならない）。
- 保持役だけを外に出してサーバーを `$INSTDIR` に残すと、入れ替えの間、承認・MCP・スマホの誰にも答えられない。実行場所を外に出せば、居なくなるのは main だけになり、サーバーが居ないのは引き継ぎの 1〜1.6 秒になる（実データでの実測。実測は強制終了ベースで、モジュールを先に読めば 0.8〜1.1 秒の見込み）。
- 保持役が持つのは、行・通番・控えという版で変わらないものだけにする。ターンの意味の状態は、今のコードがすでに持っている正規化で作り直せる。版をまたぐ直列化の形を持たずに済み、保持役のコードはほとんど変わらない。
- Claude の付け直しは、CLI と SDK が「すでに初期化された会話に加わるクライアント」として用意している形（再 initialize と `pending_permission_requests`）に乗り、承認待ち・hooks・in-process の MCP で通ることを確かめた。
- 2026-10-07、利用者の決定で、Claude の CLI を保持役に載せるのを既定にした（パッケージ版の main が起こしたサーバーだけ。`AGENT_HOST_CLAUDE_HOLDER=off` で戻せる）。載せる CLI の版は完全一致をやめ、確かめた最も古い版（2.1.284）以上で同じ major にした（更新のたびに黙って外れないように。付け直せない版が出ても、付け直せなかったターンが再開できる中断になるだけで、今の「中断して更新」と同じ）。
- 今の「中断して更新」と `restart` の回復が戻し道になるので、どこで失敗しても今より悪くならない。
- 副産物として、サーバーが落ちても main が落ちてもターンが止まらなくなる。サーバーの修正版を、作業を止めずに当てられる。

退けた案（design.md §2.2）:

- サーバー全体を外に出し、core の更新は手が空いてから: 作業が絶えない使い方では新しい版にならない。戻し道（切り替えの先送り）としてだけ使う。
- Codex の daemon / `--listen` などバックエンドごとの外部化だけ: Claude と agy にはデーモンが無く、MCP の口と承認はサーバーに残る。`--listen` は切れ目の通知が欠け、ws は認証が既定でなく、`daemon` は別の codex.exe の写しを管理して Pleiad の `-c` の設定とぶつかる。
- パイプのハンドルを新サーバーへ渡す・新旧のサーバーを会話ごとに並べる・サーバーのメモリを直列化する: 渡せない／データ置き場の単独の持ち主を崩す／壊れやすい。
- 承認を `permissionPromptToolName`（MCP のツール）で受ける: 承認は人が答えるまで長く待つ HTTP の呼び出しになり、サーバーの入れ替えで切れる。stdio の `can_use_tool` なら再 initialize で回し直せる。
- `host` MCP を HTTP に移す: 付け直しの不確かさを減らす案だったが、実測で in-process のままで付け直しが通り、HTTP は不通中に待たずに失敗する（待ち受けを保持役が持つ段階 4 が無いと今より悪い）ので取り下げた。

## 影響

実装の各段階で、その段階の変更と同じコミットで、次の文書を今の形に書き換える（この ADR の時点では書き換えない。まだ実装していない）。

- 段階 1:
  - `docs/desktop-releases.md`: 「更新UX」の「再起動を選択」「作業・承認待ち」「ロックの失敗」の行と、「適用とデータ保護」の手順（作業を中断せず、サーバーの切り替えを作業の終わりまで先送りする。ロックは切り替えの時に取る）、「リリース判定」の表（走っているターンが更新をまたいで続く。形式番号を変える版は「中断して更新」。実行場所のプロセスが止まらない）、「同梱する CLI」（公式の Node の同梱）。実行場所の置き場と掃除、`AGENT_HOST_HANDOVER` を足す

  - `docs/computer-use.md`「core と main」・`docs/inapp-browser.md`・`docs/remote.md`（常駐）: main の口が名前付きパイプになること、main が居ない間の扱い（computer use の停止・内蔵ブラウザーの中継の張り直し・resident）
  - `docs/design-system.md`: 切り替えの待ちの表示（モックで承認を取ってから、形と日付を書く）

- 段階 2・3:
  - `docs/multi-backend.md`: `AgentBackend` に付け直しの入口（`adoptTurn`）、「外部エージェントと操作ツールの版」に、付け直しを確かめた CLI の版（Claude は 2.1.284・2.1.288 を確かめ、載せる条件は 2.1.284 以上で同じ major。`VERIFIED` とは別）、Codex・agy の付け直し
