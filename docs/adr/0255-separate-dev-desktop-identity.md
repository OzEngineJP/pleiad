# 0255 開発版のデスクトップ版を、インストール版と別のアプリとして起こす

- 状態: 提案

## 状況

開発版（パッケージ版でない起動。`npm run desktop`・`electron .`）もインストール版も、Electron に渡すアプリの名前は `package.json` の `name`（`agent-host`）だった。Electron はこの名前から macOS のキーチェーンの項目（`agent-host Safe Storage`）と userData の置き場所を決めるので、同じ Mac で両方を使うと同じ項目と userData を共有した。

キーチェーンの項目の二つの許可の一覧（使ってよい署名・復号してよいアプリ）には、最初は項目を作ったアプリだけが載る。開発版の Electron が先に作ると、インストール版は起動のたびに確認を 2 つ出され、それぞれ「常に許可」を押すまで続いた。開発版の Electron は版を上げるたびに署名が変わるので、開発版も同じだった。単一起動の鍵も userData ごとなので、インストール版が動いている間は開発版を起こせなかった（#126）。

## 決定

- 開発版でだけ、`desktop/main.cjs` の最初（userData・safeStorage・単一起動の鍵を使う前）で `app.setName('Pleiad Dev')` を呼ぶ（`desktop/dev-identity.cjs`）。キーチェーンの項目は `Pleiad Dev Safe Storage`、userData は `Pleiad Dev` になる。
- 開発版の既定のデータ置き場は `~/.agent-host-dev` にする。`AGENT_HOST_DATA` を渡せばその場所を使う。
- インストール版（パッケージ版）は何も変えない。

## 理由

- 項目を作ったアプリが両方の一覧に最初から載るので、開発版とインストール版がそれぞれ自分の項目を持てば、どちらにも他方の署名の確認が出ない。インストール版の項目・鍵・保存した秘密は今のままで、移行が要らない。
- 名前を変えると safeStorage の鍵が変わる。データ置き場を共有したままだと、開発版はインストール版の鍵で暗号化した秘密を読めず、データ置き場のロック（`core/data-lock.mjs`）のせいでインストール版と同時にサーバーも起こせない。
- インストール版の名前を Pleiad に揃える件（#134）は、秘密情報とログイン状態の移行が要るので別に扱う。

## 影響

- 開発版は、新しい userData と `~/.agent-host-dev` で起動する。前の開発版の会話・設定・ログイン状態は引き継がない（前の置き場を使うなら `AGENT_HOST_DATA=~/.agent-host` を渡す。macOS では、インストール版の鍵で暗号化した秘密は読めない）。
- 開発版の Electron は版を上げるたびに署名が変わるので、開発版の項目では今までどおり確認が出る。
- `npm start`（Electron を使わないサーバーだけの起動）は変わらない。
