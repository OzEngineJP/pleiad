# 0353 ターンごとの変更の記録（撮影）を消し、Pleiad が自分から始める裏の作業を遅い場所で積み上げない

- 状態: 承認（2026-11-25。利用者の決定）
- 置き換える: [ADR 0085](0085-host-reads-git-and-turn-snapshots.md) の決定 2（ターンの始まりと終わりの撮影）・決定 3（返答の下の変更の行）・決定 6（委譲の完了通知の「変更:」行）と、決定 7 のうち右の欄の「この会話の間」の範囲。決定 1（ホストが git を読む）・決定 4（会話でしたことの時系列）は残す
- 関係: [ADR 0135](0135-git-panel-tabs.md)（右の欄の git。「コミットしていない変更」と履歴は残る）・[ADR 0270](0270-server-may-die-anytime.md)（子プロセスは `core/process.mjs` の `run()` だけが起こす）・[ADR 0227](0227-ply-shell-and-command-notices.md)（`ply_shell`・`!` は変えない）

## 状況

2026-11-24、作業場所が `G:`（Google Drive for desktop。Dokan の仮想ドライブ）にある会話が止まった。調べて分かったこと（提案書の数字）:

- `exec()` が使う `run()` は、止めたあとも出力のパイプが全部閉じるまで戻らない（`killedCloseGraceMs` が 0）。Dokan の I/O 待ちで終われない git がパイプを握っている間、`READ_TIMEOUT` 4 秒・`SNAPSHOT_TIMEOUT` 8 秒は名ばかりになる。ログの `gitStatus` は最長 **107,255 ms**。手元の試験では、パイプを握る子孫を時間切れ 1.5 秒で起こしたとき、戻るまでが grace 0 で **8,139 ms**、grace 500 ms で **2,020 ms** だった。
- `gitStatus` は「頼んだ時刻から 2 秒の TTL を過ぎたら、走っている分の後ろに新しい git を並べる」作りで、遅い場所では列が伸びる（ログの `inFlight` は最大 **5**）。
- ターンの始まりの撮影は 6 秒で待つのを諦めても止めず（中断の手段を渡していない）、次のターンがまた `add -A` を起こす。同じ場所の会話が 7 本なら始まりと終わりの `add -A` が 7 本ずつ重なる。
- 撮影は一時 index の上で `add -A` するので、コミットが 0 件（本物の index が無い）の場所では毎回すべてのファイルの中身を読む。Drive for desktop ではオンラインだけのファイルの取得まで起こしうる。
- Windows で Pleiad が起こすのは `cmd\git.exe`（ラッパー）で、ラッパーを止めると本体の `mingw64\bin\git.exe` も一緒に消えることが多い（手元の試験）。残った孤児は「止める要求は届いたが I/O 待ちで終われない」状態とみる（Dokan での再現はしていない）。だから木ごと止めても孤児は減らない。効くのは「**待たない**」と「**新しく起こさない**」の 2 つ。

利用者の判断（2026-11-25）: 返答の下の変更の行は、ほとんど見たことがなく、見る場面も無い。無くても作業の流れは止まらない。毎ターンの `git add -A` が今回の詰まりの元なので、機能ごと消す。記録できなかったときの出し方（別に検討していた表示）は「出さない」。

## 決定

### A. ターンごとの撮影と、それに乗っていた表示を消す

1. ターンの始まりと終わりの撮影を消す（`gitActivity.begin`・`attach`・`finish`、`turn.gitSetup`・`turn.gitLate`、`GIT_BEGIN_WAIT_MS`・`GIT_END_WAIT_MS`、環境変数 `AGENT_HOST_GIT_SNAPSHOTS`）。ホストが `refs/pleiad/turn/…` を書くことはもう無い。
2. 返答の下の変更の行（present の `kind: 'git'`）を出さない。会話に保存済みの古い `kind: 'git'` の present は、画面で**黙って出さない**（壊れた表示も未知の種類の表示も出さない。データ置き場のファイルは書き換えない）。
   - サーバー: `recordPresent` は git を記録せず、`shownPresents` が履歴の読み出し（`loadTranscript`・`findPresentBody`）で git を外す。
   - 画面: `web/timeline.mjs` の `buildItems` が git を飛ばし、`web/render.mjs` は何も描かない節を返す。読み取り専用のスレッドでも同じ。
   - 古い札（`turn-card`）の `card.git`・`fields.git`、古いタスク台帳の `row.git` は読まずに捨てる。
3. 右の欄の git のタブの「この会話の間」の範囲を消す（`SESSION_RANGES`・`sessionBase`・`hasSession`・`range: 'session'`、WS の `summary`・`through`）。残すのは「コミットしていない変更」と履歴。基準にしていた最初の `-start` の撮影が無くなるため。
4. 委譲の子の完了通知の「変更: … N ファイル」の行（`row.git`・`gitActivity.summary` の session の部分・`ply_task_status` / `ply_task_wait` の `git`・`gitSummary`・委譲カードの「変更」の行）を消す。
   - worktree を切った子は、今ある「作業場所: worktree <branch>（未取り込み · N ファイル）」の行（ブランチの差。`workspace` / `workspaceSummary`）に寄せる。
   - worktree を切らない子には載せない。基準が「同じ作業場所の、会話の最初の撮影から今まで」だったので、同じ場所の別の会話のコミットまで混ざって当てにならなかった（実例: main で動いた子に「34 ファイル +731 −1383 · コミット 7」と出た）。
5. 残っている隠し ref を 1 回だけ片付ける（下の C）。ユーザーのブランチ・index・作業ツリー、`refs/pleiad/archive/`（worktree を畳むときの退避）には触れない。

残すもの: `core/git-timeline.mjs`（会話でしたことの時系列。PR の記憶とパネルの「この会話で作成」に使う。`createCallTracker`・`timelineOf`）、`snapshotTree`（右の欄の変更の一覧・`changeCount`・worktree の退避に使う。ここだけが一時 index で `add -A` するので、下の見張りに乗せる）。

### B. 裏の作業は「待たない・重ねない」で書く

裏の作業は、あってもなくても誰も待たないものにする。次の 3 つを共通の仕組みにする。

- (a) **時間どおりに戻る**: 止めたあと、プロセスが終わらなくても戻る。
- (b) **終わらなかったものを数える**: 止めても終わらなかったプロセスを、場所（リポジトリ）ごとに数える。
- (c) **生きている場所には新しく起こさない**: 数えた分が 1 つでも生きている場所では、新しい裏の作業を起こさない。続けて時間切れになった場所は、決まった時間だけ休ませる。どちらも自分で戻る。

実装:

1. **`run()` の締め**（`core/process.mjs`）: `killDeadlineMs`（止めてから戻るまでの上限）・`onLeftover`（終わらなかった pid を渡す）・`killWith` を足す。裏の作業用の `runBackground` は `killTree: true`・`exitCloseGraceMs: 2000`・`killedCloseGraceMs: 500`・`killDeadlineMs: 3000`。**`taskkill` は非同期**（`TASKKILL_TIMEOUT_MS` 10 秒。以前は同期で、止まった木を待つと event loop ごと止まった）。`input` を渡す子は、入力を読まずに終わると書き込みが EPIPE の `error` になるので、標準入力の `error` を受けて捨てる（受け手が無いと未処理の例外でホストが落ちる。子の結果は `exit` / `close` が決める）。
2. **場所の見張り**（`core/place-guard.mjs`）: `createPlaceGuard` が、場所ごとの生存数（`leftover` / `alive`）・連続した時間切れ（`timedOut` / `completed`）・休み（`blocked`）・合流（`coalesce`）を持つ。場所は `git rev-parse --show-toplevel` の結果（別名は 500 まで覚える）。
3. **git の入口を 1 本にする**（`core/git-info.mjs`）: `readGit` / `writeGit` は常に見張りを通る。見張りが止めたときは例外にせず `{ ok: false, code: 'BUSY' | 'REST' }` を返し、呼び出し側は前の値を出す（`gitStatus` は最後に取れた値。無ければ「情報なし」）。`execGit`（worktree の作成・削除など、120 秒）は見張りの前に待たせないが、上限と終わらなかった分の数え上げには乗る。
4. **同じ種類は 1 本に合流**: 同じ場所の同じ種類は同時に 1 本。`gitStatus` は、TTL（読み終えた時刻から 2 秒）内なら前の値を返し、過ぎていれば走っている分に乗る（`join`。新しく並べない）。`fresh` を頼まれたときは「走っている 1 本の次の 1 本」を共有する（`trailing`。走り始めたあとに頼まれた `fresh` に前の結果は渡さない）。スナップショットも同じ `trailing`（次の 1 本は頼んだ時刻より後に始まるので、基準はずれない）。待つ人が全員いなくなったら走っている分を止める。`trailing` の「次の 1 本」は、走っている分が終わる処理の中で同期的に引き継ぐ（`slot.running` が空になる隙間を作らない。隙間に来た頼みが「何も走っていない」と見て、引き継がれる次の 1 本と並んで 2 本目を起こすため）。

### C. 隠し ref の片付けは、場所を最初に読んだときの 1 回

- 起動直後の一括の掃除は作らない（遅い場所をまとめて起こすことになり、この ADR の目的と逆）。かわりに、その場所を最初に読むとき（`status` が成功したあと・`changes`・`changeCount`・`commits`）に `tidy(root)` を 1 回だけ起こす。
- 消すのは `refs/pleiad/turn/` の下だけ（`dropTurnRefs`。ほかの接頭辞・ブランチ・タグには触れない）。`git for-each-ref` で一覧し、`update-ref --stdin`（`delete` の行）で消す。1 本も無ければ `for-each-ref` の 1 回で終わる。commit・tree・blob は到達不能になり、`git gc` が整理する。
- **数千本でも終わるように、数百本ずつ消す**: 実際のリポジトリに 2,182 本あり、1 本の `update-ref --stdin` では読みの上限（4 秒）に収まらない恐れがあった。収まらないと、60 秒ごとにやり直す・軽い時間切れとして数えられる・場所が休みに入って git タブまで休む、の連鎖になる。そこで 300 本ずつ（`CLEANUP_CHUNK`）の削除に分け、1 回ごとに掃除用の長い上限（`CLEANUP_TIMEOUT` 30 秒）を使う。全体は 90 秒（`CLEANUP_BUDGET_MS`）まで。
- **掃除の時間切れは休みに数えない**（`exec` の `counts: false`。休みに入る数えにも、数えの戻しにも載せない）。掃除は画面に出ず、遅い場所を休ませる理由にならない。止まっている場所（`BUSY` / `REST`）では起こさない・止めても終われない子は数える、は他の git と同じ。
- **途中までなら、次回は残りから続く**: 消せなかった塊（時間切れ・git が断った・全体の上限）があれば `null` を返し、そこまでに消した分は戻さない。次に呼ばれたときは `for-each-ref` で数え直すので、残りだけから続く。
- 見張りに乗せる: 場所ごとに同時に 1 本（合流の鍵は `tidy:<場所>`・`join`）、止まっている場所（`BUSY` / `REST`）では起こさない。取れなかった・消せなかった・途中までのときは記録を残さず、60 秒後（`TIDY_RETRY_MS`）以降の次の読み取りでやり直す。終わった場所は二度と起こさない。

## 決めた数と根拠

数は、実測したもの（止める時間・提案書の試験）と、判断で決めたもの（休み・連続の回数）がある。判断で決めた分は、実機の様子を見て変えてよい（`REST_LADDER_MS`・`REST_AFTER_TIMEOUTS`）。

| 項目 | 値 | 根拠 |
|---|---|---|
| 止めてから戻る上限（`BACKGROUND_KILL_DEADLINE_MS`） | 3 秒 | 正常な `taskkill /t /f` が 1.3 秒ほど（実測。試験で木ごとの停止に 1,322 ms かかり、初めに置いた短い上限では正常な停止まで「終われなかった」と数えたので、3 秒に上げた）。これを超えたものだけを「終われなかった」と数える |
| `exit` のあと、パイプを待つ猶予 | 2 秒 | `exit` のあとにパイプが閉じないのは、孫がパイプを握っているため。長く待つ意味が無いので、秒単位で切る。grace 0 では 8,139 ms、500 ms では 2,020 ms で戻った（提案書の試験） |
| 止めたあと、パイプを待つ猶予 | 0.5 秒 | 同上（2,020 ms の試験の値） |
| `taskkill` の上限 | 10 秒（非同期） | 止まった木では 10 秒を超えうる。同期だと event loop ごと止まるので、待たない形にして上限だけ持つ |
| 休みの段 | 30 秒 → 60 秒 → 120 秒 → 300 秒（以後 300 秒） | 提案書は 1 → 2 → 4 → … 最大 30 分を案にしていたが、この休みは画面に出さず（出す対象の表示を消したため）、遅い場所を人は気づかない。長く休むほど「git のタブが古いまま」に気づきにくいので、最長を 5 分に抑えた。倍々にするのは、一時的な遅れ（数十秒）と長い停止（数十分〜1 時間）のどちらでも無駄な再試行が少ないため |
| 休みに入る連続の時間切れ | 2 回目から | 1 回目はウイルス対策ソフトの走査などの一時的な遅れでも起きる。2 回続けて初めて「その場所が遅い」と決める。同じ詰まりで同時に切れた分は 1 回と数える |
| 休みの種類 | 軽い（status・一覧）と重い（撮影・`add -A`）に分ける | 重いほうの時間切れで軽いほうは休ませない。軽いほうが休むときは重いほうも止める |
| `READ_TIMEOUT` / `SNAPSHOT_TIMEOUT` | 4 秒 / 8 秒（変えない） | 時間切れが「効く」ようになったので、これまでの値がそのまま上限になる |
| `gitStatus` の TTL | 2 秒（変えない） | 同じ場所に 5 本並んだのは TTL の過ぎた後ろに並べる作りのため。TTL は変えず、合流で 1 本にする |
| `tidy` のやり直し | 60 秒 | 取れなかった理由は主に止まっている場所。休みの最初の段（30 秒）より少し長くし、ぶつけない |
| 掃除の塊 / 1 回の上限 / 全体の上限 | 300 本 / 30 秒 / 90 秒 | 3,000 本を 300 本ずつ 10 回で消すのに約 5 秒（一時リポジトリ。1 回の読みの上限 4 秒には、塊でなく全部を 1 回で消すと収まらない見込み）。1 回の上限は読みの 4 秒の数倍にし、遅い場所でも 1 つの塊が終われるようにした。判断で決めた数 |

## 理由

- 毎ターンの `git add -A` は、遅い場所では会話の数だけ重なり、Pleiad の外（会話の Bash など）の待ちまで巻き込んだ。機能が無くても作業は止まらず、見る場面もほとんど無いという利用者の判断のとおり、記録を無くすのが最も確実。入口を直すだけなら、撮影を起こす側が増えるたびに同じ穴ができる。
- 右の欄の読み取り（状態・変更の一覧・履歴）と worktree の確認は残るので、遅い場所ではこれらも詰まる。「待たない・重ねない」の仕組みは、撮影を消しても必要。見張りを `git-info` の入口に置いたので、呼び出し元ごとに足し忘れない。
- 古い present は書き換えずに黙って出さない。データを書き換えると、移行の失敗が会話の履歴を壊すおそれがあり、読み出しの側で外すだけなら戻せる。
- 委譲の「変更」の行は、基準が会話ごとの撮影だったので、撮影ごと消すと成り立たない。基準を別に作るより、既にある worktree の「ブランチの差」に寄せるほうが事実として確かで、分けた作業場所の無い子は事実を言えないので載せない。
- 起動時の一括の掃除は、遅い場所の隠し ref まで一度に読みに行く。使わない場所には触らず、読んだ場所で 1 回だけ消せば足りる。

## 影響

- 返答の下の変更の行・右の欄の「この会話の間」・委譲の完了通知の「変更:」行は無くなる。古い会話の `kind: 'git'` は出なくなる（保存はそのまま）。
- `.git` の `refs/pleiad/turn/` は、その場所を最初に読んだときに消える（commit・tree・blob は `git gc` が片付ける）。読まれない場所には残る。
- 遅い場所では、右の欄の git が「前に取れた値」のまま、または「情報なし」になることがある（休み中、または前のプロセスが残っている間）。休みと残りは自分で戻る（成功すれば連続の数が 0 になり、残りのプロセスが消えれば数が減る）。
- `ply_shell`・`!`（host-shell）は変えない。使う人が待つ前提のコマンドで、時間切れの意味が違う。
- 提案書の第 3 段（止まっているコマンドの知らせに原因の手がかりと操作を添える）は、この ADR では扱わない。

### 呼び出し元の分類

| 区分 | 呼び出し元 | 扱い |
|---|---|---|
| 見張りの対象（場所ごとの数え上げ・休み・合流） | `core/git-info.mjs` の `readGit` / `writeGit`（状態・差分・履歴・撮影）、`worktreeList` | `runBackground`＋場所の見張り |
| 上限だけ（場所は持たない） | `core/git-prs.mjs` の `runGh`、`core/agent-browser.mjs` の `listProcesses`、`core/backends/claude-held.mjs` の `askVersion`、`core/mcp-ledger.mjs` の `startTimesOf` | `runBackground`。時間どおりに戻る |
| 見張りの前では待たせないが、上限と数え上げには乗る | `execGit`（`core/git-worktree.mjs` の worktree 作成・削除・ブランチ・`update-ref`。120 秒） | 人の操作の結果を待つので休ませない |
| 変えない | `core/host-shell.mjs`（`!`）、`ply_shell`、アカウントの `whoami` / `icacls`（`runSync`）、`core/mcp-ledger.mjs` の `killTree` の `taskkill`、ログアウトの処理 | 使う人が待つ・または上限が既にある・起動時の 1 回 |

## 残したこと

見直しで挙がったが、利用者と合意した方針どおり直さないもの。

- 終わらない子が残っている間、その場所は `BUSY` のまま（「生きているものがあれば、新しく起こさない」を優先する。残りが消えれば自分で戻る）。
- `BUSY` / `REST` の間、`repoInfo` は git でない場所と同じく `null` を返す（記録が取れないときは「何も出さない」と決めた。前に取れた値を残すかは画面側の話）。
- `placeKey` は 8.3 短縮名・`\\?\` 接頭辞・シンボリックリンクを同じ場所にそろえない（別の鍵は別の場所として数える。そろえると、遅いファイルシステムへ余計な問い合わせが要る）。

## 採らなかった案

- 撮影を残して「コミット 0 のときは撮らない」「諦めた撮影は止める」だけにする案: 詰まりの元は残り、表示の意味（撮れなかったときの出し方）も決める必要が残る。利用者が機能ごと消すと決めた。
- クラウド・仮想ドライブをパスの形やボリューム情報で見分けて撮影を切る案: 見分けの漏れと、問い合わせ自体が遅い場所に触れる危険がある。見張りは「実際に遅かった」ことで決める。
- 木ごと止める（`killTree`）だけに頼る案: Windows ではラッパーを止めると本体も消えるので、孤児は減らない（上の試験）。
- 休みの最長を 30 分にする案: 画面に出さない休みが長すぎる。復旧後の最初の読み取りが 30 分遅れる。
- 起動時に全部の場所の隠し ref を一括で消す案: 遅い場所をまとめて起こす。
