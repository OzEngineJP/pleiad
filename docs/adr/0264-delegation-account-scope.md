# 0264: 委譲先の自動選択の候補をアカウントの単位にする

## 状態

承認（2026-10-24）

- 関連: [0022](0022-delegation-routing.md)（委譲先の自動選択）、[0040](0040-delegation-routing-headroom.md)（使用量の後回しとアカウントごとの判定）、[0205](0205-ai-chooses-claude-account.md)（AI が委譲の子のアカウントを選ぶ）、[0222](0222-agent-accounts-and-provider-quota.md)（登録アカウントと使用枠）、[0226](0226-delegation-candidate-drag-order.md)（候補の並べ替え）、[0229](0229-opencode-limit-retry-wait.md)（上限で止まった枠）

## 状況

段ごとの候補は「エージェント・モデル」の組で、アカウントを登録したエージェント（Claude・Codex・OpenCode）では、候補を選ぶたびに登録したすべてのアカウントを使用量で比べ、空いているものを選んでいた（ADR 0040 の「Claude のアカウント」）。

- 仕事のアカウントと個人のアカウントを両方登録すると、自動の委譲がどちらにも流れる。どのアカウントで走らせてよいかを利用者が決める口が無かった（契約上、仕事の作業を個人のアカウントで走らせてはいけない、など）。
- 固定の委譲（`backend` を書いた）でも、親の会話のアカウントをそのまま継いでいた。

## 決定

1. **段の候補は「エージェント・モデル・アカウント」の組。** 候補の id は `backend:model`（ログイン中のアカウント。アカウントを持たないエージェントはアカウント無し）と `backend@<アカウント id>:model`（登録したアカウント）。同じモデルを別のアカウントで、別の段・別の順に置ける。段は上から順に試し、アカウントの間で自動に釣り合わせない。候補のアカウントが使えなければ、ほかのアカウントへは落とさず次の候補へ進む。
2. **自動の選択の対象は、どこかの段に入っているアカウントだけ。** 新しく登録したアカウントは、段に入れるまで使わない。
3. **移行はしない（id の読み方で移す）。** 保存済みの `backend:model` は、アカウントを登録したエージェントではログイン中のアカウントの候補になる。prefs は書き換えない。アカウントを登録していないエージェントは今までどおり。
4. **アカウントを書かない固定の委譲**（と `ply_task_send` で別のエージェントへ替えるとき）も段のアカウントだけを使う。継ぐアカウントが段に入っていればそれ、入っていなければ段のアカウントの中から使用量で選ぶ。そのエージェントのアカウントが 1 つも段に無ければ `account_not_in_tiers` で断り、自動の選択で頼むように返す。自動の選択を無効にしていても同じ。
5. **`account` を書いた固定の委譲は、段に無いアカウントでも通す**（人や AI が明示したもの。今までの断る理由はそのまま）。
6. **登録を削除したアカウントの候補は、段から外す。**
7. **設定 › 委譲 › 詳しい設定。**
   - 候補の名前は「Sonnet · personal」（ログイン中は「Sonnet · ログイン中のアカウント」。ログイン中の中身が登録したアカウントと同じ人と分かれば「ログイン中のアカウント（personal）」）。下の行はそのアカウントの使用量だけ。アカウントを登録していないエージェントの候補は今のまま。
   - 段の上に、アカウントを登録したエージェントごとの 1 行「[ロゴ] Claude 使う ログイン中のアカウント · personal 使わない work」。段の中身から決まる表示で、押せる部品は無い。
   - ［＋ 候補を追加］は エージェント ▸ モデル ▸ アカウント の 3 段。段にもう入っている組み合わせは出さず、全部のアカウントが入ったモデルは消える。アカウントを登録していないエージェントは 2 段のまま。入力欄に `backend:model` を打って Enter を押すと、そのエージェントにアカウントが複数あればアカウントの段を開く。
   - 使えないアカウントの候補は行を薄くし、「使えない（認証情報なし） · ログインし直す」。「ログインし直す」は設定 › エージェント設定のそのアカウントの行の［ログインし直す］へ移る。
   - 360px では思考の強さが名前の下へ回り、名前は「Sonnet ·」の後ろで折り返す。
8. **エージェントへの返り値。** `ply_usage` のアカウントの行に `inTiers`（段に入っているか）。再試行の候補・委譲カードの内訳・エラー文の候補行は、候補の id とそのアカウントの表示名で書く（`- claude@acct-…:opus [personal] (t4): …`）。ツールの説明文にも 4・5 を書く。

## 理由

使ってよいアカウントを、利用者がすでに触っている段の候補で決められる。許可の一覧を別に持つと、段と食い違ったときにどちらが効くかを説明しなければならない。段の中身から「使う / 使わない」を出せば、5 つの段を見比べなくても読める。

明示した `account` を通すのは、人が入力欄で選ぶ操作と、AI が `ply_usage` を見て選ぶ操作を今までどおり残すため。書かないときに段のアカウントへ絞るのは、親の会話のアカウント（個人のアカウントの会話から頼んだ、など）が黙って子へ流れるのを止めるため。

## 影響

- 更新の後、アカウントを登録したエージェントの既存の候補はログイン中のアカウントだけで走る。ほかのアカウントでも走らせるには、段にそのアカウントの候補を足す。
- 段の候補の数は、アカウントの数だけ増えうる。
- `route` の返り値の `skipped[]` から `lower_priority`（選ばれなかった余裕ありのアカウント）が無くなる。
- 再試行の要求の `account` は、候補の id に畳んで受ける（前の版の画面の互換）。
