# 0374 デザイントークンの正本と配布

- 状態: 提案

## 状況

ホストの画面、モバイルの接続先一覧、公開サイトは別々に配布する。同じ配色や角丸を複数の CSS で書いていると、値を更新するたびに調整が必要になる。別リポジトリの画面でも、選んだ版のトークンを使える入口が要る。

## 決定

- `packages/design-tokens/tokens.css` を編集元にする。`@pleiad/design-tokens` は CSS と、そこから生成した既定・ダークの JSON を提供する。
- ホストとモバイルの静的ファイルには生成した CSS を含める。公開サイト向けには共通で使うライトの値を出力する。生成ファイルはリポジトリに含め、試験で正本との一致を確かめる。
- 別リポジトリで使う場合は、取り込む公開コミットの SHA を固定する。npm レジストリには公開しない。

## 理由

- CSS を編集元にすると、ブラウザーで実際に使う色・文字・余白・角丸から JSON を作れる。色や単位を CSS の形式で保てば、利用側が必要な形式を選べる。
- 静的ファイルとして含めると、ホストの `/tokens.css`、リモート端末への静的ファイルの束、モバイルのアプリ同梱という既存の配布経路で使える。
- コミットを固定すると、取り込み側が更新する版を選び、同じ入力から再ビルドできる。

## 影響

- 値の変更には生成ファイルの更新が伴う。更新手順と利用口は [デザインシステム](../design-system.md) に記す。
