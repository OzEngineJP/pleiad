# 0357 bot 専用の使用量の仕組み（チャンネルの予算・スレッドの配分・メーター・今週の使用量）をやめる

- 状態: 提案
- 改めた: [0119](0119-channel-budget-and-resting.md)（予算の部分すべて。「使用量の上限は `limited` にそろえる」「上限で終わったターンの扱い」「休憩中」「黙る自由」は残る）、[0126](0126-bot-pulse-and-stream.md)（心拍の予算と bot ごとの 1 日のトークンの上限）、[0140](0140-bot-wake-reservations.md)（予約の予算）、[0128](0128-overheard-posts.md)（聞こえた投稿を予算で絞る部分）
- [0352](0352-no-preemptive-limit-stop.md)（使用率で先回りして止めない）と同じ向き。0352 は Chats と委譲の側、この ADR は bot の側

## 状況

[0119](0119-channel-budget-and-resting.md) は、bot どうしの呼び合いを「回数」でなく「費用」で止めるため、チャンネルの 1 日の予算・1 スレッドの配分・毎ターンの残りの引き渡し・スレッドの下のメーター・bot のページの「今週」を足した。数える元は、バックエンドの週の枠の使用率を、Pleiad が使ったトークンの割合で配った推定だった。

使ってみると、次のことが残った。

- **数字が会話の感覚と合わない。** 推定の % は 0 に張り付くか、不明になる（枠を読めないバックエンド、使用率が粗い Codex）。メーター・内訳・キャッシュ率・「今週」は、何のための数字か利用者に読みにくい。
- **Chats には無い第 2 の使用量表示になった。** 利用者が費用を見る場所は設定の「使用量」と `ply_usage` の 1 か所で、bot だけが別の物差し・別の止め方を持っていた。
- **先回りの停止は 0352 で退けた考えと同じ。** サービスは本当の上限に当たったときに自分で止まる（`limited` → 休憩中）。Pleiad が推定で先に止めると、まだ動ける枠を使えないまま止める。

ユーザーが bot の画面のモックを確認して、仕組みごとやめると決めた。あわせて、bot どうしの呼び合いへの代わりの歯止め（「10 回で止める」「［続ける］」）は **足さない** と決めた。

## 決定

- **使用量の仕組みを、画面だけでなく仕組みごと消す。**
  - チャンネルの `budget = { daily, perThread }`、スレッドの `ThreadState.spend`、`core/bots/budget.mjs`・`core/channels/budget.mjs`（% への換算・数える・残りを出す）。
  - `bots.list`・`bots.get`・`bots.overview` の `usage { weekTokens, cacheRatio }`。操作 `channels.threadBudget`。`channels.update` の `budget`。`channels.get` の `spentToday`。`brain.view` の `status.budget`。
  - スレッドの下のメーター・内訳・「このスレッドの残り」、チャンネル設定の「予算」、bot のページの「今週」、活動メモの「予算の残り」。
  - 毎ターンの末尾の文脈（`<pleiad-turn-context>`）の「このスレッドの予算の残り」と、その説明。人格の固定の文の予算の案内（`guide.bot.quiet` の予算の部分）。
- **使い切りの止め方は 1 つだけ残す: サービス側の上限。** 上限に当たったら、解除の時刻まで休憩中（0119 の「休憩中」・`limited`・上限の知らせ）。これは推定でなく、バックエンドが返した上限による。
- **bot どうしの呼び合いに歯止めは置かない。** 止めるのは人の［止める］（0109）・サービス側の上限・bot 自身が黙る（0119 の「黙る自由」）。
- **心拍・予約の自発の分も同じ。** チャンネルの予算から引くこと・bot ごとの 1 日 1.5M トークンの上限・「使用枠が読めないときは自発しない」を外す。間隔の下限（5 分。コード）・眠らせる（`brain.pause`）・ふるいは残る。
- **古い保存値は読まない。** チャンネルの `budget` は出力のときに落とし（`core/channels/service.mjs` の `shown`）、スレッドの `spend` と記憶の `brain.spend` の行は誰も読まない。`brain.spend` の行は bot を消すときに片づく。保存形式の番号は上げず、移行も書かない（読まれない欄が残るだけで害は無い）。古い版へ戻すと、残った値が再び読まれて予算が効く。

## 理由

- 推定で先に止める仕組みは、数字の正しさを利用者に説明できない限り、止まったときに「なぜか」が言えない。本当の上限なら理由が言える（解除の時刻つきの休憩中）。
- 0352 で Chats の側が先回りをやめたのに、bot の側だけ残すと、同じアカウントの 2 つの動きが食い違う。
- 毎ターンの残りの引き渡しは、推定の数字を bot の判断に混ぜる。黙る自由は残すので、続けるか・ここでやめるかは bot が文脈で決められる。
- 仕組みごと消すのは、画面だけ消すと、数えるコード・保存・操作・試験が見えない所で残り続け、また足されるため（AGENTS.md「足す前に減らす」）。
- 保存値を移行で消さないのは、読まれない任意の欄は害が無く、消す移行は古い版へ戻れなくするだけだから。

## 採らなかった案

- 画面のメーターだけ消して、数えて止める仕組みは残す（止まった理由を画面に出せない状態が残る）。
- 「10 回で止める」「［続ける］」の代わりの歯止め（0119 が外した形に戻る。ユーザーが足さないと決めた）。
- 使用量の表示を Chats の設定の「使用量」へ 1 つにまとめる案は、今ある表示がすでにそれ。足すものは無い。

## 影響

- bot どうしの長い呼び合いは、人が［止める］か、サービス側の上限に当たるまで続く。費用の歯止めは人の目に戻る（0119 以前と同じ。回数の上限は 0119 で外してある）。
- 心拍・予約は、使用量が読めない環境でも、間隔の下限に従って動き続ける。眠らせていない bot は 5〜60 分ごとに見回る。
- 操作の数が 1 つ減る（`channels.threadBudget`）。`ops-surface.snap.json` を更新した。`channels.update` に `budget` を渡すと、知らない引数として `INVALID` になる（ほかの操作と同じ。承認は出ず、何も変わらない）。
- ADR 0119・0126・0140 の予算の節は、この ADR で置き換わった（履歴として残す）。living doc の `docs/channels.md`・`docs/design-system.md` は今の形だけを書く。
