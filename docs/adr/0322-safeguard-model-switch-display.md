# 0322 安全装置のモデルの切り替えを、会話・入力欄・送信待ちに出す

- 状態: 承認（2026-11-13。main に入れる直前に番号を確定）
- 承認の内容: プロダクトオーナーが、モックの形（temporary/mockups/safeguard-fallback-notice.html）を承認した。

## 状況

Claude の Fable は、安全装置が応答を止めると、CLI が別のモデル（Opus）に切り替えて続ける（`system/model_refusal_fallback`）。Pleiad はこの出来事を捨てていたため、次の 3 つが起きた。

1. 画面からは、どのモデルが答えたのか・なぜ変わったのか分からない（入力欄は選んだモデルのまま、使用量も選んだモデルの枠のまま）。
2. 拒否した応答の `stop_reason: refusal` を「main が止まった」と数え、CLI の入力を閉じていた。切り替えの続きの間は途中送信（`control.steer`）が断られ、送った文が理由の無い「送信待ち」のまま残った。
3. 切り替え先が無く止まったとき、失敗とも成功とも分からない。

## 決定

- `refusal` は「main が止まった」に数えない。切り替えが無く終わるときは、結果が来た時点で今までどおり閉じる。
- 切り替えを中立の出来事 `modelSwitch`（`switched` / `stopped`）に正規化し、会話の本文の外の出来事の行（中断の行と同じ弱い字）で出す。履歴の読み戻しも transcript から同じ行を作る。受け口は Claude だけ。
- 入力欄は選んだモデルを保ち、「⇄ 返答したモデル」の印と、返答したモデルの使用量を出す。人がモデルを替えるか、切り替わらずに終わったターンの後で消える。
- 切り替え先が無く止まったときは「応答が止まりました」とモデルを選んで送り直す口を出す。
- 理由の無い送信待ちは「作業が終わると自動で送信」と出す。

## 理由

- 拒否は続きがある出来事で、止まりではない。数えると入力が閉じ、途中送信が断られる。
- 切り替えは会話の本文ではなく出来事なので、中断の行と同じ弱い字にすると、読み物の邪魔をせず、開けば原文が読める。
- 人の選択（札）と実際の返答を分けて出せば、選んだモデルを勝手に書き換えない。

## 影響

- `core/backends/claude-normalize.mjs`・`core/backends/claude-background.mjs`・`core/system-messages.mjs`・`web/model-switch.mjs` ほか。
- サブエージェントの切り替え（`scope: local`）・撤回された途中の返答（`retracted_message_uuids`）は扱わない。Claude 以外のエージェントは受け口が無い。
