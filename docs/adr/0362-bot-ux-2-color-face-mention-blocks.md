# 0362 bot の見た目と呼び方の 2 回目: 色の顔・チャットと bot の 2 面・bot を作る 3 段・@ の宛先の塊・メンバーへの自動追加・スレッドごとの設定の廃止

- 状態: 提案
- 改めた: [0299](0299-bot-identity.md)（bot の識別表示。画像・絵文字・頭文字の順で出す → 色だけの顔）、[0157](0157-unify-chat-thread.md)・[0160](0160-header-and-destination-chip.md)（スレッドの入力欄の宛先・モデルのチップと「Bot」の行・一時チャットの流れ）、[0288](0288-sidebar-bot-strip-and-create-entries.md)（Bots の帯）
- この ADR は、同じ bot の画面のモック（`temporary/mockups/bot-ux-2.html`）の確認で決まったことを書く。実装は 5 つの commit（顔・脇の 2 面・チャットから bot を選ぶ口の撤去・作る 3 段・スレッドの入力欄のチップの撤去）と、この ADR を付けた @ の塊の commit に分かれる

## 状況

bot を使う流れで、次の 6 つが分かりにくかった。

- **bot の顔が揃わない。** 画像・絵文字・頭文字が混ざり、同じ画面で bot どうしの区別が付かない（絵文字は被る、画像は小さいと潰れる）。作る側にも「画像を切り抜く」「絵文字を選ぶ」という、bot を使う目的と関係の薄い選択があった。
- **bot と普通のチャットが 1 つの脇に混ざる。** Bots の帯・一時チャット・チャンネル・ルーティンが 1 本の木に並び、普通のチャットで bot を宛先に選べたため、「チャットで bot に話しかける」と「bot の DM で話す」の 2 つの入口が重なっていた。
- **bot を作る画面が 1 枚で重い。** 名前・アイコン・人格・モデル・承認モードを一度に求める。初めて作る人が、何も分からないまま全部を決める形だった。
- **スレッドの入力欄に、宛先・モデル・作業フォルダー・承認モードのチップが並ぶ。** 同じ bot の設定が bot のページとスレッドの 2 か所にあり、どちらが効くのか分からない。スレッドごとの上書き（`bot.overrides`）が、bot のページで直した値を静かに上書きしたままにする。
- **`@` が文字のまま。** 入力欄に `@Owl` と打つ・補完で入れるだけで、「宛先が決まった」ことが目で分からない。消すにも、名前の文字を 1 字ずつ消す。投稿した後の本文も青い字で、誰が呼ばれたかが顔で分からない。
- **宛先を選び間違えたときの動きが分かりにくい。** チャンネルの最初の投稿に `@` が無い・まだどの bot も答えていないスレッドに `@` が無いと、bot は反応しない（これは既存の規則）。しかし画面は「反応しない」ことを入力の途中で知らせず、メンバーでない bot は `@` で呼べず、先にメンバーに足す手が要った。

## 決定

- **bot の顔は、色だけの印にする。**
  - 8 色（`--bc1`〜`--bc8`。light・dark それぞれ）。`bots.json` の `color`（整数 1〜8。`bots.create`・`bots.update` で指定できる）を持つ。指定しない作成は、いちばん新しい bot の色の次へ進み、今いる bot と重ならない色を優先する（8 色を使い切っていれば順番どおり重ねる）。
  - `iconImage`（画像）・`icon`（絵文字）は、**保存値を消さず、読まない**。顔は常に色の顔（`botIcon`）。色が無い古い bot は 1 色目に倒す。
  - 大きさは、脇・チャンネルの見出し 20px・発言 32px（人の頭文字の丸と同じ）・@ の候補と入力欄の塊 16px・bot のページと作る画面は大きく（丸全体に広げる）。画素合わせの形は 32・20・16 の 3 つ（`web/channels/bot-icon.mjs`）。
  - 色は `--bot-color` として要素に渡す。デザインの検査（`tests/lint-design.mjs`）の背景の許可に `bot` の族（`--bc1`〜`--bc8`・`--bot-color`）を足す。
- **脇は「チャット」と「bot」の 2 面。** 切り替えは検索の上。チャットの面は bot を出さず、bot の面は ルーティン → Bots の行（20px の顔・名前・状態。DM のスレッドを下に畳む）→ チャンネルを出す。Bots の帯は無くす。一時チャットの呼び名は「チャット」にする。
- **普通のチャットで bot を選べる口を無くす。** 宛先とモデルの面の「Bot」の行・「# 一時チャット ›」のパンくず・一時チャットの流れの画面を外す。既にできている bot のスレッドは、bot の面のその bot の下から開く。
- **bot を作るのは 3 段（名前 → 色 → 人格）。** 初めて・bot が 0 体のときは bot の面の右が 1 段目。エージェントは最初の起動で選んだ既定、モデルと承認モードも既定のまま。作ったら DM を開いて入力欄に焦点を置く（[0358](0358-bot-ux-decisions.md)）。画像・絵文字の口は無い。
- **スレッドの入力欄から宛先・モデル・作業フォルダー・承認モードのチップを外す。** 入力欄の下は添付と送信だけ。承認モードは bot のページだけで変える。
  - スレッドごとの `model` / `effort` / `cwd` / `mode` の上書きは**読まない**。保存された `bot.overrides`（`ThreadState`）の印と会話の値は消さず、会話の作成と `createBotSessions` の `sync`（`core/bots/sessions.mjs`）は印を読まずに bot の設定へ揃える。`channels.threadSettings` の op は外し（一覧の snapshot `tests/ops-surface.snap.json` も更新）、画面からも呼ばない。
  - `@` の無い人の投稿の届き先は、DM ならその bot、スレッドなら**前に答えた bot**（今までの `conversingBot`）。
- **`@` の宛先は、入力欄の中の「顔 + 名前」の塊にする。**
  - `@` で、`here`・`everyone`・メンバーの bot・あなたの候補を出す。bot の行は 16px の色の顔と名前、選んでいる行は bot の色を淡く敷いて左に 3px の棒。`here`・`everyone`・あなたは bot ではないので顔にせず、灰色の丸に字（`@`・頭文字）を置く。DM は宛先が決まっているので候補を出さない。
  - ↑↓ で選び、Enter / Tab / クリックで確定すると、`@名前` の文字が **1 つの塊**（`span.mb`。顔・名前・× の 3 つ。`contenteditable=false`）になる。複数の塊を並べると全員に届く。**Backspace / Delete 1 回、または × で塊ごと消える**（× の読み上げ名は「宛先から外す」）。
  - **保存される本文は `@名前` のまま**。塊は表示だけで、編集欄の DOM を `@名前` の文字へ戻して読む（`web/channels/mention-blocks.mjs` の `decorate`。名前の末尾にカーソルがある間と変換中の入力は塊にしない）。コピーで貼ると `@名前`。
  - 送った後の本文も、`@名前` を bot の色の顔つきの札（`span.mention.mt`）で出す。`@` は読み上げとコピーのために視覚だけ隠して残す。
  - `@here`・`@everyone` は残す。メンバーの bot が 0 体のチャンネルでは、0 体を起こすことになるので候補に出さない（`channels.wakePreview` も 0 体なら `required: false`）。
- **`@` が無いのに誰にも届かない場合は、入力欄の上の 1 行で知らせる。** チャンネルの最初の投稿・まだどの bot も答えていないスレッドで `@` の無い文を書くと、「誰も呼ばれていないので、bot は反応しません」と［@〈bot〉を呼ぶ］を出す。押すと、勧める bot（最後に答えた bot、無ければ先頭のメンバー）の塊が入る。送る・送らないは人が決める（送れるが bot は反応しない。dispatch の規則は変えない）。
- **`@` で呼んだ bot がチャンネルのメンバーでなければ、投稿のときにメンバーに足す。** メンバーの bot がいないチャンネルでは、候補に全部の bot を出す。メンバーがいるチャンネルでは、候補はメンバーのまま（メンバーでない bot は名前を打てば `@` で呼べる）。足したら「〈名前〉をメンバーに足しました」と知らせる（`channels.post` が `addedMembers` を返す）。足すのが失敗しても投稿は残す（呼べるかは dispatch が決める）。
- **`channels.post` の `to` は API のまま残す**（画面からは使わない）。別の bot（`ply_*` ・CLI）が宛先を指定する経路を壊さないため。

## 理由

- 色の顔は、小さな画面（脇 20px・入力欄 16px）でも潰れず、bot どうしを区別する要件を 8 色で満たす。画像・絵文字の保存値を残して読まないだけにすれば、戻す（別の形で復活させる）ときの移行が要らない。
- 脇を 2 面にすると、チャットの面は bot を意識せず、bot の面は bot だけで完結する。普通のチャットで bot を選べる口を消すのは、bot に話しかける入口を DM（と `@`）の 1 つにして、覚える形を減らすため。
- bot を作る 3 段は、一度に決める数を 1 つにする。色は後で替えられるので、最初は既定のまま進めてもよい。エージェント・モデル・承認モードを最初に聞かないのは、作った後の bot のページで分かって直せるから。
- スレッドの設定を外すのは、同じ設定を 2 か所に持つと、どちらが効くか分からず、bot のページで直した値が静かに上書きされたままになるから。「今回だけ別のモデル」より「bot の設定は 1 か所」を優先する。上書きの保存値を消さないのは、戻す場合の損失と、消す移行のコストを避けるため。
- `@` を塊にして保存を文字のままにするのは、「宛先が決まった」ことを目で見せながら、dispatch・既存の投稿・他の bot の `channels.read` が読む本文の形を変えないため。1 回の Backspace で消えるのは、文字ではなく 1 つの宛先として扱えるから。
- 反応しない投稿を、送る前の 1 行で知らせるのは、送ってから「なぜ誰も答えないのか」を探す手間を省くため。dispatch の規則を変えずに、入力欄の側だけで足りる。
- 名前を指した bot をその場でメンバーに足すのは、「メンバーに足す → 呼ぶ」の 2 手を 1 手にし、足したことは知らせで見える。`@` した人がメンバーの管理を意識しなくてよい。

## 採らなかった案

- **画像・絵文字を残して、色を重ねる。** 顔の読み方が 3 通りになり、小さい画面で見分けが付かない問題が残る。
- **スレッドごとの設定を残し、チップだけ小さくする。** 2 か所の設定の食い違いは残る。
- **`@` を文字のまま、色だけ付ける。** 消すときの 1 字ずつの手間と「宛先が決まったか」が分からない問題が残る。
- **`@` を塊にするときに保存する本文も塊（`<@id>` など）にする。** dispatch・既存の投稿・`channels.read` の本文の形が変わり、他の bot の読み方・過去の投稿との互換が崩れる。
- **メンバーでない bot の `@` を断る（先にメンバーに足す手を求める）。** 名前を指した意図が分かっているのに、手が 1 つ増える。
- **`@` が無い最初の投稿の宛先を、勧める bot に自動で決める。** 誰も呼んでいないときに bot が動くと、規則「`@` が無ければ反応しない」を破る。

## 影響

- 既存の bot の画像・絵文字・`bot.overrides` は保存されたまま、画面と新しい会話の解決では使われない。再び使うなら読む側を足すだけでよい。
- 以前スレッドごとに別の値へ替えていた bot の会話は、次の `sync`（`bots.update`・`bots.setMode` など）で bot の設定へ揃う（上書きの印は読まない）。
- 古い bot（`color` を持たない）は 1 色目の顔で出る。bot のページで色を選ぶと付く。
- `channels.threadSettings` の op は無くなる（`ops-surface` から外す）。bot のページのモデル・承認モード・作業フォルダーが唯一の入口。組み込みの bot（`Bot.plain`）をスレッドで選ぶ口もこのときになくなる。
- `channels.post` が `addedMembers` を返す（`string[]`。足した bot の id）。メンバーに足すのは、人の投稿で `@` が bot の名前に当たったときだけ（bot・AI の投稿は足さない。ops の `riskOf` に変更は無い）。
- 本文の `@名前` は、塊にならない場面（名前の末尾にカーソルがある間・変換中・履歴の復元前）では文字のまま見える。次の描き直しで塊になる。
- 塊の × は 16px の押せる面（モックと同じ）。狭い画面（360px）でも同じ寸法。
- `docs/channels.md`・`docs/design-system.md` は今の形だけを書く。
