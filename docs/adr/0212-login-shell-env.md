# 0212 デスクトップ版はサーバーを起こす前にログインシェルの環境を読み込む

- 状態: 提案

## 状況

macOS で Dock・Finder・ログイン項目から Pleiad を起こすと、main は launchd の最小限の PATH（`/usr/bin:/bin:/usr/sbin:/sbin`）しか受け取らない。利用者が `~/.zprofile`（Homebrew の `brew shellenv` など）や `~/.zshrc`（gcloud など）で足した PATH は入らない（issue #82）。

main はこの環境をそのままサーバーへ渡し（`utilityProcess.fork`・`desktop/server-boot.cjs` の `serverEnv`）、サーバーがエージェントの CLI と `!` の行のシェルへ渡す。そのため、ターミナルで使えるコマンド（`gh`・`lefthook`・`gcloud` など）が会話の中で見つからない。git のフックは lefthook が見つからないまま何もせずに終わり、コミットは通るので気づきにくい。

Claude Code は起動時に `~/.zshrc` を読み込むが、シェルの写しの `export PATH=` には自分が受け取った PATH を書くため、会話のシェルの PATH は直らない。ターミナルから実行ファイルを直に起こせば起きないが、GUI からの起動では避けられない。

## 決定

- macOS・Linux のデスクトップ版の main は、`boot()` でサーバーを起こす前に、利用者のログインシェルを対話のログインシェルとして 1 回だけ走らせ（`$SHELL -i -l -c`）、その環境を main の `process.env` へ写す（`desktop/shell-env.cjs`）。言語の初期化と並べて走らせ、サーバーへ渡す env を作る前に待つ。
- シェルは `$SHELL`、無ければ OS の利用者情報のシェル。絶対パスでなければ走らせない。
- `env -0` の出力を、一度きりの印で前後を挟んで読む。rc が出す文字には紛れない。後ろの印が届いたら、シェルの終わりを待たずに返す。
- 値はシェルを優先する。PATH はシェルの並びの後ろに、main にしか無い要素を重複なしで残す。シェル自身の印（`PWD`・`OLDPWD`・`SHLVL`・`_`）と `ELECTRON_` で始まるものは写さない。
- 10 秒で時間切れにし、rc が起こした子ごと止める。読めなければ（時間切れ・シェルの失敗・印が無い）今の環境のまま起こし、理由を main のログに残す。
- Windows は読まない（GUI のアプリも利用者の環境変数を受け取る）。
- `AGENT_HOST_SHELL_ENV=off` で止める（戻し道）。読み込み中のシェルには `PLEIAD_RESOLVING_SHELL_ENV=1` を付け、rc から Pleiad が起こされても入れ子にしない。

## 理由

- 利用者が期待するのは「ターミナルと同じコマンドが使える」ことで、その正本はログインシェルの設定にある。Pleiad 側で Homebrew などの場所を決め打ちで足すと、gcloud・各種のバージョン管理（rbenv・nodenv・fvm など）のように利用者ごとに違う場所を拾えない。
- `-l` だけでは zsh の `~/.zshrc` が読まれない（gcloud の PATH はそこにある）ので `-i` も付ける。VS Code などのエディターも同じ方法で GUI 起動時の環境を解決している。
- PATH 以外の変数（`JAVA_HOME`・`ANDROID_HOME` など）も、ターミナルから起こしたときと同じにするため写す。
- 起動は 1 回のシェルの実行（手元の zsh で約 0.8 秒）だけ遅れる。言語の初期化と並べ、時間切れでも起動を止めない。

## 影響

- GUI から起こしたデスクトップ版でも、エージェントの CLI・`!` の行・git のフックがログインシェルと同じ PATH で動く。
- 起動のたびに利用者の rc を対話で 1 回走らせる。rc が対話を前提に止まるときは 10 秒待ってから今の環境で起こす。
- サーバーの付け直し（無停止の更新）では、走っているサーバーの環境は変わらない。新しい環境はサーバーを起こし直したときに効く。
