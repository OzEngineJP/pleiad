# 0089 分けた作業場所（git worktree）は、ぶつかりそうなときだけ作り、片付けまで Pleiad が持つ

- 状態: 承認（2026-10-03）。決定 2 は置換（0133）、決定 1(a)(b) と 3 の自動判定・画面での呼び名は置換（0136）、決定 5 のうち右パネルの「残っている作業場所」の置き場は置換（0135）
- 置き換えられた: 0133（決定 2：入力欄の上の 1 行で選ばせる）、0135（決定 5：残ったものを右パネルに 1 ブロック出すこと。作業場所タブの行の中へ移る）

## 状況

同じリポジトリで複数の会話・委譲の子が同時に書くと、互いの未コミットの変更を踏む。今は、人が気づいて別の場所を選ぶか、依頼元のエージェントが自分で worktree を掘って `cwd` に渡す運用で、Pleiad は何も保証せず（`docs/agent-delegation.md` は「Pleiad が自動的に worktree を作成・マージする機能ではない」としていた）、検知も警告もしなかった。作った後の片付けも手作業で、Windows ではジャンクション（`node_modules` へのリンク）ごと消してリンク先の本体を失う事故、フォルダーを掴んだまま消して登録だけ外れる事故が起きる（材料: `temporary/reports/git-worktree-ux-research.md`）。

[ADR 0085](0085-host-reads-git-and-turn-snapshots.md) で、ホストが git を読み（`core/git-info.mjs`）、右パネル「git」・入力欄のブランチ・委譲カードの変更の行を持つようになった。その上に、分けた作業場所の作成・片付けを載せる。

[ADR 0003](0003-worktree-per-task-and-local-merge.md) の「作業ごとに worktree」は、**この開発リポジトリの規則**（Pleiad を作る人とエージェントの運用）であり、製品の仕様ではない。この ADR は製品として、ユーザーのリポジトリに対して何をするかを決める。画面では「worktree」と言わず「分けた作業場所」と呼ぶ。

## 決定

1. **既定は作らない。** コーディング以外・git 管理外・読むだけの会話には何も出さない。作るのは次の 3 つのときだけ。
   - (a) 同じ Git ルートで、別の会話（委譲の子を含む）が**書き込みの範囲（workspace 以上）のターン**を実行中に、別の会話が書き込みのターンを始めようとしたとき（人が始めた会話）。
   - (b) 委譲で、同じリポジトリに書く子が 2 つ以上（または依頼元もファイルを変えている）とき。
   - (c) 人が明示したとき（入力欄の作業場所の面の「分けた作業場所で始める」）。
2. **人が始めた会話がぶつかったときは選ばせる。** 入力欄のすぐ上に 1 行「『別の会話』が同じリポジトリで作業中 [分けて始める] [このまま]」と右端の小さなリンク「いつも分ける」。送信は止めない（選ばずに送れば「このまま」）。「分けて始める」は次のターンの作業場所の予約（`setTurnSettings` の `cwd`。ターンの境界でだけ切り替わる）にし、「次のターンから適用」の行から取り消せる。「いつも分ける」は設定（台帳 `worktrees.json` の `settings.always`）に保存し、以後は確かめずに分けて始め、ターンの頭に静かな 1 行「分けた作業場所で始めました（…が作業中）[元の場所に戻す]」（present の 1 種 `kind: 'worktree'`）を会話に残す。設定 › 委譲の末尾の「分けた作業場所」から戻せる。
3. **委譲は自動で分ける。** (b) のとき、Pleiad が子ごとに作り、子の `cwd` にする。`ply_delegate` に任意の `isolate`（真偽。省略は (b) の自動判定）を足す。判定は、子が書く（書き込みの範囲のモード・`trivial` `mechanical` `implement` `ux_change` `ux_new` `visual`）うえで、同じリポジトリに依頼元以外の書き手（走っている別の会話・子、依頼元が今のターンでファイルを変えている）が居るか、同じターンから並列に呼ばれた別の子が居るとき。並列の呼び出しは 250ms ほど待ってまとめて数える（3 つ並べて呼べば 3 つとも分かれる）。`isolate: false` は分けず、`true` は 1 つでも分ける。子への指示に「作業はこの作業場所の中だけ。元の場所の絶対パスに書かない。終わったらコミットする」を足す。**取り込みは依頼元のエージェントがする**（Pleiad はマージしない）。完了通知と `ply_task_status` には `作業場所: 分けた作業場所 <branch>（未取り込み · N ファイル）`。
4. **置き場とブランチ**: リポジトリの隣 `<リポジトリの親>/<リポジトリ名>.pleiad/<短い id>`（サーバーが決める。画面から任意のパスを受けない）。ブランチは `pleiad/<短い id>`（id は `ply-` と 16 進 4 桁）。ベースは今の HEAD。依存（`node_modules` など）は Pleiad は張らない。
5. **片付け**: 子の完了後・次のターンの終わり・起動時・右パネルを開いたとき・予約の取り消しなどに状態を見て、変更なし（未コミット・未追跡・新しいコミットなし）→ 自動で消す、元のブランチに取り込み済み → 自動で消す、未取り込み → 残す。状態が分からない・使っているもの（走っているターン・ホストのシェル・走っている委譲の子・裏の作業、cwd がそこにある会話）がある → 消さない。**消す前に中の ReparsePoint（ジャンクション・シンボリックリンク）を全部列挙してリンクだけを外し（リンク先は辿らない）、外せなければ中止する。** 会話の cwd を先に元の場所へ戻し、その中を cwd に持つもの（外部 MCP・Pleiad が起こした子とその子孫・保持役の子）を畳んでから消す。**`git worktree remove` の前に、フォルダーを一時名（`<id>.ply-removing`）へ rename して戻す確かめを入れる**（Windows は cwd を掴んだ場所を rename できず、掴んだまま git を呼ぶと中身と登録を消してから落ちる）。掴まれている（EBUSY・確かめの失敗）ときは数回やり直し、だめなら「残っている」。**やり直した後に登録だけ外れて中身が残った形（半分消えた）を見つけたら、失敗にせずリンクを外して残りを消し、ブランチと台帳まで片付ける。フォルダーだけ消せなかったら台帳に `leftover` の印を付け、次の片付けで消し直す。** 消せなかった経緯は台帳（`lastError`・最近の `removeAttempts`）と `<データ置き場>/worktrees.log`（追記だけ）に残す。強制の削除（`worktree remove --force`・`branch -D`）は使わない。残ったものは右パネル「git」に 1 ブロック「残っている作業場所」を出し、操作は「エージェントに取り込みを頼む」（取り込む役の会話へ依頼文を送る）・「退避して消す」・「残す」。
6. **退避**: 隠し ref `refs/pleiad/archive/<id>/<時刻>` に作業ツリー全体（未追跡を含み、.gitignore のものは含めない。親は worktree の HEAD）を撮り、撮り直した tree が同じことを確かめてから消す。コミットの本文に作り直しに要る控え（ベース・元の場所・種類）を残し、右パネルの「元に戻す」で新しい分けた作業場所を作り直す。保存は 90 日で、片付けのたびに古いものを消す。
7. **台帳と突き合わせ**: `<データ置き場>/worktrees.json` に「作成中」を書いてから `git worktree add -b` し、失敗したら worktree・ブランチ・台帳まで戻す。起動時に台帳と `git worktree list` を突き合わせ、作成中のまま落ちたものは巻き戻し、片付けの途中で落ちたものは終わらせ（フォルダーがあれば通常の状態へ）、フォルダーも登録も無いものはブランチ（取り込み先から辿れるときだけ。決定 5 の確かめ）と台帳を片付ける。フォルダーはあるのに git が知らないものもブランチと台帳を片付けるが、中身は利用者のものかもしれないので触らない（半分消えた残りは、利用者の絞り込みを通る片付けの側で消す）。台帳の置き場・ブランチが Pleiad の決めた形でないものには、消す操作をしない。
8. **WS のコマンド**: `worktreeCheck`・`worktreeSettings`（読み取り。画面の内部の口）、`worktreeSplit`・`worktreeDiscard`・`worktreeKeep`・`worktreeArchive`・`worktreeRestore`・`setWorktreeSettings`（人の操作。`tests/ops-baseline.json` の `human-only`）。互換のある追加なので `PROTOCOL_VERSION` は据え置く。

## 理由

- 書き手が 1 人のあいだは、分けるほうが驚きが大きい（依存が入っていない・パスが変わる・取り込みの手間が増える）。だから既定は作らず、書き手が 2 人になった瞬間にだけ 1 行出す。人が始めた会話は、依存が入っていないなどで驚くことがあるので、まず選ばせる。選ばずに送れば今までどおり動く（[ADR 0016](0016-composer-never-disabled.md) の入力欄は常に使える）。
- 並行する書き込みの衝突は、エージェントにも人にも考えさせない。子ごとの作業場所に分け、取り込み（競合の解決を含む）は依頼元のエージェントが判断する。Pleiad が自前でマージすると競合の判断を持つことになる。
- **detached HEAD ではなくブランチにする。** 取り込み（マージ・チェリーピック・PR）はブランチ名で指せたほうが、依頼元のエージェントにも人にも扱いやすく、「未取り込み」の判定（元のブランチへの取り込み済みか）もブランチの先頭で決まる。一覧にブランチが増えるが、`pleiad/` の名前で見分けられ、片付けのときに一緒に消える（取り込み先が今の HEAD でないときは、先頭が取り込み先から辿れることを確かめてブランチの名前だけを外す）。
- 置き場をリポジトリの隣にするのは、ファイルのプレビューの許可（[ADR 0050](0050-local-file-access.md)）と素直にかみ合い（読み取りはデータ置き場以外を拒まない。`fileRoots` にも台帳のパスを足す）、リポジトリの中を汚さず、パスが浅い（Windows のロングパスで失敗しにくい）ため。
- 依存を Pleiad が張らないのは、リンクが消すときにリンク先まで巻き込む事故のもとになるため。必要ならエージェントが入れる（子への指示に書く）。ユーザーが張ったリンクでも、消す前に列挙してリンクだけを外す。
- 強制をしないのは、未コミット・未追跡の変更が黙って消えるのを避けるため。例外は「退避して消す」だけで、そこでは撮影して同じ tree であることを確かめた後に `worktree remove --force` を使う（git は未コミットのある worktree を強制なしでは消さない）。ブランチも同じく、退避の ref から辿れることを確かめた上で名前だけを外す。
- 退避を隠し ref にするのは、ブランチ一覧・履歴・`git status` に出さず、コミットとして復元できるため（[ADR 0085](0085-host-reads-git-and-turn-snapshots.md) の撮り方を流用）。溜まらないよう保存期間を最初から決める（90 日）。

## 影響

- ユーザーのリポジトリの隣に `<名前>.pleiad/` が増え、`.git` に `refs/pleiad/archive/` と `pleiad/<id>` のブランチが一時的に増える。残った分は右パネルで見え、取り込まれれば自動で消える。
- 分けた作業場所には依存が入っていない。書き込みの多い子は、必要なら自分で入れる（子への指示にある）。
- `docs/agent-delegation.md` の「Pleiad が自動的に worktree を作成・マージする機能ではない」は、今の形（作成・片付けは Pleiad、マージは依頼元）に変わる。ADR 0085 の影響の同じ文も置き換える。
- 作成・片付けの途中で Pleiad が落ちても、台帳が残るので次の起動で整合を取る。台帳の形が壊れた・書き換えられたものには消す操作をしない。
- 隠し ref の掃除（ターンの撮影は 30 日、退避は 90 日）は片付けと同じ契機で走る。`AGENT_HOST_WORKTREE_GRACE_MS` で、作ってから自動の片付けの対象にするまでの猶予（既定 60 秒。予約の前に消さないため）を変えられる（テスト用）。

採らなかった案:

- 既定で毎回分ける案（書き手が 1 人のときに驚きだけが増える）。
- 依存（`node_modules`）のジャンクションを Pleiad が張る案（消すときの事故のもと）。
- Pleiad 自身がマージする案（競合の判断をホストが持つことになる）。
- detached HEAD にする案（取り込みの指し先が無い）。
- 置き場を Pleiad のデータ置き場の中にする案（ADR 0050 でデータ置き場は読み取りを拒むため、プレビューと衝突する）。
