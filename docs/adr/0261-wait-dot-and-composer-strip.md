# 0261 待ちのドットと入力欄の上の段

## 状態

承認（2026-10-23）

## 状況

会話末尾の待ち表示は、本文と離れた左の溝に円の面と回転印があり、狭い画面では端に寄っていた。待ち行と入力欄の間には、履歴の余白と作業・メーターの段が重なり約70pxの空きがあった。

## 決定

- 待ちの印を本文色の8pxのドットへ共通化する。既存の文脈画面と同じ1.1秒 ease-in-out、拡大率 .7↔1・不透明度 .5↔1で脈打つ。円の台・輪郭・軌道回転を使わない。
- 送信・ツール・作業一覧・委譲カード・脇・接続・設定なども同じ部品を使う。承認待ちの ◆、完了・失敗の印と文言は維持する。ホストがオフライン・状態が古いときはドットと時計を止める。
- 待ち行・作業ボタン・文脈と使用量のメーターを、入力欄の8px上の1段に置く。待ちは左、作業とメーターは右。PCは760px列、スマホの右は作業ボタンだけ。待ちが無いときも操作は残す。
- ドットは本文の左余白に揃え、スマホでは画面端から約10px空ける。8px右に文言、その直下に左端を揃えた帯を置く。帯は1.6秒 cubic-bezier(.65,0,.25,1)で左から右へ流し、完了率は表さない。
- 経過時間はPCで右、狭い行で文言の後ろ。文言は折り返す。動きを減らす設定ではドットと帯を静止させ、文言を残す。
- 作業ボタンの背景はホバー・フォーカス時だけ。メーターの面は残し、段の左右の余りは透明。履歴と入力欄を重ねず、下の送信ボタンは右端に保つ。

## 理由

待ちの対象と印を隣り合わせにすると、処理の状態を読み取りやすい。待ちと作業を同じ段へ置けば、履歴を隠さずに入力欄までの空きを減らせる。文脈専用の青を借りず、承認・未読の意味を保てる。

## 影響

待ちの形と動きは共通部品が持ち、呼び出し元は状態の文言と表示する期間を管理する。会話の末尾に待ち用の最低40pxの枠を確保しない。データ形式・エージェントの実行には変更がない。
