# 0343 明示した委譲モデルを一覧で拒否しない

- 状態: 承認（2026-11-19）
- 置き換えた: 0311（固定の委譲と Devin の事前検査）、0309（委譲と Devin の一覧による事前検査）

## 状況

CLI が使える新しいモデルでも、Pleiad の一覧が古いと固定の委譲が `model_unknown` で止まった。自動の振り分けと送信の経路は、すでに一覧を正本としない。

## 決定

- 全 backend の固定の `ply_delegate` と `ply_task_send` のモデル変更は、指定した文字列を一覧で拒否しない。正式な ID が一覧の id または resolvedModel に正確に一致する行があるときだけ読み替え、それ以外はそのまま渡す。CLI/API が断ったらそのエラーを返し、別モデルへ落とさない。
- Devin の `resolveDevinModel` も未掲載の名前を通す。ACP の選択肢で対応を決められない名前は、その文字列を `session/set_config_option` に送る。既知の variant を代表・思考・速度へ分解する既存の ACP 表現と、実際の応答が指定に一致する確認は残す。黙って別の版を走らせないため。
- Devin の過去の ACP 選択肢による `runnableModel` の除外をやめる。自動の振り分けが一覧で候補を飛ばさない決め（0311）、失敗後の任せ直しと保留は維持する。固定の委譲は任せ直さない。
- 未掲載モデルの明示した `effort` は、一覧から対応を判断できないので文字列の形だけを確認し CLI に渡す。既知のモデルの段と互換の接続先の機能の検査は残す。対応しない段をアダプタが無視して別の強さで走ることを防ぐため。
- モデル名の形、backend の有効性、権限・承認モード・タスクの所有者と状態、接続先の検査は残す。実行先と操作の正当性を守る検査で、モデル一覧の鮮度とは別のため。
- `account` の登録・トークンと、満杯と分かっている使用枠の検査は残す。登録は Pleiad が正本で、別アカウントへ黙って落とさないため。
- host への委譲も受け側の同じ規則を通す。リモートの `ply_task_send` の設定変更は引き続き `settingsUnsupported`。現在のホスト間の送信には設定の予約・承認・失敗時の復元を届ける契約が無く、モデル一覧による拒否とは異なるため。
- 段の保存とアカウントの選択はモデル一覧で候補を消さない。未掲載の警告は残す。通常の画面でのモデル選択、モデルを省いた場合の既定の解決は変えない。

## 理由

使えるかを知る正本は CLI/API。明示した名前を通せば、古い一覧が利用の関所にならず、誤った名前も実行先の理由つきで失敗する。

## 影響

固定の委譲と設定変更では、未掲載だけを理由とする `model_unknown` が出なくなる。一覧を取り直す機能は、画面の選択肢を新しくするために引き続き必要。
