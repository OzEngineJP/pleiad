# 0211 入力欄の ↑ の呼び出しと、次の発言の候補

- 状態: 承認（2026-10-15）

## 状況

利用者から 3 つの要望があった。

- 入力欄の一番上で ↑ を押したら、前に送ったメッセージを入れたい（設定でオン・オフ）。
- Mac は ⌘+Enter で送る方がよいのでは。
- 次に送りそうなメッセージを予想し、候補として（グレーで）出したい。

調べて分かったこと（2026-10-15）:

- Mac でも ⌘+Enter はもう効いている（`web/composer/composer.mjs` が Ctrl と Meta の両方を見る）。表示だけが「Ctrl+Enter」のままだった。
- Claude Code には予測がある（Agent SDK の `promptSuggestions`）。親の会話のキャッシュに相乗りし、ほぼ使用量を使わない。Pleiad が `result` の直後に入力を閉じても届き、resume で起こし直したプロセスの 1 ターン目でも届く。
- Codex の予測（「composer predictions」）は ChatGPT のデスクトップのアプリの Pro 向けのベータだけ。CLI（0.160.0）・app-server（実験中の口を含む）・main にも予測の口は無い。CLI の TUI には 2026-09-24 に入り（#47911・#47929）、09-27 に外された（#48621）。作りは app-server の上だけで、完了したターンを使い捨ての fork にして予測させていた。
- 同じ fork を手元で測ると、会話の部分がキャッシュに乗らなかった（fork は新しいスレッドの id で、キャッシュの振り分けが分かれるとみられる）。会話が長いほど、候補 1 回ごとに会話の全量を払う。
- Antigravity（agy 1.3.5）には予測も fork の口も無い。`agy --print` は 1 回ごとに会話を利用者の履歴（`~/.gemini/antigravity-cli/` の会話の DB・brain・要約の DB）に残す（失敗で終わった回も残る）。残ると `/resume` の一覧に並び、`agy --continue` が最新の会話として拾う。消す口は対話の画面にしか無い。
- agy のログインは OS の資格情報（Windows は `gemini:antigravity`）にあり、`USERPROFILE`・`HOME` を別の場所へ向けて起こしても通る。そのとき利用者の置き場は何も変わらない（前後を比べた）。

## 決定

モックで形を合意したうえで、次のとおりにする（形は design-system.md「入力欄の呼び出しと候補」「入力欄と上端」、作り方は design.md「次の発言の候補」）。

- **↑ の呼び出し**: 一番上の見た目の行の ↑ で、送信済みのメッセージを「この会話 → ほかの会話」の新しい順で辿る。書きかけは脇へ取り、↓ と Esc で戻す。既定はオン（設定 `composer.historyRecall`）。
- **送信キーの表記**: Mac は ⌘↩・⌘⇧↩ と書く。押すキーは Ctrl と ⌘ のどちらも今までどおり効く。
- **次の発言の候補**: 返答の後の 1 行の予測だけを出す（打ちかけの補完はしない）。空の欄にグレーで出し、Tab（タッチは丸いボタン）で入れる。候補は送らない。既定はオン（設定 `composer.suggestions`）。
  - Claude はネイティブの予測を使う。
  - Codex と Antigravity は、直近の発言の要約を軽いモデルへ 1 回渡して作る（Codex は使い捨てのスレッド、Antigravity は Flash の low）。どちらも既定でオン。
  - Antigravity は agy の状態の置き場だけを使い捨ての場所へ向けて起こし、利用者の履歴に残さない。

## 理由

- 書きかけを失わない・複数行の途中では取らない・直したら呼び出しが終わる、の 3 つで、↑ を奪っても今の編集の動きを壊さない（シェルや多くのチャットのアプリと同じ慣れた操作）。
- 表記だけが違っていたので、キーの割り当てを変えずに直せる。
- 候補を Tab の印で見分け、打たずに送れなくすれば、案内（placeholder）と同じ色でも取り違えて送る事故が起きない。
- Codex は fork よりも要約のほうが、会話の長さによらず 1 回の費用がほぼ一定で、測った範囲では入力の大半（共通の土台）がキャッシュに乗る。Codex 自身が TUI で fork の作りを外した理由は書かれていない。
- Antigravity の履歴に候補づくりの会話が並ぶのは、利用者の `/resume` と `--continue` を汚すので許されない。ホームの差し替えなら、ログインはそのままで、利用者の置き場に一切書かない。

## 影響

- Codex と Antigravity の会話は、成功で終わったターンごとに、候補を作るのに軽いモデルを 1 回使う（使用枠を少し使う）。設定でオフにすれば作らない。委譲の子・bot・圧縮のターンには作らない。
- Antigravity の使い捨ての場所（一時フォルダーの下の `pleiad-agy-suggest`。agy の補助の実行ファイルで約 15 MB）が残る。回ごとにその回の会話の置き場を消し、残った古いもの（10 分）と 2 MB を超えた要約の DB は次に起こす前に消す。最初の 1 回は agy の準備で 30〜40 秒かかる（2 回目から 7 秒ほど）。
- Claude の予測は、モデル（haiku では出ないことがあった）・使用量の上限の近く・プランモードでは来ない。来なければ何も出さない。
- 送信済みのメッセージは、検索の写し（`core/session-search.mjs`）から返す（`sessions.sentMessages`。画面だけ）。写しに `!` のコマンドの並びを足した。
