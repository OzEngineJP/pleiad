# 0320 右の欄のファイルは開き直すたびに読み直し、最初の画面は段階的に出し、待っている間の見せ方を全種類のタブでそろえる

- 状態: 承認（2026-11-12）。[0294](0294-one-chrome-window-per-conversation.md) の「同じ実体パスをもう一度開く操作だけでは読み直さない」を置き換える
- 承認の内容: プロダクトオーナーが「ファイルを開き直したら読み直す」「新しいタブを待たせず出す」「待っている間の見せ方を PC の全種類のタブで出す」を承認した
- 関連: [0294](0294-one-chrome-window-per-conversation.md)（タブをまとめる）、[0295](0295-pleiad-page-origins.md)（ページの origin と親子の知らせ）、[0182](0182-session-open-window.md)（会話を開く間の見せ方）

## 状況

- 0294 は、同じ実体パスのタブを 1 枚にまとめ、同じパスをもう一度開く操作は「そのタブへ移るだけ」で読み直さないと決めた。会話のリンクを押してもタブが前に出るだけで、ディスクの内容が前に見たときと違っていても、変更の通知を取りこぼしていれば古いままだった。
- 変更の通知（`page:changed`）はその会話を見ている画面にだけ送る。ほかの会話を見ている間や、接続が切れている間に変わったファイルは、戻っても古いまま残る。
- 新しいタブの「最近のファイル」は、あとから別のファイルを開いても増えなかった。変更の通知で描き直す対象に新しいタブが入っていなかった。
- 新しいタブは、git の変更の一覧を全部作ってから件数を出していた（実測 約 1 秒）。同じ git の問い合わせは会話ごとに直列で、その間に [変更] を開くと変更のページもその後ろで待った。最初の描画のたびに、環境の知らせ（`pleiad:env`）でもう一度全部取りに行っていた。
- 待っている間の線（`.bu-load`）はスマホだけで、12 秒で消えた。PC のページのタブには待っている印も骨組みも無く、白いまま待つように見えた。

## 決定

### 1. 開き直すと読み直す

1. すでに開いているファイル・フォルダーをもう一度開くと、そのタブが前に出て、読み直す。入口は会話のリンク・アドレスバー・最近のファイル・ツリー・ページの中のリンクのすべて。クリックやスクロールで「触った」だけのタブも読み直す。
2. 入力のあるタブ（未保存の入力がある）だけは読み直さず、既存の帯「ファイルが更新されました／更新を表示」を出す。
3. ほかの会話を見ている間・接続が切れている間に変わったファイルは、その会話に戻って見たとき（会話の切り替え・再接続）に追いつく。入力の無いタブは読み直し、あるタブは帯を出す。
   - 検出は版の印（`更新時刻:大きさ`）で行う。サーバーは開くときと `page:changed` で印を渡し、タブは最後に描いた印を持つ。戻ったときに印を比べ、同じなら読み直さない。印が分からないタブ（手で再読み込みした・移動した直後）は、最大 1 回余分に読み直す。
4. 見ている間に届いた変更は今までどおり。触っていなければ自動で読み直し、触っていれば帯を出す。
5. 読み直している間は前の中身を残し、読み込み線とタブの印だけを出す。ページを白くしない。Pleiad のページ（ファイル・フォルダー・変更・新しいタブ・添付）は、親からの `reread` を受けて新しい中身を別に作り、描き終えたところで差し替える（読んでいた位置はほぼ保たれる）。HTML・可視化のページは隔離された origin で `reload` を送るので、読み直しでスクロール位置が戻る。
6. 新しいタブの再描画を、変更の通知の対象に加える（最近のファイルが増えない不具合の修正）。ファイルを開いたら、同じ会話の新しいタブも読み直す。

### 2. 最初の画面を段階的に出す（新しいタブ）

1. 3 つの見出しと [変更] [プラグイン] を最初の描画で出し、すぐ押せる。件数は後から来る。待つ間は「変更」の右に短い骨組みの 1 行を置き、件数が届いても [変更] [プラグイン] の大きさと位置は変わらない（件数の欄は固定幅）。
2. 「最近のファイル」と「作業フォルダー」は、届いた順に出す。git の後ろに並べない。待ちが 150ms を超えたときだけ骨組みを出す（最近は 3 行、フォルダーは見出しの行 1 つと 6 項目の格子）。
3. 件数は軽い数え方で取る（`only:'count'`）。変更のページと同じスナップショットの差分でファイル数だけを数えるので、変更のページの `total.files` と食い違わない。直列の待ち行列（`serial('session:<id>')`）の外で走らせ、[変更] を開いても待たせない。
4. 配色の変更（`pleiad:refresh`）で、変更・プラグイン・新しいタブを取り直さない（色は CSS の変数だけで変わる）。描いている途中の知らせも読み直さない。

### 3. 待っている間の見せ方（PC の右の欄の全種類のタブ）

1. **枠の印**（読み直しのときも同じ。HTML・可視化の読み直しでも、前の中身を残したまま線とタブの印を出す。§3 の 1）: アドレスバーの下に 2px の読み込み線（`.bu-load`）を PC でも出す。タブの印には、ファイル・フォルダー・プラグイン・新しいタブ・HTML・可視化のタブにも脈（`.bu-loading`）を付ける。
2. **中身の骨組み**: 届く中身と同じ並び・行の高さで描く。文書・コード・画像・フォルダー・表・PDF・プラグイン・新しいタブ。変更は既存の git の骨組みのまま。HTML・可視化は面 1 枚。拡張子と実際の種類が違うファイルでは、骨組みの形が少しずれることがある。届いたらその場で本物に差し替える。
3. **時間**: 待ちが 150ms を超えたときだけ出す。骨組みは 240ms（`--dur`・`--ease-out`）で現れる。線（0.8 秒の往復・ease-in-out）、タブの印（1 秒の往復・不透明度 1 から 0.3）、骨組みの光（1.6 秒・`--ease-organic`）の値は既存のまま。ページの骨組みの 150ms は、そのページが描き始めてからの数え。
4. **長い待ち**: 表示を変えない。スマホの線の 12 秒で消える動きはやめる。**60 秒を超えたら失敗として扱う**。
5. **失敗**: 線と脈を止め、既存の文言「読み込めませんでした。もう一度開いてください。」（`pages:errors.read-failed`）を出す。60 秒の打ち切りが働くのは、最初の読み込み（隔離のページ・Pleiad のページ）。読み直しの打ち切りは、線と脈を止めて前の中身を残す。
   - 最初の読み込みかどうかは、隔離のページでは「一度でも描き終えたか（`loaded`）」、Pleiad のページでは「一度でも中身を出したか（`shown`）」で決める。
   - 打ち切りの後に読み込みが遅れて届いたら、失敗の文言を外して中身を出す（`.bu-page-failed` が残らない）。
   - 描き終えたタブをアドレスバーで別のファイルへ替えたときは、新しい文書の最初の読み込みとして数える（前の文書の「描き終えた」を引きずらず、応答が無ければ 60 秒で失敗の文を出す）。
   - 描きかけのまま別のタブへ移り、戻ってきたときは、線と 60 秒の数えをもう一度立てる。判定は「隔離のページ: 描き終えた」「Pleiad のページ: 描き終えたと知らせてきた（`ready`・`failed`）」。
6. **動きを減らす設定**: 線は動かない帯、タブの印は不透明度 .55 の薄いままで脈なし、骨組みは光の無い平らな面にする。
7. **読み上げ**: 中身の入れ物に `aria-busy` を付け、骨組みは `aria-hidden="true"`。
8. **暗い配色の骨組み**: 既存のトークンでは薄すぎるので、ページの骨組みは `--surface-3` を地、`--surface-thumb` を光にする。会話の骨組み（`.history-skeleton`）は変えない。

### 4. 親とページの知らせ

- サーバー → 画面: ページを開いたとき（`pageOpen` の応答）と `page:changed` に、ファイルの版の印 `stamp`（`更新時刻:大きさ`）を載せる。印は中身を読む口と同じ関所（`inspectFile` と会話の access）を通ったパスにだけ付ける。断られるパス・読めないパス・消えたパスには付けない。変更の知らせの印は非同期の stat で取り、イベントループを塞がない。
- ページ → 親: `pleiad:page-state`（`{state:'loading'|'ready'|'failed'}`）。親は読み込み線とタブの印を出し入れする。
- 親 → ページ: `pleiad:page-command` の `reread`（Pleiad のページを前の中身を残して読み直す）。
- 親の `beginLoad` / `clearLoading` と `tab.loading` の呼び名・呼び方は変えない（Chrome の映像の行はこれを呼ぶ）。

### 5. 現在の限界

追いつき（§1 の 3）が比べるのは、そのタブのファイル自身の印（更新時刻と大きさ）だけである。次は拾えない。

- フォルダーのタブで、直下のファイルの中身だけが変わった場合（フォルダー自身の印は変わらない）。
- HTML のページの副資源（CSS・JS・画像）だけが変わった場合。
- 更新時刻の粒度が粗いファイルシステムで、同じ時刻・同じ大きさのまま書き換えた場合。

開き直し・再読み込みは、印に関わらずいつも読み直す。

## 理由

- 「開く」と「読み直す」を同じ操作にすれば、人は古い表示を疑わずに済む。通知の取りこぼし（別の会話・切断中）は、戻ったときに印を比べて埋めるのが、一番小さい仕組みで漏れない。
- 入力のあるタブだけを守れば、消えて困るのは入力だけなので、それ以外は常に最新にしてよい。
- 件数だけのために全差分（行ごとの差分・並べ替え・ファイルの中身）を作る必要は無い。同じスナップショットの差分でファイル数だけを数えれば、変更のページと必ず一致する。実測（未追跡 650 ファイル）では全差分の約 750ms が約 530ms になる。残りの大半はスナップショット（`git add -A` で一時 index に取り込む処理、約 930ms 中の大半）で、`git status` の数え方（約 40ms）は速いが、ステージ後に作業ツリーで戻したファイルや intent-to-add などで変更のページと食い違いうるので採らなかった。件数が遅れても、ボタンは件数を待たずに出る。
- 待ちを 150ms 未満では出さないのは、速い操作でちらつかせないという既存の決め（design-system §4.6）に合わせるため。60 秒は、ローカルのファイルの読み込みとしては十分長く、ネットワークの切断が混じっても人が諦めて開き直すより後になる値として選んだ。

## 影響

- `web/browser-unify.mjs`（`openInput`・`beginLoad`・`clearLoading`・`paintLocal`・`sessionChanged`）、`web/page-tabs.mjs`（版の印・`refresh`・`catchUp`）、`web/pages/app.mjs`・`new.mjs`・`skeleton.mjs`・`content.css`、`core/browser-unify-ws.mjs`・`core/git-info.mjs`・`core/git-activity.mjs`・`core/pages-routes.mjs`。
- 0294 の 6 の最後の一文は、この ADR が置き換える。
- 版の印を持たない古いサーバーとつながったときは、追いつきは従来の決めに戻る（触ったタブは帯、触っていないタブは URL が変わったときだけ読み直す）。
- 新しいタブの読み直しは、ファイルを 1 つ開くたびに最近のファイルの問い合わせを 1 回増やす。
- 変更件数の問い合わせ（`only:'count'`）は、同じリポジトリの同時の問い合わせを 1 つにまとめる（新しいタブを複数の画面・タブが同時に開いても git を重ねて走らせない）。
- 読み直しの再発行は、待っている間にパスが移った・タブが閉じられたときは、返ってきた応答を捨てる。
