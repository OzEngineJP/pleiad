# ADR 0206: HTML の開き先を 1 つの規則にし、リモートはホストの内蔵ブラウザーの映像を右パネルの「ブラウザー」で見る

- 状態: 承認（2026-10-14）
- 日付: 2026-10-14
- 関連: [inapp-browser.md](../inapp-browser.md)「リモートから見る」、[file-preview.md](../file-preview.md)「HTML の開き先」、[design-system.md](../design-system.md)「リモートの端末の『ブラウザー』」、[visualize.md](../visualize.md)、[ADR 0079](0079-html-opens-in-inapp-browser.md)（開き先の部分を置換）、[ADR 0041](0041-inapp-browser-beside-conversation.md)、[ADR 0148](0148-agent-browser-in-chrome.md)

## 状況

ブラウザー関連の見え方が、画面ごとに別々の規則で分かれていた。

- HTML ファイル・可視化の写しの開き先が、「サイドパネルに表示」（右パネルの sandbox のプレビュー）・内蔵ブラウザーのタブ・既定のブラウザー・（リモートで）「PC のブラウザーで見る」に散り、決める条件も body の `inapp-links` クラス・設定・`osActions` に分かれていた（ADR 0079 は、既定のブラウザーを選んだ人・リモート・スマホの HTML を右パネルのプレビューのままにした）。
- リモートでホストの内蔵ブラウザーを見る面（2026-09-28）は、右パネルとは別の全面の画面で「PC のブラウザー」と呼んでいた。右パネルの「ブラウザー」と同じものなのに、入口・名前・形が違った。
- デスクトップ版の本体の窓は、`target="_blank"` の素のリンク（設定・認証・PR）のうち http を黙って捨てていた（https だけ通していた）。

## 決定

1. **HTML の開き先を `htmlRoute` 1 か所で決める**（`web/file-preview.mjs`）。ファイルのクリック・パスの札・ツリー・添付・コンテキストの「開く」・ファイルのメニュー・可視化のカードの「ブラウザーで開く」は全部ここを通る。
   - ホストの画面でリンクの開き先が内蔵ブラウザー: 内蔵ブラウザーのタブ。
   - ホストの画面でリンクの開き先が既定のブラウザー、またはホストの PC の普通のブラウザー: 既定のブラウザー（プレビューを経ない）。設定「外部の読み込みの前に確認」は外のブラウザーに効かないので、設定の説明に書く。
   - リモートの端末でホストが映像を送れる: ホストの内蔵ブラウザーにこの会話のタブを足し（ホストの窓は前に出さない）、右パネルの「ブラウザー」で見る。
   - リモートの端末でホストが映像を送れない（`npm start`）: 右パネルの原文と保存だけ。
2. **右パネルの HTML は原文と保存だけにする**。sandbox の描画・外部の読み込みを止める一行・プレビュー／原文の切り替えは持たない。動かして見るのはブラウザーのタブ（内蔵ブラウザーの `file:` のタブの守りは ADR 0079 の決定 2・4・7 のまま）。可視化のカードの道具は「ブラウザーで開く」の 1 つにし、「サイドパネルに表示」と `inapp-links` の出し分けをやめる。
3. **リモートの「ブラウザー」は右パネルのモードの 1 つとして、ホストの画面と同じ部品で作る**。固定の「Claude の Chrome」タブ・ビューアのタブ列・道具の列・入口（地球のボタン・近道）は同じで、本文のネイティブの View の代わりにホストの映像を置く（`createBrowserPanel` の bridge に映像の話し手を渡す）。映像の操作（戻る・進む・再読み込み・止める・URL・タップ・スクロール・文字入力・画質・fps の表示）は全部残す。760px 以下は全面。別の面と「PC のブラウザー」という名前はやめる。見られるのはホストがデスクトップ版（`pcBrowser`）で、この端末がホストの画面でも PC の普通のブラウザーでもないとき（`osActions` が偽）。`plyDesktop.browser` はリモートの窓の preload に出さない。
4. **リンクの開き先のシートは 3 つ**: 「内蔵ブラウザーで開く（ホストの内蔵ブラウザーにタブを足して右パネルで見る）/ 既定のブラウザーで開く（この端末の既定のブラウザー）/ リンクをコピー」。localhost・ループバックは端末では開けないので、シートを挟まずホストの内蔵ブラウザーのタブで開く。HTML ファイル・可視化の写しはシートを挟まず、決定 1 の開き先で開く。
5. **用語**: 右パネルのモードは、ホストの画面もリモートも「ブラウザー」。ja の「PC のブラウザー」はやめる。en は「built-in browser」で揃え、「in-app browser」は使わない（`docs/i18n-glossary.md`）。
6. **`external()` は http も通す**（`desktop/external-url.cjs`）。資格情報つき・ほかのスキームは今までどおり開かない。

## 理由

- 開き先を条件ごとに散らすと、同じ操作が画面によって別の場所へ行き、説明も設定の文言も食い違う。1 つの関数なら、新しい入口を足してもここで決まる。
- 既定のブラウザーを選んだ人が「HTML だけは Pleiad のプレビューで開く」のは、設定の意味に反する。右パネルのプレビューを持ち続けると、動かないもの（http・フォーム・ストレージ・ポップアップ）の説明とサンドボックスの維持が要る。ブラウザーのタブに一本化し、右パネルは読むもの（原文）に絞る。
- リモートの映像を右パネルの部品に載せれば、タブ・アドレス欄・入口がホストの画面と同じになり、覚えることが減る。別の面のコードも減る。
- リモートの HTML は、ホストの PC のファイルなので、その PC の内蔵ブラウザーで開くのが自然（`file:` のまま、相対の資源も読める）。ホストの窓を前に出さないのは、ホストの人の作業を邪魔しないため。
- 採らなかった案: リモートのリンクのシートにも HTML を出す（HTML は選ぶ余地が無い。localhost と同じく挟まない）。ホストの PC の普通のブラウザーで開いた Pleiad にも映像を出す（そこでは既定のブラウザーで足りる）。

## 影響

- 既定のブラウザーを選んだ人の HTML ファイルは、右パネルに出ず既定のブラウザーで開く。外のブラウザーなので「外部の読み込みの前に確認」は効かない（設定の説明に書いた）。
- ホストの PC の普通のブラウザーでは、HTML の右パネルのプレビューも無くなる（既定のブラウザーで開く）。
- リモートから HTML を開くと、ホストの内蔵ブラウザーにこの会話のタブが増え、ホストの画面のパネルにも出る（同じタブ）。ホストの窓は前に出ず、**ホストの画面で選んでいるタブも替えない**（`select:false`・`current` はそのまま。ホストの人の作業を邪魔しない）。リモートの端末は返ったタブ ID の映像を見る。op `browser.openFile` を足した（主にリモートの端末が使う。画面とリモートの端末から呼べて、MCP・CLI には出さない。ホストの画面から呼んでも、自分の内蔵ブラウザーにタブが増えるだけ）。
- リモートが開いた `file:` のタブにも `source`（`{ kind:'file', label }`。label は会話の作業ディレクトリからの相対パスで、サーバーが渡す）が付くので、ホストの画面では ⋯（ファイルの操作）と札がホストで開いたタブと同じに出る。タブの同一判定（`fileKey`）は realpath（失敗したら resolve）で、symlink を経た道でも同じタブになる。
- 外部の読み込みの確認（止めた件数と「読み込む」・設定）は、リモートの「ブラウザー」にも出る。`state().tabs` に守りの件数と出どころ（https のオリジンだけ。パスは含めない）を載せ、「読み込む」は `browserScreencastNav` の `allowOnce`（ほかの映像の操作と同じく、会話を見ている接続だけ）。写しのタブは書き直しが要るので、サーバーが一時的に許す出どころを加えて同じタブで開き直す（タブの同一判定が同じなので「今回だけ許す」は保たれる）。
- 可視化の写しのタブの ⋯ の原文（可視化の原文）も原文だけ（右パネルの描画・プレビューの切り替えは出ない）。
- 会話がまだ無い下書きの添付をリモートで開くと、ホストのタブを足す相手の会話が無いので、失敗の通知ではなく右パネルの原文に落とす。
- ADR 0079 の決定 1・3・5・6（開き先・可視化のカード・既定のブラウザーを選んだ人・リモート）はこの ADR に置き換わる。決定 2・4・7（PC のファイルのタブ・確認・`file:` の守り）は残る。ADR 0041・0079・0148 は当時の記録として直さない。
- ホストが映像を送れない端末では、リモートの HTML は原文だけ。見たいときはホストの画面で開く。

## 残った課題

- 開いた `file:` のページの中のリンクから、`inspectFile` の範囲（会話の作業場所）の外の PC のファイルへ移れる（前からある。リモートの端末のタップからもできるようになった）。データ置き場は `protectedFile` で止まる。移った先が外部の読み込みの守りの対象かは、コードの読みだけで確かめていない。直すなら、`allowFile` のタブの移動を開いたファイルと同じフォルダーの下に絞る（`desktop/browser-panel.cjs` の `guard`）。
