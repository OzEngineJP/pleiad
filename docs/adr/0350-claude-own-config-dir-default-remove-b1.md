# 0350 Claude アカウントのコネクターを専用フォルダ方式だけにし、方式 b1 を削除する（ADR 0345 の段 2）

- 状態: 承認（2026-11-24）。2026-11-25 に、段 2a と 2b を 1 回のリリースにまとめ、b1 へ戻すスイッチを持たないと改めた（決定: 古い方式は beta で出すので捨ててよい）
- 関係: [ADR 0345](0345-claude-account-own-config-dir.md)（段 1。段 2 の承認をこの ADR で取る）・[ADR 0340](0340-claude-connectors-per-account.md)（方式 b1。この ADR で置き換える）・[ADR 0329](0329-claude-per-account-model-catalog.md)（アカウントごとのモデル一覧）・[ADR 0351](0351-claude-own-config-dir-macos-keychain.md)（macOS）

## 状況

方式 b1 では、会話の子 CLI が起動時に受け取った `CLAUDE_CODE_OAUTH_TOKEN` を使い続ける。使用量の読み取り（同じアカウントの専用フォルダで動く SDK の呼び出し）がトークンを更新すると、古いアクセス用トークンが失効し、保持中の子 CLI が `OAuth token revoked` で止まる。Claude Code 2.1.328 には、認証の失敗時にディスクの資格情報を読み直して回復する処理があるが、環境変数で受け取ったトークンは「user-supplied」として読み直さない。b1 ではこの失敗を CLI 側で回復できず、期限タイマーの隙間を埋める修正は起きる機会を減らす応急処置にとどまる。

専用フォルダ方式は、子 CLI に環境変数のトークンを渡さない。同じフォルダの CLI どうしが `.oauth_refresh.lock` で更新を直列にし、失効を検知したら更新後の資格情報をディスクから読み直す。ここまではバイナリの文字列で確かめたもので、サーバー側の失効での回復は実機で試していない。

段 1（0.43.0-beta.1）は実装済みで、入口は設定 › 外部 MCP の「専用フォルダ方式（ベータ）」と op `setConnectors` の `mode`、既定は b1 だった。段 1.5（開発 PC のコネクターをオンにした 3 アカウントを専用フォルダ方式にして 1 日使う）は、認証の停止なしで終えた。

段 1 の後に読んで分かったこと:
- `skills/synced`・`plugins/synced` は、CLI が claude.ai で有効にしたスキル・プラグインをアカウントごとに同期する場所。共有の `~/.claude` にはすでに 2 アカウント分が混ざっている。専用フォルダ方式も共有へリンクするので混ざり方は今と同じ。あるアカウントの同期がほかのアカウントの項目を消すかは分からない。
- 準備で名前が重なった項目は、削除せず `claude-usage/<名前>.pleiad-moved-<時刻>-<uuid>` に退避する。
- Windows のファイル用シンボリックリンク（`settings.json`）は開発者モードか管理者の権限が要る。開発者モードがオフの PC では準備に失敗する。
- macOS は資格情報をキーチェーンに置き、`.credentials.json` が無い。[ADR 0351](0351-claude-own-config-dir-macos-keychain.md) が有無の判定を `security find-generic-password`（`-w` なし）にし、0.43.0-beta.21 で止めを外した（止めるのは ssh からの起動だけ）。

## 決定

- 段 2 は 1 回で行う。専用フォルダ方式を唯一の方式にし、b1 のコードを削除する。b1 へ戻すスイッチ（入口のスイッチ・`setConnectors` の `mode`）は持たない。保存済みの設定の `mode` は読まずに捨てる（`enabled` だけで専用フォルダ方式を意味する）。
- 対象はコネクターをオンにしたアカウントだけ。オフのアカウントは今の長期トークンを使い続ける（長期トークンは更新されないので失効しない）。`login`（共有の `~/.claude`）は変えない。ログインの一本化は #195 で扱う。
- すでにコネクターをオンにしているアカウントは、更新後の起動で自動で準備（リンクの作成と退避）し、画面に出す。
  - 準備の結果は、設定 › 外部 MCP のアカウントの行に出す。移した項目（共有へ移した・退避した）の件数と、失敗した理由。
  - 準備に失敗したアカウントは、b1 に戻さず、コネクターを止めたまま理由を出す。理由の出し方は macOS の止め（ADR 0351）と同じ。失敗の例は、開発者モードがオフの Windows でリンクを作れない場合（`ownDirLinksWindows`）。Pleiad が共有の内容を `settings.json` に写す案は採らない。
  - ログインが無い・切れているアカウントは、今までどおり「ログインし直す」と出す。
- 退避した項目（`claude-usage/*.pleiad-moved-*`）は、30 日後に消す。起動時の準備のあとで掃除する。時刻は名前に入れた ISO 時刻から読み、読めなければ消さない。
- 本人照合（識別ハッシュ）は残し、初回確認（専用フォルダと共有のコネクター一覧の比較）は削る。
- 使用量の読み取りは、これまでどおり専用フォルダでの SDK の呼び出しとし、更新の直列化は CLI の `.oauth_refresh.lock` に任せる。同じプロセス内の準備・移行の直列化（`withClaudeUsageDir`）は残し、ロックの競合（`USAGE_REFRESH_CONTENTION`）はログイン切れとせず次の取得でやり直す。
- 長期トークンの無いアカウントのモデル一覧（`probeCatalog`）の取り方は、#195 と一緒に決める。この ADR では決めない。b1 を消しても `probeCatalog` が動くよう、モデル一覧にはこれまでどおりアカウントのトークン付きの登録（`accounts.resolve`）を渡す。
- 次は削る（b1 だけで使う仕組み）: トークンの受け渡し・`fresh()`・更新依頼・`guardUsageDir`、期限タイマー（`scheduleExpiryTimer`・`onExpiryReached`）と保持中の子 CLI の再起動、b1 用の `readAccessCredentials`、`createConnectorVerification` の初回確認、入口のスイッチと `setConnectors` の `mode`、`ownDirEnableFirst` の段取り。

## 理由

- 失効の原因は、更新する側と、古いトークンを持ち続ける側が別にいること。専用フォルダ方式では両方が同じフォルダの CLI になり、更新の直列化と読み直しを CLI が担う。Pleiad の期限判定は、タイマーの隙間を埋めても、使用量の読み取りや CLI 自身の更新との競合が残る。
- b1 へ戻せる期間を残す案（段 2a と 2b を分ける）は採らない。beta で出すので、戻す先を持つ分のコードと試験を抱えるより、失敗した理由を画面に出して直せるようにするほうが小さい。段 1.5 の 1 日で、認証の停止は起きなかった。
- 実機で見ていないのは、サーバー側の失効での回復（T1。Mac では M6）。回復が働かない場合は、会話が認証の失敗で止まり、アカウントごとの再ログインで直す。b1 の停止と同じ見え方で、b1 のほうが起きる機会は多い。
- 準備の失敗は、共有の内容を写す案より、止めて理由を出す案が小さい。写す処理は、リンクで済む環境では要らない。
- オフのアカウントまで広げると、コネクターを使わない会話にも claude.ai のコネクターと同期スキルが現れ、長期トークンの廃止（#195）と同時に決めることになる。失効はオフのアカウントでは起きない。

## 影響

- `core/claude-connectors-auth.mjs`: b1 の仕組みを削り、`createClaudeConnectorsWiring.resolve` をトークンを要求しない分岐だけにする。
- `core/backends/claude.mjs`・`core/backends/claude-usage.mjs`: 期限タイマー・保持中の子 CLI の再起動・`guardUsageDir` を削る。
- `core/claude-own-dir.mjs`: `settings.json` のリンクの `EPERM` を失敗として返し、退避した項目の掃除（30 日）を足す。
- `core/server.mjs`: 起動時に、コネクターをオンにした全アカウントを準備し、結果を行に出す。`mode` と `ownDirEnableFirst` の段取りを削る。
- `web/mcp-matrix.mjs`: スイッチを削り、移した件数と失敗の理由を行に出す。
- ほかの PC は、更新すると、コネクターをオンにしたアカウントが起動時に専用フォルダ方式へ移る。Windows は開発者モードの有無を更新の前に確かめる（オフだと、そのアカウントのコネクターは止まる）。
