# 0350 Claude アカウントのコネクターを専用フォルダ方式だけにし、方式 b1 を削除する（ADR 0345 の段 2）

- 状態: 承認（2026-11-24）
- 関係: [ADR 0345](0345-claude-account-own-config-dir.md)（段 1。段 2 の承認をこの ADR で取る）・[ADR 0340](0340-claude-connectors-per-account.md)（方式 b1。段 2b で置き換える）・[ADR 0329](0329-claude-per-account-model-catalog.md)（アカウントごとのモデル一覧）

## 状況

方式 b1 では、会話の子 CLI が起動時に受け取った `CLAUDE_CODE_OAUTH_TOKEN` を使い続ける。使用量の読み取り（同じアカウントの専用フォルダで動く SDK の呼び出し）がトークンを更新すると、古いアクセス用トークンが失効し、保持中の子 CLI が `OAuth token revoked` で止まる。Claude Code 2.1.328 には、認証の失敗時にディスクの資格情報を読み直して回復する処理があるが、環境変数で受け取ったトークンは「user-supplied」として読み直さない。b1 ではこの失敗を CLI 側で回復できず、期限タイマーの隙間を埋める修正は起きる機会を減らす応急処置にとどまる。

専用フォルダ方式は、子 CLI に環境変数のトークンを渡さない。同じフォルダの CLI どうしが `.oauth_refresh.lock` で更新を直列にし、失効を検知したら更新後の資格情報をディスクから読み直す。ここまではバイナリの文字列で確かめたもので、サーバー側の失効での回復は実機で試していない。

段 1（0.43.0-beta.1）は実装済みで、入口は設定 › 外部 MCP の「専用フォルダ方式（ベータ）」と op `setConnectors` の `mode`、既定は b1。開発 PC のコネクターをオンにした 3 アカウントは b1 のままで、専用フォルダ方式の運用の記録は無い。ADR 0345 が段 2 の条件とした「実運用で問題がないこと」は満たしていない。

段 1 の後に読んで分かったこと:
- `skills/synced`・`plugins/synced` は、CLI が claude.ai で有効にしたスキル・プラグインをアカウントごとに同期する場所。共有の `~/.claude` にはすでに 2 アカウント分が混ざっている。専用フォルダ方式も共有へリンクするので混ざり方は今と同じ。あるアカウントの同期がほかのアカウントの項目を消すかは分からない。
- 準備で名前が重なった項目は、削除せず `claude-usage/<名前>.pleiad-moved-<時刻>-<uuid>` に退避する。
- Windows のファイル用シンボリックリンク（`settings.json`）は開発者モードか管理者の権限が要る。開発者モードがオフの PC では準備に失敗する。
- macOS は資格情報をキーチェーンに置き、`.credentials.json` が無い。段 1 の `ownDirLogin` は誤って「ログインし直す」と案内する。

## 決定

- 段 2 は 2 回に分ける。段 2a で既定を専用フォルダ方式にし、段 2b で b1 を削除する。
- 段 2a の前に、次をすべて満たす。
  - 段 1.5: 開発 PC のコネクターをオンにした全アカウントを入口のスイッチで専用フォルダ方式にし、数日（例: 3 日）使って、認証の停止が起きないことを記録する。
  - 使い捨てのログインと別のデータの場所で、次の試験に合格する。実アカウントのログインは使わない・複製しない。
    - T1 失効からの回復（サーバー側の失効後も、保持中の会話が再起動なしで続く。b1 では `OAuth token revoked` が出ることも見る）
    - T2 同時更新の繰り返し（期限の直前に CLI と使用量の読み取りを同時に起動し、20 回繰り返す）
    - T3 Pleiad を通した使用量の取得と会話の同時実行
    - T4 b1 の会話を同じ ID で専用フォルダ方式で再開する
    - T5 開発者モードがオフの Windows でのリンク
    - T6 アカウント削除でリンク先が残る
    - T7 2 アカウントの同期スキルの干渉
    - T8 Linux（WSL で T1 と T4）
- 対象はコネクターをオンにしたアカウントだけ。オフのアカウントは今の長期トークンを使い続ける（長期トークンは更新されないので失効しない）。`login`（共有の `~/.claude`）は変えない。ログインの一本化は #195 で扱う。
- 段 2a の既定の切り替え:
  - コネクターをオンにするアカウントは、専用フォルダ方式で始める。
  - すでに b1 のアカウントは、更新後に最初の会話を始めるときに自動で準備（リンクの作成と退避）し、移したことを画面に出す。
  - 準備に失敗したアカウントは、その場で b1 に戻し、理由を出す。Pleiad が共有の内容を `settings.json` に写す案は採らない。
  - 段 2a の間は、入口のスイッチを「詳細」に残して b1 に戻せるようにする。リンクは b1 の動作に影響しないので、戻すときに外さない。
- 退避した項目（`claude-usage/*.pleiad-moved-*`）は、30 日後に消す。
- macOS は、キーチェーンの経路を実機で確かめるまで専用フォルダ方式を止める。「ログインし直す」ではなく「この OS ではまだ使えない」と出す。Mac のコネクターは今と同じく使えないまま（ADR 0340）。対応は別の ADR で決める。
- 本人照合（識別ハッシュ）は残し、初回確認（専用フォルダと共有のコネクター一覧の比較）は削る。
- 使用量の読み取りは、これまでどおり専用フォルダでの SDK の呼び出しとし、更新の直列化は CLI の `.oauth_refresh.lock` に任せる。同じプロセス内の準備・移行の直列化（`withClaudeUsageDir`）は残し、ロックの競合（`USAGE_REFRESH_CONTENTION`）はログイン切れとせず次の取得でやり直す。
- 長期トークンの無いアカウントのモデル一覧（`probeCatalog`）の取り方は、#195 と一緒に決める。段 2 では決めない。
- 段 2b で削る（b1 だけで使う仕組み）: トークンの受け渡し・`fresh()`・更新依頼・`guardUsageDir`、期限タイマー（`scheduleExpiryTimer`・`onExpiryReached`）と保持中の子 CLI の再起動、b1 用の `readAccessCredentials`、`createConnectorVerification` の初回確認、入口のスイッチと `setConnectors` の `mode`。段 2b は、段 2a のリリースを 1 回挟んでから行う。

## 理由

- 失効の原因は、更新する側と、古いトークンを持ち続ける側が別にいること。専用フォルダ方式では両方が同じフォルダの CLI になり、更新の直列化と読み直しを CLI が担う。Pleiad の期限判定は、タイマーの隙間を埋めても、使用量の読み取りや CLI 自身の更新との競合が残る。
- 段 1 の実機確認は、ファイル上の期限を変えたクライアント側の判定だけで、サーバー側の失効は試していない。今回の失敗はサーバー側の失効そのものなので、T1 に合格しないまま既定を変えると、別の形で同じ停止が起きるおそれがある。
- 2 回に分けるのは、b1 へ戻せる期間を 1 リリース分残すため。ほかの PC は更新で既定が変わるので、開発 PC の段 1.5 では見られない環境（開発者モードの有無など）がある。
- 準備の失敗は、共有の内容を写す案より、b1 に戻す案が小さい。b1 は 2b まで動き、写す処理は 2b で不要になる。
- オフのアカウントまで広げると、コネクターを使わない会話にも claude.ai のコネクターと同期スキルが現れ、長期トークンの廃止（#195）と同時に決めることになる。失効はオフのアカウントでは起きない。

## 影響

- `core/claude-connectors-auth.mjs`: 2a で既定の方式を変える。2b で上の b1 の仕組みを削り、`createClaudeConnectorsWiring.resolve` をトークンを要求しない分岐だけにする。
- `core/backends/claude.mjs`・`core/backends/claude-usage.mjs`: 2b で期限タイマー・`activeExpiresAt`・`guardUsageDir` を削る。
- `core/claude-own-dir.mjs`: `settings.json` のリンクの `EPERM` を失敗として返し、退避した項目の掃除（30 日）を足す。
- `core/server.mjs`: 2a で既存アカウントの自動準備と失敗時の b1 への戻しを足す。2b で `mode` と `ownDirEnableFirst` の段取りを削る。
- `web/mcp-matrix.mjs`: 2a でスイッチを詳細へ移し、設定の画面に移した件数を出す。2b で消す。
- ほかの PC は、更新すると既定が変わる。Windows は開発者モードの有無を更新の前に確かめる。Mac は止めるので動作は変わらない。
