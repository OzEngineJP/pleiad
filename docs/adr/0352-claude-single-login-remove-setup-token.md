# 0352 Claude のアカウントを専用フォルダのログイン 1 つにまとめ、会話用のトークン（setup-token）を削除する

- 状態: 承認（2026-11-25）
- 関係: [ADR 0350](0350-claude-own-config-dir-default-remove-b1.md)（コネクターをオンにしたアカウントの専用フォルダ方式。この ADR で全アカウントへ広げる）・[ADR 0345](0345-claude-account-own-config-dir.md)・[ADR 0351](0351-claude-own-config-dir-macos-keychain.md)（macOS）・[ADR 0329](0329-claude-per-account-model-catalog.md)（アカウントごとのモデル一覧）・[ADR 0340](0340-claude-connectors-per-account.md)

## 状況

登録した Claude アカウントは、認証を 2 つ持っている。1 つは会話用のトークン（`claude setup-token` の長期トークン。Pleiad が暗号化して保存し、子 CLI に `CLAUDE_CODE_OAUTH_TOKEN` で渡す）。もう 1 つは専用フォルダ `claude-usage/<id>/` の claude.ai のログイン（使用量の読み取りと、コネクターをオンにしたアカウントの会話に使う。ADR 0350）。

利用者は 1 つのアカウントにつき 2 回認可しなければならない。setup-token はブラウザーでログイン中の claude.ai アカウントで黙って発行されるため、別のアカウントのトークンを登録してしまう事故があり、持ち主の照合（`tokenChecks`）と画面の警告を足してきた。setup-token の scope は `user:inference` だけで、使用量もコネクターも読めない。

ADR 0350 は、長期トークンの無いアカウントのモデル一覧（`probeCatalog`）の取り方を #195 に回した。

## 決定

- 登録したアカウントの会話の子 CLI・内部の呼び出し（題名の提案など）・コネクター一覧の読み取り・使用量・モデル一覧は、すべて専用フォルダのログインだけで動かす。`CLAUDE_CODE_OAUTH_TOKEN` は渡さない。`login`（共有の `~/.claude`）は変えない。
- コネクターをオフにしたアカウントも専用フォルダ方式で起動し、`ENABLE_CLAUDEAI_MCP_SERVERS=false` を渡して claude.ai のコネクターを出さない。準備（リンク・設定の検査・`projectProfile`）と止める条件（版・ssh・設定・Windows のリンクの権限・macOS のキーチェーン）は、コネクターのオン・オフで分けない。
- モデル一覧は、そのアカウントの専用フォルダを準備してから、同じ環境（トークンなし・claude.ai のコネクターなし）で SDK に問い合わせる。macOS では CLI がフォルダ名から決まるキーチェーンの項目を自分で読む（ADR 0351）。失敗したら、これまでどおり保存した一覧か固定の一覧を使う。前もって読む（warm）のは、ログインのあるアカウントだけにする。
- 「使える」アカウントは、専用フォルダのログインがあるもの。ログインが無い・切れたアカウントを選んだ会話は、今の `ownDirLogin` と同じ理由で止め、「ログインし直す」から設定 › アカウントのログインへ進める。委譲も同じ条件で選べなくする。
- 新しいアカウントは、名前を決めてすぐ claude.ai のログインを回す。id は先に決め、ログインが済んだときだけ登録する。取り消し・失敗では何も残さない。
- 移行: 起動時に、保存した会話用のトークン（秘密の `claude-account:<id>`）と、持ち主の照合の記録を消す。トークンは以後読まない。トークンそのものは Anthropic 側で失効させない（Pleiad から失効させる手段が無い）。専用フォルダのログインが無いアカウントは、設定 › アカウントのカードに「ログイン」を出す。
- 次は削る: setup-token の認可（`LOGIN_KINDS` の `setup-token`・疑似端末の使い捨てフォルダ）と手で貼る欄、トークンの保存・受け渡し・伏せ字、持ち主の照合（`fetchTokenOrg`・`tokenChecks`・`ownerStatus`・`AGENT_HOST_ANTHROPIC_API`）と画面の警告、会話が止まったときの「トークンを発行し直す」、モデル一覧だけトークン付きの登録を渡す分岐（`forModels`・`resolveCatalogAccount`）。
- 使われていない止めの種類 `owner`（`needsOwnerCheck`）・`expired`・`format` と、その文言を削る。本人照合（識別ハッシュ）は残す。
- 止まった会話の失敗の行から［コネクターをオフにして送る］を外す。オフにしても同じ条件で止まるため。止めた理由の文言からも「コネクターをオフにすると送れます」を外し、直し方（ログイン・更新・設定を外す）だけを書く。

## 理由

- ADR 0350 で、コネクターをオンにしたアカウントは専用フォルダのログインだけで会話・使用量・コネクターを動かしており、オフのアカウントで setup-token を残す理由は、claude.ai のコネクターと同期スキルを出さないことだけだった。コネクターは CLI の `ENABLE_CLAUDEAI_MCP_SERVERS` で止められる（Claude Code 2.1.328 のバイナリで確認）。同期スキル・プラグインは共有の `~/.claude` へリンクしており、混ざり方は ADR 0350 と同じ。
- 認可が 1 回になり、別のアカウントのトークンを登録する事故そのものが起きなくなるので、照合と警告の仕組みを丸ごと削れる。
- モデル一覧のために長期トークンを残す案は採らない。認可が 2 回のまま残る。専用フォルダの準備は会話の前にも必ず行うので、モデル一覧で準備しても新しい書き込み先は増えない。
- 移行の自動化（トークンから専用フォルダのログインを作る）はできない。setup-token は使用量もコネクターも読めず、専用フォルダの資格情報を作れない。

## 影響

- `core/claude-accounts.mjs`: トークン・照合・秘密を削り、名前と専用フォルダの印だけを持つ。起動時に古い秘密を消す。
- `core/claude-connectors-auth.mjs`・`core/backends/claude.mjs`: 全アカウントを専用フォルダで起動し、`probeCatalog` を専用フォルダで動かす。`oauthToken` の受け渡しを削る。
- `core/claude-login.mjs`・`core/server.mjs`・`web/claude-accounts.mjs`: 認可を claude.ai のログインだけにし、新しいアカウントを名前とログインで作る。
- 更新すると、専用フォルダのログインが無いアカウントは会話に使えなくなり、ログインし直すまで止まる。使用量を表示していたアカウントは、そのまま使える。
- 開発者モードがオフの Windows では、コネクターをオフにしたアカウントも準備に失敗して止まる（`ownDirLinksWindows`）。更新の前に開発者モードを確かめる。
- 実機で見ていないもの: macOS でのコネクターをオフにしたアカウントの会話とモデル一覧、オフのアカウントでの同期スキル・プラグインの出方。
