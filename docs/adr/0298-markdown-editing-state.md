# ADR 0298: Markdown本文と編集行の状態を分ける

状態: 承認済み（2026-11-06）

## 状況

CommonMarkでは `>` だけでも引用が成立する。一方、入力欄は空白で記法を確定するため、未確定の記号に共通構造解析の装飾を付けると、縦線と生の `>` が同時に出る。空の引用行では線が途切れ、引用を解除した非空行は lazy continuation として再び引用に入ることもある。

解除後の本文をMarkdownとして引用の外に出すには段落境界が必要だが、それを編集行として追加すると、Backspaceだけで行が増える。編集上の行と送信上の区切りを区別する。

## 決定

- [ADR 0292](0292-markdown-structure-shared.md) の共通構造解析と字下げ・引用線の部品は維持する。編集中の装飾には、各行の確定済み記号が所有する構造だけを使う。
- Enterは次の編集行へ1行進む。行頭のBackspaceは同じ行・同じ行頭で最内側の構造を1段解除する。空・非空のどちらも余分な編集行を作らない。
- 解除先が共通解析で内側に戻る場合だけ、行に `breakBefore` を持たせる。これはMarkdown出力時の区切りで、DOM行・カーソル位置・削除対象の行ではない。左右移動や結合は隣の編集行に直接進む。Undo/Redoには行の種類と境界を一緒に積む。
- `value`・範囲コピーは送信Markdownを返す。`selectionStart` / `selectionEnd` / `setRangeText`はその原文offsetで扱う。区切り内の位置は次の編集行頭に対応する。原文APIが区切りを明示的に変更した場合は、変更された原文を優先する。
- 保存本文とは別の任意項目 `editing` に版1、本文長、照合値、全編集行の開始offset・種類・確定記号・境界を保存する。本文の全行被覆、記号と本文の一致、種類ごとの記号構文（本文文字を記号として隠さない）、境界の文字種、版と上限を検証する。照合値は古い組合せの検出用で、認証には使わない。
- 本文と一致しない情報・未対応版は捨て、本文を通常のMarkdownとして読む。復元後の再出力が元の本文と一致することも確認する。既存の本文だけの下書き・履歴・貼り付けの原文は書き換えない。
- Chats、チャンネル、スレッド、編集中の脇置きと復帰、分岐先の下書きに同じ情報を渡す。添付の実体は従来の別項目で保存し、編集情報には資格情報やDOMを含めない。

## 理由

共通構造解析は保存済みのMarkdownを正確に読むために維持する。未完成の入力と確定済みの編集行を別に持つことで、装飾の先付けを防ぎ、解除時にカーソルの通過する空行を増やさずに送信後の段落構造を保てる。本文と編集情報を別にすることで、既存データや未対応版でも本文を読み続けられる。

## 影響

既存の `session_fields` と `drafts` はJSON本文を保持するため、テーブル変更・データ移行は不要。旧版は追加項目を無視でき、送信本文だけでも履歴の構造は正しく読める。その場合、区切りは通常の空行として編集される。

編集情報は長さ200万文字までの本文と、本文に存在する行だけを許容する。本文と位置対応が変わる範囲置換では、影響を受けない行の状態だけを残す。添付・コードのカーソル用の行は保存本文へ混ぜない。

## 検証

`tests/unit/md-editing-state.mjs` と既存の文書モデル・下書き永続化試験で、空/非空解除、入れ子、原文offset、範囲操作、保存復元、未知版と古い情報の破棄、既存原文の維持を確認する。実画面では `tests/browser/markdown-editing-state.cjs` と `markdown-editing-persistence.cjs` で直接入力、再読込と送信履歴を確認する。
