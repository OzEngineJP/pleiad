# 0227 Pleiad のシェルのツール（ply_shell）と、長いコマンドを会話自身へ知らせる

- 状態: 承認（2026-10-18）

## 状況

2026-10-18、OpenCode の会話 3 件が約 2 時間止まった。どれも画面を確かめるために、PowerShell の `Start-Process node core/server.mjs -RedirectStandardOutput <file> -RedirectStandardError <file>` で dev サーバーを裏に起こしていた。

- `-Redirect…` を付けた `Start-Process` は、起こしたプロセスに呼び出し元のシェルの出力のパイプを継がせる。シェルは数秒で終わるが、サーバーが生きている間パイプは閉じない（手元の再現: パイプが閉じるまでの時間が、付けないと 0.3 秒、付けると子が終わるまで）。
- OpenCode（v1.19.3）の bash ツールは、シェルの終わり・上限・中断の早いものを待つ。シェルが先に終わるので上限の見張りは外れ、その後の片付けで戻らない。外からの中断（`/session/:id/abort`）は効いた。
- Claude Code の Bash・PowerShell ツールは、同じ書き方でも戻った（手元で確かめた）。
- Pleiad の入力欄の `!`（`core/host-shell.mjs`）も、同じ書き方で戻らなかった（シェルの終わりの後に `close` を待ち、上限で木ごと止めても、親を失ったサーバーに届かない）。これは修正済み（シェルが終わったら 2 秒待って締め、`leftover` を返す）。
- 長いコマンドの知らせ（[ADR 0048](0048-delegation-silence-notice.md)）は委譲の子だけが対象で、シェルのツールの名前の一覧に OpenCode の `bash` が無かった（修正済み。名前はエージェントの記述の `shellTools` に 1 か所で書く）。普通の会話には知らせる先が無い。
- エージェントが自分のシェルのツールの中で固まると、ターンの途中に差し込んだ知らせ（steer）も、そのツールが戻るまで読まれない。

## 決定

### 1. Pleiad のシェルのツール `ply_shell`

- Pleiad の MCP（会話ごとのトークンの HTTP の口。`core/mcp-bridge.mjs`）として、Claude・Codex・OpenCode・fake に渡す（能力の印 `plyShell`）。今後足すエージェントも、Pleiad の MCP を受ければ同じ口を使える。
  - Antigravity にはまだ渡さない。Pleiad の MCP は Pleiad のカスタムエージェントでしか渡せず、渡すために必ずカスタムエージェントにすると、作業場所の AGENTS.md を読まなくなる。
  - Devin は Pleiad の MCP をまだ受けていない（`mcpServers: []`）。Devin の HTTP の MCP を確かめてから渡す。
- ツールは 5 つ。
  - `run` … 終わるまで待つ（上限は既定 2 分・最大 10 分）。シェルが終わったら、パイプを握ったプロセスが残っていても少し待って戻り、残ったことを結果に書く。
  - `start` … 裏で始めて、すぐ戻る（ジョブの id を返す）。サーバーなど、終わらないもの向け。
  - `output` … ジョブの出力の続きを読む（どこまで読んだかを渡す）。
  - `stop` … ジョブを止める（子のプロセスごと）。
  - `list` … この会話のジョブの一覧。
- 走らせる場所はホスト（`core/host-shell.mjs`）。エージェントのサンドボックスの外になるので、承認は Pleiad が会話の承認モードで決める（読み取りだけのモードでは断る。尋ねるモードでは承認のカードを出す。ply_delegate と同じ）。エージェント側の承認とは二重にしない（Claude は自動で通し、OpenCode は ply_shell を許す）。
- 裏のジョブは、会話の「バックグラウンドの処理」に `kind: 'shell'` で出し、人も止められる。出力はメモリだけに持ち（stdout・stderr それぞれ 256 KB。越えた分は捨てる）、データ置き場に書かない。会話ごとの同時のジョブは 8 まで。Pleiad のサーバーが終わるとジョブも止まる（保持役には載せない。無停止の更新をまたいで生かすのは、別に決める）。

### 2. 長いコマンドを、その会話自身へ知らせる

- 普通の会話（委譲の子でない会話）で、シェルのコマンド（ネイティブのシェルのツール、ply_shell の `run`・`start`）が N 分（`AGENT_HOST_SESSION_COMMAND_MINUTES`、既定 5、`0` で切る）を超えたら、その会話自身に知らせを入れる。コマンドごとに 1 回だけ。**止めない。**
  - 会話が止まっていれば、知らせで次のターンを始める。動いていれば、差し込める（steer）エージェントにはターンの途中に差し込み、差し込めなければターンの終わりを待つ。
  - 承認待ちの時間は数えない。待つためのコマンド（[ADR 0138](0138-quiet-wait-notices.md) の形）は数えない。
- ply_shell の `start` のジョブが終わったら、その会話に知らせる（終了コードと出力の末尾）。
- **会話が知らせを読めないとき**（知らせを差し込んだのに、3 分たっても受け取られない。エージェントが自分のシェルのツールの中で固まっている）は、人にも知らせる。通知の一覧（[ADR 0149](0149-notification-inbox.md)）に「あなた待ち」として 1 件載せ、コマンドが終わるか知らせが受け取られたら決着させる。
- 委譲の子は今どおり親へ知らせる（ADR 0048）。

### 3. エージェントのシェルを切る（エージェントごとの切り替え）

- 設定「シェル」を、エージェントごとに「エージェントのもの」と「Pleiad のもの」から選べるようにする。「Pleiad のもの」では、エージェントのシェルのツールを切り、ply_shell だけを使わせる。
- 切れるかは能力の印 `nativeShellOff` で申告する。

| エージェント | 切り方 | 既定 |
|---|---|---|
| Claude | `disallowedTools` に `Bash`・`PowerShell` | エージェントのもの（戻る。裏で走らせることもできる） |
| OpenCode | 会話の権限で `bash` を全面拒否（一覧から消える） | **Pleiad のもの** |
| Codex | 切らない（`features.shell_tool` が app-server の会話ごとに効くかを確かめていない。切ると Codex のサンドボックスと安全判定も外れる） | エージェントのもの |
| Antigravity | 切らない（`run_command` を外すには Pleiad のカスタムエージェントを必ず使うことになり、作業場所の AGENTS.md を読まなくなる） | エージェントのもの |
| Devin | 切らない（ply_shell を渡していない） | エージェントのもの |

- 「Pleiad のもの」でも、その会話に ply_shell を渡せないとき（review のモードなど）は、エージェントのシェルを切らない。

## 理由

利用者の決定（2026-10-18）。エージェントのシェルのツールが戻らなくなると、知らせも中断の判断も届かない。Pleiad が走らせるシェルなら、終わりの扱いも時間の見張りも Pleiad が持てるので、どのエージェントでも、今後足すエージェントでも同じ動きにできる。ただ、モデルは自分のシェルのツールに慣れていて、Codex ではサンドボックスを失うので、全部を一律に切らず、困っているエージェント（OpenCode）から切る。

止めずに知らせるのは ADR 0048 と同じ理由（意図して走らせている長いコマンドを誤って止めない）。知らせる先を親ではなく会話自身にしたのは、普通の会話に親がいないため。会話が読めないときだけ人に知らせ、通知を増やしすぎない。

## 影響

- `core/shell-bridge.mjs`（ply_shell）・`core/session-commands.mjs`（普通の会話のコマンドの見張り）を足す。会話ごとの口は `conversationConnection` に足し、無停止の更新の付け直し（`restoreConnection`）にも載せる。
- シェルのツールの名前の正本は `core/backends/agents.mjs` の `shellTools`（`core/shell-tools.mjs`）。名前で見分けられない呼び出しは `tool.start` の `shell: true`。
- 能力の印 `nativeShellOff` を足す（全バックエンドに値を書く。`docs/backend-matrix.md` を書き直す）。設定はエージェントごと（`shellTool`）。
- 子への指示と AGENTS.md に、`Start-Process` で裏へ回すときに `-Redirect…` を付けない旨を書いた（ply_shell を使わない会話の予防）。
- OpenCode 本体の不具合（シェルが終わった後の片付けで戻らない）は、上流への報告を別に検討する。

## 追記（2026-11-23）: 会話ごとの同時のジョブの上限（8）を無くした

決定 1 の「会話ごとの同時のジョブは 8 まで」を外した。代わりの上限も置かない（[Issue #207](https://github.com/OzEngineJP/pleiad/issues/207)。利用者の決定）。dev サーバーなどの常駐と、待つだけのジョブを同じ会話で起こすと 8 本が埋まり、新しい `start` が断られていた。

上限は何も守っていなかった。

- メモリは、ジョブごとに出力を `OUTPUT_KEEP`（256K 文字）までしか持たないことで決まる。本数では決まらない。
- 止め忘れは `JOB_TIMEOUT_MS`（24 時間）で止まる。
- 終わったジョブの記録は `JOBS_KEPT`（20 件）を超えたら古い方から捨てる（保持役の記録も release する）。
- 確認なしのモードのほかは、走らせる前に毎回承認のカードが出る。人は会話の裏の一覧から止められる。
- エージェントは自分のシェルのツール（Claude Code の `run_in_background` など）で本数の制限なく裏の処理を起こせる。ply_shell だけ 8 本にしても安全は増えない。

待つだけのタイマーの道具を足す案と、断るときにジョブの一覧を添える案は入れない（後者は断る処理が無くなるので要らない）。

## 追記（2026-11-25）: `run` は待ちを過ぎても止めず、裏のジョブへ移す。PowerShell の出力を UTF-8 で読む

利用者の決定。決定 1 の `run`（「終わるまで待つ。上限は既定 2 分・最大 10 分」）を次のように変えた。本文は当時のまま残し、動きはこの追記が正。

### 決定

- `run` は **少し待つ**。待ちの間に終われば、今までと同じ結果（出力と終了コード）を返す。待ちを過ぎても **止めない**。`start` と同じ扱いの裏のジョブに移し、ジョブの id・ここまでの出力・「まだ走っています（止めずに裏のジョブに移しました）」を **すぐ返す**（エラーにしない）。続きは `output`、止めるのは `stop`。終わると `start` のジョブと同じく、この会話に知らせが届く（決定 2）。
- **待ちは既定 30 秒、上限 240 秒**（`RUN_WAIT_MS`・`RUN_WAIT_MAX_MS`）。根拠は下の「根拠」。
- `timeoutMs` は「止める上限」ではなく「裏へ移すまでの待ち」の意味に変えた（名前は変えない。呼び出し側が壊れない）。スキーマの `minimum`・`maximum` は外し、範囲外は丸める（1 秒〜240 秒）。範囲外で呼び出しごと失敗していた（下の「根拠」）。止め忘れの保険の `JOB_TIMEOUT_MS`（24 時間）は残す。
  - 呼び出しとテストを調べた。`timeoutMs` を止める上限として使っていたのは、`core/shell-bridge.mjs` の自分の試験（「上限で止め、start を使うよう書く」）だけ。書き換えた。`runHostShell` の `timeoutMs`（止める上限）は意味を変えていない。ply_shell は 24 時間の保険だけを渡し（保持役の子 `core/shell-held-child.mjs` へもそのまま渡す）、シェルの行（`!`。`core/shell-runs.mjs`）は自分の上限（`AGENT_HOST_SHELL_TIMEOUT_MS`）を使う。
  - Claude・Codex の MCP の呼び出しの待ち（660 秒）は値を変えず、`CALL_TIMEOUT_MS`（11 分）として橋の側に持つ。承認カードを待つ時間と、最長の待ち（240 秒）を足しても切れないため。
- **保持役に載ったジョブも同じ扱い**。保持役には待ちの時間ではなく 24 時間の上限で頼み（待ちで止めない）、裏へ移したら札の種類（`jobKind`）を `start` に置き直す（`held.label`）。無停止の更新をまたいで復元したジョブは、待っていた接続がもう無いので、元が `run` でも `start` として扱い、終わりを知らせる。
- **人が止めたとき**。会話の裏の一覧（`running` の `background`）には、`start` のジョブ・裏へ移った `run` に加え、**3 秒以上待っている `run`** も出す（短い `run` でちらつかせない。`RUN_LISTED_AFTER_MS`）。人が一覧から止めると:
  - 待っている `run` は、`run` の戻りで「人がこのコマンドだけを止めました。ターンは続いています」と返す（`isError`。呼び出しは失敗にしない）。ターンは終わらない（止めるのはそのジョブの `AbortController` で、ターンのものではない）。結果として戻すので、終わりの知らせの対象にはしない。
  - 裏へ移った後は、終わりの知らせ（`deliverJobEnd`）に「人が止めた」と書く。`output` にも同じ文が出る。
  - ターンが止まったときは、待っている `run` は止める（戻りを受け取る側がいない）。裏へ移したものは止めない（`start` と同じ）。
- ツールの説明・使い方の指示（`shell.tools.*`・`shell.instructions`。ja・en）を、`run` が「まだ走っています」と返すことがあり、そのときは `output` で続きを読み、いらなければ `stop` で止める、に書き直した。
- Claude のネイティブのシェルを切った会話では、ply_shell の MCP の設定に `alwaysLoad: true` を付ける。Claude Code はツールが多いと MCP のツールをツール検索の後ろに回し、スキーマを読む前の呼び出しは 1 回失敗する（この作業の最初の `run` で実際に起きた）。ply_shell が唯一のシェルになる会話では、最初から読み込ませる。

### 根拠（待ちの既定 30 秒）

実際のコマンドの所要時間で決めた（2026-11-25 に集計。個人のドライブは読んでいない）。

- **Claude のネイティブの Bash**（会話の記録 2,212 本・約 10.4 万回）: 中央値 0.6 秒・p90 8.9 秒・p95 29.3 秒・p98 100 秒。**30 秒以内が 95.1%**（10 秒以内 90.6%、60 秒以内 97.1%、120 秒以内 98.2%、300 秒以内 99.2%）。PowerShell（約 3,900 回）は 30 秒以内 91.9%。
- **OpenCode の ply_shell の `run`**（9,158 回）: 30 秒以内 90.8%。ほとんどが数秒で終わる。
- 30 秒を過ぎるのは全体の 1 割弱。そこは待たせず、ジョブの id を渡して次の手を打たせる方が、会話が止まっている時間が短い。2 分・10 分待つ旧設定は、残りの 5〜9% のために全体の待ちを引き延ばしていた。
- **上限 240 秒**: OpenCode の MCP のクライアントは約 300 秒で切れる（`fetch failed`。305 秒・312 秒で実測。`timeoutMs` に 580,000・340,000 を渡した run）。切れると結果が受け取れない。余裕を見て 240 秒。
- **旧設定の被害**: 上限で止めた `run` が 44 回（0.5%）。`timeoutMs` が範囲外（最大 2,400,000）で呼び出しごと失敗したのが 19 回。`timeoutMs` は OpenCode の run の 28%（2,561 回）、Claude の run の 86%（194 / 225 回）が付けていた。
- 参考: Claude の ply_shell の呼び出しは、run 233・start 134・output 32・stop 60・list 29。OpenCode は run 9,158・start 159・output 245・stop 40。

### PowerShell の出力を UTF-8 で読む（`core/host-shell.mjs`）

日本語の Windows の PowerShell 5.1 は、出力をコンソールの文字コード（cp932）で書く。Pleiad は子の出力を UTF-8 で読むので、日本語が化ける。ply_shell の記録で、`shell: powershell` の run 180 回のうち **25 回が化けていた**（通常の出力 12・実行時のエラー 6・構文エラー 7。エージェントが `$OutputEncoding = [Console]::OutputEncoding = ...` を自分で書いて避けている例もある）。

- 走らせる前に出力と入力（`[Console]::OutputEncoding`・`$OutputEncoding`）を UTF-8（BOM なし）にする（`powershellCommand`）。
- 構文エラー（PowerShell 5.1 で `&&` を使った 6 回すべて）は、設定より前の構文解析で出るので、利用者のコマンドは base64 で渡し、設定の後で組み立てて走らせる（同じスコープ。変数・関数・`exit`・`throw` は今までどおり）。終了コードは今までどおり最後の文の成否（失敗なら 1）で返すよう、`$?` を控える。コマンドラインの上限（32767 字）に近い長さ（UTF-8 で約 22 KB 以上。日本語なら約 7,000 字）は包まず、先頭の設定だけ付ける。
- 実機（日本語の Windows の PowerShell 5.1）で、旧と新を並べて確かめた（27 ケース: コマンドレット・native・パイプ・エラー・構文エラー・`exit`・`throw`・複数行・here-string・長いコマンドなど）。終了コードは **26 ケースが同じ**。変わるのは次の 3 点だけ。化けが直る。構文エラーの文面の頭に「`Create` を呼び出し中に例外が発生しました」が付く。`Write-Error` の文面に、包みの 1 行が付く。違った 1 ケースは、行末のバッククォートで終わる未完のコマンドが、構文エラー（終了コード 1）でなく成功（0）になること。
- シェルの行（`!`）も同じ `runHostShell` を通るので、同じく直る。

### `output` に待ち（`waitMs`）を足す（同じ日の追加）

`run` が 30 秒で裏へ移るようになると、1〜3 分かかるコマンド（試験・ビルド）は、モデルが `output` を何度も取りに行くか、`sleep` を挟んで呼び直すことになる。もともと、ある会話が `output` を 158 回取りに行った記録がある（走っている間の `output` は、今ある分を返してすぐ戻るだけ）。

- `output` に任意の `waitMs`（整数）を足した。ジョブが走っていれば、**終わるか `waitMs` が過ぎるまで待ってから**、`since` から先の出力を返す。**新しい出力が出ただけでは戻らない**（出力の多いコマンドで細かく戻らないように）。省いたら（数でなくても）、0 以下でも、今までどおりすぐ戻る。
- 上限は `RUN_WAIT_MAX_MS`（240 秒。OpenCode の MCP のクライアントが約 300 秒で切れるのと、`run` の待ちと同じ理由）。`run` の `timeoutMs` と同じく、スキーマの `minimum`・`maximum` は付けず、範囲外は丸める（弾くと呼び出しごと失敗する）。
- 待っている間に **人がそのジョブを止めたら**、止まり終わった時点で戻り、「人がこのコマンドだけを止めました。ターンは続いています」と返す（60 秒の待ちを使い切らない）。**ターンが止まった・呼び出した側が切れたら**、待つのをやめるだけで、ジョブは止めない（裏のジョブなので。待っている `run`（まだ裏へ移っていない）はこれまでどおり止める）。待ち直すことができる。
- 終わったジョブ・知らないジョブは今までどおり（すぐ返す・断る）。保持役に載ったジョブでも同じ（`job.done` を待つ）。`output` は `run`・`start` と違い、会話の書き込みの待ち行列（`withSessionWrite`）に載せない（長く待つ間に、会話への書き込みを塞がないため）。
- ツールの説明（`shell.tools.output`・`waitArg`・`run`）・使い方の指示（`shell.instructions`）・`run` が裏へ移った戻り（`shell.promoted`）・「まだ走っています」（`shell.stillRunning`）に、`waitMs` で終わるまで待てること、`sleep` を挟んで何度も呼ばなくてよいことを書いた（ja・en）。
- 試験は `tests/unit/shell-bridge.mjs`（待ちの間に終わる・出力が出続けても `waitMs` まで戻らない・省く／0／負／数でない値はすぐ戻る・上限への丸め・人が止めたらすぐ戻る・ターンが止まっても呼び出した側が切れてもジョブは走り続ける・終わった／知らないジョブ・保持役のジョブ・説明の文）。

### `ply_shell` の承認に「常に許可」を足す（2026-11-25 の追記）

利用者の決定。これまで尋ねるモードでは毎回承認カードを出していた（下の見送り案）が、汎用カードの「常に許可」で、その会話の間は確認を出さずに通すようにした。

#### 決めたこと

- `ply_shell`（`run`・`start`）の承認カードで `canAlways: true` を渡し、汎用カードの「常に許可」ボタンをそのまま使う（画面の部品・文言は足さない）。意味は Codex（`acceptForSession`）・OpenCode（`reply: always`）と同じ「この会話の間は常に許可」に揃える。
- 人が「常に許可」を選んだら、会話のデータ（`shellAlwaysAllow: true`、`store.setSessionData` で SQLite の `session_fields` に保存）に印を残す。置き場は `ply_computer` の「この会話」の `computerApps` の前例に合わせた。Pleiad を再起動しても、無停止の更新をまたいでも残り、以後はその会話の `run`・`start` でカードを出さない。一度だけの許可（`once`）では印を残さない。
- 範囲は、その会話の間の `ply_shell` の全コマンドとする。危ないコマンド（`rm`・`git push`・秘密に触れるもの）を別に毎回聞く仕組みは今回は作らず、要ると分かったら後で絞った一覧を足す。
- 読むだけのモード（`scope: 'none' | 'readonly'`）で断る扱いは変えない。判定の先頭で読むだけかを確かめるため、会話の承認モードが読むだけに変わったら、印があっても断る。
- **委譲の子・分岐（`fork`）へは引き継がない**: 会話ごとの許可であるため、`computerApps`（`inheritSettings` にも委譲の子作成にも入れない）の前例に合わせて引き継がない。委譲の子の承認が親へ中継される場合も、他のツールと同じく親側のカードは `canAlways: false` とし、子の会話側でのみ選べる。
- **取り消し**: `computerApps` を含め、会話データの許可を取り消す既存の口は無いため新しく作らない。取り消しは会話のモードを変える（読むだけにするなど）・新しい会話にすることで行う。

#### 理由・根拠

- 測った数: Claude の会話の承認モードは `bypass` 3,780・`plan` 79・`auto` 61・`default` 12。さらに、つないだコマンドが 91.7% を占めるため、コマンドの頭で覚える方式は効かない（同じコマンドだけ許す案・ネイティブの Bash の決まりを引き継ぐ案も採らない）。
- 「常に許可」のボタンは Codex・OpenCode の同じ意味の承認と共通の文言（「常に許可」 / "Always allow"）を使っており、`ply_shell` でも誤解を生まないため変えない。

### 検討して直さなかったもの（根拠が足りない・好みの範囲）

- **ネイティブのシェルを切った会話の指示**: `shell.instructions` は Bash を前提にしていない。`TOOL_HINTS` は画面の表示名で、モデルへの指示ではない。直すものは無かった。
- **Windows の既定のシェル**: Git Bash（無ければ PowerShell）。記録に困りごとの証拠が無い（Claude は `shell` を 72% の run で指定している）。
- **`cd` の癖**: OpenCode の run の 79%（7,244 / 9,158）が `cd <作業場所> && ...` で始まり、`cwd` 引数は 8%。動きは正しいので害は無い。説明に「作業場所は会話の作業場所が既定」と足す案。
- **出力の切り詰め**: 先頭だけ残して後ろを捨てる（256 KB）。「続きがあります」36 回・古い出力の取りこぼし 6 回・切り詰めの旗 5 回と少ない。末尾を残す案。
- **Git Bash の `/` で始まる引数**: Windows のパスに書き換わる。使った実感であり、記録には出ない。説明に一言足す案。


### 委譲の子の完了と終わりの知らせの重なり（2026-11-25 の追記）

#### 決めたこと

- **委譲の子は、自分の会話の `ply_shell` のジョブが 1 本でも走っている間は完了にしない**。`run` から裏へ移ったジョブだけでなく、子が意図して残す `start` のジョブも同じである。これは、ジョブを残したまま結果だけが親へ返ると、親がジョブの終わりを作業の終わりと誤認し、残ったプロセスの所在も分かりにくいためである。ジョブが終わると終わりの知らせを子へ届け、子がジョブの無い状態で返答を終えたときに完了とする。
- 待っている間の親から見える状態は、新しい status を増やさず、既存の ADR 0170 の形に寄せる。タスクは `running` のままで、`ply_task_status` / `ply_task_list` の `backgroundWaiting` に shell のジョブを出す。`waiting` は人の承認待ちの意味なので使わない。
- 逃げ道は、子が `ply_shell` の `stop` で止めることと、依頼元の `ply_task_cancel`（または子の会話の中断）である。取り消しでは子の会話の `ply_shell` のジョブも止める。個別の委譲用の上限は置かず、ジョブの既存の上限（24 時間）を使う。`start` のジョブは完了を阻むので、残す必要が無ければ子が `stop` する（子への指示には足していない。止め忘れは取り消しかジョブの上限で終わる）。
- `output`（`waitMs` を含む）・`stop`・待ちの間に終わった `run` の戻りで終了コードや停止の印を返したジョブは、**終わりを受け取り済み**としてジョブに印（`endReceived`）を付け、`deliverJobEnd` の知らせを出さない。保持役に載ったジョブでは印を札にも残し、サーバーを入れ替えて復元したジョブにも引き継ぐ。
- `output` の `waitMs` で待っている呼び出しは、ジョブの終わりで先に戻り始める。`onJobEnd` から通知を 1 回分のイベントループだけ遅らせ、さらに `deliverJobEnd` の送信直前にも `endReceived` を確かめるのは、この競合で同じ終わりを二重に届けないためである。`run` が待ちの間に終わった場合は `kind: run` のままなので、これまでどおり通知は出ない。

#### 子の記録の調べ（ply-task-4a10133e…・Grok）

- Grok の子は、`ply_shell` を使わず、Grok 自身の長い処理の機能（`long-running-background-tasks` の PowerShell のスクリプト `watch_pleiad_beta26.ps1`）で CI の見張りを裏に起こし、「終わるまで見張って報告します」と書いてターンを終えた。会話の記録に `ply_shell` の呼び出しは無い。
- Grok は `plyShell: true` を持つが、`shellTools: []`・`shellDefault: 'native'` で、設定 `shellTool` が `{"claude":"ply"}` のとき Grok はネイティブのシェルのまま動く。Grok の裏の処理は Pleiad から見えず、コードで完了を止める手は無い（`ply_shell` のジョブを残した子だけが対象）。そのため、下の指示の 1 文で補う。

#### 子への指示

委譲された会話へ入る既定の指示（`guide.commandLifetime`）に、ターンを終えると完了として依頼元に返ること、待つ作業は `ply_shell` の `run` の `timeoutMs` か `output` の `waitMs` で待ち切ってから終えること、待てないなら待っていないことを結果に書くことを足した。
