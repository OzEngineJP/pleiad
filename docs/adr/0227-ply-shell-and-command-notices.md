# 0227 Pleiad のシェルのツール（ply_shell）と、長いコマンドを会話自身へ知らせる

- 状態: 承認（2026-10-18）

## 状況

2026-10-18、OpenCode の会話 3 件が約 2 時間止まった。どれも画面を確かめるために、PowerShell の `Start-Process node core/server.mjs -RedirectStandardOutput <file> -RedirectStandardError <file>` で dev サーバーを裏に起こしていた。

- `-Redirect…` を付けた `Start-Process` は、起こしたプロセスに呼び出し元のシェルの出力のパイプを継がせる。シェルは数秒で終わるが、サーバーが生きている間パイプは閉じない（手元の再現: パイプが閉じるまでの時間が、付けないと 0.3 秒、付けると子が終わるまで）。
- OpenCode（v1.19.3）の bash ツールは、シェルの終わり・上限・中断の早いものを待つ。シェルが先に終わるので上限の見張りは外れ、その後の片付けで戻らない。外からの中断（`/session/:id/abort`）は効いた。
- Claude Code の Bash・PowerShell ツールは、同じ書き方でも戻った（手元で確かめた）。
- Pleiad の入力欄の `!`（`core/host-shell.mjs`）も、同じ書き方で戻らなかった（シェルの終わりの後に `close` を待ち、上限で木ごと止めても、親を失ったサーバーに届かない）。これは修正済み（シェルが終わったら 2 秒待って締め、`leftover` を返す）。
- 長いコマンドの知らせ（[ADR 0048](0048-delegation-silence-notice.md)）は委譲の子だけが対象で、シェルのツールの名前の一覧に OpenCode の `bash` が無かった（修正済み。名前はエージェントの記述の `shellTools` に 1 か所で書く）。普通の会話には知らせる先が無い。
- エージェントが自分のシェルのツールの中で固まると、ターンの途中に差し込んだ知らせ（steer）も、そのツールが戻るまで読まれない。

## 決定

### 1. Pleiad のシェルのツール `ply_shell`

- Pleiad の MCP（会話ごとのトークンの HTTP の口。`core/mcp-bridge.mjs`）として、Claude・Codex・OpenCode・fake に渡す（能力の印 `plyShell`）。今後足すエージェントも、Pleiad の MCP を受ければ同じ口を使える。
  - Antigravity にはまだ渡さない。Pleiad の MCP は Pleiad のカスタムエージェントでしか渡せず、渡すために必ずカスタムエージェントにすると、作業場所の AGENTS.md を読まなくなる。
  - Devin は Pleiad の MCP をまだ受けていない（`mcpServers: []`）。Devin の HTTP の MCP を確かめてから渡す。
- ツールは 5 つ。
  - `run` … 終わるまで待つ（上限は既定 2 分・最大 10 分）。シェルが終わったら、パイプを握ったプロセスが残っていても少し待って戻り、残ったことを結果に書く。
  - `start` … 裏で始めて、すぐ戻る（ジョブの id を返す）。サーバーなど、終わらないもの向け。
  - `output` … ジョブの出力の続きを読む（どこまで読んだかを渡す）。
  - `stop` … ジョブを止める（子のプロセスごと）。
  - `list` … この会話のジョブの一覧。
- 走らせる場所はホスト（`core/host-shell.mjs`）。エージェントのサンドボックスの外になるので、承認は Pleiad が会話の承認モードで決める（読み取りだけのモードでは断る。尋ねるモードでは承認のカードを出す。ply_delegate と同じ）。エージェント側の承認とは二重にしない（Claude は自動で通し、OpenCode は ply_shell を許す）。
- 裏のジョブは、会話の「バックグラウンドの処理」に `kind: 'shell'` で出し、人も止められる。出力はメモリだけに持ち（stdout・stderr それぞれ 256 KB。越えた分は捨てる）、データ置き場に書かない。会話ごとの同時のジョブは 8 まで。Pleiad のサーバーが終わるとジョブも止まる（保持役には載せない。無停止の更新をまたいで生かすのは、別に決める）。

### 2. 長いコマンドを、その会話自身へ知らせる

- 普通の会話（委譲の子でない会話）で、シェルのコマンド（ネイティブのシェルのツール、ply_shell の `run`・`start`）が N 分（`AGENT_HOST_SESSION_COMMAND_MINUTES`、既定 5、`0` で切る）を超えたら、その会話自身に知らせを入れる。コマンドごとに 1 回だけ。**止めない。**
  - 会話が止まっていれば、知らせで次のターンを始める。動いていれば、差し込める（steer）エージェントにはターンの途中に差し込み、差し込めなければターンの終わりを待つ。
  - 承認待ちの時間は数えない。待つためのコマンド（[ADR 0138](0138-quiet-wait-notices.md) の形）は数えない。
- ply_shell の `start` のジョブが終わったら、その会話に知らせる（終了コードと出力の末尾）。
- **会話が知らせを読めないとき**（知らせを差し込んだのに、3 分たっても受け取られない。エージェントが自分のシェルのツールの中で固まっている）は、人にも知らせる。通知の一覧（[ADR 0149](0149-notification-inbox.md)）に「あなた待ち」として 1 件載せ、コマンドが終わるか知らせが受け取られたら決着させる。
- 委譲の子は今どおり親へ知らせる（ADR 0048）。

### 3. エージェントのシェルを切る（エージェントごとの切り替え）

- 設定「シェル」を、エージェントごとに「エージェントのもの」と「Pleiad のもの」から選べるようにする。「Pleiad のもの」では、エージェントのシェルのツールを切り、ply_shell だけを使わせる。
- 切れるかは能力の印 `nativeShellOff` で申告する。

| エージェント | 切り方 | 既定 |
|---|---|---|
| Claude | `disallowedTools` に `Bash`・`PowerShell` | エージェントのもの（戻る。裏で走らせることもできる） |
| OpenCode | 会話の権限で `bash` を全面拒否（一覧から消える） | **Pleiad のもの** |
| Codex | 切らない（`features.shell_tool` が app-server の会話ごとに効くかを確かめていない。切ると Codex のサンドボックスと安全判定も外れる） | エージェントのもの |
| Antigravity | 切らない（`run_command` を外すには Pleiad のカスタムエージェントを必ず使うことになり、作業場所の AGENTS.md を読まなくなる） | エージェントのもの |
| Devin | 切らない（ply_shell を渡していない） | エージェントのもの |

- 「Pleiad のもの」でも、その会話に ply_shell を渡せないとき（review のモードなど）は、エージェントのシェルを切らない。

## 理由

利用者の決定（2026-10-18）。エージェントのシェルのツールが戻らなくなると、知らせも中断の判断も届かない。Pleiad が走らせるシェルなら、終わりの扱いも時間の見張りも Pleiad が持てるので、どのエージェントでも、今後足すエージェントでも同じ動きにできる。ただ、モデルは自分のシェルのツールに慣れていて、Codex ではサンドボックスを失うので、全部を一律に切らず、困っているエージェント（OpenCode）から切る。

止めずに知らせるのは ADR 0048 と同じ理由（意図して走らせている長いコマンドを誤って止めない）。知らせる先を親ではなく会話自身にしたのは、普通の会話に親がいないため。会話が読めないときだけ人に知らせ、通知を増やしすぎない。

## 影響

- `core/shell-bridge.mjs`（ply_shell）・`core/session-commands.mjs`（普通の会話のコマンドの見張り）を足す。会話ごとの口は `conversationConnection` に足し、無停止の更新の付け直し（`restoreConnection`）にも載せる。
- シェルのツールの名前の正本は `core/backends/agents.mjs` の `shellTools`（`core/shell-tools.mjs`）。名前で見分けられない呼び出しは `tool.start` の `shell: true`。
- 能力の印 `nativeShellOff` を足す（全バックエンドに値を書く。`docs/backend-matrix.md` を書き直す）。設定はエージェントごと（`shellTool`）。
- 子への指示と AGENTS.md に、`Start-Process` で裏へ回すときに `-Redirect…` を付けない旨を書いた（ply_shell を使わない会話の予防）。
- OpenCode 本体の不具合（シェルが終わった後の片付けで戻らない）は、上流への報告を別に検討する。
