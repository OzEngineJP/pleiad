# 0136 worktree は指定されたときだけ作り、画面でも worktree と呼ぶ

- 状態: 承認（2026-10-05）
- 置き換えた: 0133 の全部、0089 の決定 1(a)(b) と 3 の自動判定、および画面での呼び名

## 状況

[ADR 0133](0133-worktree-auto-split-by-default.md) では、人が始める会話が同じリポジトリの別の書き手とぶつかると、自動で worktree を作ることにした。[ADR 0089](0089-worktree-on-demand.md) の委譲も、`isolate` を省略したときに書き手と並列の呼び出しを数えて worktree を作る。

worktree は Git のオブジェクトを共有するが、作業ツリーを 1 つごとに書き出す。巨大なリポジトリでぶつかるたびに作るとディスクを消費し、依存の無い新しい場所や変更の取り込みも増える。実際に 1 つの長いターン中に 4 つ作られた。ユーザーは作成するか自分で決めたい。

## 決定

1. 人が始めた会話は、別の会話が同じリポジトリに書き込み中でも自動で worktree を作らない。作るのは入力欄の作業場所の面にある「worktree で始める」と、明示的な `worktrees.split` だけ。
2. ぶつかっている間はチップの末尾に弱い字で「· ほかの会話も書き込み中」と示す。誰が書いているかはチップの title と読み上げ、面の末尾の弱い 1 行に示し、その下に「worktree で始める」を置く。この知らせは送信の動作を変えない。
3. 自動作成のスイッチと、台帳の `settings`、WS の `worktreeSettings` / `setWorktreeSettings`、操作 `worktrees.settings` / `worktrees.setSettings`、CLI の対応する口、送信の `keepPlace` を消す。古い台帳の `settings.always` は読まず、次の保存で落とす。台帳の形式番号は変えない。
4. 委譲は `isolate: true` が明示され、Git の場所であるときだけ worktree を作る。省略と `false` は今の作業場所を使う。エージェントには、ユーザーが worktree を指示したときだけ `isolate: true` を付け、同じリポジトリに書く子を並べるなら worktree を使うかユーザーに聞くよう伝える。
5. 画面・エラー・エージェントへの呼び名は ja / en とも「worktree」にする。Pleiad の外で作った worktree の札は「Pleiad の外」/ “Outside Pleiad”。会話の fork など、worktree と無関係の語は変えない。
6. 前の版で会話に残った present `kind: 'worktree'` は新しい文言で描き続ける。新しくは発行しない。手で worktree を作った後の予約と取り消し、片付け・退避・復元・取り込みの操作は続ける。

決定 1 の例外として、[ADR 0213](0213-remember-repository-turn-settings.md) は前回 worktree で送ったリポジトリで次の会話にも worktree を予約する。送信前に示し、取り消せる。

## 理由

worktree を作るかどうかと、そのディスク使用量、パスの変更、取り込みの手間をユーザーが選べる。衝突の知らせで、同じ作業ツリーへの並行書き込みに気付ける。Git を使う人には「分けた作業場所」より「worktree」が直接伝わる。

## 影響

同じ作業ツリーへ複数の会話や子が同時に書くことが既定で起こりうる。自動作成を明示的にオンにした既存の利用者も、次の衝突から元の場所で始まる。操作一覧から 2 件が消える。
