# 0359 「ログイン」「アカウント」「接続先」を 1 つの「接続先」にまとめ、bot も互換の接続先で動かせるようにする

- 状態: 承認（2026-11-26）。決定 6 の「委譲の候補はアカウントの単位のまま（互換の接続先は候補にしない）」は [ADR 0361](0361-delegation-compat-candidates.md) で置き換え（互換の接続先も候補にできる。同じエージェントの委譲が接続先を継ぐ動きは残す）
- 関係: [ADR 0011](0011-compat-endpoints.md)（互換の接続先）・[ADR 0224](0224-bot-account.md)（bot のアカウント）・[ADR 0264](0264-delegation-account-scope.md)（委譲の候補はアカウントの単位）・[ADR 0329](0329-claude-per-account-model-catalog.md)（アカウントごとのモデル一覧）・[ADR 0353](0353-claude-single-login-remove-setup-token.md)（Claude のアカウントのログインは 1 つ）・[ADR 0222](0222-agent-accounts-and-provider-quota.md)（登録アカウントと使用枠）

## 状況

「どの枠・どの請求で動くか」を、画面は 3 つの言葉で別々に出していた。

- **ログイン**: 設定のエージェントのカードの［ログイン］［ログアウト］と、頭の行の「ログイン中」「未ログイン」。CLI が今ログインしている口。
- **アカウント**: Claude Code・Codex・OpenCode のカードの「アカウントと接続先 ▾」の中の「アカウント」の節。登録した公式のサブスクの口。入力欄のモデルの面にも「アカウント」の行がある。
- **接続先**: 同じ面の中の「接続先」の節。URL とキーで足す互換の口。入力欄のモデルの面にも別の「接続先」の行。

利用者にとってはどれも「このエージェントを、どの口で動かすか」の 1 つの選びなのに、設定のカードは節が 2 つ（見出し h4・説明の段落・暗号化の注記つき）、入力欄は行が 2 つ、右クリックメニューは項目が 2 つ、「既定」の札も 2 か所だった。Claude の「アカウント」の画面（灰色の面に白いカード、各カードに［編集］［削除］、下に［＋ 追加］）が分かりやすいのに、互換の接続先は別の形だった。

bot のページの「アカウント」の節（ADR 0224）は、互換の接続先を選べなかった。互換の接続先を使いたい bot は、会話の入力欄で毎回選び直すしかなく、ルーティン・委譲は公式でしか動かなかった。

## 決定

画面の概念を **「接続先」**（en: connection）1 つにまとめる。接続先には 3 種ある: **CLI のログイン**（どのエージェントも同じ名前）・**登録したアカウント**（公式のサブスクを別に足したもの）・**互換の接続先**（URL とキー）。内部の名前（API・保存・設定のキー・MCP の引数 `account` / `endpoint`・`ply_usage` の `login`・i18n のキーの接頭辞）は変えない。

1. **設定 › エージェント設定。** Claude Code・Codex・OpenCode・Grok は同じ部品・同じ順の 1 つの面を持つ（頭の行の［接続先］で、カードの中に下へ開く）。
   - 面は灰色の面（`.mp-panel`）に白いカードを 1 列に並べる。順は CLI のログイン → 登録したアカウント → 互換の接続先。末尾に文字だけの［＋ 接続先を追加］。
   - 各カードは名前・状態の 1 行・文字だけの操作。アカウントと互換のカードは［編集］［削除］、必要なときだけ［ログインする］（ログインし直す）・［接続を確認］（確認に失敗した互換）・［既定にする］（既定でないとき）。CLI のカードは［ログアウト］（ログイン中）と、必要なときだけ［ログインする］・［既定にする］。
   - 頭の行は［状態を確認］［接続先］だけ（Devin の頭の行は変えない。Antigravity は ADR 0366 で 2 つ目以降のアカウントを持ったので、Claude・Codex と同じ［接続先］の面）。状態は「接続先 N」、対応が要るものがあれば「⚠ 対応が要る接続先 N」。
   - CLI のログインの名前は「CLI のログイン」（エージェントの名前は付けない）。
   - 消す: h4 の見出し、説明の段落（環境変数 ANTHROPIC_API_KEY があるときの ⚠ の 1 行だけ残す）、一覧の下の暗号化の注記（API キーの欄の下にだけ残す）、確認済みの接続先の［接続を確認］、互換の URL・モデルの行。
2. **［既定にする］は 1 つで、新しい会話の既定を決める。** データの形は変えない（互換の既定は `defaults`、アカウントの既定は prefs の `claudeAccount` など）。互換を選ぶと既定の互換の接続先を書く。アカウントか CLI のログインを選ぶと、既定の互換の接続先を公式に戻して既定のアカウント（CLI のログインは空）を書く。「既定」の札は、新しい会話の既定の 1 つの接続先にだけ付く（これまでは「既定のアカウント」と「既定の互換の接続先」で 2 つ付きえた。設定のカードは名前の後ろの「· 新しい会話の既定」、入力欄の一覧は右端の「既定」。bot のページの一覧には付けない）。入力欄で選んでも既定にはならない。
3. **入力欄。** モデルの面の「アカウント」の行と「接続先」の行を 1 行の「接続先」にし、2 段目は CLI → アカウント → 互換の 1 つの一覧にする（選べる先が CLI のログインだけで、それを選んでいる会話には行を出さない）。週の使用量の棒は公式の枠を使う行（CLI のログイン・アカウント）だけ。右クリックメニューは「接続先（次のターン）」1 つ（「アカウント」の項目は消す）。予約の帯・警告の文も 1 つにする。
4. **会話は 2 つの欄のまま持つ。** セッションは `claudeAccount`（アカウント）と `compatEndpoint`（互換）を別々に持つ。互換を選ぶと互換の欄だけが効き、アカウントの選びは残したまま使わない。公式を選ぶと互換の欄を外す。ターンの始めは、互換が効いていればアカウントの解決を飛ばす。消えた接続先は送信を止めて理由を会話に残す（公式へ黙って落とさない）。
5. **bot の接続先は 1 つの一覧。** bot のページの「接続先」は、入力欄と同じ部品・同じ順で互換の接続先も並べる。保存は `bots.json` の `account` に加えて `endpoint`（互換の接続先の id。`''` = 公式）を足す。`bots.setAccount` は `{ botId, account, endpoint? }`（human-only のまま。`endpoint` を渡さなければ今のまま）。
   - bot の会話・ルーティン（実行と試し実行）・心拍・`ply_delegate` で bot が起こした子は、bot の接続先で実際に動く。休憩の key は互換の bot だけ `@${endpoint}` を足す。
   - 接続先を変えると bot のモデルとエフォートは既定へ戻る（互換のモデルは公式では通らないため）。bot のエージェントを替えると `account`・`endpoint` とも `''` に戻る。
   - **DB。** `endpoint` は欠けていれば `''` と読むので、`bots.json` の `version` は上げず、`core/schema-migration.mjs` にも足さない（ADR 0224 が `account` を足したときと同じ。古い版は `endpoint` を読み捨てるだけで、書き戻しても互換の選びが消えるだけで壊れない）。
   - スレッドの入力欄は、bot が互換の接続先のときだけ読み取りの「接続先」の行を出す（変えるのは bot のページ）。
6. **委譲の候補・使用量・MCP・サーバーの文言。** 委譲の候補とチップ（ロゴ・モデル・接続先・エフォート）、使用量のバッジ・一覧、ログインが切れた行、コネクター・プラグインの表、MCP のツールの説明、サーバーのメッセージを「接続先」の言葉にそろえる。委譲の候補は ADR 0264 のとおりアカウントの単位のまま（互換の接続先は候補にしない。委譲の子は同じエージェントなら持ち主の互換の接続先を継ぐ）。
7. **変えないもの。** Plus、外部 MCP のログイン、サイトのログイン、gh、OS のサインイン、Chrome のプロファイル、初回の案内。Devin の頭の行（Antigravity の頭の行は ADR 0366 で撤回し、Claude・Codex と同じ［接続先］にした）。
8. **英語。** 統一した概念は「Connection」。互換の接続先そのもの（URL とキー）を指す文は「compatible endpoint」「endpoint」のまま。

## 理由

- 「どの口で動かすか」は 1 つの選びなので、見る・選ぶ・既定にする場所を 1 つにしたほうが、迷わず、画面の部品も減る（節・行・メニュー項目・既定の札が 2 つずつあった）。
- Claude の「アカウント」の画面は、すでに承認済みで読みやすい。同じ部品を Codex・OpenCode・Grok・互換にも使えば、エージェントごとの違いは「足せる種類」だけになる。
- データを 2 つの欄のまま持てば、保存・API・MCP の引数・既存の会話を 1 つも壊さずに、画面だけを替えられる。「互換を選ぶとアカウントの選びは残したまま使わない」は、今までの動き（互換の会話ではアカウントを使わない）と同じ。
- 互換の接続先を bot にも持たせないと、キー課金や安い接続先で動かしたい bot が、会話ごとに選び直すしかなかった。bot が接続先を持てば、ルーティン・委譲もその接続先で動く。

## 影響

- 設定のカード・入力欄・右クリックメニュー・予約の帯・警告・bot のページ・スレッドの入力欄・委譲の候補・使用量・MCP の説明の言葉が変わる。画面の規則は `docs/design-system.md` の「Claude のアカウント」「互換の接続先の管理」「設定 › エージェント設定」「入力欄の設定（面〔2 段〕・使用量の棒の置き場）」「bot のページ」「委譲の候補」（承認済み（2026-11-26））。用語は `docs/i18n-glossary.md`。
- `bots.get` / `bots.list` が `endpoint` を返す。`bots.setAccount` が任意の `endpoint` を受ける（ops の一覧の形が変わる。`tests/ops-surface.snap.json` を更新）。能力の印は `accounts` と `compatEndpoints` の 2 つのまま（公開のラベルだけ統一）。
- 互換の接続先の bot は、ルーティンの休憩の key が変わる（`@${endpoint}`）。bot の変更記録（changeLog）は `endpoint` の欄を持たない（今のまま）。
- 設定の ［ログインする］は、既定では畳んだ［接続先］の中に入る。ログインしていない CLI の頭の行にあった［ログイン］は無くなる（頭の状態の「⚠ 対応が要る接続先」から開く）。テストはその前提に直した（`tests/browser/missing-agent.mjs` は行の `data-sig` で状態を待つ）。
- 削除したもの: 設定のカードの h4 と説明の段落、入力欄のアカウント行、右クリックメニューのアカウント項目、互換の URL・モデルの行。
- 試験: `tests/unit/server-bot-compat.mjs`（bot の互換の接続先を、会話・ルーティン・試し実行・委譲・接続先の削除・再起動まで、偽のサーバーで通す）、`tests/browser/agent-conn-panel.mjs`・`limit-agent-switch.mjs`・`work-dialog-composer.mjs`・`missing-agent.mjs`、`tests/unit/bots-store.mjs`・`web-account-models.mjs`。

## 追記（2026-11-26）: Pleiad から外せないエージェントは［ログアウト］を出さない

決定 1 で CLI のカードに［ログアウト］を置いたが、OpenCode は Pleiad から外す口が無く（`auth.logout()` は「端末で `opencode auth logout` を実行してください」で失敗する）、押すと必ず失敗した。

- 能力の印 `logout` を足す（`core/backends/agent-marks.mjs`。Claude Code・Codex・Devin・Grok は `true`、OpenCode と Antigravity は `impossible`）。画面は名前でなくこの印で、［ログアウト］を出すか決める。`describeBackends` は、印と `auth.logout()` の両方があるときだけ `logout` を返す。
- 外せないエージェントのログイン中のカードは、［ログアウト］の代わりに「外すには、端末で次のコマンドを実行します」と、コマンドの 1 行（ログインの案内と同じ等幅 + ［コピー］）を出す。コマンドはバックエンドが `auth.logoutCommand()` で返す（`describeBackends` の `logoutCommand`。OpenCode はログインの案内と同じ書き方）。
- 変えないもの: Claude Code・Codex・Grok の［ログアウト］、Antigravity・Devin の頭の行。画面の形は `docs/design-system.md` の「外せないエージェントの CLI のログインのカード」。
- 「影響」の「能力の印は `accounts` と `compatEndpoints` の 2 つのまま」は接続先の印の話で、`logout` はそれとは別に足した印。
- 同じ日の続き: Antigravity は ADR 0366 で［接続先］の面を持ち、CLI のログインのカードに載った。印 `logout` が無いので上のとおり［ログアウト］は出ないが、`agy` には外すコマンドが無く `logoutCommand` も持たないので、カードに外し方が何も出ていなかった。外すコマンドが無い外せないエージェントは、カードの同じ場所に「外すには、{{agent}} の CLI 側でログアウトします（Pleiad からは外せません）」の 1 行だけを出す（名前は埋め込み、エージェントで分けない。コマンドを推測で作らないので、等幅の行と［コピー］は出さない）。上の「変えないもの」の Antigravity の頭の行は ADR 0366 で無くなり、残る頭の行は Devin だけ（外せるので［ログアウト］［状態を確認］のまま）。試験は `tests/browser/agent-conn-panel.mjs`。
