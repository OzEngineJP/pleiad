# 0334 系譜（枝の印）の読み込みは、本文を運ばず指紋と抜粋だけの概要にする

- 状態: 提案
- 日付: 2026-11-15
- 関連: [ADR 0182](0182-session-open-window.md)（会話を開く窓。系譜は窓の手前を概要で埋める）、[ADR 0179](0179-remote-throughput-and-list-size.md)（大きい返事は WS の外・gzip）。番号は並行する枝と重なりうる（仮）。

## 状況

会話を開くと、系譜（枝の印。`web/branches.mjs`）が家族のほかの枝を `loadSession { outline: true }` で 1 本ずつ読む。この返事は発言ごとに `{ uuid, role, text（全文）, tools, toolCalls: [{ name }] }` で、`bulk` を付けていなかった。ツールの入出力と提示は載せないので全文よりは軽いが、人と AI の本文はそのまま載るので、長い会話のある家族では大きい。実測では 2,417 発言で約 2.9 MiB、383 発言で約 800 KiB だった。中継越しでは、これが WS に 1 本のストリームで乗り、後ろの小さい返事を待たせる。

画面が outline の本文から読むものは、次の 3 つしかない。

1. **同じ発言か**（`commonPrefix`・`junctions`・`boundary`・分岐点 `k`）。Claude の fork は複製した発言に新しい uuid を振るので、uuid が合わなければ役割・本文・ツール名で比べる。比べる結果は真偽 1 つで、本文そのものは要らない。
2. **札の抜粋**（`distinguish`）。名前が兄弟とぶつかる枝にだけ、分岐後の最初の人の発言の先頭 200 字（`excerptOf`）を出す。
3. **窓の手前の埋め**（`withPrefix`）。窓だけを持つとき、手前を概要で埋めて通し番号を揃える。使うのは件数と、1 の比較だけ。

ほかに家族の写しの発言を読む所は、件数だけ（`client.mjs` の `branchIsFresh`・`placeJunctions`）。目次・地図は今の枝の窓（`state.messages`）から作り、概要は読まない。

## 決定

1. **`outline: { digest: true }` と頼まれたら、本文を運ばず、発言ごとに `{ uuid, role, fp }`（人の発言で本文があれば `ex` を足す）だけを返す。** `fp` は本文とツール名から数える 53 ビットの指紋（既存の `hash53`。`JSON.stringify([text, toolNames])` を数える）、`ex` は札の抜粋（`excerptOf` と同じ。1 行に畳んだ先頭 200 字）。`outline: true`（真偽）は今までの形（本文・ツール名つき）で返す。
2. **画面は `outline: { digest: true }` を `bulk: true` つきで頼む。**
3. **指紋・抜粋・比較は 1 つの関数にして、サーバーと画面が同じものを使う**（`web/outline.mjs`、`hash53` は `web/hash53.mjs`。`web/history-sync.mjs` が持っていたものを移した）。窓の全文の発言は、画面が同じ関数で指紋を数える（同じオブジェクトは 1 度だけ。`WeakMap`）。比較（`sameContent`）は、両方が全文なら今までどおり本文とツール名をそのまま比べ、どちらかが概要なら指紋で比べる。全文どうし・概要どうし・全文と概要のどの組み合わせでも結果は同じ。
4. **古い・新しいの組み合わせは、頼みの形だけで決める**（ADR 0182 の「能力を引数だけで決める」と同じ）。
   - 新しい画面 × 新しいサーバー: 概要（digest）。
   - 新しい画面 × 古いサーバー: 古いサーバーは `outline` を真偽として読み（オブジェクトも真）、今までの形で返す。画面の比較は全文の形も読めるので、結果は変わらない（軽くならないだけ）。`bulk` は ADR 0179 より前のサーバーでも未知の欄として無視される。
   - 古い画面 × 新しいサーバー: `outline: true` は `digest` を持たないので、今までの形のまま。
5. **返事の置き場は、概要でも `bulk` を使う。** outline は流れの出来事（ストリーム）と順序を合わせる必要がない読み出しで（`watch` に登録せず、画面は履歴ではなく系譜の写しにだけ使う）、読み直しの古さは `branches.load` が `revision` で捨てる。ADR 0182 が `bulk` を避けるのは、返事が出来事より後になると壊れる所（`syncHistory`・窓でない全量の読み）に限られ、ここは当たらない。

## 理由

- 画面の判定は「同じか」と「抜粋」の 2 つだけで、本文は要らない。指紋は同じ本文とツール名から同じ値になり、違うものが一致する確率は 2⁻⁵³ ほど（比べる対の数でも無視できる）。今までの全文比較との違いは、この確率だけ。
- 抜粋は「本文が空白だけでない人の発言」の先頭 200 字で、全文から数えるのと同じ関数で数える。条件（`text.trim()` が空でない）も `excerptOf` が空でないことと同じなので、`find` の結果も変わらない。
- 指紋を JSON の配列で数えるのは、本文とツール名の区切りで別の組が同じ文字列になる曖昧さを避けるため。
- `ex` はサーバーが人の発言ぜんぶに付ける。どの枝がどこで分かれるかをサーバーは知らず、札で使う発言は、分岐の後の最初の人の発言で、呼び出しごとに違うため。200 字までなので全文よりずっと小さい。
- 古い形を残したのは、古い画面（古いバージョンのアプリ・殻）が `outline: true` を使い続けるため。サーバーに能力の印を足さないのは、頼みの形で決まる方が古い側にも新しい側にも安全なため（ADR 0182 と同じ判断）。

採らなかった案:

- **`outline: "digest"` のような文字列にする**: 古いサーバーも真と読むので動くが、`{ digest: true }` の方が将来の欄（例: 抜粋の長さ）を足しやすい。
- **本文の先頭の抜粋だけにして、比較は先頭 N 字で行う**: 先頭が同じで途中から違う発言を見分けられず、分岐点がずれる。
- **サーバーが分岐点まで計算して返す**: 画面は窓の全文と今の枝の最新の履歴（送信直後）を持つので、画面の側で比べる方が古さの問題が出ない。サーバーが家族の全部の組を比べると、読み出しが重くなる。

## 影響

- **測った値**（2026-11-15。手元の大きい会話 8 本の写し。サーバーの outline と同じ写し方で、返事の JSON の文字数と gzip 後。ネットワークは通さずプロセス内）:
  - 5,789 発言（42.1 MiB の会話）: 5,353 KiB → 1,044 KiB（1/5.1）、gzip 2,424 KiB → 283 KiB。
  - 4,932 発言: 4,253 KiB → 840 KiB、gzip 2,220 KiB → 269 KiB。
  - 3,209 発言: 2,450 KiB → 531 KiB、gzip 1,195 KiB → 175 KiB。
  - 8 本の合計（15,402 発言）: 13,340 KiB → 2,661 KiB、gzip 6,357 KiB → 792 KiB（1/8.0）。
  - 概要の大きさは発言 1 件あたり約 180 バイトで、本文の長さによらない（uuid・指紋・人の発言の抜粋が占める）。ここで使った会話（Pleiad の `conversations/*.json`）は、本文よりツールの入出力が大きい（outline には元から載らない）。人と AI の本文が長い会話ほど、削れる割合は大きい。
  - サーバーの CPU 時間（概要を作って JSON にするまで）は、5,789 発言で 27 ms → 75 ms。全文を 1 度ずつ数えるためで、返事を WS で運ぶ時間よりずっと小さい。
- 窓の全文の発言の指紋は、画面で 1 度ずつ数える（窓の分だけ）。
- 同じ内容の発言の指紋は、サーバーと画面で同じ関数・同じ正規化（本文と、`toolCalls` の名前 → `tools` の順のツール名）で数えるので一致する。この対応が崩れると分岐点がずれる。`tests/unit/server-fork.mjs` が、実際の `loadSession` の概要の `fp` を、画面が全文の窓から数える値と突き合わせる。
- テスト: `tests/unit/outline-digest.mjs`（全文・概要・混在の `commonPrefix`、家族の読み込みで分岐点・境・札の抜粋・窓の手前の埋めが全文のときと同じ、新旧のサーバー、`bulk` の配線）、`tests/unit/server-fork.mjs`（実サーバーで概要の形と、`outline: true` が今までの形のままであること）、`tests/unit/branches.mjs`（頼みの形）。
- 仕様の今の形は `docs/design.md`（系譜の読み込み）と `docs/design-system.md` §7「分岐」の「系譜と更新」。
