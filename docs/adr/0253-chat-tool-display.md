# 0253 ツールの初期タブと端末表示を統一する

- 状態: 承認（2026-10-22）

## 状況

ツールの主面が空でも結果タブが選ばれ、結果の到着が閲覧中のタブを切り替えていた。バックグラウンドのコマンドはコマンドと出力が別の薄い面で、ツール行の端末表示と異なっていた。共有の作業ツリーの変化が、委譲した子だけの変更に見える問題もあった。

## 決定

- 行と「ツール実行 N」は閉じたまま始める。最初のタブは実データで決め、出力・差分・本文・画像・委譲の内訳があれば主面、未着・空なら入力とする。明示的な検索 0 件は結果として扱う。入力に差分や本文がある編集・書き込みは主面、パスしか無い開始時は入力。計画確認は成功後も入力、失敗時はエラーを主面に置く。
- 未閲覧の行だけ到着した結果に応じて既定タブを更新する。一度開いた行と人が選んだタブは保持する。タブのない TODO・専用の質問・承認・visualize の成果物は従来のまま扱う。
- シェルのツール行と子・背景パネルのコマンド詳細は、明暗共通の暗い端末面にする。プロンプト・コマンド・出力・実行中のカーソル・判明した終了コードを等幅で並べる。最大 340px のスクロールとし、末尾の 30px 以内を見ている場合だけ新着へ追従する。動きを減らす設定ではカーソルを点滅させない。
- 出力を取得できない先はコマンドと状態、「出力の取得に対応していません」の 1 行を表示する。ply_shell のジョブはサーバーが提供する出力取得・停止の能力を画面にも伝える。Claude SDK の子の出力取得は変更しない。
- 委譲カードの「変更」は worktree を使う子だけに表示する。

## 理由

ユーザーが承認した UI の推奨案に従い、最初に読める内容を示しながら、閲覧中の選択と位置を保つ。同じコマンドの出力に同じ部品を使う。共有の作業ツリーの変化を 1 人の子へ帰属させない。

## 影響

ツール行と背景の詳細が端末部品を共有する。バックグラウンドの能力情報で既存の出力取得・停止を画面へ伝える。実データのある場合の初期タブ、端末の更新とスクロール、共有・worktree の子を試験で確認する。
