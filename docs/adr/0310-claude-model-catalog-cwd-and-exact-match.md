# 0310 Claude のモデル一覧は作業場所ごとに引き、短い一覧で完全な一覧を上書きせず、一覧に無い名前は系統名へ縮めない

## 状態

承認（2026-11-28）。実機の調査と試験付き。0309（モデルの確かめは選ぶときに一本化し、送信直前には見ない）の続編として、一覧そのものの取り方と「当て方」を直す。

## 状況

Claude Code の `supportedModels()` が返すモデル一覧は、問い合わせる**作業場所（cwd）で変わる**。2.1.322 の実測:

- cwd 無し: 5 行（`default`・`opus`・`sonnet`・`haiku`・`claude-fable-5-1[1m]`）。系統の別名の行 `fable` が無く、Fable は `claude-fable-5-1` まで
- プロジェクトの cwd あり: 14 行（`fable` → `claude-fable-5-2`、`claude-fable-5-1`、Opus 5.5・4.x・Sonnet・Haiku の版つき行）

この違いから 3 つの不具合があった:

1. **選択欄が間違った一覧を出す。** 画面のモデル一覧の要求（`agents.models`）は cwd を渡していなかったので、プロジェクトで Fable 5.2 が選べるのに選択欄には無く、あっても `fable` の行は 5.1 の名前で出た。server 側・op のスキーマは最初から `cwd` を受け取るのに、画面が付けていなかった
2. **短い一覧が完全な一覧を上書きする。** `loadCatalog` は cwd ごとの一覧と「どれか 1 件取れた一覧」（`anyCatalog`）を覚えるが、どちらも最後に取れたもので無条件に置き換わる。途中で短い一覧が返ると、取れていた完全な一覧の版つきの行が消える
3. **一覧に無い名前を系統名へ縮めていた。** `matchClaudeModel`（`backend.matchModel`）は、正式な ID がどの行にも当たらないとき系統の行へ落としていた（`claude-fable-5-2` → `fable`）。別名の指す版は CLI が決めるので、頼んだ版と別の版で黙って走る。同じ系統の行から版つきの名前を借りて、一覧に無い `fable` の隠しの行が「Fable 5.1」と出ることもあった（実際は CLI の決める版で走る）

あわせて確認した事実:

- 送信の経路（`sendModel`）は 0309 どおり形だけを見てそのまま渡すので変更不要。当たらない名前をそのまま送れば、CLI/API が理由を付けて断る
- 保存の経路（`store.setModel`・`nextSettings`）は選んだ値をそのまま書くので変更不要（実際の ID への置き換えはどこにも無い）
- 0309 の `canonicalModel` は「一覧の id か `matchModel` で当たる→その id、外れる→渡された名前のまま」なので、当て方（`matchModel`）を狭めればそのまま通る

## 決定

- **モデル一覧の要求に、その選択が効く作業場所を付ける。** 会話の選択欄は `vocabCwd`（予約の場所 → 会話の場所 → 下書きの場所、Chats で bot を選んでいるときは bot の最初のフォルダー、作ったばかりの会話は予約が届くまで下書きの場所）を付け、取得の鍵（`vocabKey`）にも場所を入れる。エフォートの段と同じ場所にそろえる（段は最初から場所を付けていた）。bot の設定画面は bot の最初のフォルダー（実際に bot が走る場所。`core/bots/sessions.mjs` の `pickCwd`・`checkModelEffort` と同じ）とアカウントで引く
- **短い一覧は完全な一覧を上書きしない。** 系統の行があるのにその系統名の別名の行が無い一覧を「短い一覧」とみなす（`catalogIsComplete`。2.1.322 の実測の形）。手元に完全な一覧があるところへ短い一覧が届いたら、それを取り置かず、失敗と同じ間隔で取り直す。どの条件でも最後に取れた完全な一覧だけを `anyCatalog`（別の条件の一覧で先に答える手元の答え）に持たせる。完全な一覧を一度も取れていなければ、短い一覧も使う（無いよりは出す）
- **名前の当て方は正確な一致だけにする。** `matchModel`・`matchClaudeModel`・`canonicalModel` が当てるのは、一覧の id（大文字小文字は問わない）と行の `resolvedModel` の一致だけ。`[1m]` を剥がして同じ系統の 1M の行へ寄せる特別な読みも外す。当たらない名前はそのまま返し、確かめ（`validModel`）・断り（`model_unknown`）は選ぶときの経路が今までどおり担う
- **隠しの別名（保存済みの `fable` / `opus` / `sonnet` / `haiku` を無効にしないための、一覧に出さない行）の名前は版を付けず系統名だけにする。** 同じ系統の別の版の行から版つきの名前を借りない（「Fable 5.1」は実際に別名が指す版と違いうる）。段と説明は同じ系統の行から借りる。一覧にその系統の別名の行があるときは、その行がその版の名前で出る（`fable` → 「Fable 5.2」）

変えないもの:

- 既定（`''`）の `resolvesTo` は今までどおり、利用者の設定のモデル → SDK の既定の行の順で当てる（当て方は同じく正確な一致だけ）
- 互換の接続先の会話は形だけを見る従来どおり
- 隠しの別名は引き続き有効（`fable` で保存した会話は `fable` のまま送れる）

## 根拠

- **系統名へ縮めると黙って別の版で走る。** `'claude-fable-5-2' → 'fable'` の読み替えは一見便利だが、`'fable'` がどの版を指すかは CLI の版・設定で変わる。名前を黙って変えないのが 0309 の「黙った差し替えをしない」に沿う。使えなければ CLI/API が理由を付けて断るので、選び直せる
- **「確かめは選ぶとき」はそのまま。** 当たらない名前も渡された名前のまま `validModel`（一覧 → 取り直し → backend の最後の判断）で確かめ、無ければ `model_unknown` など選ぶときの断りになる。`ply_delegate` に無い名前を書いても、子は既定のモデルでは作られない
- **短い一覧の見分け方は別名の行の有無。** 行数（「N 行以下」）や版の数え上げだと、CLI の版アップで行が増減するたびに誤判定する。系統の別名の行が欠ける形は、その一覧が系統の行を持つのに別名が無い（= 別名を選ぶと CLI の決める版で走る）という実害と一致する
- **隠しの別名に版つきの名前を付けると、実際と違う版で走るように見える。** 別名は「CLI が決める版」を意味するので、名付けられるのは系統名だけ

## 影響

- 画面: `web/client.mjs`（一覧の頼み方・取得の鍵に cwd）・`web/composer-vocab.mjs`（`modelsRequest`・`vocabKey` に cwd）・`web/channels/bot-page.mjs`（bot のフォルダー・アカウント）・`web/channels/thread-composer.mjs`（スレッドの bot の場所）。表示だけの一覧（委譲カード・委譲の設定）は、そのタスクの場所・今の場所で引く
- core: `core/backends/claude-models.mjs`（`match` の系統名への推し量りを外す・隠しの別名の名前・`catalogIsComplete`）・`core/backends/claude.mjs`（`loadCatalog` が短い一覧を拒否して取り直す）
- 文面: `ply_delegate` の説明（ja/en）・`docs/agent-delegation.md`（「正式な ID も同じ系統の行に当てる」を消し、「正確に一致する行だけ。当たらなければ縮めない」へ）
- 試験: `claude-model-match.mjs`（当て方の表）・`claude-catalog-stale.mjs`（短い一覧で上書きしない）・`composer-vocab.mjs`（頼み方に cwd）を更新
