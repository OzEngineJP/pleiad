# 0364 スレッドの bot の返事は、保存は今のままにして、開いているスレッドの画面にだけ書きかけを流す

- 状態: 承認（2026-11-26。モックの節 06「スレッドの bot の返事を、書いたそばから流す」の ToBe の承認による）
- 改める: [0109](0109-bot-and-dispatch.md)（「スレッドには生の流れを流さない」。保存と配る投稿の畳み方は変えず、開いているスレッドの画面にだけ書きかけを足す）、[0024](0024-watch-open-session-stream.md)・[0315](0315-two-watch-slots-modal-right-pane.md)（接続が見る会話の口に 3 つ目 `thread` を足す。`turnEnd` は全部送る・宣言しない接続には全部送る、は変えない）
- 根拠: モック `temporary/mockups/bot-settings-memory-skill.html` の節 06 と、レポート `bot-settings-memory-skill-report.md` の 4 章 6

## 状況

bot の返事は、サーバーが 1 秒に 1 回・文の切れ目・40 字以上の条件で投稿に畳み、`channelPost` で配っていた（ADR 0109）。条件を満たすまで本文は `…` のままで、長い文を書いている間は、数秒から数十秒、何も増えないように見える。同じ会話を Chats で開けば `text.delta` の流れが見えるのに、スレッドでは見えない。

ADR 0109 が生の流れを流さないとしたのは、画面の購読が 1 接続 1 会話（ADR 0024）で、複数の bot の流れをスレッドへ送る道が無かったため。ADR 0315 で購読の口が 2 つ（`main`・`modal`）になり、口を足す形ができた。残る懸念は 2 つ。(1) 断片が 1 秒おきの更新で一瞬見える（保存する本文の話。画面だけの流しなら保存の条件は要らない）。(2) 全接続に配ると中継のスマホの通信が増える（ADR 0024 の動機）。

## 決定

- **保存は変えない。** `channelPost` の進捗は今までどおり 1 秒に 1 回・文の切れ目まで・40 字以上、最終の本文の組み立て（道具の前後の文を順に空行でつなぐ・`postText` の上限）も同じ。流しは「保存より先に画面へ見せる写し」で、投稿・記録・通知には入らない。
- **接続の見る会話に 3 つ目の口 `thread` を足す。** `watchSession { slot: 'thread', channelId, threadId }` で、スレッドの画面が開いているスレッドを宣言する（会話の id ではない）。サーバーは、そのスレッドに書いている bot の会話（`botHost.threadOfSession`）の `text.delta`・`text.end`・`tool.start` だけを、この口の接続へ足して送る（`core/server.mjs` の `wanted`）。道具の結果・思考・稼働などは足さない。ids を省く（または片方だけ）と口を外し、`"ok"` を返す。
- **宣言した接続だけが増える。** `thread` の口を持つのは、スレッドを開いている接続（画面）だけ。ほかの接続（別のスレッドを開いた画面・main しか宣言しない中継のスマホ・宣言しない古い画面やテスト）への配信は増えも減りもしない。`main` を宣言した接続が絞られる規則（ADR 0024）は変えない。1 つの接続の `thread` の口は 1 つで、別のスレッドを開けば替わり、閉じれば外す。
- **口を宣言した時点の書きかけを、返事に載せる。** 開いた時にすでに書き始めていた分が欠けないよう、`watchSession` の返事に `threadStream: [{ sessionId, events }]` を付ける。材料は会話の流れの記録（`runtime.turns.get(sessionId).stream.events`）で、口を置くのと同じ同期の中で切る（`core/bots/thread-stream.mjs` の `threadStreamSnapshot`。続く `text.delta` は結合し、`streamSeq` は最後のものを残す）。以降の出来事は同じ `streamSeq` の続きで届くので、画面は `streamSeq` が既出のものを捨てて重ならない。
- **秘密情報の伏せ（ADR 0217）はそのまま効く。** 出来事は `emitGlobal` の `secretStream`（文をまたぐ値の保留）→ `emitOne`（記録へ入れる）→ `sendTo`（送る直前の全文の伏せ）を今までと同じ道で通る。送りの口を足しただけで、伏せる場所を迂回する道は作らない。返事の写しは、記録から取り出した伏せ済みの出来事を `sendTo` でもう一度伏せて送る。
- **画面は、確定前の分を投稿の本文の下に出す**（`web/channels/stream-model.mjs`・`web/channels/thread-stream.mjs`）。
  - 出来事は会話ごとに貯めるだけにし、描くのは 1 コマに 1 回（`web/live-turn.mjs` の `appendText` と同じ。`requestAnimationFrame` でまとめる）。
  - 出すのは書きかけの全体から、保存された投稿の本文を先頭から外した残り（確定前の分）。`channelPost` で本文が伸びれば、その分は本文に吸収されて残りが縮む。本文が書き出される前（`…`）は書きかけの全体が出る。
  - 黙る印 `[[no-reply]]`（ADR 0119）は書きかけの段階でも出さない（`core/bots/silence.mjs` の `stripSilentMark` と同じ規則の写し。試験で突き合わせる）。
  - 届いた分は 120ms（`--dur-fast`・`--ease-out`）で浮かび上がる。`prefers-reduced-motion` では動かさず、出すだけ。読み上げは保存された本文だけ（流れの途中の文字は `aria-hidden`）。
  - ターンが終わったあとも、最後の本文（`channelPost`）が届くか 4 秒たつまでは書きかけを残し、本文が一瞬縮んで見えるのを避ける。
  - スレッドを閉じる・別のスレッドを開く・タブが非表示の脇に変わるときは口を外す。再接続したら宣言し直し、返事の写しで取り直す。
- **ADR 0109 の「独り言を引っ込める」を、保存する本文の話に限る。** 1 秒おきの保存に断片が出るのを避ける理由は、そのまま残る。画面の流しは保存と別の経路なので、道具の前の文も含めて書いたそばから出る。

## 理由

- 待つ間に何も増えないのが、スレッドで bot と話すときのいちばん大きな不安だった（Chats では見えているので差が目立つ）。保存の条件を緩めると、断片が投稿に書かれて全接続・通知・記録へ配られる。流しを保存と分ければ、保存の意味と配信の量を変えずに、見える所だけ変えられる。
- 流しの宛先を、スレッドを開いている接続の口に限ったのは、ADR 0024 が解いた問題（全会話の文字の流れが全端末へ届く）を戻さないため。口の判定は既にある `wanted` の中に足すだけで、`sendTo` の経路（伏せ・全接続への巡回・中継）は 1 本のまま。
- 返事の写しを `watchSession` に載せるのは、画面を開くのと書き始めが前後しても、書きかけが欠けないため。既にある流れの記録を使うので、新しい保存先・表は作らない。
- 採らなかった案: 保存の間隔を縮める（全接続に `channelPost` が増え、スマホの通信が増える）、全接続に流す（ADR 0024 の問題の再発）、`main` の会話を bot の会話に替える（スレッドを開くたびに主の会話が止まる）、書きかけを投稿の本文へ直に書く（保存・通知・記録が断片を持つ）。

## 影響

- 画面の遅延: 書きかけは `text.delta` の到着から 1 コマ内に出る。保存された本文はこれまでどおり 1 秒おき。
- 使う側の約束: スレッドの画面を足すときは、開いたら `watchSession { slot: 'thread', ... }` を送り、閉じたら外す。`wanted` を変えるときは、`thread` の口の会話も許可の範囲に入る。
- 試験: `tests/unit/server-thread-stream.mjs`（宣言した接続だけに届く・ほかの接続と中継のスマホは増えない・伏せが効く・写しと続きの `streamSeq`・外す・別のスレッドへ替える）、`tests/unit/thread-stream-model.mjs`（書きかけの組み立て・本文との突き合わせ・沈黙の印の写し・DOM の動き）。
- 既知の限り: 保存する本文が上限（`postText`）で切られたときは、書きかけが本文と先頭から合わなくなり、確定前の分は出さない。確定前の分は、本文に吸収されるまで素の文字（Markdown は描かない）。
- 保存の形・表・形式番号は変えていない。古い版の画面は `thread` の口を宣言しないので、今までどおり。古い版のサーバーは `slot` が `modal` 以外を `main` と読み、`sessionId` が無いので、新しい画面を古いサーバーにつなぐと、その接続の `main` の宣言が外れて全部届く状態（宣言前と同じ）に戻る。返事に `threadStream` が無いので流しは出ず、投稿は今までどおり保存のたびに更新される。次に会話を開けば `main` はまた宣言される。
