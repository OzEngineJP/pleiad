# 0323 設定 › アプリ情報・更新を、版と更新だけのページにし、リリースノートを 1 種類の行にする

- 状態: 承認（2026-11-13。main に入れる直前に番号を確定）
- 承認の内容: プロダクトオーナーが、モックの形（temporary/mockups/settings-about-update.html）を承認した。

## 状況

「アプリ情報・更新」には、版・更新の操作・更新の設定（チェックボックス）・常駐・「外の AI から Pleiad を使う」・リリースノートが 1 つのページに並んでいた。
- 主な操作（確認・ダウンロード・再起動）が、状態の文と離れていた。
- 更新したあとに見えるリリースノートは今の版 1 つで、何版か飛ばして更新した人は、途中の版で何が変わったか読めなかった。
- 常駐（アプリ全体の動き方）と「外の AI から使う」（外部 MCP の向き）は、版と更新の話ではない。

## 決定

- ページは版と更新だけにする。常駐は新しいページ「全般」（メニューの先頭。使えないデスクトップ版以外ではメニューごと出さない）、「外の AI から Pleiad を使う」は設定 › プラグインの外部 MCP の下へ移す。
- 上の枠は、版・状態の 1 行・主ボタン 1 つ（更新を確認 → ダウンロード → 再起動して更新）。再起動の確認は同じ場所で文とボタンを入れ替える。更新の設定はスイッチの行にする。
- リリースノートは 1 つの節に同じ形の行だけを並べる（版 · 日付 / 題。押して開く）。更新が見つかった間は「新しいバージョン」、更新したあとは「今回の更新」を先頭に置き、次の更新まで残す。6 版までは全部、超えたら 5 版 +「ほか N バージョンを表示」、古い版は 10 版ずつ。
- 途中の版のノートは、確認のたびに GitHub の Releases の一覧から作る（先行版も含める）。前に入っていた版を `updates.json` の `previousVersion` に残して、「今回の更新」の範囲を決める。

## 理由

- 1 つのページに 1 つの話題だけを置くと、主な操作と状態が近くなる。
- 途中の版の変更は、同じ形の行で並べれば、どの版で変わったかが分かる（版ごとの項目を 1 つに合算しない）。
- 一覧はすでに更新の確認で GitHub へ問い合わせており、1 回の読みで間の版を作れる。同梱のノートは入っている版以前だけを持つので、新しい版は配布元から取るしかない。
