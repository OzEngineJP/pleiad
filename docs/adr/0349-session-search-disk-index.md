# 0349 セッション検索の本文を、メモリの写しの走査からディスクの索引（SQLite FTS5・2 字ずつの語）で引く

- 状態: 提案
- 置き換えた: [ADR 0080](0080-session-fulltext-search.md) の「索引は作らず、本文の写しをメモリに持って都度走査する」と、Issue #225 の写しの予算。照合・関連度・抜粋・絞り込み・入力・返す形は 0080 のまま
- 関係: [ADR 0115](0115-records-in-sqlite.md)（データ置き場の node:sqlite）

## 状況

- 0080 は 812 件で +96MB と測って写しを持つ形を選び、FTS5 は node:sqlite の版依存と、trigram が 3 字未満の語（「翻訳」「CI」）を引けないことで退けた。会話が増えれば写しも比例すると書いたが、上限は設けなかった。
- 2026-11-24 のこの PC は会話 6,162 件（ネイティブの履歴 2.9GB）、写す発言 18.4 万、本文 8,860 万字（非 ASCII 46%・最大の会話 178 万字）、ツールの入力の短い項目 9,230 万字。全部を写すと見積もり約 720MB になる。
- 0.43.0-beta.15（#225）は写しに 256MB の予算を設け、超えた古い会話を題・状態・場所だけで当たる形にして落ちるのを止めた。古い会話を本文で探せない、機能を削った暫定の対処。
- データ置き場はもう node:sqlite（`pleiad.db`）を使っている。FTS5 は Node 22.16.0 以上の node:sqlite にある（22.13.0・22.15.0 は `no such module: fts5`、22.16.0・24.22.1・Electron 44 の Node 24.22.0 は使える。2026-11-24 に確かめた）。リポジトリの Node の下限は 22.13.0。

## 決定

- **索引はデータ置き場の別のファイル `search-index.db`。** 記録ではなく会話の履歴から作り直せる写しなので、`pleiad.db` には入れない。表は 3 つ。
  - `conv(id, sig)`: 会話ごとの読み始めた時刻（今の写しの sig と同じ意味）。
  - `msg(rowid, conv, idx, uuid, role, at, text, tool)`: 今の `extractMessages` と同じ対象の発言と、入力欄の ↑ に使う `!` のコマンド（role `shell`。索引の語には入れない）。
  - `fts`: FTS5（`content=''`・`contentless_delete=1`・`tokenize='ascii'`）の 2 列（本文・ツールの入力）。rowid は `msg` と同じ。
- **語の切り方（2 字ずつ）。** 今と同じ NFKC と小文字に畳み、字（`\p{L}\p{N}\p{M}`）の連なりごとに、各字を頭に「その字と次の字」（連なりの最後は 1 字）を空白区切りで入れる。記号と空白は区切りで、語には入れない。
- **引き方。** 語ごとに候補の発言を引く。1 字は前方一致（`"猫"*`）、2 字以上は 2 字の並びのフレーズ。字だけの語はフレーズの一致がそのまま部分一致なので確かめない。記号を含む語と "…" の語は、字の連なりごとの候補の AND で絞り、本文（"…" は畳まない本文、ほかは畳んだ本文）の部分一致で確かめる。字の無い語（記号だけ）は全部の発言を確かめる。
- **照合から先は今の関数のまま。** 候補の発言のある会話について、候補の発言を `matchSession` に渡す。題・状態・場所は一覧の行で今と同じに当てる。AND・場所はフォルダー名・関連度・抜粋と ranges・sessionIds などの絞り込み・includeToolInputs・speaker・hits・カーソルは変えない。新しい語の書き方・設定・画面は足さない。
- **outline と sentMessages は `msg` から引く。** outline は最初の人の発言・数・最後の時刻、sentMessages は role user と shell を今と同じ順に返す。
- **作り始め。** 起動の後、今の `start` と同じく一覧を新しい順に裏で読み、会話ごとに 1 つのトランザクションで入れ、会話の間でイベントループへ返す。入っていない会話がある間は今と同じく `partial: true`（その会話は題・状態・場所で当たる）。
- **更新。** 入口は今と同じ（loadSession の `ingest`、ターンの終わりの `refresh`、一覧の lastModified が sig より新しい会話の読み直し）。入れ直すときは、入っている発言と idx・uuid・本文が同じ先頭は残し、最初に違う発言から後ろだけ消して入れる（ネイティブの履歴は末尾に足されるので、ふつうは足した発言だけ書く）。会話の削除（`deleteSessionOf`）と、一覧から 3 回続けて消えた会話は行を消す。
- **形式と作り直し。** `search-index.db` の `user_version` を索引の形式番号にする。`data-schema.json` と `pleiad.db` の DB_VERSION は上げない。開けない・番号が違う・引いて壊れていた（`SQLITE_CORRUPT`・`SQLITE_NOTADB`）ときは、ファイル（`-wal`・`-shm` も）を消して空から作り直す。移行も控えも作らない。古い版はこのファイルを読まず、古い版で動いた後に戻ったときは sig より新しい会話の読み直しで追いつく。
- **消すもの。** 写しの Map と写しの予算（`budgetBytes`・`copySize`・`skipped` と、それに合わせた partial の例外）。

## 理由

架空のデータ（実データの会話の長さの分布・非 ASCII の割合に寄せた 6,162 件・9,160 万字・15 万発言。ツールの入力は入れていない）で、Windows 11・Node 24.22.1 で測った。12 の語のうち、2 字の語・1 字の語・日本語・全角・"…" を含む。4 つの方式で当たった会話と発言の数は全部同じだった。

- **今の走査:** 1 語 22–66ms。写しはヒープ +181MB（実データの見積もりは約 720MB）。10 倍では数 GB になり持てない。
- **FTS5 trigram ＋ 3 字未満は本文を instr:** 作る 84 秒・781MB。3 字以上は 0–6ms だが、「翻訳」566ms・「CI」534ms・「猫」446ms・「翻訳 ci」989ms。3 字未満は全部の本文を見るので会話の数に比例し、10 倍で 5 秒前後になる。本文の表に LIKE だけで引く形も、この 3 字未満の引き方と同じ速さになる。引き方も 2 つに分かれる。
- **自前の 2 字の表（FTS5 を使わない）:** 1,540 件で作る 352 秒・215MB、「CI」286ms・「の」510ms、一番長い会話の入れ直し 10.4 秒。遅い。
- **選んだ 2 字ずつの FTS5:** 作る 60 秒・437MB（発言の表 206MB・索引 227MB）・開く 0.4 秒。「翻訳」1ms・「CI」68ms・「猫」0ms・「ゲートウェイ」1ms・「"worktree remove"」13ms・「ｇａｔｅｗａｙ」1ms・「翻訳 ci」40ms・「している」69ms・1 か所しかない語 9ms。遅いのはほぼ全部の発言（12.5 万）に当たる 1 字の「の」368ms だけ。ヒープは増えない。一番長い会話（1,339 発言・84 万字）の全部の入れ直し 1.5 秒、1 発言の足し 18ms。
- 1 つの引き方で 1 字・2 字・日本語・英字・記号入りの語を今と同じ結果で返せる、いちばん小さい形が 2 字ずつだった。trigram は 3 字未満に別の引き方と全部の走査が要る。
- 別のファイルにするのは、形式の移行と `scripts/copy-data-dir.mjs` が `pleiad.db` 全体を `VACUUM INTO` で写すため。索引を入れると毎回 GB 級を写す。作り直せる写しなら、壊れたときも番号が違うときも消すだけで済む。

## 影響

- Node の下限を 22.13.0 から 22.16.0 に上げる（`package.json` の engines、CI の必須ジョブ名 `test (…, 22.13)`、`evaluation-release.yml`、README・AGENTS.md・docs/desktop-onboarding.md・ADR 0115 の下限の記述）。デスクトップ版は Electron の Node 24 なので変わらない。FTS5 の無い Node へ今の走査で戻る道は作らない。
- ディスクは本文の字数にほぼ比例する（1,540 件 116MB → 6,162 件 437MB）。実データはツールの入力が加わるので約 0.9GB、10 倍で約 9GB と見積もる（ツールの入力の分は測っていない）。上限は設けない。作り始めは実データで 2 分前後、10 倍で 20 分前後（裏で、最初の 1 回だけ）。
- メモリは写しを持たず、SQLite のページキャッシュだけになる。
- node:sqlite は同期で、書いている間はサーバーが止まる。会話ごとに分け末尾だけ書くので、ふつうは数 ms〜数十 ms、長い会話を初めて入れるときは 1 秒を超える。
- `tests/data-writes-allowlist.mjs` に `search-index.db` を足す。`scripts/copy-data-dir.mjs` は写さない（写した先で作り直す）。docs/design.md「セッション検索」と docs/desktop-releases.md「適用とデータ保護」に索引のファイルを書く。今の照合の tests は、同じ結果を返すことを確かめる形で残す。
- 承認されたら 0080 の状態を「置換（0349）」にし、`- 置き換えられた: 0349` を足す。
