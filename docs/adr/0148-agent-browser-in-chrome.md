# 0148 エージェントのブラウザー操作を PC の Chrome の専用の窓に移し、内蔵ブラウザーは見るだけのビューアにする

- 状態: 承認（2026-10-06）。状態 C の「約 5 分で打ち切られた」・B で前に出す頻度・対応する OS・サイトの利用の確認のカードの「ログイン済み」の行は置換（0153）。専用の窓の最小化・focus emulation を常に付けること・自動の一時停止は置換（0154）。Chrome への接続の置き場は 0167、操作待ちのカードは 0168（計画の detached の待ちを outlivesTurn にした）。第 11 段まで実装済み（2026-10-09。第 9 段: 引き継いだ Chrome の窓の上端のピル、第 10 段: Chrome のプロフィール、第 11 段: 委譲した子の Chrome の窓を親の会話から扱う）。映像・止める／引き継ぐ／戻す・Chrome だけへの切り替え・操作待ちのカード・hand_to_user・区切って返す待ちと「続けてください」・端末からの操作・browser.chromeOpen・窓を閉じる操作（閉じた窓の静止画は `uploads/chrome-window/`）を実装した。outlivesTurn はターン終了後もカードを残し、detached と違って承認待ちに数えるために使う（0168）。頭の行の入口は 1 つのブラウザーボタンにまとめた（2026-10-09）。一部置換（0291・0293・0294）: 右のパネルは見るだけの映像ではなく操作できる会話の Chrome のウィンドウになり、内蔵ブラウザーのビューア（第 7 段で残したもの）はやめる（0291）。「引き継ぐ」と窓ごとの一時停止、「戻すのは人だけで時間では戻さない」は、人が触ったタブを人の操作にし 60 秒で AI に戻す形に替える（0293）。映像の画質の選び方は 0294
- 状態の追記（2026-10-09）: 第 11 段まで実装済み。窓の数は承認済みの入口統合に合わせて「Claude の Chrome」のタブの札に、一覧は ⋯ のメニューに置く（入口への数の表示は用いない）。

## 状況

エージェントのブラウザー操作は、内蔵ブラウザー（Electron の `WebContentsView`。[ADR 0041](0041-inapp-browser-beside-conversation.md)）を会話ごとの CDP 中継（[ADR 0043](0043-agent-browser-via-per-session-cdp-relay.md)）で操作する形だった。人もエージェントも同じタブを触り、ログインの保存領域は Pleiad の中（`persist:pleiad-browser`、[ADR 0078](0078-inapp-browser-profiles.md) のプロフィール）にある。

- エージェントが使えるログインは Pleiad の保存領域のものだけで、普段の Chrome でログイン済みでも入り直す。そのログインにはパスワード管理・パスキー・拡張が無い。
- 「引き継ぐ」は中継の接続を閉じるだけで、エージェントのターンは止まらず、同じ鍵ですぐ再接続できる。引き継いだことも戻したことも、エージェントには伝わらない。
- エージェントがログイン・CAPTCHA・2 段階認証で詰まったときに、人へ頼む口が無い（文で頼んでターンを終えるしかない）。
- ADR 0078 のプロフィールは、この PC ではメイン以外が作られておらず、使われていない。使っているのはユーザー本人だけ。

ユーザーの依頼（2026-10-06）は、エージェントのブラウザー操作を PC の本物の Chrome に寄せること。調べと試作で分かっていること（`Chrome 154`。実機で確かめたもの）:

- `chrome://inspect/#remote-debugging` をオンにすると、`/json/version` は無いが `DevToolsActivePort` に書かれた動的ポートへ WebSocket で直接つなげる（agent-browser 0.38 の `--auto-connect` が同じ用途）。
- 許可のダイアログは接続 1 本ごと（切ってつなぎ直すと再び出る。許可も拒否も記憶されない）。約 5 分で打ち切られ、ダイアログの窓は残る。Pleiad が前面だと Chrome の窓の背後に出ることがあり、`AttachThreadInput` 方式の `SetForegroundWindow` で前に出せる。`WM_CLOSE` で閉じられ、閉じると接続は即座に失敗する。
- `chrome.exe` に `chrome://inspect/#remote-debugging` を渡しても開かない（新しいタブになる）。
- 「自動テスト ソフトウェアによって制御されています」の帯は、トグルをオンにしただけでは出ない（Chrome をすべて閉じて開き直すと、トグルがオンのままでも出なかった）。その Chrome の起動中にエージェントがつないだことがあると、Chrome を起動し直すまで窓に出ることがある。
- Chrome 全体が 1 つのブラウザーとして見え、全プロフィール・全窓のタブと、`Storage.*`・`Network.getAllCookies` が、つないだ側に見える。agent-browser の `tab list` はプロフィールを区別しない。直接つなぐと、中継を前提にした「止める」「引き継ぐ」・サイトの利用の確認・画面の転送が効かない。
- `Target.createTarget`（`newWindow`・`background`）は前面を奪わないが、プロフィールを選べない（最後に前面だったプロフィールに作る）。`chrome.exe --profile-directory --new-window` はプロフィールを選べるが、10 回中 9 回前面を奪う（約 0.2 秒。題の nonce で HWND を見つけ、すぐ `SW_MINIMIZE` で戻せる。前面を取らない起動の方法は無かった）。
- `window.open` のタブは同じ窓に入る（`popup` 指定は別の窓）。`newWindow` ごとに別の windowId・HWND。
- 最小化・覆われた窓の `Page.startScreencast` は `Emulation.setFocusEmulationEnabled(true)` が必須（付けると約 29 fps、付けないと 0〜1 フレーム）。
- CDP の `Input.dispatch*` は `GetLastInputInfo` を進めない。窓の題の nonce で HWND を対応づけられる。`Browser.getWindowBounds` は DIP。
- `Fetch.enable` で主フレームの遷移（クリック・リダイレクト・スクリプト・`Page.navigate`）は要求の前に止められる。`window.open` で開いたタブの最初の要求は止められない（`openerId` で開いたことは分かる）。
- プロフィールのボタンの「仕事用」は管理されたプロフィールの札で、`info_cache` の `name` とは別。

## 決定

### 道は 1 つ: 会話ごとの専用の Chrome の窓

- エージェントのブラウザー操作は、**PC の Chrome（つないでいれば Edge）に開く、会話ごとの専用の窓だけ**で行う。内蔵ブラウザーはエージェントが触らない。Chrome につなぐ道とそうでない道を並べず、選ぶ設定も置かない。
- agent-browser への渡し方は ADR 0043 の形を保つ。会話ごとの鍵付きの loopback の中継を立て、`agent-browser.json` の `cdp` にその URL を渡す。中継は ADR 0043 の「偽装」から**「パススルー + 絞り込み」**に作り直す: `Target.getTargets` と `targetCreated`・`targetInfoChanged`・`targetDestroyed` をその会話の窓のタブだけに絞り、`Target.createTarget` の context の指定は信じず、ブラウザー全体に効く `Browser.*`（`Browser.close` など）・`Storage.*`・`Network.getAllCookies` は断るか書き換える。普段の窓とタブ・ほかの会話の窓は、エージェントに見せない。`AGENT_BROWSER_PIN_TAB=1` も渡す（無いと最初の `open` が「アクティブなタブ」を書き換えうる）。
- 専用の窓の開き方: そのプロフィールのエージェントの窓が無いときだけ `chrome.exe --profile-directory=<dir> --new-window <url>` で開き、題の nonce で HWND を見つけてすぐ `ShowWindow(SW_MINIMIZE)` で最小化する。起動から最小化までの約 0.2〜0.3 秒の間、窓が一瞬見える（前面を取らない起動方法は無かったため、この一瞬の表示を許容する）。すでにあるときは、その窓から（CDP で前面を奪わずに）タブや窓を足す（具体の手段は実装の段で決める）。専用の窓だけが閉じられたときは、次に使うときに黙って開き直す。Chrome が閉じた・許可が取り消されたときは理由を 1 行で出して案内し直す。

### 初めてつなぐときの流れ

- つなぐのは、**エージェントが初めてブラウザーのツールを使うとき**と、**設定 › エージェントのブラウザーの「つなぐ」**だけ。前もっては聞かない。エージェントは `hand_to_user` と同じ**操作待ち**（承認待ちと同じ扱いで、委譲の待機時計も止める）。会話に依頼のカード、右パネルに同じ案内を出す。
- 接続は Pleiad が **1 本を保ち、会話をまたいで使い回す**（切ってつなぎ直すとダイアログが再び出るため）。
- 流れは 4 つの状態（A〜D）で進む:
  - **A 準備（初回だけ）**: トグルがオフのとき。`chrome://inspect/#remote-debugging` を Chrome で開き、トグルをオンにする案内。`chrome.exe` に `chrome://` を渡しても開けない（新しいタブになる）ため、「アドレスをコピー」を主のボタンにし、「コピー → Chrome のアドレス欄に貼り付けて開き、トグルをオン」の 2 手で案内する。オンになれば Pleiad が自動で次（B）へ進む。
  - **B 許可待ち**: Pleiad が接続を求めると、Chrome に「リモート デバッグを許可しますか？」が出る。Pleiad が前面だと Chrome の窓の背後に出て気づけないことがあるため、Pleiad が前に出す（前面の権利を使い、通らなければ `AttachThreadInput` 方式）。画面には「Chrome に許可の確認が出ています」と出し、「ダイアログを前に出す」ボタンも残す。
  - **C 許可が得られなかった**: 約 5 分で打ち切られた、または利用者が「キャンセル」を押した。5 分で切れたときは、Pleiad が残った確認を `WM_CLOSE` で閉じる（接続も即座に失敗し、閉じるのは拒否と同じ扱いで再接続時にまた出る）ので、利用者に閉じる操作は頼まない。ボタンは「もう一度」（B からやり直し、トグルがオフなら A から）と「やめる」。「やめる」を押すとエージェントには「ユーザーが許可しなかった」と返り、パネルは「つながっていません」＋「つなぐ」になる。
  - **D つながった**: 依頼のカードは済みになり、右パネルは通常の状態へ進み、そのままブラウザーのツールの結果が返る。
- **2 回目以降**: トグルはオンのままなので A は挟まず B から始まる。聞かれるのは Chrome か Pleiad を起動し直したあと、エージェントが最初にブラウザーを使うときだけ。
- つないだあとは、Chrome を起動し直すまで、Chrome の窓に「自動テスト ソフトウェアによって制御されています」の帯が出ることがある。案内（B・D）には、この帯が Pleiad の接続によるもので、Chrome を起動し直すと消えることを 1 行で添える。
- **利用途中の切断**: 使っている途中に許可が取り消された（Chrome の帯の「[設定] でオフにする」が押された・トグルが戻された等）ら、A か B に戻して案内し直す。

### 右パネルは見るだけの映像

- 右パネルのブラウザーは、その会話の専用の窓を縮めて**映すだけ**にする（`Page.startScreencast`。窓の大きさは Pleiad が決める）。押す・打つは操作にならない（触れると「見るだけ · 操作は引き継いでから」と出す。タッチでは常に）。URL を打つ・戻る・進むは Chrome の窓で行うので、道具の列（戻る・進む・再読み込み・アドレス欄・⋯）は外し、**状態の一行**に替える。
- 映像の転送: `Page.startScreencast` には `Emulation.setFocusEmulationEnabled(true)` を**常に付ける**（最小化・覆われた窓でも約 29 fps のフレームを送るために必須。付けないと 0〜1 フレームになる）。
- 一度つないだあとは、Chrome を起動し直すまで、Chrome の窓に「自動テスト ソフトウェアによって制御されています」の帯が出ることがある（Pleiad からは消せない。トグルがオンなだけでは出ない）。
- 状態の一行の語: 「Claude が操作中」「待機中」「Claude からの依頼 · ログイン」「あなたが操作中」。ボタンは「止める」「引き継ぐ」「Chrome で開く」「Chrome で操作する」「Claude に戻す」。
- 状態: 未接続（手順 2 つ＋つなぐ）・許可待ち・操作中（エージェントが押した位置に一瞬輪を出す）・待機中・依頼待ち・あなたが操作中（映像に薄い幕。中継はコマンドを全部断り、撮影も断る）・エラー。会話の頭の行に Chrome の入口を置き、操作中は弧を出す。
- 新しい色は使わない。依頼のカードの種類の字だけ承認カードと同じ `--ink-mark`、輪は `--line-blue`。動きは `--dur`・`--ease-out` で、動きを減らす設定では入れ替え・薄くするだけにする。状態の一行は `role=status`、映像は「Claude の Chrome の窓の映像（見るだけ）」と名付ける。
- 右パネルを映像にしても、入力の遅延と IME は問題にならない（操作は引き継いで本物の窓で行う）。

### 引き継ぎ: 一時停止をエージェントに必ず伝える

- 「引き継ぐ」は**中継の状態としての一時停止**にする。接続は切らず、以後のコマンドは「人が操作中。`hand_to_user` を呼んで戻るのを待つこと」という文で断る。「戻す」で一時停止を解く。「止める」は今のとおり（次の人の送信まで断る。ターン開始で鍵を作り直す）。止める・引き継ぐ・一時停止は窓ごとに働く。
- 会話のブラウザーの塊に「あなたが引き継ぎ · Claude に戻しました · 1 分 12 秒」の行を残す。**戻したときに会話のターンが終わっていたら**、ボタンは「Claude に戻して続ける」になり、決まった 1 文（「Chrome を戻しました。続けてください」）を**人の送信として**会話に見える形で送る。
- **引き継ぎで窓を前に出すのは Pleiad**（Electron の main。押された直後の前面の権利を使い、通らなければ `AttachThreadInput` 方式の `SetForegroundWindow`）。CDP の `activateTarget` や `bringToFront` だけでは窓が最小化から戻るだけで前面に来ない。
- **戻す場所は A＋C**。A: パネルと会話の「Claude に戻す」（C の土台として必ず持つ）。C: Pleiad のオーバーレイのピル（[ADR 0073](0073-computer-use-ui.md) と同じ部品）を Chrome の窓の上端に重ねる。ピルを出すのはエージェントの窓が前面にある間だけで、文言は「Claude が操作中「題」· 止める · 引き継ぐ」「あなたが操作中 · Claude に戻す」。Esc は握らない。**ページの中に帯を差し込む案（B）は採らない**: 「戻す」「止める」は安全のための操作で、信頼できないページに置くと、ページが帯を消せる・偽の帯で人を誤らせる・帯がアクセシビリティの木に入るとエージェント自身が押せる、が残り、ページの見た目と撮影を変え、移動のたびに差し直しになる。C は Pleiad の窓なのでページから見えず・偽れず、`setContentProtection` で撮影にも写らない。
- **自動の一時停止**: 人が窓を前に出しただけでは止めない（Alt+Tab で通り過ぎる・見るだけ、が多い）。**前面にあるエージェントの窓で、人が実際に入力したとき**に止める（OS の `GetLastInputInfo` が進んだら。エージェントの入力は CDP なので進まない。確度は高いが試行は少ない）。止めたら会話に帯「一時停止中 · あなたが Chrome で操作しています」を出し、止めた瞬間に送られていたコマンドは通っているので、返り値で「人が操作を始めたので止めた」と返して戻した後は `snapshot` からやり直させる。**戻すのは人だけ**で、時間で自動では戻さない（人が離れた後にエージェントが入力の途中のフォームを送りかねない）。

### `ply_browser`: ツールを 4 つにする

- 専用の MCP サーバー `ply_browser`（ADR 0078。会話ごとの Bearer の HTTP・agy は stdio の中継・3 つのバックエンドへ渡す）は、渡し方をそのまま使う。ツールは次の 4 つ（プロフィールのものは Chrome のプロフィールを指すようになる）:
  - `list_browser_profiles` / `use_browser_profile`（名前・用途のメモ・今のものか）。
  - `hand_to_user`（仮）: 引数は `reason`（login / captcha / two_factor / payment / other）と人に見せる 1 文 `message`。会話に依頼のカード（「Chrome で操作する」/「断る」）を出し、**承認待ちと同じ扱い**で呼び出しの中で待つ（委譲の待機時計も止める）。返り値は「戻した」か「断った」と、戻したときの時刻・URL・題。一時停止中に呼ばれたら、新しい依頼を出さずに戻るまで待つ。エージェント向けの指示に「ログイン・CAPTCHA・2 段階認証・支払い・個人情報の入力の手前では、自分で入力せずこれを呼ぶ。戻ったら `snapshot` からやり直す」と書く。
  - `close_browser_window`: 引数なしで自分の窓を閉じる。親は `{ task: "ply-task-…" }` で委譲した子の窓を閉じる。閉じたら会話に「Claude が窓を閉じました」を残す。

### プロフィールは Chrome のものだけ

- プロフィールは **Chrome（つないでいれば Edge）のプロフィール**になる。右パネルの頭の pill（位置と形は ADR 0078 の承認済みのまま。印は Chrome の線画、名前は Chrome のプロフィール名）のメニューに「Chrome」（Edge は別の群）の下に並べ、用途のメモを弱い字で出し、最後に「プロフィールを管理…」を置く。新しく作る項目は無い（作るのは Chrome で）。切り替えると、前のプロフィールの窓は閉じずに残し、新しいプロフィールの窓は次に使うときに開く。操作中・依頼待ち・あなたが操作中は切り替えられない。
- **表示名は `Local State` の `profile.info_cache` の `name` に、フォルダー名（`Profile 1` など）を弱い字で添える**（読み取りのみ。Cookie・鍵・ほかの項目は読まない。プロフィールのボタンの「仕事用」などは管理されたプロフィールの札で、`info_cache` の `name` とは別で画面上の表示と一致しないことがあるため）。用途のメモは Pleiad の設定に持つ（AI が選ぶ手がかり）。
- **初めて使うプロフィールの承認カードは出さない**。Chrome の許可と、サイトの利用の確認で足りる。AI が替えたときは今どおり知らせ（「<エージェント名> が『…』に切り替えました」）を出す。
- 設定 › ブラウザーの「プロフィール」の節は「エージェントのブラウザー」に置き換える（つないでいるブラウザーの行と状態・「切る」「つなぐ」、Chrome のプロフィールの一覧・メモ。「新しい会話のプロフィール」は残す）。

### Pleiad のプロフィールの機能は削除する

- ADR 0078 のプロフィール（保存領域を複数に分ける機能・`prefs.json` の `browserProfiles`・`browserDefaultProfile`・`browserNewProfile`・`browserLastProfiles`・会話のメタの `browserProfile`・設定の節・タブの列の pill とメニュー・`browser.listProfiles`・`browser.useProfile`・`browser.setProfile`・保存領域の削除の仕組み）は**そのまま削除する**。内蔵ブラウザーの保存領域は `persist:pleiad-browser` の 1 つに戻る。
- **移行・片付けの知らせ・古い値の読み替えは作らない**（使っているのはユーザー本人だけで、メイン以外のプロフィールはこの PC に無い）。メイン以外の保存領域のディレクトリと古い prefs の値が残っても、誰も読まない。

### 内蔵ブラウザーは見るだけのビューアとして残す

- 内蔵ブラウザーは**人が見るためのビューア**として残す。エージェントは触らない。残るもの: タブ・アドレス欄・DevTools・「別の窓に出す」、リンクの開き先（`linkOpen`）、HTML ファイルと可視化の写しを開く `file:` のタブとその守り（[ADR 0079](0079-html-opens-in-inapp-browser.md)）、外部の読み込みの確認、リモートの端末から PC の localhost・ファイルを見る「PC のブラウザーで見る」（画面の転送）、頭の行の地球の入口。ビューアの⋯に「Chrome で開く（エージェントの窓へ）」を足し、人が見ているページをエージェントに渡せるようにする。
- ビューアから外すもの（エージェントとの接点）: プロフィール、エージェントの中継（`setAgent`・`agentFor`・「操作中」の印と行）、「止める」「引き継ぐ」。
- 全廃は採らない。リモートから localhost を見る唯一の経路を Chrome に向け直すと、人のタブがエージェントの窓に混ざり、`file:` の守りは CDP の `Fetch` で作り直しになる。覚えることは「見る = Pleiad、使わせる = Chrome」の 2 つになる。

### サイトの利用の確認

- 確認の本体（ADR 0042 の `confirmAgentSites`・承認カード・「このサイトは常に」・委譲元の会話にも出す）は変えない。「このサイトは常に」の単位は**エージェント＋プロフィール＋サイト**（プロフィールは Chrome のもの）。
- 主フレームの遷移（クリック・リダイレクト・スクリプト・`Page.navigate`）は `Fetch.enable`（Document の要求）で要求の前に止められる。ただし **`window.open` で開くタブの最初の要求は止められない**（開いた側のセッションの `Fetch` は効かず、`Target.targetCreated` から attach しても要求の送出に間に合わないため。開いた後は `openerId` で把握できるため閉じるなどの対応は可能）。確認が ON（既定は OFF）のときは、設定に「Chrome では一部の移動（window.open で開くタブの最初の要求など）を止められません」と書いて出す。人の入力の検出（`before-input-event`）が無くなる代わりに、上の「自動の一時停止」の検出を使う。

### 委譲したとき

- 窓は**会話ごとに 1 つ**で、委譲した子も自分の窓を持つ。子が初めてブラウザーを使うとき、背面か最小化で開く。プロフィールは親の会話の今のものを引き継ぎ、子は `use_browser_profile` で替えてよい（替えたら子の会話に記録を残し、委譲のカードの行も替わる）。
- 子が `hand_to_user` を呼んだら、委譲のタスクは承認待ちと同じ `waiting`（カードの字は「承認待ち」）。依頼のカードは**子の会話と親の会話の両方**に出し、親のカードから「Chrome で操作する」→「Claude に戻す」まで済ませられる（子の会話のカードも同時に済みになる）。並行する子が**同じプロフィール・同じサイト**で同時にログインを求めたら、親のカードは 1 枚にまとめて待っている作業を並べ、前に出すのは最初に頼んだ子の窓にする。Cookie はプロフィール単位で共有されるので、1 回のログインで全員を再開する（戻したときに各自が `snapshot` からやり直す）。
- 右パネルは**自分の会話の窓だけ**を映す（親の会話で子の窓は映さない）。親の委譲のカードの下に細い行（Chrome の印・プロフィール・状態・「Chrome の窓を見る」・×）を足し、「Chrome の窓を見る」で子の会話を開く。頭の行の Chrome の入口は、この会話と委譲した子の開いている窓の数を右下に小さく出し（1 つなら出さない）、操作中があれば弧を出す。押すと窓の一覧（会話の題・プロフィール・状態）。**数に上限は設けない**（一覧は長ければ縦に流す）。
- 止める・引き継ぐ・自動の一時停止は窓ごと（止まるのはその子だけ）。
- **窓は自動では閉じない**（結果を見せる・続きに使うかはタスクによる）。閉じるのは、子自身（`close_browser_window`）・親（同じツールに子のタスク ID）・人（右パネルの「窓を閉じる」・委譲のカードの ×）。閉じた後は最後の画面を静止画で残し、会話に「Claude が窓を閉じました」を記録する。会話を消したときは窓も閉じる。
- サイトの利用の確認は今と同じく親の会話にも出す。

### スマホ（リモート）

- 今の「PC のブラウザーで見る」と同じ経路（画面の転送。中継の WS に映像を流す）で Chrome の窓を映す。依頼は下からのシート（この端末で操作する / PC で操作する / 断る）。端末から操作するときだけ、窓の表示の大きさを端末に合わせ、戻すと元に戻す（エージェントの操作中に変えるとページの形が変わる）。パスワード管理・パスキーは端末では使えないことを 1 行で添える。

### 進め方

この ADR の実装は段で進める。**第 1 段**は内蔵ブラウザーのプロフィールの削除（`ply_browser` のサーバーの骨組み・内蔵ブラウザーのそれ以外の機能は保つ）。以降は Chrome への接続・絞り込みの中継・専用の窓・映像・状態の一行・`hand_to_user`・`close_browser_window`・ピル・プロフィールの一覧・委譲の順に足す。段ごとに `docs/inapp-browser.md` などの今の形を書いた文書を更新する。

## 理由

- 一番の不満は、普段の Chrome でログイン済みなのに Pleiad で入り直し、パスワード管理・パスキー・拡張も使えないこと。Chrome につなぐのが最も短い解で、Cookie を写す道（ADR 0041 が退けた。Windows の App-Bound Encryption で他のアプリから読めない）より安全。
- 道を 1 つにするのは、「見る = Pleiad、使わせる = Chrome」より先の選択をユーザーに持たせない（設定で内蔵と Chrome を選ばせると、承認・確認・引き継ぎ・映像の経路が二重になる）ため。
- Chrome 全体が 1 つのブラウザーとして見える性質上、直接つなぐ（`--auto-connect`）と全プロフィールの Cookie・全タブがエージェントに見え、止める・引き継ぐ・確認も効かない。ADR 0043 の中継を「絞り込み」に作り直して同じ位置に残すのは、会話への束縛・鍵・止める・確認を Electron に依存しない部分として保てるため。
- 右パネルに映すだけにすれば、右パネルへの Chrome のストリーミングの難点（遅延・IME・背面のスロットリング）が問題にならない。実際の操作は本物の窓で行う。
- 一時停止を中継の状態にするのは、エージェントに確実に伝え（人が戻すまで待たせる）、接続は切らずに保てる（Chrome の許可は接続のたびに出る）ため。ターンの途中で人が窓に入ったとき、エージェントが入力の途中のフォームを送らないことが、この機能の安全の中心。
- 「戻す」「止める」を信頼できないページに置かないのが B を採らない理由。C は ADR 0073 の部品なので語彙がそろう。
- 内蔵ブラウザーを残すのは、リモートから PC の localhost・ファイルを見る経路と、HTML ファイルの守りが、Chrome の映像では作れないため。外すのはエージェントとの接点だけで、残る部品は今より少ない。
- Pleiad のプロフィールを移行なしで削除するのは、ADR 0078 の保存領域が、この ADR で道が Chrome に移ることで役目を失うため。メインの保存領域（ビューアのログイン）は残る。
- 採らなかった案: 内蔵ブラウザーの全廃（上記）。Chrome のプロフィールを一時ディレクトリへコピーして使う（`agent-browser --profile`。Windows は Chrome を閉じる必要があり、日常運用に向かない）。Pleiad が自前で別プロセスの Chrome を起動する（ログイン済みの普段のプロフィールを使えない）。

## 未確認

本物の Chrome での確認で済んだ項目（許可の前面化と再接続、起動時の最小化、題の nonce による HWND 特定と GetLastInputInfo、主フレームの Fetch 遮断、window.open の同一窓格納、フォーカスエミュレーションによる映像フレーム生成、プロフィールの札の正体など）を除き、以下を残す。

1. **agent-browser の束縛**: `AGENT_BROWSER_PIN_TAB=1` の効き。`agent-browser close` が外部の Chrome に何をするかは確かめた（`Browser.getVersion` だけを送り、Chrome もタブも閉じない。ただしデーモンが居ないと新しく起こすので、止めるのには使わない。[ADR 0180](0180-agent-browser-daemon-lifetime.md)）。
2. **映像の大きさ**: 専用の窓の表示の大きさ（1100×720 想定）は右パネルでは 0.5〜0.6 倍で縮小され、小さい字が読みにくい。エミュレーション（`Emulation.setDeviceMetricsOverride` は本物の窓の形が変わる）や `Page.captureScreenshot` の周期取得などの検討。
3. **別モニター・DPI の違うモニター**: `Browser.getWindowBounds`（DIP）と HWND（Win32 矩形・DPI 倍率）の対応づけや、窓の移動・最大化の追従。
4. **Chrome が前面のときの createTarget の前面**: 利用者が別の Chrome の窓を操作しているときに、エージェント側で `Target.createTarget` や窓操作を行った場合に前面を奪うか。
5. **ログイン待ちをまとめる判定**: 並行する子が「同じプロフィール・同じサイト」でログインを求めた判定を、`hand_to_user` 呼び出し時の origin で揃える案の検証。
6. **閉じた窓の静止画**: 閉じる直前の `Page.captureScreenshot`（人が × で直に閉じたときは最後の映像のフレーム）。置き場は ADR 0115 の規則で決める。
7. **Edge**: `edge://inspect/#remote-debugging` は確認済みだが、Edge 固有のページ（sync の確認・組織の起動 URL）が専用の窓に混ざらないか。
8. **リモートの映像**: `desktop/browser-screencast.cjs` は Chrome 向けに書き直す。worker 側（間引き・ack・hub）と画面（`web/remote-browser.mjs`）の再利用性の詳細。

## 影響

- [ADR 0078](0078-inapp-browser-profiles.md) は置き換える。[ADR 0041](0041-inapp-browser-beside-conversation.md)（人のログインの保存領域は残る。エージェントとの共有は無くなる）・[ADR 0043](0043-agent-browser-via-per-session-cdp-relay.md)（中継の接続先と、Electron の webContents に包む部分）・[ADR 0042](0042-preview-loads-external-by-default.md)（Chrome で止められない移動）・[ADR 0079](0079-html-opens-in-inapp-browser.md)（プロフィールの段落）・[ADR 0091](0091-control-surface-host-delegation-browser.md)（`browser.*` の 3 つの操作）には、この ADR の変更を追記する。
- 内蔵ブラウザーの保存領域は 1 つ（`persist:pleiad-browser`）になる。人のログインはここに残る。
- ADR 0043 の中継は、Electron の `webContents.debugger` に包んだ偽装から、Chrome へのパススルー + 絞り込みになり、`desktop/browser-relay.cjs`・`browser-navigation.cjs`・`agent-browser-bridge.cjs` は大きく作り直す。`desktop/browser-screencast.cjs` も Chrome 向けに書き直す。
- サイトの利用の確認は、ON のとき一部の移動を止められない（上記）。既定は OFF なので、影響は ON にした人だけ。
- 内蔵ブラウザーのプロフィールの削除の後、`ply_browser` はツールの無い骨組みになる。次の段で上の 4 つのツールを載せる。
- `docs/inapp-browser.md`・`docs/design-system.md`・`docs/computer-use.md` は、段ごとに今の形へ直す。
