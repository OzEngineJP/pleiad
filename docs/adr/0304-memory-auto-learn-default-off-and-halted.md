# 0304 自動の記憶整理は既定で止め、ON・OFF を世代で切り、分類不能な失敗は止まる

## 状態

承認（2026-11-09）。一部置換（[0308](0308-antigravity-catalog-fetch-places.md)、承認（2026-11-10））: Antigravity の受動の照会と一覧の引き直しの範囲。`agy models` は人の明示に加え、このプロセスでログイン済みと確かめた所（`/usage` での確かめ・使用量の読み取り・認証を通ったターン）でも起こす。一覧が無いときの送信の関所は自分で一覧を取り、'in' の間は TTL 超過の一覧を `models()` の読み取りをきっかけに裏で引き直す。ほかの決定は引き続き有効

## 状況

記憶の自動整理（夜の整理 `core/memory/learn.mjs`）と、bot との静かな会話の要約（`core/memory/episodes.mjs`）は、設定を変えたことのない人にも既定で動いていた。利用者が止めたいときのスイッチは「止める」（`memoryLearnPaused`）だけで、実行の途中で切っても取り返した結果を書き込めた。また、失敗は種類を問わず間隔を空けて繰り返すだけで、止まったこと・止まった理由が残らなかった。認証の切れたバックエンドを呼び続ければ、認証を求める画面を繰り返し開くおそれがあった。

Antigravity については、使用量の定期的な照会が CLI（`agy`）の起動を含んでおり、未接続でも照会を続けていた。

## 決定

- **自動の記憶整理は既定で止める。** 新しい総合スイッチ `memoryAutoLearn`（既定 OFF）を置き、従来はこのキーが存在しなかったため、今回の更新では全員が一度 OFF になる。保存している記憶・設定・これまでの整理の履歴は消さない。あとから ON にした人の値はそのまま保持する。会話の要約は下位の `memoryEpisodeSummary`（既定 OFF）で別に止められ、本体が OFF の間は要約も走らない。従来の `memoryLearnPaused` は読みだけ残し、true が残っていても OFF として扱う。
- **設定画面の「記憶」は承認どおり全般／bot に置く。** bot 個別のスイッチは増やさず、全 bot 共通の 1 か所とする（bot の記憶ページは統一の設定へ導線を張る）。
- **ON・OFF は世代（`memoryLearnFrom`）で切る。** ON にするとき `memoryLearnFrom` を単調増加で進め、OFF では消さない（同じ瞬間の OFF→ON でも世代がぶつからない）。実行は世代を始めに固定し、AI を呼ぶ直前・記憶を書く直前・要約の保存で毎回確認する。途中の OFF・OFF→ON は世代の違いで検出し、古い世代の結果も失敗も新しい世代に書かない・記録しない。中止は失敗・停止へ変えない。ON の保存は、先に OFF を保存してから世代・「止める」の解除を経て最後に ON とする順（途中で失敗しても有効なまま残らない）。
- **分類不能な失敗は 1 回で止める（`halted`）。** 自動再試行するのは、取り直せばよいと確証のある失敗だけ（使用量の上限 `learner turn: limited`、自分の返答の形の失敗 `learner returned …`）。それ以外の失敗は認証切れかどうか見分けが付かないため再試行せず、理由とともに `halted` として残す。一時エラーは 15 分から倍々で 6 時間まで、連続 5 回で `halted`。`halted` は夜の整理・scoped 整理・会話要約の全部に効き、明示の「もう一度」（`learnNow`）または自動整理の再有効化だけが解除する。**解除の判定は時刻の大小でなく世代でする**:`halted.gen` に止まった実行の世代を残し、現世代が違うときだけ解除する（ON と失敗が同じ瞬間・時計が後戻りしても、ON のままの世代は勝手に解除しない）。遅れて届く古い世代の失敗は、走っている新しい世代を止めない。状態（停止・失敗の回数・再試行の予定・次回）は保存し、画面へ出せる形にする。再起動でも `halted` は復元し、明示の操作まで AI は呼ばない。
- **並行する別の経路の状態を踏まない。** 実行中にエピソード側が記録した失敗の回数・再試行の予定・停止は、その実行の成功で消さない。実行の途中で別経路が停止を記録したら、残りの書き込み・AI 呼び出しも打ち切る。`learnNow` は、OFF・実行中では状態を変えずに `{skipped:'off'|'running'}` を返す（実行中の回に相乗りしない）。
- **再有効化の直後に溜まった分を走らせない。** 夜の整理は `memoryLearnFrom` 以後を床に次回予定へ回し、会話要約もスレッドの最後の発言が `memoryLearnFrom` より前のものは予約しない。
- **Antigravity の受動の照会は CLI を起こさない。** 認証状態の確認・モデル一覧は、保存済みの情報だけを返す。使用量のみ、公式の読み取り専用スラッシュ（`agy --print /usage --output-format json`。バージョン 1.1.11 の変更履歴で追加された無課金の読み取りで、未認証でも対話を開かない境界は現行の headless 仕様として扱う）に限って照会する。照会の失敗が「要ログイン」と確定できるもの（`AUTH_REQUIRED`）のときだけ以後の受動の起動を止め、それ以外の失敗は従来どおり投げ返す。サジェストは公式の `--print`・非 TTY の保証内で従来どおり起こすが、未ログインが確定しているとき（`authGuess === 'out'`）だけ新規の起動を抑える。明示の照会（`listModels`）だけが `agy models` を起こし、待ち時間・出力に上限を設ける。
- **モデル一覧は境界内で残す。** 明示の照会で取れた一覧は、上限付きの写し（`antigravity/models.json`。行・id・表示名・全体のバイト数を固定、原子的に書く）として置き、次のプロセスが CLI 無しで復元する。写しは認証の証拠に使わない。写しが無い・壊れている間は、`validModel` が形の良い保存済みの id をそのまま通し（選んだモデルを勝手に戻さない）、一覧があるときは一覧どおりに検査する。**覚えている段だけは写し無しでは検査できない**（段はモデル id に入るため、検査を省けば別の強さで動いてしまう）ので、一覧が無いのに段が選ばれていれば、その発言を「一覧の確認が要る」という直し口の分かる失敗として止める（`requireModelCatalog`。黙って既定の強さには落とさない。設定の「状態を再確認」で一覧を引けば直る）。未知の段の id を捏造してまで走らせはしない。明示の照会（`authStatus` の `probe`）だけがこの一覧を引き直す。
- **未確定の失敗を「ログアウト」と言わない。** 明示の照会の失敗が要ログインなら確定のログアウトを返すが、タイムアウト等の未知の失敗は `unconfirmed` と固定の文言（`antigravity.auth.unconfirmed`）を返し、生の stderr・URL・パスは出さない。

## 理由

- 自動で AI を呼び記憶へ書く処理は、利用者が止め方を知る前から動いていてはいけない。既定 OFF と、ON・OFF の世代による中止は、「止めたつもりが動いていた」を起こさないため。
- 失敗を全部再試行すると、認証切れ・設定の誤りのような直してもらうべき失敗で CLI を繰り返し起こし、認証の画面を何度も開き得る。「再試行してよい失敗」を名指しの許可リストに絞り、それ以外を 1 回で止めるのはこのため。
- 実行の途中で世代が替わったり別経路が停止を記録したりしても、古い世代の結果・失敗を新しい世代へ持ち込まないのは、ON・OFF・停止の意味を時間の経過に対して一貫させるため。
- Antigravity の受動の照会を保存済みの情報と公式の読み取り専用経路に限るのは、未接続の人のところで対話的な認証を始めないため。一覧を写しておくのは、プロセスを再起動するたびに利用者が選んだモデル・段が黙って「既定」へ戻るのを防ぐため。受動化で `authStatus` の素の呼び出しは一覧を引かなくなったので、引き直しの入口は人の明示の操作（`probe`）に限る。
- 未知の失敗で「未ログイン」と断定しないのは、タイムアウトや一時的な起動失敗で「接続をやり直して」という表示を誤って出さないため。同じ理由で、未ログインの確定があるまでサジェストの起動は止めない（保証内の機能を無用に欠かせない）。

## 影響

- 既存の利用者は今回の更新で自動整理が一度 OFF になる（記憶・設定は残る）。再度 ON にすれば従来どおり動くが、再有効化直後に過去分をまとめて整理はしない。
- `memory.learnStatus` の様子は停止・失敗・再試行・次回を含む形に広がる。画面（設定「記憶」・bot の記憶ページ）は別の変更でこの形を使う。
- 夜の整理・会話要約の失敗は、理由が画面から読める状態で止まる。解除は利用者の操作だけ。
- 対象: `core/memory/learn.mjs`・`core/memory/episodes.mjs`・`core/bots-host.mjs`・`core/ops/settings.mjs`・`core/ops/memory.mjs`・`core/backends/antigravity*.mjs`・`core/server.mjs`（`validModel` の配線）。試験: `tests/unit/memory-learn-gate.mjs`（世代ラッチ・再起動・DB 書き込み失敗）・`ops-settings.mjs`・`antigravity-passive.mjs`（写しの復元・probe の未確定・サジェスト抑止）・`server-agy-default-model.mjs`・`server-antigravity.mjs`・`antigravity-accounts.mjs`。
