# 0024 流れの出来事は、接続が開いている会話の分だけ送る

- 状態: 承認（2026-09-26）。「1 つだけ」は 2 つの口に改訂（0315）
- 置き換えられた: [0315](0315-two-watch-slots-modal-right-pane.md)（接続が見る会話を `main` と `modal` の 2 つの口にした。`modal` は作業のダイアログが子の会話を映す間だけ。送り方・`turnEnd` は全部送る・宣言しない接続には全部送る、は変えない）

## 状況

サーバーは出来事を全部の接続に配り、画面は開いていない会話の分を捨てていた（`isMine`）。複数の会話やその委譲の子が同時に走ると、全部の会話の文字の流れ（`text.delta` など）が全端末に届く。中継を通るスマホでは、暗号化と流量の制御の窓（1 ストリーム 256KB）を大きな返答と分け合うので、裏で何かが走っている間だけ操作全体が重くなる、と報告があった。
リモートの設計（docs/remote.md §11 の 10）は、会話単位の購読を「実測してから別に決める」としていた。2026-09-26 に実データで測り、会話を開くのと一覧の取り直しが重い原因と合わせてこの件を決めた（`temporary/reports/session-load-performance.md`）。

## 決定

- 接続は「いま開いている会話」をサーバーに伝える。`loadSession` の `watch: true`（開くとき・枝を切り替えるとき）と、読み直しの要らない `watchSession { sessionId }`（枝の切り替えに失敗して元の会話に戻るとき）。
- 伝えた接続には、流れの出来事（`web/session-stream.mjs` の `streamEvents`）をその会話の分だけ送る。
- `turnEnd` は全部送る。一覧の完了の印・デスクトップの通知・実行中の数が、開いていない会話の完了で動くため。
- 流れ以外の出来事（状態・タイトル・承認・`running` など）は今までどおり全部送る。
- 伝えていない接続（古い画面・試験のクライアント）には今までどおり全部送る。`PROTOCOL_VERSION` は据え置く（足しただけ）。
- 送らなかった分も「届け先がいた」とみなす。接続が 1 本も無いときだけ溜める（今までと同じ）。

## 理由

- 画面は開いていない会話の流れを使っていない。開いたときは `loadSession` の途中参加のスナップショット（`stream.events` と `streamCursor`）で追いつく。宣言は読み出しを待つ前にサーバーが同期で決めるので、宣言の後に来た分と重なっても `streamSeq` で重複が落ちる。
- 開いている会話はもともと画面ごとに決まっている（複数の窓・端末はそれぞれ別の会話を開ける）。接続ごとに持てば、窓ごとの違いがそのまま表せる。
- 購読を別の往復にすると、開くたびに中継の往復が 1 回増える。開くときは必ず `loadSession` を読むので、そこに載せる。

## 影響

- 開いていない会話の流れを使う機能を新しく作るときは、`turnEnd` のように送る対象（`WATCH_EXEMPT`）に足すか、その機能の側で読み直す。
- 委譲の子など開いていない会話の中身は、今までどおり `loadSession`（`live` なし）で読む。バックグラウンドのダイアログはこの形。
