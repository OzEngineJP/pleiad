# 0146 端末の AI から、リモートのホストへ作業を委譲する

- 状態: 提案
- [ADR 0013](0013-remote-via-relay-with-noise.md) の「リモートのための機能は足さない」「端末は全権限で、端末ごとの権限は入れない」を、**端末の AI という主体を委譲に限って受ける**ことで一部置き換える。主体と危険度は [ADR 0082](0082-control-surface-principals-and-risk.md)、human-only の範囲は [ADR 0094](0094-human-only-five.md)、委譲の規則は [docs/agent-delegation.md](../agent-delegation.md) に合わせる。[ADR 0010](0010-os-actions-only-on-host-screen.md) は変えない
- 追記: ホスト側の端末ごとの許可（`agentDelegation`）は、ホストの「ほかの端末からの操作を許可する」1 つにまとめる（[ADR 0239](0239-remote-single-permission.md)。提案の間は追記に留める）

## 状況

デスクトップ版の端末は、ホストの Pleiad を画面（リモートの窓）として全権限で使える（ADR 0013）。一方、端末の会話の AI がホストの PC に仕事を頼む口は無い。ホストの接続口は `/mcp/` と `/api/ops` を通さず（remote.md §4.2）、端末の画面の経路（`/ws`）は人（human）の権限で動く。AI にこの経路をそのまま使わせると、AI が human の権限を持つことになり、主体を分ける ADR 0082 が崩れる。

手元の PC では、会話の AI は `ply_delegate` で子の会話を作り、子の承認モードは親の強さまで継ぎ、子の承認は親の会話にも出て、そこで答えられる（docs/agent-delegation.md）。「ホストの PC にいる AI に、端末から同じように任せたい」という要望（issue #57）に、新しい道具を増やさずに応える。

## 決定

- **新しい MCP は作らず、既存の委譲の拡張にする。** `ply_delegate` に任意の `host`（ペアリング済みのホストの名前）を足す。省けば今どおり手元。`ply_task_status`・`ply_task_wait`・`ply_task_send`・`ply_task_cancel`・`ply_task_list` は同じ `ply-task-` の ID で、ホストのタスクにも効く。委譲先の自動の振り分けはホストを選ばない（AI が `host` を書いたときだけ）。ホストの操作の一覧を直接呼ぶ道具（`call_op` など）は入れない。ホストの道具（シェル・ファイル・computer use）は、任されたホストの AI がホストで使う。
- **ホストの接続口に、端末の AI 用の口 `/agent` を足す。** 端末のストリームのうち WebSocket の `/agent` は、`/ws` への転送とは別に、接続口が同じプロセスで受ける（ローカルのサーバーの HTTP・WebSocket へは出さない）。防火壁の表（remote.md §4.2）には、`/agent` を `forward.mjs` が通さないことと、接続口が自分で受けることを足す。口で交わす便りは固定の種類だけで、AI の依頼は委譲の 6 つ（`delegate`・`status`・`wait`・`send`・`cancel`・`list`）に限る。任意の操作を呼ぶ道は無い。
- **主体は agent で、`via: 'remote'`・端末の `deviceId`。** 会話には束縛されず、依頼元は「端末の会話」（`requester: { deviceId, sessionId, title }`。`deviceId` は接続の認証で確かめたもので、端末の言い分を使わない）。ホストのタスクの親（`parentSessionId`）は `remote:<deviceId>:<端末の会話の ID>` の仮の ID で、所有の判定・通知・承認の中継の祖先の辿り方がこれを「祖先」として扱う。記録（`by`）には agent・`via: remote`・`deviceId`。画面の human の権限は渡さない。
- **許可は両側とも既定オフ。** ホストは端末（`devices.json` の 1 件）ごとに `agentDelegation`、端末はホスト（`hosts.json` の 1 件）ごとに `agentUse`。ホストの許可は、デスクトップ版の端末にだけ出す。どちらも人だけが変えられる: ホストは WS コマンド `setRemoteDeviceAgent { id, enabled?, stopAll? }`（human-only の「リモートのペアリング」の組。ADR 0094 の 5 つは増えない）、端末は「ほかのホストにつなぐ」窓（同梱の file: の窓）の IPC。ローカルのサーバーの設定・操作の一覧には置かない（端末の AI が `set_setting` で触れてしまうため）。両方オンのホストだけが、AI の `ply_delegate` の説明に名前で出る。 ホストの許可を**入れるのはホストの PC の画面だけ**で、端末の画面（中継越しの `/ws`）からは入れられない（片側の判断で相手の PC の AI に仕事が流れないように。切る・「すべて止める」は端末からもできる）。切る・取り消す・「すべて止める」は、受け付けて子を作る前の依頼を今打ち切り、子を作る直前にも許可を確かめ直す。動いているタスクの上限は任された子の子孫も数え、確かめる前に枠を予約する。
- **「AI からの依頼を受ける」をオンにすることは、手元の委譲と同等の振る舞いを許すこと。** ホスト側に承認モードの上限は持たない。依頼元の会話が確認なしのモードなら、ホストの子も確認なしで、ホストの PC で動く。入れるときにその場で確かめる。任された作業の数と「すべて止める」を出し、端末を取り消せば任された作業も止める。
- **子の承認モードは依頼元（端末の会話）に合わせる。** 端末は依頼元の会話の承認モードの位置（範囲・自律・強制できるか）を送り、ホストは委譲先を決めた後で `resolveDelegatedMode`（手元の委譲と同じ関数）に `parentMode: 'cap'` の形で渡す。収まる委譲先が無いなど `escalation` が立つときは、ホストは子を作らずに計画（委譲先・モード・鍵）を返し、端末が**依頼元の会話で 1 回だけ**確かめ（`permission.delegateEscalation`。常に許可は出さない）、許可されたら同じ鍵で確定を送る。ホストは計画が変わっていれば断る。`ply_delegate` の呼び出し自体は、依頼元の会話の通常のツールの承認に従う（手元と同じ）。
- **子の承認は依頼元の会話に中継し、そこで答えられる。** ホストは子の承認を、手元の中継と同じく依頼元へ「中継する承認」（承認の ID・受領証・見出し・入力）として流し、端末のローカルのサーバーが依頼元の会話の中継のカード（見出しに ⇄ ホスト名）として出す。「常に許可」は出さない。ホストの画面にも同じカードが出て、先に答えた方で決着する。決着（どこで答えたか・取り下げ・子が止まった）はホストが流し、端末のカードを畳む。つながり直したとき、ホストは今待っている分を送り直す。ホストがオフラインの間は、端末のカードのボタンを止めて理由の 1 行を出す。 質問のカード（AskUserQuestion）も同じ道で中継し、選んだ項目を送る。設定の変更の承認（受領証つき・ターンを止めない承認）は端末から答えられないので、答えるボタンの無い「ホストの画面で答えてください」の知らせとして流し、AI の `ply_task_status` にも書く。
- **承認の答えは、端末の画面（human）から来たものだけを運ぶ。** 端末の画面の `resolvePermission`（human-only のまま）→ 端末のローカルのサーバー（中継のカードの ID からホストと承認の ID を引く）→ main（parentPort の橋）→ `/agent` の `answer` → ホストの `resolvePermission`（`by: human`・`via: remote-device`・`deviceId`）。ホストは、自分が中継した今待っている承認の ID・中継したときの受領証・1 回だけを照合し、外れたものは捨てて記録する。端末の AI はこの道を使えない: 端末の AI が呼べる道具（MCP・CLI）から `answer` を作る道は無く、`ply_task_send` などの委譲の道具も答えを運ばない。
- **経過の読み出し: 端末の画面（人）が、任せた子の会話の経過を同じ口から読める**（承認済み（2026-10-07）。バックグラウンドの詳細を、手元の委譲と同じ筋で見せるため）。口に `view` の便り（ホスト → 端末は `viewed`）を足す。`answer` と同じく端末の AI の依頼（委譲の 6 つ）には入れず、端末の AI の道具（`ply_task_*`・MCP・CLI）にも足さない。道は、端末の画面の詳細（操作 `delegation.hostView`。画面（人）だけで、MCP・CLI には出さない）→ 端末のローカルのサーバー → main の橋 → `/agent` の `view`。ホストは、端末・許可（`agentDelegation`。切れば読めない）・**この端末が任せた子とその子孫**を照合してから読み、それ以外のタスクは `NOT_FOUND`。読むだけで、書く・止める・答える道は足さない。運ぶ前に絞る（末尾 40 発言・ツールの入力と出力は 1 つ 2 KB・考えた内容は 4 KB・画像と添付は枠だけ・発言 1 件 48 KB・答え全体を口の上限の内側に。古い分は省いた件数を端末に知らせる）。記録は、子の会話の変更の記録へ端末ごと・タスクごとの最初の 1 回だけ「読んだ」（`by: human`・`via: remote-device`・`byDevice`。会話の中身も読んだ回数も残さない）。更新は、詳細を開いている間だけ端末が差分を引く（持っている発言の位置と直前の発言の署名＝`cursor` から続きだけ）。ホストは購読を持たず、終わったタスクは 1 回読んで止まる。ホストの子がホストで任せた孫は、答えの子孫の要約（題・状態・親）を端末の一覧へ字下げの行で足す（端末の台帳には保存しない。完了通知・上限・取り消しの数え方には触れない）。承認・質問のカードは、中継のカードと同じカード・同じ答えの道で詳細の筋でも答えられる（`relay` に承認を求めている子の会話の ID を添え、孫の詳細にはその子の分だけ出す）。読み出しを知らない古いホストは、`ready` の `view` で先に分かり、今の依頼と結果の 2 つの箱に戻す。
- **作業場所はホストのパスとホストの規則で解釈する。** `cwd` はホストのパス（省けばホストのホーム）、`isolate` はホストの worktree の規則。初版は絞らない。
- **切れたとき。** オフラインのホストへの `ply_delegate` は、待たずに失敗を返す。走っている途中で切れたら、ホストの子は続きを走り、つながり直したら端末が状態と完了を追いつく（ホストの便りと、端末の同期の要求）。ホストが 10 分以上オフラインのままなら、依頼元の会話へ不通を知らせ（続けば 60 分あけてもう 1 回）、つながり直したら追いつきを 1 通で知らせる（[ADR 0171](0171-remote-delegation-notices.md)）。 オフライン中の止める（`ply_task_cancel`・会話の中断・「すべて止める」）は「止める予定」として残り、つながり直したら送る。ホストが許可を切った・知らない ID を返したときは、動いていた写しを理由つきで終わらせ（追えなくなった印を付ける）、つながり直せばホストの状態に戻す。
- **ホストでの出どころと歯止め。** ホストの側では、端末の AI が作った会話に出どころの印（`⇄ laptop の AI から`・依頼元の会話の題・継いだ承認モード）を付ける。任された会話からは、さらに `host` を指定させない。ホストから先へ渡る鎖は作らない。端末の AI から始まった委譲の鎖には、委譲の深さの上限（4）を効かせる。端末ごとの同時タスク数（8）と依頼の頻度（1 分に 20 件）にも上限を置く。ホストの UI トークンは `/agent` でも渡さない。 端末の取り消し・「すべて止める」は、任された子とその子孫（ホストの中で子が作った孫まで）を止め、子の会話に「止めた」印を付けて、あとから届く孫の完了通知で新しいターンを始めない。

## 理由

- **委譲の拡張にした**のは、手元の委譲の規則（承認モードの継承・引き上げの確認・承認の中継・完了通知）をそのまま使え、AI の新しい道具が増えないから。作業はホストの中で速く、中継を流れるのは依頼・状態・結果・承認だけ。
- **`/agent` を別の口にした**のは、端末の AI の依頼を `/ws` で運ぶと、画面の human の権限を AI に渡すことになるから。別の口にして、口の上で「AI の依頼」と「人の答え」を別の種類の便りにし、`invoke` に出す操作を委譲の 6 つに限れば、ホストは何が人から来て何が AI から来たかを見分けられる。
- **承認の答えを運ぶ道を 1 本の human の経路に限った**のは、答える権限が承認モードの根（ADR 0094）だから。main がホストの `/ws` に人として直接話す案は、答えるだけのはずが、ローカルのサーバーに「人としてホストへ話す」一般の口を渡すことになるので採らない。この経路は、手元の委譲で中継のカードへの答えがローカルの画面の口から来ると信じているのと同じ強さの信頼で、ホストは端末側の human-only と、画面の WS からだけ作ることを信じる。
- **ホスト側に承認モードの上限を持たなかった**のは、手元の委譲と同じ振る舞いにするため（利用者の決定）。代わりに、入れる人の判断をその場の確かめで求め、両側の既定オフと、出どころの印・任された作業の数・すべて止める・取り消しで止める・記録で、うっかりと誘導を防ぐ。確認なしのモードで動く端末の AI は、同じ OS の利用者の権限で端末の保管庫を読み、人としてホストにつなぐことが原理的にできる（ADR 0082 の「確認なしの会話はデータ置き場を書ける」と同じ構図）。スイッチはその場合の防壁にならない。
- **両側に置いた**のは、端末だけ・ホストだけの許可では、片側の判断で相手の PC の AI に仕事が流れてしまうから。端末側の許可を窓の IPC に置くのは、ローカルのサーバーの設定にすると端末の AI が自分で入れられるから。
- **仮の親 ID にした**のは、端末の会話の ID がホストに無く、委譲の台帳・通知・承認の中継が「親の会話」を前提に作られているから。親を一般化して作り直すより、仮の ID を「祖先」として扱う方が、手元の仕組みを崩さない。

- **読み出しを別の便りにした**のは、端末の画面が詳細を開くのは人の操作で、端末の AI が使う口の上の 6 つの依頼とは権限が違うから。`answer` と同じく口の種類で分ければ、ホストは何が人から来て何が AI から来たかを見分けられ、見せる範囲をホストが 1 か所で決められ、許可のスイッチ 1 つで止められる。端末のローカルのサーバーに「人としてホストへ話す」一般の口を渡す案（`/ws` で `loadSession` を読む）は、承認の答えを直接送る案と同じ理由で採らない。更新を差分の引き直しにしたのは、今の詳細の読み直し（`refreshDetail`）と同じ作りで済み、ホストに誰が何を見ているかの状態を持たせずに済むから（遅れは最大 4 秒で、手元の詳細と同じ）。

## 影響

- ホストの接続口に、`/agent` を受けるモジュール（`core/remote/agent-port.mjs`）が増える。端末の main にも、ホストへの線（`core/remote/agent-link.mjs`）と、ローカルのサーバーとの橋（`desktop/remote-agent-bridge.cjs`）が増える。`npm start` の端末（main が無い）は対象外。
- `devices.json` の端末に `agentDelegation`、`hosts.json` のホストに `agentUse`（どちらも真偽。上限の決まった台帳）。委譲のタスクは今の `agent_tasks` の行で、端末の行には `host`・ホスト側の `taskId` を持たせる。
- 端末側のタスクは、手元の完了通知の仕組みで依頼元の会話に届く。無音・コマンドの通知（ホストの子が黙っている・長いコマンド）は、初版ではホスト側の便りに含めない。
- docs/remote.md の §1・§4.2・§9・§11-8、docs/agent-delegation.md、docs/design.md の human-only の一覧を更新する。ADR 0013・0082・0094 には、この ADR を指す追記を 1 行足す。
- 端末とホストの版が合わないとき、古い方は `/agent` を知らない（RESET 3）。端末は「ホストが未対応」として扱い、手元の委譲は影響を受けない。
- `/agent` に `view`・`viewed` の便りが増える（ホスト: `core/remote/agent-port.mjs`・`agent-view.mjs`。端末: `agent-link.mjs`・`agent-service.mjs`・`core/remote-delegation.mjs`・操作 `delegation.hostView`）。`AGENT_PROTO` は上げず、`ready` に `view` を足して見分ける（読み出しを知らない新しい端末 → 古いホストは `view` が無いので今の 2 つの箱、古い端末 → 新しいホストは `view` を使わないだけ）。

## 採らなかった案

- **新しい MCP（`ply_remote`）・ホストの操作の一覧を中継越しに呼ぶ道具（`call_op`）**: ホストの OS を端末の AI が 1 手ずつ動かす形になり、往復と送る量が増え、ホストの画面に承認が出ず、ADR 0010 と computer use の守りを作り直すことになる。
- **端末の main が人の `/ws` で承認の答えをホストへ直接送る**: 上の理由。
- **経過を端末の人の `/ws`（`loadSession`）で読む**: ホストの全会話・設定が見える人の権限をローカルのサーバーに渡し、見せる範囲を絞る層が無く、許可を切っても読めてしまう。
- **経過をホストが押し出す（購読）**: 差分の引き直しで足りる（遅れは手元の詳細と同じ最大 4 秒）。ホストに購読の台帳（端末・タスク・口）を持たせ、切れ・取り消し・許可を切る・版替えで外す後始末が要る。遅れが気になると分かってから、差分の上に足せる。
- **ホスト側で承認モードの上限を持つ**: 利用者が採らなかった（手元と同じ振る舞い）。
- **委譲の自動の振り分けがホストを候補に入れる**: 初版は AI が `host` を書いたときだけ。将来の選択肢として残す。

## 追記（2026-10-09）: 深さの上限と、任された会話からの host の禁止を外した

深さの上限と、任された会話からの host の禁止を外した。理由：利用者の判断で、手元の委譲（2026-09-27 に上限を廃止）と揃える。「決定」の「ホストでの出どころと歯止め」のうち、「任された会話からは、さらに `host` を指定させない」「ホストから先へ渡る鎖は作らない」「委譲の深さの上限（4）」が外れ、ホストどうしが互いに任せ合う鎖（A → B → A …）も作れる。端末ごとの同時タスク数（8）と依頼の頻度（1 分に 20 件）の上限は、そのまま残す。
