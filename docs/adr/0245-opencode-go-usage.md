# OpenCode の使用量を Go の契約枠で読む

## 状態

承認（2026-10-22）

## 状況

OpenRouter のキー別上限は OpenCode Go の契約枠を表さない。Go のモデルに一致する枠がなく、表示と委譲の自動選択で使用量が不明になっていた。設定では先頭アカウントのコピーとアカウント配列の両方を描き、同じ枠と理由が重複していた。

## 決定

- OpenRouter のキー別枠は照会も表示もしない。Go の取得先は `GET https://opencode.ai/zen/go/v1/usage`。既存 OpenCode 認証の OAuth access または API キーを Bearer にし、cookie・追加のログイン UI は作らない。
- `usage.{rolling,weekly,monthly}.{percent,resetsAt}` を5時間・週次・月次に対応させる。percent は0〜100の百分率、rolling は300分、weekly は10080分。月次は固定30日の期間を与えず、取得したリセット日時を使う。
- Go の枠の provider は `opencode-go`。認証ストアの `opencode` とモデルの接頭辞を区別し、表示と委譲の両方で一致させる。
- ChatGPT・GitHub Copilot の枠は残す。アカウント → 接続先 → 期間で一度だけ描き、現在の接続先以外は「ほかの接続先 N」に畳む。既定モデルは実際の接続先へ解決する。
- 認証なし・OAuth期限切れ・契約なし・取得失敗を区別する。契約なしの判定には403の契約エラーを必要とし、一般の401/403・通信失敗では判定しない。前回値は同じアカウント・接続先・認証の世代でだけ引き継ぐ。生の認証・応答・例外本文は表示・記録しない。

## 理由

契約全体の3本の枠は既存認証で取得できる。モデルの接頭辞と provider の一致を保つことで、使用量の札と委譲が同じ枠を判断に使える。接続先ごとの表示とキャッシュにより、他の契約や認証変更前の値を現在の使用量として見せずに済む。

## 影響

OpenRouter のみの接続でも OpenCode の行を残し、使用量が表示できないことを伝える。設定の Pleiad での使用実績は別の集計として残す。使用量 API の互換性や取得失敗は既存の更新・再試行・前回値の仕組みで扱う。
