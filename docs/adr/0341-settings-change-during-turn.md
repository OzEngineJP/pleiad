# 0341 作業中に選んだ設定は予約し、送ったら効かせ、［今すぐ変える］で止めて続けられるようにする

- 状態: 承認（2026-11-18）
- 関係: [0067](0067-main-panel-declutter.md) の決定 6 を一部置換（設定の変化の行を出す）。[0077](0077-steer-before-reservation-while-waiting.md) の `active` の間の扱いを置換（`waiting` の扱いは維持）。[0228](0228-agent-picker-list.md)・[0252](0252-composer-column-and-header.md) の面を前提にする。

## 状況

作業中（この会話のターンが走っている間）にモデル・エフォート・承認モード・エージェントを選ぶと、その場で効くもの（Claude のモデル・承認モード）はその場で変わり、効かないものは「次のターンから適用」の予約（`nextSettings`）に入った。どちらに回るかは選ぶ人に見えず、次の問題があった。

- 選んだ値が、今の作業に効いたのか次からなのか分からない。帯の「次のターンから適用」は、その場で効いた値を語らない。
- 予約を今の作業に効かせる手段が無い。急ぎで変えたいときは、自分で止めて、同じ頼みを送り直していた。
- 作業中に送った発言は、予約があると今の作業の終わりを待つ（ADR 0077 の `active`）。予約の設定で走るのは次の送信からで、送った発言の扱いが読めない。
- 予約の後に選び直すと、予約に負けて選び直しが効かないことがあった（v3 の不具合 1）。
- Pleiad 自身の判定（承認・ツールの許可）が、作業の途中で承認モードを変えても、作業を始めたときのモードのままだった（不具合 10）。
- OpenAI Codex は、再開のターンで選んだモデルを渡していなかった。

ADR 0067 の決定 6 は「設定の変化を知らせる行は出さない」としていた。止めて続ける形にすると、行が無ければ、会話のどこから設定が変わったかが記録から分からない。

## 決定

1. **作業中に選んだ値は全部予約にする。** その場で効くものも、選んだ時点では会話の値を変えない。入力欄の上の帯は見出し「以下の設定に変更予定」と、項目「名前: **値**」（エージェント → モデル → エフォート → 承認モードの順）、右に［今すぐ変える］［取り消す］を出す。作業中でなければ今までどおり帯を出さず、次の送信がそのまま新しい設定で動く。
2. **送ったら効かせる。** 作業中に送った発言は、予約を効かせてから渡す。全部がその場で効く（`setModelLive`・`setEffortLive`・`setModeLive`）なら止めずに切り替えて途中送信し、効かないものがあれば今の作業を止めて、送った発言を新しい設定の最初のターンにする。送信待ちは止めない（`paused` にしない）。
3. **［今すぐ変える］** は送らずに同じことをする。止めたときは、新しい設定で今の作業を続けさせる内部のターンを流す（AI には止めたこと・止めたコマンドの名前をそのまま伝える。画面の発言には出さない）。
4. **止めることは画面に出さない。** 止めたターンに中断の印を付けず（`interrupted: null`）、CLI の中断の行も、続けさせる文も出さない。送信待ちの理由も変えない。
5. **跡の行を出す。** 予約を効かせたら、会話に 1 行「Claude Code から OpenAI Codex に切り替えました」「エフォートを high から xhigh に変えました」を残す。止めずに切り替えたときは「作業の途中で…変えました」。値は太字、エージェントはロゴを添える。「中断」「止めた」は行にも開いた中身にも書かない。開けるのはエージェントの切り替えだけで、引き継ぎの説明を置く。行はターンの記録（presents の `settingsChange`）に残り、開き直しても出る。
6. **止める・止めないの決まり。** エージェント・作業ディレクトリ・アカウント・接続先の変更は必ず止める。Claude で、Bypass で始めていないクエリーを `bypass` に変えるときは止める。OpenAI Codex と Antigravity は必ず止める。Devin・Grok・OpenCode のエフォートは止める（その場で効かせる手段が無いため）。委譲の子は止めず、予約のまま次のターンを待つ。止めてから続くまでの上限は 20 秒で、超えたら予約のまま残して失敗を知らせ、次のターンの開始で効かせる。
7. **返答が終わって裏のコマンドだけを待つ間（`phase: waiting`）は止めない。** 送った発言は今の設定のまま途中送信し、予約と帯を残して次のターンから効かせる（ADR 0077 のまま）。
8. 予約の後に選び直したら、走っていてもいなくても予約を書き直す。承認モードをその場で変えたら、Pleiad 自身の判定もその時点から新しいモードで行う。OpenAI Codex はターンの開始ごとに選んだモデルを渡す（既定に戻したら設定ファイルのモデル）。

## 理由

- 「全部予約・送ったら効く」なら、選んだ値がいつ効くかの答えが 1 つになる。帯が今の作業との違いを全部語り、選ぶ人は効く・効かないの区別を覚えなくてよい。
- 送った発言は、たいてい新しい設定で頼みたいもの。予約の後に送ったのに古い設定で走る（または待たされる）のは、送った意図とずれる。
- 止めたことを行に書くと、使う人は失敗が起きたと受け取り、［今すぐ変える］を避けるようになる（v5 の確認）。設定が変わったことだけ書けば、記録として十分に読める。
- 裏のコマンドだけを待つ間に止めると、終わらない裏（開発サーバー・ブラウザー）まで止まる。この間は今までどおり、送信を先に届けるほうが害が小さい。

## 影響

- 作業中に送ると、効かないものがある予約では今の作業が止まる。止めたくなければ［取り消す］で予約を消してから送る。
- 予約を効かせた跡の行は、作業中に効かせたとき（送った・［今すぐ変える］・止めて続けた）だけ出す。作業の自然な終わりの後に予約が効く場合は、次のターンの開始で効くので行を出さない。
- バックエンドの能力の印に `liveEffort` を足す。新しいバックエンドは、エフォートをその場で変える手段があるときだけ立てる（[multi-backend.md](../multi-backend.md)）。
- ADR 0067 の決定 6 の「設定の変化を知らせる行は出さない」は、この決定の跡の行に限って置き換える。失敗の行はそのまま。

## 追記（2026-11-26）

決定 1 の「作業中でなければ予約にせず」は、実装と違っていた。止まっている会話でも、選んだ値が今の値と違えばサーバーは予約（`nextSettings`）を持つ。チップは選んだ値を出す。帯は、走っているターンがあるときと、返答が終わって裏だけを待つ間だけ出す。止まっている会話から送るときは、送った瞬間も含めて帯を出さない。

## 追記（2026-11-28）

設定を選んですぐ送ると、送信が設定を適用してから予約の保存が終わり、今と同じ予約が残ることがあった。サーバーは送信時点の設定を使う場合も、実行中のターンへの適用や次のターンの準備に先立って予約の書き込みを待つ。予約を保存する直前に会話の現在値と比べ、送信待ちの発言が現在値を変えうる間だけ、今と同じ選択も予約に残す。画面は承認モードを含めて現在値と異なる項目を表示し、変更項目が空なら帯を隠す。
