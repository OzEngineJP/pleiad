# 0318 委譲の子（孫を含む）の会話はメインの画面に出さない。どの入口から開いても、依頼元の根の会話をメインに、子をモーダルで開く

- 状態: 承認（2026-11-11）。[0315](0315-two-watch-slots-modal-right-pane.md)〜[0317](0317-modal-child-composer-stop-name-tags.md) の段 5。「子の会話をメインの画面で開く」道（頭の「会話として開く ↗」と「↖ 依頼元: 題」）を置き換える
- 承認の内容: プロダクトオーナーが「子の会話のモーダルを主と同じ部品で作り直す（6 段）」のうち、段 5「子の会話がメインの画面に現れる道をすべて無くし、モーダルを唯一の場所にする」を承認した
- 前提: [0315](0315-two-watch-slots-modal-right-pane.md)（見ている会話の枠が主とモーダルの 2 つ）・[0316](0316-modal-conversation-search-and-menus.md)（モーダルの検索とメニュー）・[0317](0317-modal-child-composer-stop-name-tags.md)（入力欄・中断・名札）

## 状況

- 子の会話は、モーダル（`#workDialog`）でも、メインの画面でも開けた。モーダルの見出しの「会話として開く ↗」で、子がメインの画面に出て、頭に「↖ 依頼元: 題」の戻り道が付いた。段 1〜4 でモーダルが主と同じ部品（右の欄・検索・メニュー・入力欄・中断・名札）を持ったので、メインに出す必要が無くなった。
- 子をメインに出す道は、見出しの ↗ のほかに 15 か所以上あった（Chrome の窓の ⋮・委譲カード・脇の検索と右クリックの「開く」・OS の通知・通知の一覧・電話の承認通知の `?open=`・起動と再接続での復元・ロックの待ち・「ほかの会話から送られた」の「開く」・Channels の bot のページ、分岐の木の行ほか）。入口ごとに行き先が違い、同じ子が主にもモーダルにも出ると、見ている会話の枠が二重になって通知の「見ているか」の判定がずれた。
- 保存していた「開いていた会話」の id（`agent-host-current`）が子のとき、起動でその子がメインに出た。

## 決定

1. **会話を開く入口は 1 つ**: `openConversation(id)`（`web/client.mjs`）。行き先の決めは `web/child-route.mjs` の `childRoute(id, 一覧)`。
   - 子でない会話はこれまでどおり `select`。
   - 委譲の子は、依頼元を辿って根まで行き（孫・ひ孫も同じ）、**根をメインに `select` し、その子を `openWork('t:<taskId>')` でモーダルに出す**。根が今の会話なら、メインは動かさない。
   - 画面の一覧の行に、子のタスクの id（`delegation.taskId`）を載せる（`core/session-list-delta.mjs` の `slimRow`）。タスクの id が無い古い記録の子、モーダルの一覧に出ない子は、根だけを開く。
   - Esc で閉じると根の会話に戻る（メインは変わっていない）。
2. **入口はすべて `openConversation` を通す**: 通知（OS・一覧・スマホ）・脇の検索と右クリックの「開く」・行のメニュー（「元の会話を開く」「分岐の木の行」）・ロックの待ち・Chrome の窓（⋮・委譲カード）・「ほかの会話から送られた」・Channels の bot のページ・起動と再接続での復元・電話の通知の `?open=`・デスクトップの「会話を開く」。
3. **無くすもの**: モーダルの「会話として開く ↗」（Channels のスレッドの `scope.openSession` も）、メインの頭の「↖ 依頼元: 題」（`#parentChatEntry`）、その翻訳キー（`session.parentLine`・`session.parentLineAria`・`dialog.work.openChat`）。
4. **残すもの（例外）**:
   - 依頼元の会話を消した子（[0147](0147-delete-sent-sessions.md)）と、端末の AI から任された子（`delegation.remote`）は、脇の一覧に行として出る根。メインで開く。頭の「⇄ 端末 の AI から」（`#remoteOriginLine`）は残す。
   - ホストに任せた子の「ホストで開く ↗」（手元の窓にホストのリモートの窓を出す。[0317](0317-modal-child-composer-stop-name-tags.md) の中断はそのまま）。
   - 親の右の欄で子のタブに切り替える動き（[0303](0303-browser-chrome-unify.md)）。
5. **検索から子を開いたとき**は、モーダルの筋の中で一致した発言へ送る。主の `revealMessage` と同じ輪を使い、目次はモーダルの目次（段 3）に渡す。
6. **保存した id の読み替え**: 起動・つなぎ直しで、保存していた会話の id が子なら、その根を開く（`restoredSession`）。**モーダルは復元しない**（開いていた子を戻すと、起動のたびにダイアログが開いて何を見ているか分かりにくい。通知・検索・`?open=` から開けば子へ行ける）。
7. **「見ている」の判定**: モーダルで見ている子（`modalWatchId()`）も、メインで見ている会話と同じに「見ている」と数える。見ている会話の完了・返事待ちの通知は出さない。
8. **承認の通知の行き先**: サーバーが載せる `via`（承認を中継した直接の依頼元）はそのまま。孫の承認は、開く側で根まで辿って、根をメインに、孫をモーダルで開く。

9. **開く途中の入れ替わり**: 開く途中には待ち（会話の読み込み・タスクの行・最初の描画）がある。待ちの間に後の `openConversation` や利用者の選び直し（`select`）があれば、前の呼び出しは何もせずに終わる（順番札 `createOpenGate`。`web/child-route.mjs`）。最後に呼んだ会話だけが開く（子 → 孫を続けて呼んでも孫で終わる）。待ちの間に利用者がモーダルを閉じた・別の子へ替えたときは、その子の筋へ検索の発言を送らない。
   - **モーダルが開いているとき**: 子でない会話・別の根の子を開くなら、先に今のモーダルを閉じる（前の根の子を上に残さない）。同じ根の別の子は、モーダルの中身を替える。
   - 最初の描画の後に溜まっていた読み直しが済むまで待ってから検索の発言へ送る。待ちは読み直しの終わりの印で起こす。上限は 3 秒で、越えたら待たずに終える（子のモーダルは開いたまま・発言へは送らない。メインに子は出ない）。

## 理由

- 子がメインとモーダルの両方に出ると、同じ会話を 2 か所で見てしまい、入力欄・承認・通知の「見ているか」が二重になる。モーダルが主と同じ部品を持った今は、メインに出す理由が無い。
- 入口が 15 か所以上あるので、1 つ漏らすと子がメインに出る。1 つの関数に集め、「行き先は子かどうか」を一覧の行（脇の一覧と同じ決まり）だけで決めれば、漏れを試験で確かめられる。
- 戻り道「↖ 依頼元」は、メインに子が出ることを前提にしていた。モーダルなら Esc で根に戻れる。
- 例外の 2 つは、脇の一覧に行として出る会話で、そこから開くのはふつうの会話を開くのと同じ。子として扱うと、一覧の行を押しても何も起きない。

## 残る場合

- 古い子（`delegation` の記録が無い子）は、一覧に載る行からは子と分からないので、ふつうの会話としてメインに出る。子と引くにはサーバーに `delegation` の問い合わせが要る。今回は直さない。

## 影響

- 一覧に無い（件数で切れた）子の id は、子と分からないので、ふつうの会話としてメインに出る。一覧が切れた古い保存の id でしか起きない。
- 保存していた子の id を根へ読み替えるので、前の版で子を開いたまま閉じた場合、次の起動は根になる。
