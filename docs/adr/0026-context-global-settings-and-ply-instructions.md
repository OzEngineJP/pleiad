# 0026 設定のコンテキストは全体の設定だけにし、「指示」に Pleiad の指示を置く

- 状態: 承認（2026-09-27）。既定の項目「委譲の進め方」は置換（0210）
- 置き換えた: 0023、0014（画面の部分）
- 置き換えられた: 0210（既定の項目「委譲の進め方」）

## 状況

設定 › コンテキストは「設定する範囲」のプルダウンで全体の設定と場所ごとの設定を切り替えていた（0014）。全体の設定を開くと、今の会話の作業場所で探した結果が一覧に並ぶため、リポジトリの AGENTS.md が「全体の設定」に出て、ホームのファイルの一覧に見えた（2026-09-27 の指摘）。「探す場所を増やす」で足した場所は、種類を問わず・探す形式も問わず、ユーザーの範囲として全部を探していた。
委譲の指示は末尾の「Pleiad が入れる指示」のカードに 1 つのスイッチだけで置き、中身は編集できなかった（0023）。自分で決まりを足したい利用者は、指示ファイルを書くしかなかった。

## 決定

- **設定 › コンテキストは全体の設定だけ。** プルダウンと、カード右上の継承の一言、末尾の「探す場所を増やす」を外す。各カード（指示・Skills・外部 MCP）は、担当（1 つ。ユーザーと作業場所で共通。0014 のまま）の下に 2 段:
  - ユーザー（~/.claude・~/.codex と足した場所）: 探す形式、見つかったもの（スイッチ）、「＋ 探す場所を足す」。
  - 作業場所（Git のルートから作業フォルダーまで）: 探す形式だけ。何が見つかるかは場所ごとなので、ここには並べない。
- **今いる場所で何が渡るかは会話の右パネル。** 種類ごとに「ユーザー／この場所と親フォルダー／追加した場所」で分けて出し、一番上に場所の面（全体の設定どおり／<親> の設定どおり／このフォルダーだけの設定 · n 項目）と「この場所だけ変える」（担当と行のスイッチをこのフォルダーだけ変える。「全体の設定に戻す」「終わる」）。場所ごとの設定（places）の形と継承はそのまま使う。
- **探す場所は種類ごと。** 足した場所はそのカードの種類にだけ効き、その段の探す形式で探す。`context-scans.json` を形式 3 にし（`roots` を種類ごとに持つ）、形式 2 の並びは 3 種すべてへ写す（今までどおり全種類で探す）。移し方は形式 1 と同じ（バックアップ・コピーの上で移行・検証・置き換え）。
- **「指示」のカードの上に「Pleiad の指示」。** Pleiad が会話に毎ターン入れる指示の一覧。並べ替え・スイッチ・中身・編集・削除、「＋ 指示を追加」（名前・本文・入れる会話〔すべて／依頼元だけ／委譲された会話だけ〕・エージェント〔Claude Code・Codex〕）。合計と項目ごとのトークン数を数字で出す。
  - 既定の項目「委譲の進め方」「委譲した会話では任せない」は編集できる（札「既定」→「既定から変更」、「既定に戻す」）。編集していない既定は辞書の文を会話の言語で引き、Pleiad の更新で新しい文面になる。
  - 「委譲の振り分けの使い方」は `ply_delegate` の約束なので編集・スイッチを持たず（札「委譲と連動」）、委譲先の自動選択が有効なときだけ入る。
  - Antigravity は会話ごとの指示を渡す口が無いので選べない（理由を一行）。
  - 入れる経路は 0023 のまま（`ply_agents` の instructions の後ろ。Claude は append、Codex は developerInstructions）。担当によらない。保存は `prefs.json` の `plyInstructions`（全体だけ）。前の版の `addedContext`（委譲の指示のスイッチ）は、既定の 2 項目のスイッチとして引き継ぐ。
- 「Pleiad が入れる指示」のカードは無くす。会話の頭の札は「Pleiad の指示 n」。

## 理由

- 設定の画面の問いは「どこでも何を渡すか」、右パネルの問いは「この場所で何が渡ったか」。全体の設定に今の場所の探索結果を混ぜると、ファイルの置き場所の一覧に見える。場所の上書きは、その場所の会話から変えるほうが、何が変わるかを見ながら決められる。
- 足した場所を全種類・全形式で探すと、Skills のつもりで足したフォルダーの AGENTS.md まで全場所に渡る。
- 委譲の指示をスイッチだけにしておくと、少し変えたいときに全部切って指示ファイルへ書き写すしかない。既定の文を編集できれば、変えた部分だけ持てる。更新のたびに編集した文を上書きしないよう、編集していない既定だけを新しい文面にする。
- 振り分けの使い方は `ply_delegate` の引数の約束そのもので、変えると委譲が壊れる。
- 採らなかった案: 場所ごとの Pleiad の指示（プロジェクト固有の決まりはリポジトリの AGENTS.md に書ける）、既定の更新を「新しい既定があります · 見る」で知らせる（編集した人に差分の判断を求めるほどの頻度ではない）。

## 影響

- 仕様は context-management.md（形式 3・探す場所）、context-runtime.md「Pleiad の指示」、画面は design-system.md §9「コンテキスト」、委譲の側は agent-delegation.md。
- 保存済みの場所ごとの設定は、その場所の会話を開かないと見えない（設定の画面から一覧できない）。
- 指示欄の中身は、項目・並び・スイッチ・振り分け・承認モード・エージェントで変わる。変えなければ同じバイト列でプロンプトのキャッシュを外さない（0023 と同じ）。

## 追記（2026-10-09）

既定の項目「委譲した会話では任せない」は、「さらに委譲しない」の一文を外し、名前を「委譲された会話でのコマンドの扱い」にした（理由: 委譲の深さの上限を廃止したのに、子へ委譲を禁じる文が残っていて、MSI の子が委譲を断った）。上の決定は書き換えない。利用者が編集した子向けの指示は上書きせず、既定のままの項目は新しい名前と文面になる。
