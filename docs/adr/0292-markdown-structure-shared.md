# 0292: 入力欄と履歴の Markdown を同じ構造の解析で描く（CommonMark のブロック・深さの上限なし）

## 状態

承認（2026-11-06）

- 関連: [0059](0059-inline-attachments-markdown-composer.md)（自分の発言と AI の返答は同じ Markdown の描画）、[0060](0060-markdown-composer-inline-attachments.md)（入力欄は Markdown をその場で整える編集欄。1 行 = 1 ブロック）、[0141](0141-rich-paste.md)（HTML の貼り付けを Markdown にする）、[0178](0178-edit-resend-in-composer.md)（送り直しは入力欄で）

## 状況

入力欄（`web/md-doc.mjs`・`web/md-editor.mjs`）と履歴（`web/render.mjs`）は、Markdown のブロックを別々の決まりで読んでいた。

- 入力欄は行頭の空白の数を 2 で割って深さにし、リストは 3 段・引用は 2 段までしか整えなかった。履歴は行頭の空白で深さを数える独自の読み方で、4 字下げ・タブ・番号の幅（`1. ` は 3 字）を CommonMark と違って読んだ。
- 同じ原文が、入力欄と履歴で違う入れ子・違う番号（`3.` から始まる並びが 1 から）・違う記号（入力欄は全段 ●）に見えた。項目の中の段落・引用・コード、引用の中の見出し・リストは、片方では構造、片方では平文だった。
- 字下げの幅も 2 か所でばらばらで、2 桁の番号が字に重なり、360px の幅で深い入れ子は字が 1〜2 字まで細った。

2026-11-06 にユーザーが、ずれを調べた報告と、直した形のモック（ToBe）を承認した。決まった形は下の「決定」と `docs/design-system.md` の「Markdown のリストと引用」に書く。

## 決定

1. **構造は CommonMark のブロックの読み方に合わせ、1 か所で解く。** `web/md-structure.mjs` の `parseStructure` が、行の並びを入れ子のブロックの木（引用・リスト・項目・段落・見出し・コード・表）にし、行ごとに「どの入れ物の記号を、その行のどこからどこまで読んだか」（`marks`）と行の役割（`role`）を返す。履歴は木を HTML にし、入力欄は行ごとの情報で 1 行の種類・字下げ・記号を決める。どちらも同じ関数を呼ぶ。
   - リストの深さの上限は無い。2 字・4 字・タブの字下げは、親の項目の中身の始まり（記号の幅＋空白）に対して読む（タブは 4 列刻み）。番号付きの並びは最初の番号を保つ（表示は数え直すが、原文は変えない）。記号の種類（`-`・`*`・`+`、`.`・`)`）が変われば別の並び。記号と番号の入れ子は混ざってよい。
   - 項目の中の段落・引用・見出し・コードは項目の中に描く。空行と詰めた・緩いリスト（tight / loose）は CommonMark のとおり（空行 2 つでも並びは切れない）。
   - 引用の深さの上限も無い。引用の中の見出し・リストは入力欄でも構造として整える。全角の `＞` は引用にしない。
   - 1 つの改行は `<br>`（チャットの今の扱い。CommonMark は soft line break をそう描いてもよい）。
   - 病的な入力で再帰が尽きないよう、記号を読む深さは 100 段まで（`MAX_NEST`。見た目の上限ではない）。
2. **字下げ・記号・番号の決まりも同じ部品から。** `listClass`（記号の種類のクラス）・`itemMarker` / `itemBullet`（入力欄に出す番号・記号の形）・`markerExtra`（2 桁以上の番号の分の幅）・`lineIndent` / `indentCss`（行の字下げ）を `md-structure.mjs` に置く。値は `web/tokens.css` の `--md-list-indent`（1 段目 1.5em）・`--md-list-step`（1 段ごとに +1.2em）・`--md-quote-indent`（12px）・`--md-quote-nest`（4px）で、履歴の `<ul>`・`<ol>`・`<blockquote>` と入力欄の行が同じ変数を使う。
   - 記号は ● ○ ■ の 3 段の周期（入力欄も。入力欄は字の • ◦ ▪ では書体で小さくなるので、`itemBullet` の形を CSS で描き、履歴の list-style と同じ大きさにする）。番号は記号の幅（`--mk` 字）だけ字下げを足し、字に重ねない。
   - 入力欄の見出し・コードは字の大きさが違うので、字下げは欄の字で固めた長さ（`@property --md-em` / `--md-ch`）で数え、履歴と同じ幅にする。
3. **狭い幅。** 字は最低 12 字を残す。履歴は 6 段以上の入れ子のリスト・引用を `.md-scroll`（`role="region"`・`tabindex="0"`・読み上げの名前 `timeline.md.scroll`）で包み、その囲みだけを横へ送る。ページは横にはみ出さない。入力欄は欄ごと横へ送る（`overflow-x:auto`。編集の欄の中に別のスクロールの囲みを作らない）。
4. **入力欄は編集の欄のまま。** 行の飾りは `md-editor.mjs` の `decorate` が、行の子要素には触れず、属性（`data-mk`・`data-bt`・`data-q`・`data-pos`・`data-fence`）と行の CSS 変数（`--md-ind`・`--md-mk-at`・`--md-bar-img`・`--md-bar-pos`）だけを付け替える。キャレット・選択・IME の変換中の字・Undo の履歴は動かない。Tab / Shift+Tab / Enter は親の項目の中身の始まりにそろえる（`1. ` の下は 3 字、`- ` の下は 2 字。タブで書いた原文はタブのまま）。空の項目で Enter して並びを抜けるときは、前に空行を挟む（挟まないと次の行は遅延の続きとして項目に入る）。
5. **畳む単位は一番外のブロックのまま。** `renderMarkdownBlocks` → 自分の発言の畳み（`bodyUnits` → `foldIndex`）は一番外のブロックごとで、リストを途中で切らない。行数の見積もり（`blockLines`）は、入れ子の字下げの分だけ 1 行の字数を減らし、全角を 2 と数える。
6. **入力欄で整えないもの。** 表・チェック欄・打ち消し線・setext の見出し・横線は、入力欄では平文の行のまま（履歴では今までどおり描く）。リンクの参照定義と文字参照（`&amp;` など）は、どちらでも読まない（文字のまま）。生の HTML は文字のまま。

## 理由

### 自前の解析とライブラリの比べ

| | 自前（`md-structure.mjs`） | markdown-it 15 | commonmark.js 0.31 | micromark 4（mdast） | marked 18 |
|---|---|---|---|---|---|
| 原文との対応 | 行ごとに入れ物の記号の文字の範囲（`marks`）と中身の始まり | ブロックの行の範囲（`map`）だけ | 節ごとの開始・終了の行と列 | 字ごとの位置（一番細かい） | 無し |
| 入力欄の 1 行の種類 | そのまま出る | 行ごとの記号の範囲は自分で数え直す | 同左 | トークンから組み直す | 使えない |
| 書きかけ（ストリーミング） | 全文を読み直す（閉じていないフェンスは末尾までコード） | 同じ | 同じ | 同じ | 同じ |
| 安全 | 生の HTML を読まない。リンク・画像の安全化は今の `render.mjs` のまま | `html:false`・`validateLink` を設定し、描画は差し替える | `safe` を設定し、描画は差し替える | 既定で HTML を出さない | 安全化しない（別の部品が要る） |
| 依存（npm の展開の大きさ） | 0（19KB の 1 ファイル） | 2.0MB ＋ 依存 6 つ | 0.67MB ＋ 依存 3 つ | 0.21MB ＋ 依存 20 前後 | 0.56MB |

- 入力欄が要るのは「この行のどこまでが外の記号で、どこから中身か」で、どのライブラリもそれを行の単位では返さない。ライブラリを入れても、行ごとの記号の範囲を数える層は自前で書くことになり、2 つの読み方がまたずれる。
- 書きかけの扱いはどれも全文の読み直しで、差が無い。安全化は今の `render.mjs`（`safeUrl`・外の画像はリンクにする・HTML は文字）を通し続けるので、ライブラリの描画は使わない。
- `web/` はバンドラーの無い素の ESM で、外部ライブラリを足さない方針（`render.mjs` の頭）。commonmark.js のブロックの読み方（開いている入れ物を続ける → 新しいブロックを始める → 段落の遅延の続き）を写した 1 ファイルなら、依存を増やさずに仕様どおりの構造が取れる。

### 見た目

- 1 段目 1.5em・以降 +1.2em は承認したモックの幅で、履歴の今の 1.6em から大きく変えず、深い段ほど字の幅を残す。記号の周期は、形だけでなく字下げと一緒に深さを見せる（モック末尾で ● だけの案とも比べた）。

## 影響

- 送る原文は変わらない（解析は表示と編集の操作だけに使う）。前の版で書いた発言も、新しい読み方で描き直される（4 字下げのリスト・番号の始まり・全角の `＞` の見え方が変わる）。
- 入力欄の操作の変化: 並びを Enter で抜けると前に空行が入る。番号の下の Tab は 3 字。全角の `＞` で始めた行は引用として続かない。
- 自分の発言の畳みの位置は、行数の見積もりの変化で少し変わることがある（リストを切らないのは同じ）。
- 試験: `tests/unit/md-doc.mjs`（構造・往復・Tab・Enter）、`tests/unit/markdown-xss.mjs`・`user-message.mjs`（履歴）、`tests/browser/composer-editor.cjs`（入力欄の飾り・操作）。
