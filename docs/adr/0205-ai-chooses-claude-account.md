# ADR 0205: 依頼元の AI が、委譲する子の Claude のアカウントを登録済みの中から選べる

- 状態: 提案
- 日付: 2026-10-13
- 関連: [agent-delegation.md](../agent-delegation.md)「Claude のアカウントを選ぶ」「子の設定を替える」、[ADR 0094](0094-human-only-five.md)、[ADR 0134](0134-parent-changes-child-settings.md)、[ADR 0040](0040-delegation-routing-headroom.md)

## 状況

委譲する子の Claude のアカウントは、自動の振り分けが使用枠で選ぶか、固定の委譲なら親の会話から継ぐかのどちらかで、依頼元の AI が書く口は無かった。[ADR 0094](0094-human-only-five.md) はアカウントを human-only の 5 つの 1 つにし、[ADR 0134](0134-parent-changes-child-settings.md) は「`ply_task_send` ではアカウントは替えない（AI はアカウントを選べない）」とした。

そのため、ユーザーが「この作業は仕事のアカウントで」「個人のアカウントの枠が切れたので別のアカウントで続けて」と頼んでも、AI は委譲の後で子のアカウントを指定も変更もできなかった。ユーザーは、AI が登録済みのアカウントを選べるようにする方向を決めた（2026-10-13）。

## 決定

1. **`ply_delegate` に省略できる `account` を足す。** 書けるのは `backend: "claude"` と一緒のときだけ。`backend` が無ければ断る（自動の振り分けは今どおりアカウントも選ぶ）。Claude 以外の `backend` も断る。
2. **`ply_task_send` に省略できる `account` を足す。** 子が Claude のとき、または同じ送信で `backend: "claude"` に替えるときだけ使える。人の入力欄と同じ予約（`nextSettings.account`）に入れるので、子の次のターンから効く。
3. **書ける名前は `ply_usage` が出す。** Claude の `accounts` の各行に `account` を付ける。ログイン中のアカウントは `login`、登録したアカウントは内部の id（`acct-` と 12 桁の 16 進）で、トークンが無い行には `runnable: false` を付ける。
   - 内部の id は登録のたびに作る乱数で、資格情報ではない。トークンは id を鍵にして別のファイルに暗号化して保存しているので、id を知ってもトークンは読めない。
   - メールアドレスは今どおり伏せ、資格情報は返さない。
   - 人が付けた表示名を名前にしなかったのは、表示名はメールアドレスを含むことがあり（伏せると一意でなくなる）、後から変えられるからである。
4. **断る。黙ってほかのアカウントに落とさない。** 次のときは、選べる名前を添えて断る。
   - 登録に無い名前。
   - トークンが無いアカウント。
   - そのモデルの使用枠が満杯と分かっているアカウント（`ply_task_send` の `quota_full` と同じ判定）。使用量が分からないだけなら断らない。
   - `host` と一緒に書いたとき。アカウントはこの PC のもので、ホストのアカウントとは別だから。ホスト側でも `account` の付いた依頼は断る。

   断る理由はすべて書く前に確かめ、断ったら何も作らず、何も変えない。
5. **`account` を書いた子は公式の接続先で走る。** 互換の接続先は Claude のアカウントのトークンを使わないので、親の会話の接続先は継がない。`ply_task_send` で互換の接続先から外れるときは、モデルを公式の一覧で確かめ直す。
6. **記録は今の筋に乗せる。**
   - 子の会話の変更の記録（欄 `account`。値は伏せた見出し。by: `agent`）。
   - タスクの `routing.target.account`・`accountLabel`。
   - `routing.changed.from` の元のアカウント。
   - 委譲カード（「依頼元が変更（元: …）」にアカウントの見出しが出る）。
7. **ADR 0094 の 5 つは変えない。** human-only のまま残るものは次のとおり。
   - アカウントの登録・ログイン・削除・一覧の操作（`claudeAccounts` など）。
   - 新しい会話の既定のアカウント（設定 `claudeAccount`）。
   - 人の会話のアカウントの切り替え。

   AI が選べるのは、自分が委譲する子のアカウントを、人がすでに登録してトークンを入れたものの中から選ぶことだけ。

## ADR 0094・0134 のアカウントの行がどう変わるか

- ADR 0094 の「アカウント」の行（AI が替えると、契約・課金の主体を替えることになる）は、**人の会話と既定**について今も成り立つ。委譲の子については、自動の振り分けがすでに使用枠で登録済みのアカウントを選んでいる。この ADR は、その選択を依頼元の AI が明示的に書ける口を足すだけで、新しいアカウントを足す・トークンを入れる・人の会話を替える力は与えない。ADR 0094 の本文は書き換えない。
- ADR 0134 の「アカウントは替えない」は、この ADR が承認されたら「`account` を書いたときだけ替える」に置き換わる。書かなければ、今どおり子の会話のアカウントのまま走る。

## 理由

- ユーザーがアカウントを指定したのに AI が従えないと、委譲を諦めて自分で作業するか、人が子の会話を開いて切り替えるしかない。人と AI が同じことをできるようにする（[ADR 0007](0007-symmetric-ai-and-human.md)）。
- 選べる範囲を「人が登録してトークンを入れたもの」に限れば、課金の主体は人が前もって認めた中に収まる。登録・削除・既定は human-only に残す。
- 知らない名前・使えないアカウントを黙って別のアカウントに落とすと、AI はユーザーの指定どおりに動いたと思い込む。`model_unknown` と同じく、断って選べる名前を返す。

## 影響

- `ply_usage` の Claude の行に `account`（と必要なら `runnable: false`）が増える。
- `ply_delegate` / `ply_task_send` の説明・Pleiad の指示（振り分けの使い方）・操作の一覧（`delegation.delegate`・`delegation.taskSend` の入力）に `account` が増える。
- 承認されたら、ADR 0134 の状態に「一部置換（0205）」を書き足す。
