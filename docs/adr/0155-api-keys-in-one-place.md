# 0155 外部サービスの API キーを設定 › API キー 1 か所にまとめる（置き場・同意の分け方・移行）

- 状態: 承認（2026-10-07）。画面の名前（「API キー」）とカードの［差し替える］は置換（0217。設定 › 秘密情報と変数のカードの［編集］の中で差し替える）
- 置き換えた: [ADR 0022](0022-delegation-routing.md) の判定器のキーの置き場と「キーの登録が外部送信の同意」、[ADR 0150](0150-voice-call.md) の通話のキーの置き場と「キーの登録が同意」。互換の接続先のキーの置き場（[ADR 0011](0011-compat-endpoints.md)）。キーの伝え方（フラグ設定のファイル・stdin。[ADR 0012](0012-compat-endpoint-key-injection.md)）と、キーを画面・ログ・エラー文に出さない決まりは変えない
- 関連: [ADR 0094](0094-human-only-five.md)（秘密の値の組にコマンドを足す。組は 5 つのまま）、docs/design.md「API キー」、docs/design-system.md「設定 › API キー」

## 状況

外部サービスのキーを入れる欄が 4 か所に散っていた。OpenRouter のキーは Claude Code の接続先・Codex の接続先・通話・委譲の判定器（Jev）で別々に持ち、Cerebras のキーは判定器だけ。保存先も `compat-endpoint-secrets.json`（接続先と判定器）と `voice-secrets.json`（通話）に分かれ、同じキーを何度も入れさせる。差し替えや削除が「どこに効くのか」はどの画面からも分からず、通話の［削除］は確認なしで消え、判定器の確認は同じキーを使う接続先や通話に触れない。「暗号化できない」の注意も画面ごとに別の文だった。

そのうえ 0022・0150 は「キーを登録すること」を外部送信の同意にしていた。キーを 1 か所にまとめるなら、「キーがあること」と「その機能がそのキーを使うこと」を分けないと、まとめた後に登録しただけで通話や判定器が送り始めてしまう。

利用者が AsIs / ToBe のモックを見て決めた（2026-10-07）。

## 決定

- **置き場は 1 つ。** 設定 › API キー（エージェント設定の直下の新しいタブ）にキーを 1 回だけ登録する。接続先・通話・判定器は「どのキーを使うか」を選ぶだけで、キーの入力欄は使う側から無くす。
  - `<data>/api-keys.json`（秘密でない台帳）: `{ keys: [{ id: 'key-…', provider, label, createdAt, lastCheck }], uses: { voice, 'judge:jev', 'judge:cerebras' }, guide, migration }`。`provider` はプロバイダー（`openrouter`・`cerebras`・接続先のプリセット名・`custom`）。`core/api-keys.mjs`、上限 200 件。
  - `<data>/api-key-secrets.json`: キーの値（`core/secret-store.mjs`。エントリ `key:<id>`。Claude のアカウント・MCP と同じ safeStorage。暗号化できない起動は 0600 の平文で、画面の注意はこのページにだけ出す）。
  - 接続先は `compat-endpoints.json` の各行の `keyRef`（値を持たない）。通話・判定器の割り当ては `api-keys.json` の `uses`（prefs の `voice` は AI も書ける設定なので置かない）。
- **同意は「選ぶ操作」に移す。** キーを登録しただけでは、通話・判定器・接続先のどれも外部へ送らない。通話・判定器は「使うキー」を人が選んで（`setApiKeyUse`）初めて送り始め、接続先は保存の時にキーを選んだとき。外部送信の注意（「選ぶと…送られます」）は選ぶ欄のすぐ下に残す。未登録ならその場で登録でき、登録先は API キー（登録して使う）。
- **画面。** カードに名前・登録済みと確認の結果・使っている所（各設定へのリンク）・［差し替える］［確かめる］［削除］。［確かめる］はキーそのものだけを確かめる（OpenRouter は `GET /key`、Cerebras は `GET /v1/models`。料金はかからない。確かめ方の無いプロバイダーは出さない）。差し替えた後は使っている所を**自動で**順に確かめ直して ✓ / ⚠ で並べる（接続先の確認は短い応答を 1 回生成するので、差し替える欄に料金の一文を出す。失敗した接続先は今までどおり `EndpointError` で止まり、黙って公式に戻らない）。削除は使っている所と削除後に起きること（通話は使えなくなる・判定器は使われなくなる・接続先の会話は選び直し）を並べて聞き直し、通話中なら通話を切る。
- **接続先のフォーム。** 「● 登録済みのキー（API キーで管理）／○ 別のキーを入れる」。別のキーも API キーに 1 件として並ぶ（置き場は 1 つ。同じプロバイダーで同じ値のキーがあれば重ねない）。
- **ページの名前は「API キー」。** 値の違う同じプロバイダーのキーをまとめる案内は、このページの先頭に節として一度だけ出す（［まとめる］［このままにする］のどちらでも二度と出ない）。まとめ直す入口やメニューの印は足さない。
- **移行（起動時・冪等）。** 古い置き場を読み、プロバイダー（接続先はプリセットか URL のホスト）と値の sha256 が同じものは 1 件、違うものは元の場所が分かる名前の別の件にする（id は値から決めるので、途中で止まってもやり直せる）。**通話・判定器は、今キーを登録済みの所だけそのキーを選んだ状態で引き継ぐ**（接続先にしかキーが無い人は「使わない」のまま。送信を始めない）。暗号化された古いキーを読めない起動（`SECRET_LOCKED`）・台帳が壊れている起動では**保留**して何も書かず、古い置き場を読み続ける（画面は理由を 1 か所に出し、編集は出さない）。壊れた古い置き場は飛ばして続け、ファイルには触れない。
- **古い置き場は消さない。** `compat-endpoint-secrets.json`（`compat-endpoint:<id>`・`delegation-routing:<service>`）と `voice-secrets.json`（`openrouter`）は移行で消さず、キーを差し替える・使うキーを選び直す・消す・接続先を保存するたびに古い方にも同じ状態を書く（消した・選ばなかったときは古い方からも消す。開発版と配布版が同じデータ置き場を使うことがあり、古い版は古い置き場だけを読むため）。古い置き場への書き込みと古いコマンド（`setVoiceKey` などは今は API キーへ橋渡しする）を外すのは次のリリース以降（段階 5）。
- **権限。** キーを入れる・差し替える・消す・割り当てる・案内に答えるコマンド（`setApiKey`・`deleteApiKey`・`setApiKeyUse`・`resolveApiKeyGuide`）は human-only の「秘密の値」の組に足す（組の数は 5 のまま。0094）。操作の一覧には `apiKeys.list`（read。値を持たず、使っている所の名前だけ）と `apiKeys.check`（write。キーそのものを確かめる。AI も呼べる）。`voice.status`・`delegation.routing`・`endpoints.list` は `hasKey` を残して `keyRef` を足す。
- **キーを別のホストへ送らない。** ホストの決まっていないプロバイダー（接続先のプリセット名・`custom`）のキーは、使った接続先の URL のホストを持ち（`host`）、そのホストの接続先でだけ選べる。まだどのホストにも結び付いていないキー（API キーのページで「その他」として登録したもの）は選べるが既定にせず、初めて保存した接続先のホストに結び付く。OpenRouter・Cerebras は URL のホストが `openrouter.ai`・`cerebras.ai` のときだけ（プリセットを選んだまま URL を別のホストへ変えたら、そのキーは使えない）。接続先のフォームは合うキーだけを出し、既定は「ホストが確かに合うキー」か「別のキーを入れる」。サーバーの確認（`connectionOf`）も、keyRef のキーと接続先のホストが合わなければ確認の前に断る。
- **読めないときは保留する。** 古い置き場の暗号化されたキーを読めない理由は問わない（`SECRET_LOCKED`・暗号器が答えない・復号に失敗する）。ファイルそのものが解析できないとき（`SECRET_FILE_BROKEN`）だけ、その置き場を飛ばす。キーを持つ接続先が keyRef を持たないときは、空のキーで送らず `EndpointError` で止まる（キーの要らない接続先 `auth: none` は今までどおり）。
- **削除は台帳を先に保存する。** 保存に失敗したら何も変わらない。接続先の keyRef を外すのはその後で、途中で止まっても、台帳に無いキーを指す参照は使うときにも次の起動（`pruneDangling`）にも止まる。移行は接続先の keyRef を結果のとおりに書き、残っていた古い keyRef は消す。
- **キーが変わったら通話を切る。** 通話中のキーと違うキーになった（差し替え・選び直し・「使わない」・削除）とき、画面へ終わりの理由（`key-changed`・`no-key`）を送って接続を閉じる。
- **伏せる。** キーの値は画面・操作の返り・ログ・イベント・エラー文に出さない（単体テストが全部に目印を入れて見る）。

## 理由

- キーを 1 か所にまとめれば、同じキーを入れ直す手間と、散った保存先・暗号化の注意の重複が無くなる。差し替え・削除が「どこに効くか」を、押す前に見せられる。
- 「登録＝同意」のままだと、まとめた後は登録しただけで通話・判定器が送り始める。選ぶ操作へ移せば、キーを置くことと送ることを分けられ、移行でも今の同意を保てる（登録済みの所だけ引き継ぐ）。
- 古い置き場を消さず同じ状態に保つのは、同じデータ置き場を開発版と配布版が使うため。古い版は古い置き場だけを見るので、消すと古い版が突然キーを失い、残して食い違えば古い版が消したはずのキーで送り続ける。
- 画面が値を持たず、割り当ても台帳に置くので、AI が書ける設定（prefs）に外部送信の同意が入り込まない。

## 追記（2026-10-08）: 割り当て `computer:decider`

[ADR 0165](0165-computer-use-wait-until-decision-model.md) の `wait_until` の問い（決定モデル pplx-decider）に使う OpenRouter のキーとして、`uses` に `computer:decider` を足した。

- 同意の分け方は通話・判定器と同じ。登録しただけでは送らず、人が選んで（`setApiKeyUse`）初めて画面を送り始める。選ぶ欄は設定 › コンピューターの操作に置き、通話と同じ部品で作る。欄の下に「wait_until に問いを付けたとき、撮った画面が OpenRouter（Perplexity）へ送られます」と書く。
- 「使っている所」（`{ kind: 'computer' }`。設定 › コンピューターの操作へのリンク）、削除の確認（「wait_until の問いは使われず、画面の差分だけで待ちます」）、差し替えた後の確かめ直しの対象になる。
- **古い置き場を持たない。** この割り当ては移行の後に足したので、移行で引き継ぐものも古い版が読むものも無い。古い置き場へ書き写さず、移行を保留している起動では「選ばれていない」とみなす（問いを使わない）。保留の間は選ぶ欄を出さない。

## 追記（2026-10-09）: 割り当て `judge:cerebras` の廃止

[ADR 0177](0177-judges-via-openrouter.md) で委譲の判定器を OpenRouter にまとめ、`uses` から `judge:cerebras` を外した（判定器は Jev・Qwen とも `judge:jev` のキー）。

- 読み込むたびに `judge:cerebras` を落とし、それがキーを指していて `judge:jev` が空なら、最初に登録した OpenRouter のキーを `judge:jev` に選ぶ。台帳は起動では書かず、次の保存で書く。
- 古い置き場からの移行では `delegation-routing:cerebras` を取り込まない（古い置き場には残す）。選んでいたことだけを同じ規則で引き継ぐ。
- 台帳にある Cerebras のキーの行と値は消さず、使う所の無いキーとして残す（利用者が消す）。［確かめる］は OpenRouter（`GET /key`）だけになり、Cerebras のキーは確かめ方の無いプロバイダーと同じ扱い。設定 › API キーの追加の選択から Cerebras を外した（互換の接続先の `cerebras.ai` の見分けは残す）。

## 追記（2026-10-10）: プロバイダー `cerebras` の廃止

[ADR 0183](0183-cerebras-is-a-plain-compatible-endpoint.md) で、名前付きのプロバイダー `cerebras` を外した（`cerebras.ai` の互換の接続先のキーは `custom`。台帳を読むとき、`provider` が `cerebras` のキーを `custom`・host なしに直す）。
