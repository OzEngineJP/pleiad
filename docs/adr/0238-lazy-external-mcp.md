# 0238 外部 MCP は一覧の写しで広告して遅延起動し、残ったプロセスは台帳で掃除する

- 状態: 承認（2026-10-20）

## 状況

外部 MCP はターンの始まりに `contextBridge.open` で全件つなぎに行っていた。呼ばれない MCP まで毎ターン起きて、作業場所が違えば別のプロセスで、終わった後も温存の 10 分までは子を抱えていた。さらにサーバーが倒れると stdio の MCP の子孫が残り、次の起動でも回収する経路が無かった（POSIX は `detached` を使っていないので木ごとの停止も届かない）。

案は 2 つあった。

- A: 外部 MCP を保持役（`core/holder`）の子に載せ、サーバーと切り離す。
- B: 一覧の写し（snapshot）をデータ置き場に残して遅延起動にし、起こしたプロセスの台帳をデータ置き場に残して起動時に孤児を掃除する。

## 決定

**B。** 画面のモックで承認済み（2026-10-20）。

- `pleiad.db` に `mcp_tool_cache`（一覧の写し。key = 項目 id + 定義の hash、最大 128 件）と `mcp_processes`（プロセスの台帳。根の PID・当時のサーバーの PID と起動時刻・閉じた/止めた記録、最大 256 行）を足す（後から足す表。形式番号は上げない）。
- 一覧の写しがある MCP は、ターンの始まりにプロセスを起こさず `standby` にしてツールを広告する。最初の `tools/call`（または resources/prompts の要求）で起きる（`wake`。同時の呼び出しは同じ起動にぶら下がるのでプロセスは 1 つ）。起きたら一覧を裏で取り直し、変わっていれば広告を差し替える。
- 一覧を持たない（初めて見る・定義が変わった）MCP は従来どおりその場で 1 回つなぎ、一覧を覚える。
- `restarted`（無停止の更新の開き直し）でも写しがあれば起こし直さず、最初の呼び出しで起きる。最初の呼び出しには従来どおり「起こし直し」注意を添える。
- 起動に失敗した呼び出しはエラーの返りにし、行は失敗へ。ターン内では起き直さない。
- 起こした stdio の根の PID は spawn が確定した時点で台帳に記録する（connect に失敗しても残る）。POSIX では `detached` でプロセスグループを分ける（`DetachedStdioTransport`）。閉じるときは Windows `taskkill /T`・POSIX `kill(-pid)` で木ごと止め、台帳の行を閉じる。
- 起動時に、台帳の閉じていない行のうち記録の親（当時のサーバー）が死んでいるものを木ごと止める。親の PID を別のプロセスが使い回しているだけかもしれないので、起動時刻を台帳と突き合わせる（突き合わせられなければ止めない＝誤爆を防ぐ側）。掃除の記録はサーバーのログと台帳だけに残し、会話には出さない。
- HTTP/SSE の MCP はローカルの子を持たないので台帳の対象外（遅延起動は同じ）。
- 画面: standby の行は中抜きの丸と「ツール n · 使うときに起動」、起きている間は脈動する丸と「起動しています」＋末尾の稼働表示に「<名前> を起動しています」。起動中の掃除は出さない。

## 理由

- A は保持役の配線・権限・生存管理まで一緒に動く必要があり、この修正の目的（起こし過ぎ・取り残し）に対して作りが大きい。B は既存の接続プールと DB の枠の中に収まる。
- 一覧の写しは「起きたら取り直す」前提なので、古い MCP を止めずに広告できる（エージェントに見えるツールは前回のまま、起きてから新しい一覧に差し替わる）。ツールの合計が 500 件を超えた場合の会計も、広告した分をそのまま数えるので変わらない。
- 台帳は「閉じた記録の無い行」だけを掃除するので、正常に閉じた MCP ・別の生きたサーバーの子には触らない。親の起動時刻の突き合わせで、PID の使い回しに対して保守側（止めない）に倒せる。

## 影響

- 呼ばれない MCP はプロセスを起こさない。ターンの送信の進み具合（「外部 MCP に接続中 n/m」）は、一覧を持たなくて実際につなぐ分だけを数える。
- サーバーが倒れても、次の起動で取り残した MCP の木を回収する。失敗した掃除はサーバーのログで追える。
- 一覧の写し・台帳は欠けても失った記録が無い（写しは取り直せる・台帳は掃除の履歴）ので、形式番号を上げず後から足す表にした。
