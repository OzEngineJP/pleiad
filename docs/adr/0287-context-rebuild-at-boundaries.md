# 0287 会話の区切りは、要約に代えて記録から組み立て直せるようにする（試験的な機能）

- 状態: 承認（2026-11-05）

## 状況

会話の区切り（放置の後・エージェントの切り替え）では、今はエージェントに頼んだ要約（`/compact`）か、履歴の JSON の写し（切り替えの引き継ぎ）を渡している。要約はエージェントが作るので何が残るか分からず、JSON の写しは発言・ツールの結果・内部の記録がそのまま入って長く、渡したものを人が確かめにくい。

区切りで渡したいのは「この会話で何があったか」であり、それは Pleiad の記録（conversations.mjs の messages・presents）がすでに全部持っている。記録から決まった形に畳めば、要約を頼まずに区切りを作れる。

## 決定

試験的な機能として「会話の区切りで、記録から組み立て直す」を置く（設定 › 試験的な機能。既定は切。形は design-system.md「記録からの組み立て直し」）。入切は次の区切りから効く。

- **引き継ぎの組み立ては区切りの種類に依らず 1 つの部品**（core/context-rebuild.mjs の `buildRebuildPackage`）。中身は、人の発言（全文。多いときは先頭と末尾をそのまま、間を 1 行の一覧に）、索引（ファイル・コマンド・URL・委譲の結果・成果物の数と先頭の並び。中身の要約はしない）、直近のやりとり（末尾から数往復、ツールの結果ごと）、履歴の全文の写し（handoff-<sha>.json）の場所。上限は `REBUILD_LIMITS` にまとめる。
- **放置後の送信の区切り**: 入っている間は放置の自動圧縮を予約も発火もしない。次の送信の直前に、圧縮と同じ条件（全体・エージェントの行が入っていて、使用トークンが最小サイズ以上）に、エージェントごとの `rebuildIdleMinutes`（プロンプトのキャッシュの持ち時間の目安）を過ぎたことを足して組み立てる。区切りの直前に今のネイティブの会話を捨て、新しい会話へ記録からの引き継ぎで渡す。
- **エージェントの切り替え**も同じ部品で組み立てる。今までの入力欄の 1 行の引き継ぎの文は変えない。
- **組み立てに失敗したら今の経路へ戻す**（捨てる前の会話を引き戻してそのまま続ける）。区切りの記録は start/complete/failed を `contextRebuild` イベントで配り、complete/failed は会話の記録（`rebuilds`）に残す。画面は「記録から組み立て直しました」の区切りのカードで、開くと渡した内訳と「渡した全文を開く」。

## 理由

- 要約はエージェント任せで内容が読めない。記録からの組み立て直しは決まった形なので、何を渡したかが区切りのカードで確かめられる。
- 区切りの度にエージェントへ往復しない分、要約の分の使用量と時間が要らない。
- 索引は「何があったか」の数と場所なので、要約にありがちな「判断の混じった抜き出し」にならない。全文が要るエージェントは写しのファイルを自分で読める。

## 影響

- 試験的な機能の間は既定は切。入れても、組み立てに失敗した境界では今までの経路（前の続き・JSON の写し）へ戻る。
- 入っている間、放置した会話の自動圧縮は止まる（設定 › 自動圧縮の面は理由と入口を出して止まった見た目にする）。切れば予約・発火ともに今までどおり。
- 会話の巻き戻しは `rebuilds` も `compactions` と同じく区切りの記録として掃除する。
