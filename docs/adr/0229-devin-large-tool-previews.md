# 0229 Devin の巨大なツール情報を表示用に縮める

- 状態: 承認（2026-10-18）

## 状況

Devin の ACP は Edit の前後の全文をツール通知に含める。大きいソースの編集で 1 行が受信上限の 1 MiB を超え、履歴再生のたびに接続が終了して同じ会話へ送信できなくなる。受信後も生の差分を保持すると、会話の記録と画面への転送が大きくなる。

## 決定

- 送信側のサイズ上限を外す。受信側の上限は 64 MiB とし、上限超過時はその行だけ次の改行まで捨て、本文を含めずログで通知する。接続を終了しない。
- 保持役と共通の行読み取りを使い、チャンクごとのバイト数の加算と行完成時の結合で処理する。
- 破棄した応答の ID は特定しない。期限なしの待機要求には通常の要求と同じ期限を設け、返事を失ったまま待ち続けないようにする。
- ツール情報は保持・保存・表示する前に上限付きの抜粋にする。巨大な差分は変更部分と短い前後、元の長さ、省略の印を残す。通常の結果テキストには共通の結果上限を使う。
- Devin CLI 自身の DB と編集の実行内容は変更しない。

## 理由

通常の Edit が復帰不能な接続障害になるのを防ぎつつ、改行の来ない出力から本体のメモリーを守る。表示用の抜粋を受信直後に作ることで、履歴再生と通常の応答の両方で巨大な差分の複製と保存を避ける。

## 影響

上限を超えた通知や承認要求は欠落する。応答の欠落は要求の時間切れになりうる。受信上限までの JSON の解析には一時的なメモリーが必要となる。表示用のツール情報から完全な差分は復元できない。

上限と処理の詳細は [multi-backend.md](../multi-backend.md#devin-acp-の大きなツール情報) に記載する。能力契約と保存スキーマは変更しない。
