# 0160 会話の頭を狭い画面で 2 行にし、宛先とモデルを 1 つのチップに、使用量を入力欄の上の帯へ

- 状態: 承認（2026-10-07。画面の形は 2026-10-07 にユーザーが承認（モック「会話の頭と入力欄の帯」の ToBe-A と「決めてほしいこと」1〜6 をすべて推奨案））

## 状況

スマホの会話の頭の行は、中身に 422px 要った（脇の開閉・パンくず 95px・通話・目次・プラグイン・使用量 67px・「…」）。360・412 の画面では題だけが縮んで 0〜20px に潰れ、ページが横に 10〜62px はみ出した（360 では「…」が画面の外）。モバイル版の殻では「⇄ ホスト名」が 0px の題の下に押し込まれた。「狭い画面: 目次・プラグインは … へ逃がさない」（2026-09-30）と「使用量はヘッダー」（2026-09-25）の決定を守ったまま収める余地が無かった。

入力欄では、「誰に送るか」（宛先のチップ。[ADR 0157](0157-unify-chat-thread.md)）と「どのモデルで動くか」（モデルのチップ）が別のチップで、面の形も置き場所も違った。

- Chats の未送信で bot を選んでも、作業ディレクトリ・モデル・承認モードのチップは会話の値のままで、bot への投稿には使われないのに効くように見えた。
- スレッドの 360・412 では、モデルのチップが幅 10〜16px に潰れて名前が消えた（Chats の詰め方がスレッドには効いていなかった）。
- スレッドのモデルの面は字の一覧のメニューで、Chats の面（エージェント・使用量・モデル・エフォート・アカウント）と別の部品だった。宛先の bot がどのエージェントで動くかはどこにも出なかった。
- スレッドの「bot なし」は、どのエージェントで動くかを選べなかった（`channels.threadSettings` は backend を受けるが、画面に口が無かった）。

入力欄の上の帯の右端の ✳（バックグラウンドの入口。[ADR 0076](0076-composer-strip-and-background-chip.md)）は、今の会話のエージェントのロゴが入力欄のどこにも無いため、「ここでエージェント・bot を選ぶ」と読まれた。使用量はスマホでは枠の名前を外した「▬ 66%」で、帯の「文脈 ▬ 31%」と別の場所・別の形の 2 つの率だった。

## 決定

形・大きさ・出る条件は [design-system.md](../design-system.md) の「会話の頭（狭い画面）」「会話の頭の行のアイコン」「入力欄と上端」「入力欄の設定」「会話の圧縮」（入力欄の上の帯）「バックグラウンド」「一時チャットの流れ」「スレッドの空間モデル」。

1. **狭い画面の頭**: 700px 以下は題を 2 行の塊にする（1 行目に題、2 行目に所属と出どころ「# 一時チャット」「⇄ ホスト名」「⇄ 端末の AI から」（委譲の子の「↖ 依頼元: 題」は [ADR 0318](0318-child-conversations-only-in-modal.md) で無くした）を弱い字で）。480px 以下で頭に残すアイコンは通話・目次・「…」だけにし、プラグインと git は「…」の先頭の「開く」行へ移す（変更ありの点は「…」の右上）。頭の行の横のはみ出しを 0 にする。2026-09-30 の「… へ逃がさない」は 481px 以上に残る。
2. **使用量は入力欄の上の帯へ**: 頭から外し、文脈のメーターと同じ形の札「5時間 ▬ 66%」で帯にいつも出す。使用量は次に送るエージェント（入力欄で選んだもの）の枠なので、入力欄の近くに置く。
3. **宛先とモデルを 1 つのチップ「誰に · どのモデル」に**し、添付のすぐ後ろ（行の先頭）に置く。bot はアイコンと名前、bot なしはエージェントのロゴ。開くと 1 枚の面: 上に宛先の札、下に選んだ宛先の動かし方（エージェント・使用量・モデル・エフォート・アカウント）。札を押すと面を閉じずに下が描き替わる。Chats の未送信とスレッドで同じチップ・同じ面。作業ディレクトリ・承認モードのチップは、宛先が実際に使う値を出す。
4. **Chats の未送信で bot を選んだときは表示だけ**: 作業ディレクトリ・モデル・承認モードは bot の既定を出し、その場では変えない（送った後、スレッドの中で変える）。最初の投稿に設定を添えるサーバーの変更はしない。
5. **承認モードは独立したチップのまま**（安全に関わるので名前を入力欄に見せる）。
6. **スレッドの「bot なし」でエージェントを選べる**。選んだエージェントは会話を作るまで画面が持ち（選び直せる）、最初の設定か最初の送信でそのエージェントの会話を作る。作った後のエージェントは替えない（会話の backend は作るときだけ決まる）。サーバーは、組み込みの bot の会話の設定の予約を bot の既定のエージェント宛てにしない（以前は作業場所などを予約すると、次のターンから Chats の既定のエージェントへ切り替わっていた）。
7. **バックグラウンドの入口は帯の右端の札**（文脈と同じ面 `--surface-1`）にし、1 本でも数を出す（[ADR 0076](0076-composer-strip-and-background-chip.md) の「2 本以上は数」を改める）。デスクトップも同じ部品。
8. **入力欄の下の行の詰め方**を Chats とスレッドで 1 つにする: ① ブランチ・段（· high）を外し、承認モードを短い名前に ② bot なら「· モデル」を外して名前だけ ③ 作業ディレクトリ 9 → 7 字・宛先とモデル 6 字（bot なしのモデル名は 4 字）まで … で詰める ④ それでも入らなければ 作業ディレクトリ → 承認モード → 宛先とモデル の順にアイコンだけ。外した字は読み上げ名と title に残る。今までの「3 字/2 字まで削る」段はやめる（「c…」「O.」は読めない）。

## 理由

- 頭で最初に読みたいのは「どこの・何の会話か」。題が消える代わりにアイコンを全部残すより、よく使う通話・目次と、それ以外をまとめた「…」に絞るほうが、題（360 で 186px）が読める。プラグインと git は変更ありの点を「…」に移せば、気付く手がかりは残る。
- 宛先とモデルは、どちらも「この送信を誰がどう受けるか」の答え。1 つのチップにすると、入力欄のチップは宛先があってもなくても 3 つにそろい、スレッドでも Chats でも同じ形・同じ面になる。bot のアイコン／エージェントのロゴが入力欄に出るので、帯の ✳ を「選ぶ所」と読まなくなる。
- Chats の未送信で bot を選んだときに効かない値を見せない。その場で変えられるようにするには投稿に設定を添えるサーバーの変更が要り、送った後のスレッドで同じことができる。
- 使用量を帯に置くと、文脈の率と同じ形で並び、何の率かが語で分かる。2026-09-25 の「設定を開かなくても目に入る」は帯で満たす。
- 2 段の面（今の宛先の動かし方 →「宛先を替える ›」）は面が短いが、宛先を替えるのに 1 回多く押す。宛先の札が多いチャンネルで面が長くなるなら見直す。

## 影響

- 頭の 2 行目は 700px 以下だけ。701px 以上はパンくずを題の左に置く今の形。
- 頭の使用量のチップ（`#usageChip`）は帯へ移り、使用量の面（全エージェント）は帯の札から開く。スレッドの入力欄は帯を使わないので、使用量の札も出さない（宛先とモデルの面の使用量の 1 行で見る）。
- 宛先のチップ（`#chatDest`）とスレッドの宛先のチップ・モデルのチップの別々の面は無くなり、`web/composer-controls.mjs` の `paintWhoChip`・`renderModel`・`fitComposerRow` を Chats とスレッドが共に使う。
- bot のページの「動かし方」は今のまま（同じ面に寄せるのは別の段）。
