# 0328 会話の Chrome のウィンドウのダウンロードを中継が拾い、エージェントと人に見せる（保存先は Chrome のまま）

- 状態: 承認（2026-11-14）
- 関連: [ADR 0148](0148-agent-browser-in-chrome.md)（エージェントからのブラウザー全体の命令 `Browser.*` を断る決定は保つ。中継自身がブラウザー全体のダウンロードのイベントを受ける点を足す）、[ADR 0294](0294-one-chrome-window-per-conversation.md)、[ADR 0321](0321-hand-over-ai-tab.md)
- 承認の内容: プロダクトオーナーが、次の 4 点を承認した。
  1. 入れるのは段 1（拾う・見せる・止める）と段 2（エージェントが保存先を決める）。ただし実装の前に、分かっていない 3 点を実機で確かめる。結果で段 2 の形が変わるなら、段 2 には入らず段 1 だけを入れる。
  2. PC の入口は ⋮ の左のボタン。スマホは ⋮ に点・メニューに「ダウンロード」・一覧は欄いっぱい。
  3. 保存先を指定しないダウンロードは、Chrome のいつもの保存先のまま。
  4. 実行ファイルなどへの人の確認は入れない（後の段）。

## 状況

エージェントが会話の Chrome のウィンドウでリンクやボタンを押すと、ファイルは人の Chrome のいつもの保存先に落ちる。中継は `Browser.*` を断るので（ADR 0148）、次のことが起きていた。

- `agent-browser download`・`wait --download` は `browser command denied` で失敗する。エージェントは、押して落とせたのか・どこに落ちたのかを知る手段が無く、保存先のフォルダーを推測して探していた。
- 人は右の欄の映像を見ているだけで、Chrome の窓は画面の外にある。ダウンロードが始まったこと・進み具合・終わったことが、Pleiad の画面のどこにも出ない。止める手段も無い。

実装の前に、本物の Chrome（157。試験用のユーザーデータ置き場に 2 つのプロフィール）で次を確かめた。

- **CDP の「既定の context」は固定でなく、最後に窓を開いた・使ったプロフィールに替わる。** 既定でないプロフィールの `browserContextId` を付けたブラウザー単位の命令（`Browser.setDownloadBehavior`・`Browser.cancelDownload`）は `Failed to find browser context for id …` で失敗する。`eventsEnabled` は接続全体の旗で、どのプロフィールのダウンロードのイベントも届く。
- **`Browser.downloadWillBegin` の `frameId` から、始まったタブを引ける。** 主フレームのリンクはタブの targetId、`target=_blank`・`window.open` は開いてすぐ消えるタブの targetId（`openerId` で元のタブが分かる）、cross-site の iframe は iframe の target の id、同じ process の iframe は target でないフレームの id。
- **`agent-browser download <selector> <path>` は、`Browser.setDownloadBehavior { behavior: 'allowAndName', downloadPath: <親フォルダー> }` をタブのセッション宛てに送り、Chrome が GUID の名前で落としたファイルを agent-browser 自身が `<path>` へ改名する。** 既にあるファイルへも黙って上書きし、作業フォルダーの外も受ける。`wait --download <path>` は改名しない。
- `behavior: 'default'` のままでも、実行できる形のファイル（無害な中身の .exe・.msi・.bat など）は警告なしに保存された。Chrome の「保存前に場所を確認」がオンのプロフィールでは、保存のダイアログが出てダウンロードは進行中のまま止まる。

## 決定

### 1. 中継が、会話のタブで始まったダウンロードだけを拾う

- 中継は Chrome への接続のたびに `Browser.setDownloadBehavior { behavior: 'default', eventsEnabled: true }` を送る。`browserContextId` は付けない。保存先は替えない。
- 届いた `Browser.downloadWillBegin` の `frameId` から会話のタブを引き、引けたものだけを会話ごとの記録（`core/chrome/downloads.mjs`）に入れる。利用者自身のダウンロードと、ほかの会話のダウンロードは記録しない。
- ダウンロードのイベントは、エージェントの接続には配らない。
- 記録は中継のプロセスの中だけに持つ（会話ごとに 50 件）。サーバーの更新・再起動で消える。終わったものは会話の 1 行として残る（4）。
- Chrome との接続が切れたとき、進行中のものは「分からない」にして画面から外す。つなぎ直して同じダウンロードの進み具合が届けば戻す。

### 2. エージェントは `ply_browser` の `list_downloads` で読む

- 状態・名前・受け取った量・始まったページの URL・保存された絶対パス（終わったもの）を、自分の会話の分だけ新しい順に返す。`wait`（120 秒まで）で進行中のものが終わるのを待てる。
- エージェントからの `Browser.setDownloadBehavior`・`Page.setDownloadBehavior`・`Browser.cancelDownload` は断り続ける。断る文で、押して始めること・`list_downloads` で確かめることを伝える。

### 3. 人は右の欄の入口と一覧で見る・止める

- 形は [デザインシステム](../design-system.md#会話のブラウザー承認済み2026-11-06) の「ダウンロード」に定める。
- 止めるのは人だけ（操作 `browser.cancelDownload`。画面とリモートの端末から）。**止めるボタンは、Chrome が止められるダウンロードにだけ出す。** 会話のプロフィールが CDP の既定の context でない間は `Browser.cancelDownload` が効かないので、ボタンを出さない。既定の context がまだ分からない間は出し、押して Chrome に断られたら、そのダウンロードは以後止められないものとして出し直す。

### 4. 終わったダウンロードは会話に 1 行残す

- 完了・失敗・止めた、のどれかになったときに、会話の行（present の `chromeDownload`）として残す。完了の行のファイル名から、ファイルを開く・ファイルの操作を出せる。

### 5. 段 2（エージェントが保存先を決める）は入れない

承認の 1 の条件に当たったので、段 2 は実装していない。確かめた結果、承認した最低線のうち 2 つを中継だけでは守れない。

- **「人が止められる」**: 会話のプロフィールが CDP の既定の context でないと、止める命令が効かない。
- **「上書きしない形だけ通す」**: 改名と上書きは agent-browser の中で起き、中継からは見えない。中継が見るのは親フォルダーまでで、最終のファイル名を知らない。

また、タブのセッション宛ての `Browser.setDownloadBehavior` が既定の context（会話のものとは限らない）に効くこと、`wait --download <path>` は改名しないことから、承認した形（agent-browser の命令をそのまま通す）とは違う作りになる。

## 理由

- **保存先を替えない（`behavior: 'default'`）。** 保存先を替える命令は既定の context にしか効かず、会話のプロフィールが既定でないときに利用者自身のダウンロードの保存先を替えてしまう。`default` と `eventsEnabled` だけなら、どのプロフィールの保存の動きも変えずにイベントだけを受けられる。
- **始まったタブを引けたものだけを拾う。** イベントはブラウザー全体のものが届く。利用者が普段の窓で落としたファイルの名前と保存先を、エージェントにも会話にも出さないため。引けなかったものは捨てる側に倒す。
- **エージェントにイベントを配らない・命令を通さない。** エージェントが必要なのは「終わったか・どこにあるか」だけで、`list_downloads` で足りる。命令を通すと、5 の 2 点を守れない。
- **止めるボタンを条件付きにする。** 押しても止まらないボタンを出さない。既定の context は中継が引き直し、替わったら一覧を出し直す。

## 影響

- `Browser.setDownloadBehavior { behavior: 'default' }` は、同じ Chrome につないだほかの CDP の客が既定の context に掛けていた保存先の設定を、既定へ戻す。Pleiad のほかに CDP で保存先を替える道具を同じ Chrome で使っている場合に限る。
- Chrome が失敗と「Chrome の側で人が止めた」を区別して返さないので、どちらも「ダウンロードできませんでした」と出す。
- 記録はサーバーの更新・再起動で消える（会話の 1 行は残る）。更新・再起動をまたいだ進行中のダウンロードは、Chrome では続くが、一覧には戻らず、終わっても会話の 1 行にならない。
- 確かめていないこと: Safe Browsing の判定が付く本物の危険なファイルでの Chrome の警告の出方、「保存前に場所を確認」の保存のダイアログが本番の隠した窓でどこに出るか、利用者が別のプロフィールの窓を前面にしただけで既定の context が替わるか。
- 段 2 を入れるなら、次の形から選び直す: 保存先は中継が自分の受け皿のフォルダーへ向け、完了後に中継自身が「上書きしない名前」で作業フォルダーへ移す。止められない間の扱いは、止めるときにそのプロフィールの隠した窓を 1 枚開いて既定にしてから止める、または完了後に受け皿のファイルを捨てる。
