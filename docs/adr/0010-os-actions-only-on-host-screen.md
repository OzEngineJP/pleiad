# 0010 OS の操作はサーバーのある PC の画面からだけ

- 状態: 承認（2026-09-23）。一部置換（0294）: 「開く」に、許可した拡張子のファイルを既定のアプリで開く操作（openDefault）を足す。ホストの画面だけ・10 秒に 5 回までは変えない

## 状況

ファイルの操作（右パネル・ツリー・会話のファイルリンク・画像）を 1 つのメニューにまとめるにあたり、「エクスプローラーで表示」「ブラウザーで開く」を足したい。これらはサーバーのある PC の上で動くので、LAN のブラウザーやリモートの窓（remote.md）から押されると、見ている人の手元ではなくホストの PC で窓が開く。既定のアプリで開くと、`.bat` や `.lnk` が実行されうる。

## 決定

- ファイルに対する操作は 1 つのメニューにまとめ、⋯・右クリック・Shift+F10 のどれでも同じ中身を開く。
- エクスプローラー・ブラウザーの操作は、**サーバーのある PC の画面から見ているときだけ**出す。遠隔では出さず、代わりの説明文も出さない（保存とコピーは残る）。
- サーバーは WebSocket の接続ごとに、接続元がループバックで中継のヘッダーが無いかを記録し（`core/os-open.mjs` の `isLocalRequest`）、`hostCapabilities` で画面に伝える。`revealPath` / `openPath` は遠隔の接続から断る。
- 「開く」は `.html` / `.htm` のファイルだけ。パスは `/file-preview` と同じ許可範囲で、実体を解決した後の値を渡す。シェルを通さない（`cmd /c start` を使わない）。10 秒に 5 回までに制限する。

## 理由

- 遠隔の画面から押せると、利用者の意図しない PC で窓が開き、実行もされうる。
- 画面で隠すだけでなくサーバーで断ると、画面の不具合や改ざんでも越えられない。
- 拡張子を絞ると、既定のアプリ経由の実行を防げる。

## 影響

- 画面の規則は design-system.md「ファイルの操作」、仕様は file-preview.md。
