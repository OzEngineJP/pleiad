# 0314 使えるエージェントが無いときは、案内・一覧・選択欄・失敗の行で知らせて、その場で直せるようにする

## 状態

承認（2026-11-11）。docs/design-system.md「エージェントの行」と docs/desktop-onboarding.md「使えるエージェントが無いとき」を置き換える。初回の案内の「あとで」は無くなる（[ADR 0033](0033-choose-working-directory-in-onboarding.md) の本文は書き換えない）。

## 状況

- エージェントが 1 つも使えなくても、初回の案内は「あとで」で閉じられ、会話画面では送信して初めて失敗が出た。失敗の行も「見つかりません」の 1 文で、どこを直せばよいかが分からなかった。
- Claude Code は本体（CLI・ログイン）のほかに SDK が要るが、画面は本体の状態だけを見せ、SDK が無いだけで送れない利用者が原因を探せなかった。
- 「使えるか」の判断が画面ごとに散らばり、入力欄・案内・設定で言うことが違っていた。
- インストールの直後やログインの直後に、利用者が状態の再確認を押し直す必要があった。

## 決定

1. 「使えるエージェントがあるか」を `web/agent-usable.mjs` の 1 つの関数で決める。Claude Code は CLI・ログイン（または確かめ済みの接続先）・SDK の 3 つ、ほかは能力の印と状態の形から読む（id の比較は `core/backends` の外に書かない）。
2. 初回の案内は閉じられない（「あとで」を無くし、Esc・外側の押下でも閉じず、使える行を選ぶまで［会話を始める］を無効にする）。歯車で設定へ行ける。
3. 2 回目以降、起動時に使えるものが 0 個なら、同じ案内を毎回出す（作業フォルダー欄なし）。使えるようになると自動で閉じる。
4. 使っている途中で 0 個になったときは、ダイアログではなく、空の会話の中央に同じ一覧を出し、送信ボタンだけ無効にする。
5. 入力欄のエージェントの選択欄は、使えるものを上、使えないものを下（その場の操作つき）に並べる。bot・ルーティンのエージェント欄も同じ部品にする。
6. 送れなかった行は、そのエージェントが使えないときだけ、いちばん近い原因を 1 行で言い、設定と同じ形の行で直させ、直ったら［再送する］を出す。
7. 行は 1 つの部品を全部の画面で使い、案内・一覧・設定の「エージェント設定」のページが見えている間は 4 秒ごとに、まだ使えると分かっていないエージェントだけを裏で再確認する。

### 出さない場面とその理由

- **未確認・確認の失敗・オフライン・時間切れ・「たぶん」**: 使えないと分かっていない。出し間違えると、使える利用者を会話から締め出す。Devin・Grok・OpenCode・Antigravity は、起動できなかった・時間切れのときは「ログインしていない」でなく「確かめられなかった」を返す。Pleiad に登録したアカウントで走るかもしれないものも「たぶん」。
- **SDK の取得の同意の記録がある場合**: 窓を出すのは、SDK を一度も取っていない（記録が無い）ときだけ。記録があって今は無いなら、取り直せるので窓は出さない。
- **ログインの期限切れ**: 窓は出さない（起動時に 0 個とは数えない）。会話が失敗したときに、失敗の行で知らせる。
- **ログインを進めている途中**: 4 秒ごとの再確認で「ログイン」へ戻さず、「待っている」を保つ。保つのはこの窓で始めたログインが走っている間だけ（ほかの窓のログインは保たない）で、ログインの案内の有効時間（10 分）を過ぎたら外す。［やめる］は返事の中身によらず必ず待ちを外し、状態を読み直して「ログイン」へ戻す。
- **確かめられなかったときの失敗の行**: 起動しただけでは出さない。送れなかった発言の原因が分かったときだけ。
- **初回の窓**: 閉じられないのは、画面とサーバーの［会話を始める］の判定がそろっているため。そろわない場合だけ閉じられる。選べる行は `canPick`（使える、または確かめたが確かめられなかった行・登録した接続先だけの行）で、窓もサーバーの completeSetup も同じ関数を通す。未確認（まだ確かめていない）の行は選べず、［状態を確認］が次の一歩。入っていない・ログアウトと確かめた・SDK が無い行は選べない。確認が失敗し続ける 1 つだけの人も、その行を選んで［会話を始める］へ進める。出し直しの窓の条件は変えない。
- **SDK の取得に失敗した（理由が出ている）が同意の記録が無いもの**: 窓の条件に数えない（一覧の［もう一度取得］で直す）。初回の窓ではその行は選べない。失敗の文は「取得できませんでした: 理由」で、理由が無いときは「:」を付けない（1 つの部品で全部の画面にそろえる）。
- **発言のある会話**: 一覧は出さない。送れなかった行（とサイドバーの行）が同じことを言うので二重にしない。空の会話へ戻ると一覧が出る。送信ボタンは押せる（押すと送れなかった行が出る）。
- **リモートの窓・スマホ**: ログインや取得はホストの PC のもので、手元では直せない。一覧と「ホストの PC でログイン」だけ見せる。
- **SDK を裏で取り直している間**: すぐ使えるようになる。案内は出さず、進捗つきの一覧にする。
- **検知できないログインの失効**: CLI は期限が切れてもログイン済みを返す。会話が 401 で失敗したときだけ、失敗の行と設定の行で知らせる（[ADR 0212](0212-claude-auth-expired.md)）。

## 理由

- 直せる場所に原因を置く。送ってから失敗を知るより、使えない時点で知り、その場で直せるほうが短い。
- 判断を 1 つの関数に集めれば、画面ごとのずれが無くなり、単体の試験で決め方を固定できる。
- 迷うときに「出さない」側へ倒すのは、案内の出し過ぎで締め出す害のほうが、出し損ねて失敗の行で知らせる害より大きいから。
- 使っている途中でダイアログを出さないのは、下書き・会話の読み返しを止めないため。

## 影響

- 初回は使えるエージェントが 1 つ無いと先へ進めない。互換の接続先だけで使う場合は、確かめ済みの接続先があれば使える扱い。
- 行の部品は設定のエージェント設定のカードにも使う。古い状態表示のスタイルは使われなくなる。
- 起動時のトーストは廃止し、サイドバーの既存の `#authNeed` の行に 1 行出す。リモートの窓では「<名前> · ホストの PC でログイン」と言う（手元では直せないので、文は一覧と同じ）。
- 試験: `tests/unit/agent-usable.mjs`（判断）、`tests/unit/onboarding.mjs`、`tests/browser/missing-agent.mjs`（本物の画面）。
