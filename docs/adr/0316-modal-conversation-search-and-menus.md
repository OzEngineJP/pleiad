# 0316 子の会話のモーダルにも、会話内検索と発言・ファイルのメニューを主と同じ部品で出す

- 状態: 承認（2026-11-11）。[0315](0315-two-watch-slots-modal-right-pane.md) の段 3（検索・メニュー）。入力欄・停止・名札は別の ADR で決める
- 承認の内容: プロダクトオーナーが「子の会話のモーダルを主と同じ部品で作り、検索とメニューを出す。分岐・編集・再送信は出さない」ことを承認した。基本方針は「主と基本的に差分を作らない」
- 前提: [0315](0315-two-watch-slots-modal-right-pane.md)（モーダルの中の右の欄・一覧の開け閉め）

## 状況

- 子の会話のモーダル（`#workDialog`）は、読むだけの筋に検索も発言のメニューもファイルのメニューも持たず、Ctrl+F は裏の主の会話を探していた。子の会話を読んでいる最中に押すと、見えていない会話の目次が開く。
- 発言のメニュー（⋮・右クリック）は、読むだけの筋では操作の列ごと外していた。ファイルのリンクの右クリックは、ダイアログの中では出さなかった。
- 会話内検索の部品（`createConversationToc`）は、document の keydown・body の下のシート・`body > main` と `#sidebar` の inert・固定の id を主の画面に決め打ちしていて、2 つ作れなかった。

## 決定

主と同じ部品を使い、モーダルだけの見た目・実装は作らない。違いは下の「主との違い」だけ。

1. **会話内検索の部品を面ごとの別のものにする。** `createConversationToc` は、筋（要素か、いまの筋を返す関数）・シートを置く先（`host`）・キーを受ける先（`keyScope`）・検索中に止める面（`inertNodes`）を受ける。省くと主の画面（document・body・main と sidebar）。主は 1 つ目（今の DOM のまま）、モーダルは 2 つ目。片方の keydown・inert・シートはもう片方に及ばない。
2. 会話の白い面の見出しの右端（主の頭の右端のボタンと同じ部品・並び。↗ の左）に、主と同じ「会話内を検索」のボタン（`#workTocEntry`。絵・名前・title・Ctrl+F は主の `#tocEntry` と同じ）と「パネルを開く」のボタン（`#workBrowserEntry`。`setupBrowserEntry` の 2 つ目で、名前・押した状態・Ctrl+Shift+B・開いている間はタブの列の ✖ へ受け渡す動きまで主と同じ）を並べる。並びは 検索・パネル・（狭いとき ⋯）・[停止]・↗。パネルは、委譲した子は子のタブ、サブエージェントは親のタブを開け閉めし（開いているタブが無ければ新しいタブ）、委譲先ホストの子には出さない。700px 以下はパネルのボタンを隠して ⋯ にたたみ（主の頭と同じ。中はパネルの開け閉めだけ）、600px 以下はタブの数 [N]。目次は、その時に選んでいる子の筋を対象にし、右の欄（0315 の付け替えでダイアログの中にある）に出す。位置（右）・幅（340px）・文言・並び順・既定の範囲（発言）・現在の一致の印・発言への移動は主と同じ。子を替える・読み直すと目次は閉じて作り直す。
3. **Ctrl+F・Ctrl+Shift+B・Alt+↑↓・End は最前面の面に効く。** モーダルだけが開いている間は子の筋・子の欄、閉じれば主。設定などほかのダイアログが重なっているときは何もしない。Esc は一段ずつ（目次 → 欄 → モーダル）で、主と同じ順。760px 以下の全面の目次・700px 以下の下からのシートでも、Esc 1 回で閉じるのは目次だけ。
4. 目次と欄・一覧の関係は主と同じ規則に従う（0315 の 7。目次は右の欄に出るので、幅の計算・761〜1150px の一覧の自動の畳み・700px 以下の下からのシート・760px 以下の全面は同じ）。
5. **発言のメニュー**（⋮・右クリック・長押し・Shift+F10）は主と同じ部品（`web/message-actions.mjs`）で、項目だけを絞る（`CHILD_MENU` = `canFork: false`, `editable: false`）。自分の発言（依頼・追加の指示）は「コピー」「エージェントに渡した原文を見る」、返答は「返答をコピー」「不適切な AI の内容を報告」。「ここから分岐」「編集して再送信」「再送信」は出さない（子から分岐は作らせない）。
6. **ファイルのメニュー**（リンクの右クリックとファイルの ⋮）は、項目も順も主と同じ（エクスプローラーで表示・既定のアプリで開く・パスをコピー・相対パスをコピー・保存）。相対パスは子の作業場所（0315 の `workContext`）で解く。中クリックは主と同じ（欄で開く）。「会話で使う」は、受ける入力欄が来る段まで出さない。作業場所を持たない中身（委譲先ホストの子）には、独自のファイルのメニューを出さない（ファイルは別のマシンにある）。
7. メニュー・目次のシート・title は、`showModal` の最前面の上に出す（ダイアログの中に置く。0315 の右の欄の ⋮ と同じ）。
8. **読むだけの子**（`subagentThread`・`hostTaskThread`）にも、検索・コピー・原文・報告を出す。原文は発言自身の文、報告は外部の URL を開くだけで、どちらも相手側の会話を要らないので出せる。委譲した子（`taskThread`）と同じ項目になる。依頼文の無い筋（依頼元の記録から依頼文が分からない読むだけの子）は、発言の並びが空でも返答があれば検索の入口を出す。

### 主との違い（これだけ）

- 「最新へ」のボタン（`.nav-latest`・文言・走っている間の弧）と Alt+↑↓・End は主と同じに出す。違いは 3 つ: 新着の青い丸は出さない（筋は読み直しのたびに作り直すので、届いた返答を数えられない）、位置を記憶しない（測るだけ）、右端の寄せは 16px（ダイアログには地図の目盛りが無い）。
- リンクの上の URL の状態行（`.url-status`）は、ダイアログでは本文の枠の左下に出す（主は入力欄の上）。出す条件（デスクトップ版のホストだけ・タッチでは出さない）は主と同じ。
- 「会話で使う」は出さない（段 4 まで）。
- 目次はダイアログの枠の内側に出る（760px 以下の全面・700px 以下のシートも枠の中）。
- 頭のボタンは 30px のまま（主の 700px 以下は押しやすい 44px）。⋯ の中は、ダイアログに会話の操作が無いのでパネルの開け閉めだけ。

## 理由

- 検索とメニューを主から分けて作ると、片方だけ直る・直らないが続く。部品に「どの面か」を渡せば、同じ規則を保てる。
- 検索は最前面の会話を探すのが自然で、子の筋が見えているときに裏の会話を探すと、目次の発言が画面にない。
- 分岐・編集・再送信は、この画面に入力欄がない（段 4 まで）うえ、子の会話の途中から分岐を作る使い方を想定していない。コピーと報告・原文は発言自身で完結する。
- 作業場所を持たない中身に独自のメニューを出すと、解けないパスを開く操作が並ぶ。

## 影響

- `web/conversation-toc.mjs` の引数が増える（省略時は従来どおり。Channels のスレッドの目次も従来どおり）。
- `web/thread-nav.mjs` を足した。モーダルの目次が使う発言の並びの取り方で、本体の `createConversationNav` と同じ「最新へ」とキー（Alt+↑↓・End）を `frame` / `keys` を渡したときだけ持つ。位置の記憶と新着の丸は持たない。
- `web/link-menu.mjs` の `.url-status` は、会話の列とダイアログの子の会話の 2 つの面にそれぞれ一行を持つ。
- `web/header-entries.mjs` の `setupBrowserEntry` を、ダイアログの頭にも 1 つ作る（引数で対象の会話を差し替える。本体の部品は変えない）。
- `web/message-actions.mjs` に `CHILD_MENU` を足した。`web/link-menu.mjs`・`web/file-preview.mjs` は、ダイアログの中でも作業場所を持つ筋のリンクにメニューを出す。
- `docs/design-system.md` の「バックグラウンド」に検索・メニューの規則を足した。
- 段 4 で入力欄を足すときは、「会話で使う」を出し、メニューの「分岐」を出すかは別に決める。
