# 通話モード（承認済み 2026-10-06、[ADR 0150](adr/0150-voice-call.md)）

声で話しかけると、聞き取って会話へ送り、返事を読み上げる。聞き取り（STT）と読み上げ（TTS）は OpenRouter の API を、ホスト（Pleiad の本体）が呼んで行う。見た目の決まりは `docs/design-system.md`「通話モード」、設定・費用の安全弁・`/voice-ws` は `docs/design.md`「通話モード」。ここは、構成・遅延の設計・測り方・確かめ方をまとめる。

## 構成

```
画面（web/voice/、素の ESM）                              ホスト（core/voice/、Node。ws は既にある）
──────────────────────────                               ───────────────────────────────────────────
engine.mjs  状態機械                                      host.mjs     /voice-ws・出来事の振り分け・キー・使用量
 ├ capture.mjs   getUserMedia → AudioWorklet → 16kHz s16le  ├ session.mjs   通話 1 本（プロトコル・限度・遅延の内訳・止めた所の覚え）
 ├ send-gate.mjs 静かな間は送らない（プリロール 300ms）      ├ cutter.mjs    発話の区切り（無音・投機・片）
 ├ turn-hold.mjs まとめ待ち（確定を溜めて 1 通にする）       ├ stt.mjs       OpenRouter の聞き取り（片・投機・予備のモデル・順番・busy）
 ├ link.mjs      /voice-ws（バイナリ + JSON）               ├ tts.mjs       OpenRouter の読み上げ（逐次 PCM）
 └ player.mjs    PCM 24kHz の再生キュー・位置              ├ reply-reader.mjs  返事の差分 → 読む文（コード・表・ログは読まない）
index.mjs   部品の差し込み（slot の契約）                    ├ wait-voice.mjs    受け取りの一言・待ちの実況（決まった文。時計は渡される）
                                                 ├ phrase-cache.mjs  決まった文の音を通話の中で 1 回だけ合成して使い回す
                                                 └ speaker.mjs   文ごとに合成を並行・中断
 ├ view.mjs        通話ボタン・マイク・スピーカー・状態の一行（×）・聞き取れなかった行・返事の下の一行
 ├ notices.mjs     失敗の知らせの出し分けと消える条件（DOM なし）
 ├ live-bubble.mjs あなたの声の吹き出し（組み立て中の文・まとめ待ちの線）
 ├ send-queue.mjs  声で確定した発言の直列の送信
 ├ chat-send.mjs / delivery.mjs  Chats へ入力欄を通さず送る・配送の一行（3 つの言い方）
 ├ sounds.mjs      効果音
 ├ reading-mark.mjs 話している場所の下線
 └ settings.mjs    設定 › 通話
```

- **別の WebSocket（`/voice-ws`）。** `/ws` は JSON のイベント配信で、大きなイベントと音声の高頻度のバイナリを同じ口に混ぜない。トークンは `/ws` と同じ（URL の `token`）。**キーを持つこの PC の画面からだけ**受ける（中継越しは 403。`ready` の `voice` も中継越しの接続には 0 を返し、通話ボタンを出さない。リモートの通話は今回の範囲外）。
- **キーはホストだけが持つ。** 設定 › 秘密情報と変数（`api-key-secrets.json`。Electron の safeStorage で暗号化。`npm start` は権限 0600 の平文）に登録した OpenRouter のキーのうち、設定 › 通話の「使うキー」で選んだもの（`setApiKeyUse`。human-only）を使う。**選んだときから音声と読み上げる文章が OpenRouter へ送られ、登録しただけ・「使わない」では何も送らない**（[ADR 0155](adr/0155-api-keys-in-one-place.md)。それまでは「キーの登録が同意」だった）。使うキーを消す・「使わない」にすると通話は切れる（`keysChanged`）。画面・ログ・エラーの文・AI の操作の返りにキーは出ない（`redactKey`。テストが見る）。確認は設定 › 秘密情報と変数の［確かめる］（OpenRouter の `GET /key`）。古い口 `setVoiceKey`・`deleteVoiceKey` は、同じ値のキーを登録して「使うキー」に選ぶ橋渡しとして残してある（後片付けで外す）。
- **ユーザーの発言は今の送信の経路へ、入力欄を通さずに送る（2026-10-07）。** まとめ待ちを終えた 1 通を画面が受け、会話へは `sendMessage` に直に渡して会話の行に置き（入力欄の書きかけに触れない・混ぜない。「送信」の節）、スレッドへは `channels.post` で送る（ホストは送らない）。返事の読み上げは、ホストが `emitGlobal` の `text.delta`・`text.end`・`userMessage`・`turnEnd`（と、待ちの実況のための `tool.start`。名前だけ）を見て作る。通話が見る会話は、Chats は会話の id、スレッドはそのスレッドの bot の会話（`store.get(id).bot` の `channelId`・`threadId`）。新しい会話は最初のターンで id が決まるので、見ていない会話の直近 3 秒は覚えておき、見始めたら渡す。

## プロトコル（`/voice-ws`）

上り: 音声フレーム（バイナリ。16kHz s16le モノラル）と JSON `hello`（見る先）・`target`・`mute`・`spk`・`halt`（`barge`＝話して割り込んだとき。同じ扱い。止めたとき鳴っていた文の `id` つき）・`resume`（続きを読む）・`discard`（まとめ待ちの取り消し。ここまでの発話を、話している最中・認識待ちのものも結果を出さずに捨てる）・`lat`・`handed`（声で送った 1 通が AI に渡った。受け取りの一言の起点）。
下り: JSON `ready`（区切りの長さ `turnHoldMs`・話して止める `bargeIn` を含む）・`error`（`code`・致命か。聞き取りの失敗は `utt` と、失敗の種類 `kind`・HTTP の `status` だけを添える。本文・キーは渡さない）・`limit`・`speaking`・`busy`（文字がまだ出そろっていない。`last` = 振った発話の番号の最大）・`partial`・`final`・`drop`・`seg`（読む文の始まり。`skip` = 言い添えの種類 `code`・`table`・`log`、決まった文（一言・実況）は `notice`）・`seg.end`・`seg.fail`・`cancel`・`turn.end`・`lat`、バイナリ `[1][文の id uint32 LE][PCM 24kHz s16le]`。詳しい項目は `core/voice/session.mjs` の冒頭。

## 聞き取り

OpenRouter の `POST /audio/transcriptions` は**同期のみ**（ストリーミングも途中結果もない）。そこで、ホストが音声を区切って送る（出どころは運営者の別の製品の有料モードの読解。`cutter.mjs`・`piece-text.mjs`・`stt.mjs` の冒頭に書いた）。

| 仕組み | 中身 |
|---|---|
| 発話の区切り | 声のあと無音 600ms（8 フレーム）か最長 30 秒（15 秒から。10 秒を超えたら最初の無音で割る扱いを 20 秒に）。声が 200ms に届かない発話（咳・物音）は送らない。音声の時計だけで動く。**区切りはここでは細かいまま**で、言いよどみを 1 通にまとめるのはクライアントの「まとめ待ち」（下） |
| 片（途中の文字） | 声の頭から 1.0 秒を超えたあと無音 171ms（息継ぎ）か 2.5 秒（強制）で切り、頭に直前の 2 秒を付けて先に送る。返った文字から前の片と重なる頭を文字合わせで除いて、吹き出しへ足す。重なりが見つからない・片が失敗したら、その発話の途中経過はあきらめて確定を待つ（二重に読むより安全）。**確定は発話全体を 1 回で認識した結果**（片のつなぎではない）。費用は片なしの約 3 倍 |
| 投機 | 無音が 341ms に届いた時点で、区切ったときと同じ音声を先に送る。声が戻れば捨てる。往復を無音の待ちに隠し、確定が約 1.1 秒 → 約 0.75 秒になる |
| 予備のモデル | `microsoft/mai-transcribe-2` は共有枠で、混む時間帯は 4〜5 割が 429。429 を受けたら待たずに予備（`assemblyai/universal-3-5-pro`）へ送る。Retry-After の間は主を「混んでいる」とみなし、片は主を飛ばして予備へ直接送る（確定と投機は主を先に試す）。前の片が予備へ行った発話は、冷却が明けても予備で揃える |
| 順番 | 区切った順に確定を出す（前の結果を待つ）。後の発話が先に返っても入れ替わらない |

## まとめ待ち（承認済み 2026-10-07、[ADR 0156](adr/0156-voice-call-turns.md)）

通話は「話している途中で細かく区切って先に認識に回す」ので、そのまま 1 通ずつ送ると、言いよどみ（「で、あのー、」「あ、なんか、」）が何通にも分かれた。そこで、確定を**クライアントで溜めて 1 通にまとめる**（`web/voice/turn-hold.mjs`。純粋な状態で、時刻は呼ぶ側が渡す）。

- **送る時**: 最後の声（クライアントが測った音量。0.012 以上）から待ち時間が過ぎ、かつホストの `busy`（話している・区切って確定を待っている）が閉じたとき。声が戻れば待ち時間は最後の声から数え直す。待ち時間は STT の確定待ちを含めない（返事の始まりは、待ち時間と確定の遅い方）。`busy` が閉じないまま 20 秒を超えたら、出ている確定だけで送る。
- **区切りの長さ**（設定 › 通話の「話の区切り」。`voice.turnHold`）: 短め 0.7 秒・**標準 1.2 秒（既定）**・長め 2.0 秒。ホストが `ready` の `turnHoldMs` で渡す。標準は、返事の始まりが今より約 0.5 秒遅れる代わりに、言いよどみが 1 通にまとまる長さ。
- **末尾の規則**（待つ長さを変える）: 末尾が「、」・つなぎ語（で・けど・から・あの・えーと…）・助詞（を・は・に…）なら 1.5 倍（標準で 1.8 秒）、文末（。・？・「です」「して」「ください」）なら 0.65 倍（標準で 0.78 秒）、言いよどみだけ（「えーと」「あの」。「はい」「うん」は答えなので除く）は 2 倍で、それでも次が無ければ送らずに捨てる。0.5〜3.2 秒に収める。
- **順番**: 後の発話の途中の文字が前の確定より先に届いても、発話の番号順に並べる。確定は先頭から途切れず確定している分だけが普通の字、あとは途中の文字（弱い字）。
- **［いま送る］・［取り消す］**: 待ち時間を待たずに送る（確定が出そろうのは待つ）・溜めた言葉を捨てる。取り消したら、送信ゲート（先読み・ハングオーバー）を初期化してホストへ `discard` を送り、ホストは話している最中の発話・認識待ちの発話を結果を出さずに捨てる（`stt.mjs` の `discard()`）。画面も `busy` の `last` までの番号の文字を捨てる（二重の守り）。取り消したあとの声は新しい発話として始まる。マイクのミュートは、いま話している分を確定させたあと、待たずに送る。
- **見え方**: 組み立て中の文は 1 つの吹き出しに伸び、下に細い線（残り）と「まだ聞いています · あと 0.7 秒で送ります」［いま送る］［取り消す］。同じ残りがマイクの縁の弧にも出る（`hold` の姿）。「考え中」は送ったあと、最初の音までだけ（言いよどみの間には出ない）。詳しくは `docs/design-system.md`「通話モード」。

## 送信（承認済み 2026-10-07）

声で確定した発言は**入力欄を通さず**、直列のキュー（`send-queue.mjs`）で話した順に 1 通ずつ会話へ送る。以前は共有の入力欄に書いて `submit()` を呼んでいたため、送信中なら黙って return して 2 通目が入力欄に残り、1 通目は await のあとで入力欄を読むので 2 通目が混ざり、書きかけの文にも触れていた。

- Chats は `chat-send.mjs` が `sendMessage`（新しい `messageId`）へ直に渡す。会話がまだ無ければ作ってから、会話を開いている途中・切り替えている途中は終わるまで待つ。受理された発言は会話の行（`.mw` の中の `.m.user`）に必ず置く。受理の応答より先に `userMessage` が届いても声の行になるよう、送る前に `messageId` を控える（`delivery.mjs`）。
- **状態は 3 つの言い方にそろえる**（声で送った行だけ。入力欄から送った発言の言い方は変えない）: ✓「AI に渡しました」／回る弧「差し込み待ち · 次の区切りで渡します」（作業中のターンへ割り込ませている最中）／時計「送信待ち · この作業が終わると送ります」＋［取り消す］（いまは渡せず順番待ち。面を一段薄くする）。記号・字・面の濃さで区別し、色だけに頼らない。送信待ちの行は入力欄の脇の送信待ちの一覧には出さない（二重に出ない）。
- 「差し込み待ち」は実際に渡っていないことの正しい表示。Claude の途中送信（`priority: "next"`）は**次のツール結果の区切り**で折り込まれ、その瞬間の `isReplay` の user が `userMessage.delivered` になる（`core/backends/claude.mjs` の `takeDelivered`）。区切りにわずかに間に合わないと次のツールが終わるまで待つ（`docs/multi-backend.md`）。この待ちそのものは CLI の仕様で、画面で消せない。渡った瞬間に「AI に渡しました」へ変わることだけが保証される。
- スレッドは `channels.post`（すぐ投稿が並ぶ）。送信待ちの状態は無い。

## 話して止める（承認済み 2026-10-07）

読み上げ中にも声を聞き、話したら読み上げを止める。以前は読み上げ中とその後 700ms はマイクの音声を捨てていた（半二重）ので、話しても認識されなかった。

- **効く条件**: 設定 › 通話の「話して読み上げを止める」（`voice.bargeIn`。既定オン）が入っていて、**エコー除去が効いている**（`voice.echoCancellation`。ブラウザーのエコー除去の制約を付けて録音している）とき。効かないときは今までの半二重のまま（読み上げの間と、終わってから **300ms**（700ms から短縮）は音声を送らない）。ヒントの一行に理由（「いまはマイクを閉じています」。エコー除去がオフならその旨）。
- **設定は通話を始めるときに決まる**（区切り・話して止める・エコー除去。録音の制約と `ready` の値）。通話中に替えたら次の通話から効く（設定の画面にも書く）。ヒントの一行は、設定の今の値ではなくこの通話の値（`engine.echoCancellation`・`bargeEnabled`）で理由を出す。
- **判定**: 読み上げ中のフレームは捨てず、読み上げ用の高い閾値（`BARGE_THRESHOLD` = 通常 0.012 の 3 倍 = 0.036）を超えた声の区間を積算し、**250ms**（約 3 フレーム）に届いたら割り込み。超えないフレームは積算を 1 フレームぶん減らす（1 フレームの途切れは次の声で取り戻せる）。スピーカーの音がエコー除去のあとも回り込んで閾値を超え続けるときは、誤って止まる（［続きを読む］で戻れる）。**この閾値は実機のスピーカーでは確かめていない**（単体は決めた入力で判定だけを見る。`tests/unit/voice-turns.mjs`）。
- **止める**: `player.cancel()`（音は 25ms で絞る）と `{ t: 'barge', id }`（止めたとき鳴っていた文）をホストへ送る。止める前の約 0.6 秒のフレームは持っておき、止めたら送信ゲートを頭から開く（話し始めが欠けない）。
- **止めた場所**: 返事の下に「ここで読み上げを止めました · [続きを読む]」（新しい発言を送るまで残る）。ホストは止めた文と、止めている間に届いた文を覚えておき（`halt`・`barge` のあと `speak` が捨てずに溜める）、`resume` で止めた文から読み直す。止めた文の番号が無い（再生が始まる前に止めた。合成は先行するので、耳に届いていない文が溜まっている）ときは、耳に届いていない最初の文から読み直す（最後の文から読んで前を飛ばさない）。読み直したあと、聞き終えた文は覚え直さない。新しい発言（`userMessage`）が来たら捨てる。［止める］ボタンも同じ扱い。

## 待っている間の声（承認済み 2026-10-07、[ADR 0158](adr/0158-voice-call-waiting.md)）

強いモデルが考えたりツールを使ったりしている間の無音で、聞こえているのか分からない、という困りごとへ。軽いモデルを足さず（遅延・費用・外部送信先が増える）、**決まった文**で答える。`core/voice/wait-voice.mjs`（時計は渡される純粋な状態）。設定 › 通話の「受け取りの一言」「待ちの実況」（`voice.ackPhrase`・`voice.narration`。既定はどちらもオン。通話を始めるときに決まる）。

| | いつ | 何を |
|---|---|---|
| 受け取りの一言 | 声で送った 1 通が AI に渡って（画面の「AI に渡しました」。画面が `handed` を送る）1.5 秒たっても、返事の読み上げ（本文が流れ始めた時点を含む）が始まっていないとき | 「はい、確認します」「少し待ってくださいね」「はい、承知しました」「ちょっと見てみますね」を順に回す（同じ文が続かない） |
| 待ちの実況 | 返事の読み上げも一言も鳴っていない無音が 6 秒続き、そのターンにツールが動いたとき。間隔は最低 12 秒、1 ターンに最大 4 回 | ツールの種類から: ファイルを読む系「ファイルを読んでいます」・検索「調べています」・コマンド「コマンドを動かしています」・Web「Web を見ています」・委譲「別のエージェントに任せています」・編集「ファイルを直しています」・画面操作「画面を操作しています」・分からないもの「作業しています」。新しいツールが動かないまま待ち続けるなら「まだ作業しています」 |

- **言わない場合**: 送信待ち・差し込み待ち（渡った合図が来ていない）・返事が先に来た・利用者が話している最中（聞き取りの `busy`）・止めた（割り込み・［止める］。次の発言が渡るまで）・そのターンが終わった・スピーカーのミュート・設定でオフ。声で送ったターンだけ（入力欄から送った発言では言わない）。
- **ツールの名前だけを見る。** ホストは `tool.start` の名前だけを通話へ渡し（`host.mjs`）、引数・ファイル名・コマンドの中身は読まない（秘密や長い文字が混ざるため）。名前 → 種類は Claude・Codex・agy の各名前（`toolKindOf`）。画面の見出し・TODO の更新などは対象にしない。
- **無音の数え始め**は、返事・一言・実況の読み上げの見積もりの終わり（文字数 × 130ms。英語は 70ms）。返事の読み上げが鳴っている間は言わない。**返事が始まったあとのターンの残りを一切言わない規則にはしていない**: 前置きの返事を読んだあとの長いツールの連鎖が、利用者の待つ無音そのものだから。うるさくならないことは、無音 6 秒・間隔 12 秒・最大 4 回で抑える。
- **一言の最中に返事の 1 文目が来たら、一言を最後まで読んでから返事に続ける。** 一言は約 1 秒で、途中で切ると語が欠ける。返事の合成は並行して進み、再生キューが文の番号順に並べる。割り込み・［止める］は一言も止める。
- **音は通話の中で 1 回だけ合成して使い回す**（`phrase-cache.mjs`）。2 回目からは TTS を呼ばず、費用の計上（`ttsChars`）も 0。最初の 1 回は、一言が出るときに合成する。
- **返事とは別の扱い**: 画面へは `seg { skip: 'notice' }`（読んでいる場所の下線を探さない・「考え中」を終わらせない・返事の最初の音の遅延 `lat` に数えない・`turn.end` の `spoke` に数えない）。

## 効果音（承認済み 2026-10-07。既定はオフ）

設定 › 通話の「効果音」: オフ／少なめ（送った音と止めた音だけ）／すべて（`voice.sounds`）。各音は約 200ms 以内で小さく、形で区別する（上がる＝始まる、下がる＝終わる・戻る、同じ音 2 回＝待ち）。読み上げ中は鳴らさない（止めた音だけ例外）。聞こえない人には画面の表示が同じことを伝える。通話の `AudioContext` は通話を終えると閉じるので、効果音は自分の `AudioContext` を持つ。

| 音 | 鳴るとき | 少なめ |
|---|---|---|
| 送りました（低めの 1 音） | まとめた 1 通が受理されたとき | ○ |
| 止めました（一気に下がる滑り） | 話して読み上げを止めたとき | ○ |
| 通話の開始（上がる 2 音）・終了（下がる 2 音） | 始まった・終えた | すべてのみ |
| 待ち（同じ音 2 回） | 声の発言が送信待ちに入ったとき | すべてのみ |
| 失敗（下がる 2 音） | 送れなかった・聞き取れなかった・読み上げられなかった | すべてのみ |

## 失敗の知らせ（承認済み 2026-10-07、[ADR 0159](adr/0159-voice-call-notices.md)。見た目は [design-system.md](design-system.md)「通話モード」）

失敗は **その場の失敗**と **通話の状態**に分かれる。画面（`web/voice/index.mjs`）は engine の `notice`（`code`・`kind`・`status`）を `web/voice/notices.mjs` の判定へ渡し、判定が出す・消すを部品へ伝える。

| 失敗 | 出る所 | 消える時 |
|---|---|---|
| 聞き取れなかった（`stt`・`stt-busy`） | 会話の末尾の 1 行。別の発話の吹き出しが出ているあいだは、その吹き出しの中 | 次に話し始めた（聞き取り中・吹き出しが出た）・通話を終えた。続けて失敗したら同じ行が「続けて N 回」に替わる（何か聞き取れたら 0 に戻る）。キーの拒否（401・403）は 1 回目から別の文 |
| 読み上げられなかった（`tts`） | 返事の下の一行（`.vc-hint` の `fail`） | 次の発言を送った・通話を終えた |
| 権限なし・マイクが見つからない | 入力欄の下の 1 行（×） | 許可が下りた・マイクが繋がった（`devicechange`）・×・次の通話 |
| キー不足・1 日の上限（`no-key`・`daily-limit`・`limit-daily`） | 同上 | 設定が変わった（`voiceChanged`・`settingsChanged` の voice）・×・次の通話 |
| マイクが使用中・始められない（`start`・`start-timeout`） | 同上 | ×・次の通話 |
| 通話の長さの上限・声が聞こえず終了・つながりの切れ（`limit-call`・`limit-idle`・`link`） | 同上 | 別の会話へ移った（通話が終わったあとも 500ms ごとに見る）・×・次の通話 |

- ホストが渡すのは失敗の種類だけ: `error { code, utt, kind, status }`（`kind` = `timeout`・`permanent`・`transient`、`status` = OpenRouter の HTTP の状態。本文・キー・応答の中身は渡さない）。`401`・`403` は「キーが拒否された」、`429` は「混み合い」。
- 時間では消さない。読む時間は人によるため、目を離している間に終わった通話の理由も、戻って読める。
- 範囲外: 声で送った発言が送れなかったとき（`sendFailed`）は、これまでどおり入力欄の下の一行（×だけが付く）。

## 読み上げ

- **逐次の PCM。** `POST /audio/speech` に `response_format: "pcm"`（24kHz mono s16le）。応答が PCM でない・レートが違うなら 1 バイトも流さずに失敗させる。奇数バイトは持ち越し、先頭の無音（0〜320ms）は声の 80ms 前まで詰める。
- **1 文目が閉じた時点で出す。** エージェントの `text.delta` を `reply-reader.mjs` が文に割る（。！？・ASCII の `.!?` のあと空白・改行）。各ブロックの 1 文目だけは、読点が 8 字を超えていればそこで切る。2 文目以降も閉じたらすぐ合成を始め（同時に 3 本まで）、音は文の番号つきで流す。並べるのはクライアントの再生キュー（前の文が終わるまで後の文の音は持つ。文の間に 120ms）。
- **読むのは返事の本文だけ。** コードのブロック・表・長い作業ログは読まず、ブロックの終わりに「コードは画面に出しました」（表・ログも同じ形）と短く言う。種類ごとに 1 ターンに 1 回。1 ターンに読む量には上限（1500 字）。記法（`**`・`` ` ``・リンク・URL・絵文字）は外して読む。
- **止める。** スピーカーのミュート（読み上げを止め、ミュート中の文は合成を頼まない。解除すると次の文から）と、返事の下の［止める］（止めた場所から「続きを読む」まで、このターンの残りは読まない）。どちらも進行中の合成を `AbortController` で中断し、鳴っている音は 25ms で絞って止める。話して止める（割り込み）は「話して止める」の節。
- **話している場所の下線**（`reading-mark.mjs`）。ホストが送る文（記法を外した読み上げの文）を、画面の返事の本文の文字から探し（句読点・空白・大小を除いた文字で突き合わせる）、その文の下に 2px の線を `requestAnimationFrame` で伸ばす。DOM は作り直さない（本文の外の層の線の幅だけを動かす）。音が出そろう前は文字数から見積もる。画面の外なら「話している場所へ ↓」。

## 遅延の設計

目標: 声の終わり → 返事の最初の音を短くする。内訳と縮め方:

| 区間 | 設計 |
|---|---|
| 声の終わり → 確定 | 無音 600ms の待ちは縮めない（行が割れる）。**投機**で往復を隠し、片で途中の文字を先に出す。区切りは音声の時計だけで決め、クライアントのゲートは区切りの無音（900ms）を流し切る |
| 確定 → 最初の文が閉じる | エージェントの速さ。**返事の全体を待たず**、1 文目が閉じた時点（または 8 字を超えた読点）で合成を出す |
| 最初の文 → 最初の音 | 逐次の PCM（最初のバイトまで約 0.35 秒）。合成は文ごとに並行。AudioContext は通話の開始時に作って resume 済み（最初の音で作ると遅れる）。再生は currentTime + 20ms から背中合わせ。先頭の無音を詰める |
| STT の混雑 | 予備のモデル（429 を待たない） |
| 画面の体感 | 話し終えたあとは「まとめ待ち」（吹き出しの下の線と縁の弧が残りを示す）。確定した文字は片で先に出ている。「考え中」は送ったあとだけ。**代償**: 返事の始まりが、待ち時間（既定 1.2 秒）と確定の遅い方になる（今より約 0.5 秒）。設定の「話の区切り」で短くできる |

## 遅延の測り方

- **ホストのログ**（標準出力）。`voice.final`（`speechEndToFinalMs` = 最後の声のフレームを受けてから確定を出すまで・STT の往復・モデル・route・投機か）、`voice.latency`（確定ごとに 1 行。`speechEndToFinalMs`・`finalToFirstTextMs`・`firstTextToSentenceMs`・`sentenceToFirstAudioMs`・`finalToFirstAudioMs`）、`voice.latency_client`（クライアントが測った確定 → 最初の音が鳴るまで）、`voice.stt.request`・`voice.tts.request`（`firstChunkMs`・`tookMs`・`audioMs`・費用）。本文とキーは出さない。
- **画面の開発用の表示。** `localStorage.setItem('ply-voice-debug', '1')` のあと通話すると、画面の左下に直近の「声の終わり→確定 / 確定→最初の文 / 文→音（ホスト）/ 確定→音」が出る。
- **声の終わり → 最初の音** = `speechEndToFinalMs` + `finalToSoundMs`（クライアント）。偽の OpenRouter では 651ms + 238ms ほど（STT 220ms・TTS 最初のバイト 150ms の模擬を含む。**本物の値ではない**）。
- **本物のキーでの測り方**（ユーザーがキーを入れてから）: (1) 設定 › 通話にキーを登録する。(2) 開発用の表示を有効にする。(3) ヘッドホンで（スピーカーだとエコーで測りが乱れる）、同じ短い質問を 10 回話して、ホストのログの `voice.latency` と `voice.final` を集める（中央値と最大）。(4) 混む時間帯の 429 の率は `voice.stt.request` の `model` が予備だった割合と、`voice.stt.cooldown` の回数。(5) エージェントの最初の文までの時間（`finalToFirstTextMs` + `firstTextToSentenceMs`）はバックエンドの速さなので、通話の遅延と分けて見る。(6) 日本語の TTS は聞き比べる（`ttsModel`・`ttsVoice` は設定で替えられる。vtc の実測では `x-ai/grok-voice-tts-1.0` が最初のバイト 344ms・誤読が少ない。`deepgram/aura-2` は速いが日本語の誤読が多い）。

## 費用の安全弁

- **1 回の通話の長さの上限**（既定 30 分）と **1 日の通話の長さの上限**（既定 120 分。この PC の日付）。超えたら通話を終える（1 日の上限に達していれば始められない）。設定 › 通話で替える。上限を上げる向きは AI からは承認カード（`guarded`）。
- **声が聞こえないまま 10 分**たった通話は終える（つけっぱなしで周りの音を送り続けない）。
- **無音・雑音を送らない。** クライアントの送信ゲート（RMS 0.012）と、ホストの区切り（声が 200ms に届かない発話は送らない・文字が空や記号だけの結果は捨てる）。
- 使用量は日ごとの台帳（`voice-usage.json`。直近 31 日。通話の長さ・聞き取りの秒数・読み上げの字数）で、設定 › 通話に今日の分を出す。

## 前提と未確認

- **Electron**: `desktop/main.cjs` の権限ハンドラーは、本体の画面（メインフレーム・同じ origin）の音声入力（`media` で `audio` だけ）に限って許可する。映像・ほかの枠・ほかの権限は今までどおり断る。Electron の実機でマイクが取れるかは**確かめていない**（ヘッドレスの Chromium で確かめた）。
- **macOS**: `NSMicrophoneUsageDescription` と `com.apple.security.device.audio-input` の entitlement（`build/entitlements.mac.plist`。electron-builder の既定の entitlement を含めた）を足した。署名・公証した配布版は**確かめていない**（Mac が無い）。
- **Android**: `RECORD_AUDIO` を足した。通話はいまは中継越しの画面に出さないので、実機は**確かめていない**。
- 中継越し（リモート）の通話・複数の端末での同時の通話は、範囲外。
- **話して止める（2026-10-07）の閾値は実機のスピーカーで確かめていない。** `BARGE_THRESHOLD`（0.036）・`BARGE_MS`（250ms）は、決めた入力での判定を単体で見ただけで、この PC のスピーカー・マイクの組み合わせ（エコー除去あり）で自分の声と読み上げの回り込みを分けられるかは未確認。誤って止まる・止まらないときは、この 2 つの値（`web/voice/engine.mjs`）と設定の「話して読み上げを止める」で調整する。
- **Claude の「差し込み待ち」**は、次のツール結果の区切りで折り込まれるまで続く（CLI の仕様。区切りにわずかに間に合わないと次のツールが終わるまで待つ）。画面は折り込まれた瞬間に「AI に渡しました」へ変わるが、この待ちは縮められない。
- **通話を終えたとき、まとめ待ちに残っていた言葉は送る**（ADR 0158。以前は捨てていた）。言いよどみだけなら捨てる。［切る］・会話を移る・つながりが切れる・上限、どの終え方でも、その言葉を話していた会話へ（会話を移っていたら移る前の会話へ、送り先を指定して）送る。画面に出ていた確定と途中の文字をそのまま 1 通にする（途中の文字は確定より誤りが多いことがある）。まだその会話を見ているなら会話の行に配送の一行が出る。別の会話へ移っていたときは、その会話の行は出せないので、読み上げ用の通知で知らせるだけ。［取り消す］で捨てた言葉は送らない。
- **受け取りの一言・待ちの実況の聞こえ方・タイミングは実機で確かめていない**（偽の TTS・時計で見た）。1.5 秒・6 秒・12 秒・4 回と、音の長さの見積もり（文字数 × 130ms）は、使って調整する。
