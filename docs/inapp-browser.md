# 会話のブラウザー

会話の右の欄は、利用者が開くファイル・フォルダー・git・プラグイン・HTML・可視化を端末内のページとして描く。PC・スマホ・Chrome が無い会話で同じタブを使い、開いただけでは会話の Chrome にタブを作らない。エージェントが開いた Web のタブは Chrome の映像で表示する。

アドレスバーの隣の「ページ ⌄」から「Chrome の映像」を選ぶと、そのページを会話の Chrome に開く。往復しても Chrome のタブを増やさず、「ページ」に戻ると保持していた iframe を表示する。端末内のタブと履歴は端末が持ち、映像のタブとは区別する。HTML はパス、可視化は元のパスまたは題を表示し、タブの印もファイル・可視化にする。

画面の形は [デザインシステム](design-system.md#会話のブラウザー承認済み2026-11-06)、決定の理由は [ADR 0294](adr/0294-one-chrome-window-per-conversation.md)〜[0297](adr/0297-screencast-ack-paced-quality.md) にある。右の欄を広げると会話に重ねて表示し、閉じると会話へ戻る。

## タブとアドレスバー

PC のタブは開いた順に並ぶ。列の頭には映す会話を選ぶ combo（「この会話」と、窓のある直接の子の会話）、右端には固定の ＋（タブの列のスクロールの外）を置く。Chrome のタブは選んだ会話の全ウィンドウのものをまとめて出し、子を選んでいる間はその子のタブだけにする。AI が操作中のタブには弧の印を付け、そのタブを選ぶとエージェントを追う。種類の印・題・閉じる × の下に戻る・進む・再読み込み・アドレスバー・「ページ ⌄」・⋯ を置く。ファイルのツリーとプレビュー／原文もこの行から操作する。タブの題を本文の上で繰り返さない。

アドレスバーは Web なら URL、ファイルなら区切りごとのパスを出す。PC もスマホも絶対パスで、PC は作業場所までを弱くする。スマホは幅が狭いので「… › 今の名前」にし、押すと絶対パス全体を文字で直せる。コピーも絶対パスになる。幅が足りなければ祖先から省き、現在の名前は最後まで残す。祖先の名前を押すとそのフォルダーへ移り、Ctrl＋クリックや中ボタンなら新しいタブで開く。今の名前・区切り・省いた部分を押すと、パス全体を文字で編集できる。Enter で移動し、Escape や欄の外で取り消す。

入力したパスは、会話の作業場所を基準に検査する。`./`・`../`・絶対パスなど、パスと分かる入力は存在しなくても検索へ送らない。曖昧な `docs/a.md` は検索せず、`./docs/a.md` のように書く案内を出す。通常の検索語は Chrome の検索先を使う。

ファイルの変更が届くと、まだ触っていないページは自動で読み直す。クリック・スクロール・選択などで触った後は「更新を表示」を出し、押すまで今の表示を保つ。入力済みのページを更新・移動・閉じるときは確認する。同じ実体パスをもう一度開く操作だけでは読み直さない。

ファイルのツリーは、右の欄が 640px 以上ならページの左側、狭ければページに重ねて出す。並べるときの初期幅は 208px、160〜320px かつ欄の 40% 以内で、境界のドラッグか左右キー（16px 単位）で変える。開閉と幅は会話ごとに覚える。重ねるときは 280px（欄の右端に少なくとも 48px を残す）で、保存した幅は変えない。矢印は選択と枝の開閉だけを行い、クリック・Enter は現在のタブ、Ctrl／⌘＋クリック・中ボタン・Ctrl／⌘＋Enter は新しいタブで開く。同じ実体パスのタブがあれば選ぶ。「現在のファイルへ戻る」「すべて畳む」、行の ⋯・右クリック・Shift+F10 を備える。狭い画面では Escape で閉じてツリーのボタンへフォーカスを戻す。

ファイルと HTML の扱いは [ファイルを会話の横で読む](file-preview.md)、保存した写しは [可視化](visualize.md) を参照。

## 人とエージェントの操作

Chrome の映像をクリック・入力・スクロールすると、そのタブは人の操作になる。画面内のページの操作では Chrome の持ち手を変えない。映像を手元で拡大・移動するだけでも変えない。ほかの映像タブではエージェントが続けられる。

画面内のページには操作の受け渡しを設けず、タブの黒い点・常設の「あなた」やエージェント名の札を出さない。Chrome の映像で人が操作したときだけ、短い「あなたが操作中」と「AI に戻す」を出す。札・行・頭の行のアイコンの印は「いま見ているタブ」ではなく「この会話に人が触っているタブがあるか」で出す。「AI に戻す」はその会話の人のタブを全部 AI に戻す（`chromeResume`）。明示的な停止の理由と人への依頼のカードは残す。

人の操作のタブは、最後に触ってから 60 秒でエージェントへ戻る。ただし `hand_to_user` で人の返事を待つ間、PC の窓を出している間、明示して止めた間は時間で戻さない。戻った直後の最初の操作は一度断り、エージェントに snapshot の撮り直しを求める。操作の持ち手の変化は、次のツールの返事にも添える。

「PC で操作する」は選んだ Chrome の窓を PC に出し、時間では戻さない。OS の窓で人が触ったことを自動検知する仕組みではない。「AI に戻す」で戻す。Windows では会話専用の窓を普段は画面の外へ隠す。macOS は OS の制約で見える窓のまま使う。

### 中継の門

エージェントへの Chrome DevTools Protocol（CDP）の中継は、会話のタブ・iframe・worker と、そこから開いたタブだけを通す。別の会話や普段の窓は一覧・イベント・ログへ出さない。接続ごとの CDP のセッションも照合する。ブラウザー全体の強い操作、ほかの出どころの保存データ、Cookie の一括取得などは断る。

人の操作のタブでは、`core/chrome/tab-holder.mjs` の `HUMAN_TAB_READS` にある読むためのコマンドと購読の解除だけを通す。snapshot・screenshot・題や URL の読み取り・接続の維持に必要なものに限る。`Runtime.evaluate`・`Runtime.callFunctionOn` は読むつもりでも断る。スクリプトの登録・実行、DOM の変更、タブを閉じること、大きさの変更も断る。`Fetch`・`Debugger`・`Overlay`・`Emulation` の購読は通さない。

Pleiad のページへの移動は、自分の会話のページと隔離した表示だけを許す。別会話のページ、本体のポート、`file:` は断り、ページ内の要求にも検査を掛ける。Cookie の結果から `pleiad_*` を除き、その Cookie の変更も断る。Pleiad のページの橋をエージェントが追加・削除することも許さない。通常の開発サーバーは、本体のポートと区別して開ける。

## 映像とページの大きさ

映像は見る画面ごとに、返事待ちの 1 枚だけを送る。返事を待つ間に届いた古い映像は残さず、最新の 1 枚へ置き換える。画面の返事が来たら次を送り、遅い端末が別の端末を待たせない。Chrome への受領の返事は画面の返事を待たずに返す。

映像の自動調整は、表示の箱と端末の Device Pixel Ratio（物理画素と表示の大きさの比）を基準に、長辺 1920px までの 7 段で行う。固定の fps や画質の選択は置かない。

| 段 | 大きさの倍率 | JPEG の品質 |
|---|---:|---:|
| 0 | 0.4 | 30 |
| 1 | 0.4 | 55 |
| 2 | 0.67 | 30 |
| 3 | 0.67 | 55 |
| 4 | 0.67 | 80 |
| 5 | 1 | 55 |
| 6 | 1 | 80 |

映像は段 3 から始める。送ってから返事までの時間から往復の通信時間を引き、直近 3 枚の中央値が 50ms を超えれば下げ、5 枚の中央値が 25ms 以下なら上げる。上げてすぐ下がった段は 30 秒試さない。複数の画面へ別の品質で撮れない Chrome では、一番低い段にそろえる。

ページが 300ms 動かなければ、段 6 の静止画を 1 枚送る。動くまで繰り返さない。最低段でも遅ければ知らせ、返事が 3 秒無ければ最後の映像を薄くして再接続する。映像だけの帯域の上限はまだ設けず、送信量を記録する。

ページの大きさは、人が操作しているスマホ、PC で開いているパネル、映像を見るだけのスマホ、エージェントだけの順で決める。スマホで操作中はその幅と高さ・DPR を使う。見るだけのスマホは幅 800 DIP（表示上の単位）と画面の縦横比、エージェントだけなら 800×800 DIP にする。変更はエージェントにも知らせる。

## PC から使う

PC の映像は普通のブラウザーのページに近い触り心地にする。文字の上のドラッグはページの選択として送り（リンク・画像の上ではページのドラッグになる）、続けた押しは 2 回・3 回と数えて語・行の選択にする。ホイールはページのスクロール。映像を手元で拡大している間は、ドラッグとホイールは映像だけを動かす。

右クリックはページを右クリックさせず、手元にメニューを出す。点の下のもの（今の選択・編集できるか・リンク）はページへの読むだけの問い合わせで決め、コピー・切り取り・すべて選択・リンクをコピー・リンクを開くを並べる。切り取りは編集できる選択のときだけ出し、リンクを開くは人の移動の口を通る。

Ctrl/⌘+C はページの選択を読んで手元のクリップボードへ書く。Ctrl/⌘+X は書けたときだけ消すキーを送る（消せるのは編集できる選択だけ）。Ctrl/⌘+A と Shift+矢印は修飾つきのキーとして送り、Ctrl/⌘+V の貼り付けは手元の文字を入力として送る。矢印キー・日本語の変換は今までどおり。

映像の上のカーソルの形は、点の下のものへ問い合わせて合わせる。カーソル・右クリックの下調べ・選択の読み取りは読むだけの問い合わせで、人の操作として数えない。映像の上を通るだけではエージェントを止めない（[ADR 0296](adr/0296-human-touch-takes-tab.md)）。

## スマホから使う

スマホの入力欄の上には「ブラウザーを開く」の入口を置く。会話に人が触っているタブがある間は、別のタブを見ていても「AI に戻す」を添える（右の欄を閉じていても戻す入口が残る）。縮小映像・残り秒・操作中の点は出さない。開いた画面は「会話に戻る／アドレス／表示切替／[N]／その他」のバーで、戻る・進む・再読み込みはその他メニューに置く。[N] のタブ一覧は全幅で、上段に閉じる・会話の切替・＋、カードは選んだ会話のタブだけを出す。タブを押した直後に選択を反映し、新しい映像・ページが届くまでアドレスバーの直下に細い読み込み線を出す。ファイル・フォルダー・git・プラグイン・HTML・可視化は端末内で描き、Chrome の映像へは表示のメニューから切り替える。全画面のページは外枠と中身の角を丸めない。

Chrome の映像の文字入力は、ページの入力位置に重ねた透明な入力欄へ直接入れる。入力モードと確定キーを合わせ、既存の値は端末へ写さない。日本語の変換中と確定を Chrome へ送る。パスワードの欄も直接打ち、重ねる欄を `type=password` にする。スマホでは打っている間だけ、パスワード管理・パスキーが端末から使えない案内をキーボードの上に出す。位置が分からなければキーボードの上に入力欄を置く。

ページの選択肢、JavaScript の確認、ファイルの選択は端末のシートで答える。ファイルは 10 個・合計 8 MiB まで端末からホストへ送り、ホストのパスを端末へ返さない。タップ、長押し、長押ししてドラッグを送れる。二本指の拡大・移動とキーボードに合わせる移動は、手元の映像だけを動かす。通信の道は [リモート対応](remote.md#85-会話のブラウザーとリンク) を参照。

## Pleiad のページと認証

通常のファイルの配信では、表示の出どころ（origin。スキーム・ホスト名・ポートの組）は 3 つに分ける。ファイルのスクリプトを Pleiad 本体の権限で実行しない。

| 出どころ | 用途 | 認証 |
|---|---|---|
| `http://127.0.0.1:<main>` | 本体の画面・WebSocket、端末内のページ | 本体の `agent_host_token` Cookie |
| `http://localhost:<pages>` | Chrome で開くファイル・フォルダー・git・プラグイン・新しいタブ・HTML の外枠 | 派生した `pleiad_pages` Cookie |
| `http://localhost:<isolated>` | 可視化の束、HTML とその資源の実行 | 可視化のハッシュ／HTML の鍵。認証 Cookie は使わない |

ファイルのページと隔離のリスナーは `127.0.0.1`・`::1` だけで待つ。本体を LAN に公開しても広げない。Host は自分の `localhost:<port>` と完全一致、HTTP は GET・HEAD だけを許す。ポートはデータ置き場の `page-ports.json` に覚え、塞がっていれば取り直し、開いていたタブの行き先も直す。

ファイルのページの Cookie は、本体の鍵から用途を分けて作る。`HttpOnly`・`SameSite=Strict`・`Path=/_pleiad/` とし、Chrome へ本体の鍵を渡さない。Cookie はポートで分かれないため、入口で `Sec-Fetch-Site` も検査する。`same-origin`・`none` と、ヘッダーの無いブラウザー以外の要求だけを受け、`same-site`・`cross-site` は断る。URL に本体の鍵を入れない。

既定のブラウザーでフォルダーを開くときは、決めた行き先だけの入場券を使う。入場券は 60 秒・一度限りで、GET かつ `Sec-Fetch-Site: none` またはヘッダー無しの入口だけで引き換える。Cookie を入れて決めたページへ移し、鍵や入場券をログへ残さない。

ファイルのページは Pleiad のテーマと言語に従う。Markdown を安全な要素へ絞り、SVG は画像として表示し、HTML・可視化の新しいタブは `pageOpen` が返す隔離 URL で開く。隔離の配信は ADR 0295 の v8 の約束に従う。ファイルのメニューなどからの頼みは、会話・タブ・送信元を確かめ、必要な確認を本体で出し、サーバーでもパスを検査し直す。

Chrome が無い会話でも同じページのタブ列・アドレスバー・ツリーを使う。ファイルを開くだけで接続を求めず、後から接続してもページを勝手に映像へ移さない。Web のリンクは既定のブラウザーで開く。

## Chrome への接続

エージェントのブラウザーは Windows と macOS 14 以上のデスクトップ版で使える。OS の操作の層と Chrome が使えないホストには、ブラウザー用の環境変数・指示・`ply_browser` を渡さない。バックエンドの能力の印 `browser` でも渡し先を絞る。

接続は設定 › ブラウザーの「つなぐ」、または会話の接続カードで人が許す。許可の前に Chrome へ確認を出さない。許可した接続の確認には Pleiad が答える。「Chrome の確認に自動で答える」をオフにした場合や押せない場合は、人が Chrome で押す。初めてリモート デバッグをオンにする操作は、確認なしの会話でも人が「オンにしてつなぐ」を押す。

接続の状態は `off`・`setup`・`consent`・`permission`・`denied`・`connected`・`unsupported` で表す。準備や確認は無期限で待ち、確認の打ち切りに備えて出し直す。接続の開始・切断・確認を前へ出す操作はホストの PC の画面からだけ行う。カードの許可と有効化はリモートの人も答えられる。

### OS ごとの層

Chrome の発見は `DevToolsActivePort` を使う。試験では `AGENT_HOST_CHROME_USER_DATA` で専用の User Data に替え、利用者の Chrome を操作しない。OS の層は `desktop/chrome-os/`、会話の窓は `core/chrome/windows.mjs` が扱う。

### プロフィールと窓

Chrome のプロフィールは会話で選び、⋯ から変更する。新しい会話の既定は設定で選べ、未選択なら Chrome の最後に使ったものを使う。既定を変えても既存の会話へは広げず、会話での変更は次に開く窓から使う。プロフィールごとのメモも残せる。表示名とフォルダー名だけを読み、メールアドレスを取り出さない。選択済みのプロフィールで窓を開けないときは、別のプロフィールへ黙って切り替えない。子の会話には作成時の選択を写す。

会話ごとのウィンドウは画面上のまとまりで、裏では描画を止めないためタブごとに OS の窓を持つ。普段使う窓は閉じない。会話の窓を閉じても必要なら開き直せる。接続の保持役が更新を越えて Chrome への接続と会話の範囲を引き継ぐ（[ADR 0167](adr/0167-chrome-connection-held-across-updates.md)）。

### エージェントへの渡し方

中継は loopback の鍵付き WebSocket で会話を分ける。`core/agent-browser.mjs` が会話ごとの設定ファイルに接続先を書き、`AGENT_BROWSER_CONFIG`・`AGENT_BROWSER_SESSION`・`AGENT_BROWSER_SOCKET_DIR` などを渡す。エージェントは設定済みの `agent-browser` を使い、`--cdp` を足したり Chrome を起こしたりしない。デーモンは会話ごとに持つ。Windows ではターンの前に起こし、標準入出力を引き継がせない（[ADR 0285](adr/0285-prestart-agent-browser-daemon.md)）。使わないまま 24 時間経ったものと、完了した子・削除した会話のものを片付ける（[ADR 0180](adr/0180-agent-browser-daemon-lifetime.md)）。

サイトを使う前の確認は既定 OFF。ON では、主フレームが別の出どころへ移ると会話で「一度だけ / このサイトは常に / 断る」を聞く。「常に」はエージェント・プロフィール・出どころごとに覚える。人の操作では聞かない。`window.open` や履歴からの復帰には移動前に止められない場合があり、断った後に閉じるか空のページへ戻す。送信や購入ごとの承認とは別の設定である。

## 人への依頼と委譲

ログインなど人の入力が要るときは `hand_to_user` を呼ぶ。人は会話のカードから映像または PC の窓を開いて操作し、終わったらエージェントへ戻す。依頼中は 60 秒で戻さない。`fill_secret` は選んだ入力欄へ秘密情報を入れ、値をエージェントへ返さない。

委譲した子の会話は別のタブの範囲を持つ。親のカードから子の依頼に答えられるが、親子のタブは混ぜない。親が閉じられるのは所有を確認できる直接の子だけである。詳しくは [エージェント間委譲](agent-delegation.md#承認の中継と承認待ちの伝達) を参照。
