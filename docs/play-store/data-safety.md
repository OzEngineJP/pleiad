# データセーフティの回答案（下書き）

Play Console の「アプリのコンテンツ › データ セーフティ」に入れる回答の案。コード（2026-11-13 の `main`）を読んで、アプリが端末の外へ送るものを確かめた結果から組み立てる。アプリの送るもの・使う SDK を変えたら、この表とプライバシーポリシー（`site/privacy/`）を一緒に直す。

Pleiad Plus（[ADR 0263](../adr/0263-accounts-and-hosted-relay.md)。運営する公式の中継とアカウント）への任意のログインが入っている。ログインしたときは、開発者の運営するサーバーが、アカウントのメール・ユーザー ID・ログインの方法と、つなぐための情報（識別子・接続元の IP・時刻・量）を受け取る。ログインしなくても、アプリは起動時と前面にいる間（5 分ごと）に Plus の設定を取りに行く（下の表。アプリの版と種類だけを送り、利用者に結び付く情報は送らない）。

## Google の定義（回答の前提）

[Google Play のデータ セーフティ セクションの情報を提供する](https://support.google.com/googleplay/android-developer/answer/10787469) より:

- **収集**は、アプリから端末の外へデータを送ること。ライブラリ・SDK と、アプリが制御する WebView が送るものも含む。SDK が集めるものも開発者が申告する。
- 収集として申告しなくてよいもの: 端末の中だけで処理するもの、**送り手と受け手のほかは（開発者も）読めないようにエンドツーエンドで暗号化して送るもの**、その場の要求のためにメモリで一時的に扱うだけのもの。
- **共有**は、集めたデータを第三者へ渡すこと。利用者の操作で利用者が予期して渡すもの・開発者の代わりに処理する事業者へ渡すものなどは共有に数えない。

## 判断が分かれるもの: 自分の中継に見える識別子

自分の中継は利用者（ホストの持ち主）が運営し、開発者は運営しない。中身はエンドツーエンドで暗号化されるが、識別子とトークンは中継が読める形で送る（つなぐ相手を決めるため）。Google の定義の「収集」は「端末の外へ送ること」なので、送り先が開発者でなくても当たると読める。Plus の公式の中継は開発者が運営するので、迷わず収集に当たる。

- **案 1（推奨・慎重な側）**: 「デバイスなどの ID」を、目的「アプリの機能」で収集と申告する（ML Kit の分と同じ種類に目的を足すだけで、回答は増えない）。
- 案 2: 利用者が自分で運営するサーバーとの通信で、開発者も第三者も受け取らないとして申告しない。

過少な申告は差し戻し・削除の理由になり、多めの申告は害が小さいので、案 1 にする。

## 回答

### 概要の質問

| 質問 | 回答 | 理由 |
|---|---|---|
| 必須のユーザーデータの種類を、アプリで収集または共有していますか | はい | ML Kit の QR コードスキャナーの収集、中継へ送る識別子（どちらもログインしなくても送る）。メールアドレス・ユーザー ID はログインが任意なので「任意」 |
| アプリで収集するユーザーデータはすべて、転送時に暗号化されますか | はい | 中継は `wss://` だけ、Plus のサーバーは `https`、ホストへはエンドツーエンド、ML Kit は HTTPS |
| ユーザーがデータの削除をリクエストできる方法を提供していますか | はい | Plus にログインするとアカウントができる（初回のログインで作られる）ので、Play のアカウント削除の要件（アプリの中の道と、Web の削除の URL）に当たるとして答える。アプリの中の道: 「アカウントを管理」（ホストの一覧のアカウントの行とシートから）で開くページで、Plus を退会できる（`mobile/www/app.js` の `Plus.openAccount()`、[ADR 0263](../adr/0263-accounts-and-hosted-relay.md) 決定 5）。退会で消えるのは Plus のデータ（つないだ PC・同期した内容・利用の記録）で、ログインに使うアカウント（メールアドレス・ユーザー ID）は残り、退会と操作の記録・通信の記録は退会の後も一定の期間残る（プライバシーポリシーの「保存の期間と削除」と同じ）。Play の要件は、アカウントと結び付くデータの削除を求め、残すものがあれば削除のページに書くことを求めるので、ログインに使うアカウントまで消せるようにするまでは、審査で指摘されうる。端末の中の情報はホストの削除・ログアウト・アンインストールで消え、自分の中継とホストの記録は利用者が持つ |
| アカウント削除の URL（Play Console の「データの削除」の欄） | https://account.pleiad.dev/account （2026-11-13 の候補。**人が確かめる**） | アプリの「アカウントを管理」は、`/v1/auth/config` の `urls.profile`（公開の設定で `https://account.pleiad.dev/profile`）を、Android は Custom Tab、iOS は既定のブラウザーで開く（`PleiadPlusPlugin.kt`・`PleiadPlusPlugin.swift` の `openAccount`、`PlusManager` の `profileUrl()`。`urls.account` は使わない）。`/profile` は `/account` へ移るので、Play の欄にはアプリを入れなくても開ける `/account` を入れる。公開のページ（未ログイン）で確かめたこと: 動く（200）、ログインのボタンが出る、ページの部品に「Pleiad Plus を退会」のリンクと、退会のあとに「退会しました」を出す処理（`?deleted=1`）がある。**確かめられていないこと**: ログインが要るため、退会の操作がアプリへ戻らずにページの中で終わるか、確認の文・削除の対象と残すもの（あれば）が書いてあるか、ページがストアの掲載のアプリ名か開発者名に触れているか（見出しは「Pleiad」だけ）。Play の要件（動く・範囲に合う・アプリへ戻らずに依頼できる・掲載の名前に触れる・残すものを書く。[アカウント削除の要件](https://support.google.com/googleplay/android-developer/answer/13327111)）に照らして、使い捨てのアカウントで退会まで試してから入れる |

### データの種類

| 種類 | 収集 | 共有 | 一時的な処理 | 必須か任意か | 目的 |
|---|---|---|---|---|---|
| アプリの情報とパフォーマンス › 診断 | はい（ML Kit） | いいえ | いいえ | 任意（QR を読まずにコードを貼ってもペアリングできる） | 分析 |
| デバイスなどの ID | はい（ML Kit の識別子、中継へ送る `deviceId`・`hostId`） | いいえ | いいえ | 必須（中継につなぐのに要る） | アプリの機能、分析 |
| 個人情報 › メールアドレス | はい（Plus にログインしたとき。ID トークンに入っていて Plus のサーバーが受け取る） | いいえ | いいえ | 任意（Plus のログインは任意。ログインしなくても自分の中継で使える） | アプリの機能、アカウント管理 |
| 個人情報 › ユーザー ID | はい（Plus のアカウントの ID（`uid`）。同じくログインしたとき） | いいえ | いいえ | 任意（同上） | アプリの機能、アカウント管理 |

要る・要らないの判断（Google の定義に照らして）:

- **メールアドレス・ユーザー ID は「収集」に当たる。** アプリが ID トークン（メール・`uid` を含む）を Plus のサーバーへ送る（端末の外へ送る）。Google の定義で「メールアドレス」は利用者のメールアドレス、「ユーザー ID」はアカウント ID などの、特定できる人に結び付く識別子。
- **「共有」には当たらない。** 送り先は開発者自身のサーバーで、ログインの基盤は開発者の代わりに処理する事業者（Google の定義で共有に数えない）。広告・解析には使わない。
- **ログインの方法（Google か Apple）・名前は、専用の種類を足さない。** アプリは名前を受け取らず（プロフィールのページはブラウザー側）、ログインの方法はユーザー ID に付く属性。受け取る内容が増えたらこの表も増やす。
- **IP アドレス・接続の時刻・量**は、Google の「データの種類」の一覧に専用の項目が無い。接続元の IP は「デバイスなどの ID」の収集に含めて申告しており、時刻・量は利用者の内容に当たらない（アプリのアクティビティの項目は「アプリの操作の記録」で、中継の接続の記録とは別）。
- **音声**は収集しない。マニフェストは `RECORD_AUDIO` を宣言しているが、いまの画面は録音しない（下の「気づいたこと」）。

既存の行（ML Kit の診断・識別子）は、Plus のログインの有無によらず変わらない。

ほかの種類（位置情報・個人情報のうち名前・住所・電話番号など・金融情報・健康とフィットネス・メッセージ・写真と動画・音声ファイル・ファイルとドキュメント・カレンダー・連絡先・アプリのアクティビティ・ウェブ閲覧）は、どれも「いいえ」。会話の中身・送るファイル・端末名はホストへのエンドツーエンドの暗号化なので申告しない。

## 気づいたこと（まだ直していない）

- QR は Google のコードスキャナー（`GmsBarcodeScanning`。Play 開発者サービスの画面）で読む。Google の説明では、これは**アプリがカメラの権限を求めなくても動き**、画像の処理は端末の中で行い、Google は画像も結果も保存しない（[Google コードスキャナー](https://developers.google.com/ml-kit/vision/barcode-scanning/code-scanner)）。今のアプリは読む前に `Scanner.requestPermissions()` でカメラの権限を求め、マニフェストに `CAMERA` がある。外せば、利用者に尋ねる権限と審査で説明する権限が 1 つ減る（プライバシーポリシーの「権限」も直す）。
- `AndroidManifest.xml` は `RECORD_AUDIO` を宣言しているが、マイクを使う画面は無い（通話モードは中継越しの画面には出さない）。使わない権限は外す。外すまでは、審査で聞かれたら「宣言だけで録音しない」と答える。データセーフティの回答（音声は収集しない）は変わらない。
- プラグイン（`@capacitor-mlkit/barcode-scanning`）は、使っていない同梱の ML Kit のバーコードのモデルと CameraX もアプリに入れる。ML Kit の開示は同じなので回答は変わらないが、アプリが大きくなる。

- 依存が増えていないか: `mobile/android/app/build.gradle`・`capacitor.build.gradle`・`mobile/package.json` のプラグイン。
