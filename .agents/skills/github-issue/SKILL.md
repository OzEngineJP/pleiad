# issue を登録する

このリポジトリは公開されている。issue の本文・タイトル・コメントは誰でも読める。

1. **作るか決める。** 利用者が頼んだときだけ作る（自分で気づいた課題は、タイトルとラベルの一覧で確かめてから）。1 つの課題に 1 つ。`gh issue list --state all --search "<語>"` で重複を見て、近いものがあればコメントか本文の「関連」に `#<番号>` を書く。
2. **本文を書く。** 参照はリポジトリにあるもの（`docs/` の節・ADR の番号・コードのファイル）だけ。`temporary/` の下は読者が開けないので書かない。`temporary/issues/<nn>-<題>.md` に Write tool で書く。
3. **伏せ漏れを見る。** 手元のパス・名前・アカウント・キー・社名や顧客名・使用量の実数・実データの画面を入れない（パスは `~`・`<作業場所>` にする。画像は fake で撮ったものだけ）。
4. **参照先を確かめる。** 書いたファイル・ADR の番号が実在するかを `git ls-files`・`ls docs/adr` で見る。
5. **登録する。** `gh issue create --title "<領域>：<内容>" --label "<ラベル>" --body-file temporary/issues/<nn>-<題>.md`。ラベルは `gh label list` から選ぶ。
6. **報告する。** 番号・URL・タイトルを一覧で返す。

## 本文の型

```markdown
## 概要
何が起きるか・何が足りないかを 1〜3 文で。どの版からか。

## 現状
- 事実の箇条書き。推測は「原因（推測）」に分ける。再現の手順があれば版・OS・バックエンド・モデルも。

## 期待する挙動（作業なら「やりたいこと」）
- どうなってほしいか。案が複数なら並べる。

## 関連
- #<番号>、ADR <番号>、`docs/<ファイル>` の節、コードのファイル
```
